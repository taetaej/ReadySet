# SlotBoard 공지 모달 기획 가이드

SlotBoard 진입 시 뜨는 공지 모달의 **기획 기준**이다. 새 공지를 띄우거나 기존 공지를 교체할 때,
"무엇을 넣고, 어떤 톤으로 쓰고, 어떤 뱃지를 다는가"를 이 문서로 판단한다.
(파일: `src/components/reachcaster/SlotBoardNoticeModal.tsx`)

## 0. 이 모달은 무엇인가 — 성격 정의

- SlotBoard에 들어온 사용자에게 **"한 번은 보고 넘어가야 할 소식"**을 전하는 1회성 알림이다.
- 쓰는 경우: 새 솔루션 오픈, 중요한 기능 업데이트, 기간성 이벤트/점검 안내.
- 쓰지 않는 경우: 상시로 알아야 하는 기능 설명·사용법(→ Docs/툴팁/SpinX), 개인화된 알림(→ 알림 센터).
- **한 번에 하나의 소식만** 다룬다. 여러 소식을 한 모달에 욱여넣지 않는다. 가장 중요한 하나만 고른다.

## 1. 공지에 꼭 들어가야 하는 요소 (필수 구성)

위에서 아래로 다음 순서를 지킨다. 요소를 늘리지 않는다.

| 요소 | 필수 | 내용 기준 |
|---|---|---|
| 뱃지(상태 라벨) | O | 소식의 성격을 한 단어로. (유형은 2번 참조) |
| 제목 | O | 무슨 소식인지 한눈에. 솔루션명·핵심 키워드를 담아 짧게. |
| 본문 | O | 1~2줄. "그래서 사용자가 뭘 얻는가"를 말한다. 기능 나열 금지. |
| 주 CTA(행동 버튼) | O | "이 소식으로 사용자가 할 다음 행동" 하나. 보통 "자세히 알아보기 → Docs". |
| 게시 기간 | O | 시작일·종료일을 반드시 정한다. 끝나면 저절로 사라져야 한다. |
| 닫기 수단 | O | 쉽게 닫고 "오늘 하루 안 보기"로 미룰 수 있어야 한다. |

- **게시 종료일 없는 공지는 만들지 않는다.** 영구 노출되는 공지는 공지가 아니라 소음이다.
- CTA가 가는 곳은 Slot이 없어도 항상 열리는 안내 페이지여야 한다. (특정 Slot/시나리오로 바로 보내지 않는다)

## 2. 뱃지(상태 라벨) 유형

소식의 성격에 맞춰 아래 중 하나를 고른다. **한 공지에 뱃지는 하나.**

| 뱃지 | 언제 | 예시 상황 |
|---|---|---|
| `NEW` | 신규 솔루션·기능 첫 오픈 | BudgetOpt 2.0 신규 오픈 |
| `UPDATE` | 기존 기능의 눈에 띄는 개선 | 결과 화면 차트 개편, 내보내기 추가 |
| `EVENT` | 기간성 이벤트·캠페인 안내 | 사용성 설문, 한정 프로모션 |
| `NOTICE` | 운영 공지·점검·정책 변경 | 정기 점검, 약관 변경 안내 |

- 뱃지는 **무채색**으로 둔다. 뱃지에 색을 넣어 강조하지 않는다. (강조는 CTA 하나뿐 — `ui-design-principles`)
- 위 4종으로 부족하면 새 유형을 늘리기 전에 "정말 다른 성격인가"를 먼저 따진다. 유형이 많아지면 의미가 흐려진다.

## 3. 카피 톤

- **함께·돕는 톤.** 사용자를 가르치는 뉘앙스는 피한다.
  - (지양) "~를 이해할 수 있어요" → (지향) "~를 분석할 수 있어요 / 해볼 수 있어요"
- 숫자·기능을 늘어놓지 말고 **사용자가 얻는 결과**를 말한다.
  - (지양) "매체별 최적화, SpinX 해석, 결과 분석 기능 제공"
  - (지향) "더 정교해진 모델이 예산 배분을 설계하고, SpinX와 함께 더 쉽고 깊이 있게 분석할 수 있어요"
- 전문 용어(KPI·CPM·GRP 등)는 그대로 쓴다. 쉬운 말로 바꾸면 오히려 전문성이 떨어진다. (`user-guide-docs-guide`)
- 과장·호들갑 금지. 느낌표 남발, "최고의/역대급" 같은 표현은 쓰지 않는다. 담백하게.
- 제목은 소식, 본문은 가치, CTA는 행동 — 역할이 겹치지 않게 쓴다.

## 4. 노출·빈도 원칙 (기획 판단)

- SlotBoard **메인 화면 진입 시에만** 뜬다. 작업 중인 화면(생성/수정/상세)을 가로막지 않는다.
- "오늘 하루 안 보기"는 **그날만** 숨기는 장치다. 영구 숨김이 아니다. 다음 날 다시 보여 소식을 놓치지 않게 한다.
- 새 소식으로 교체하면 이전에 "안 보기" 한 사용자에게도 다시 노출된다. **소식이 바뀌면 반드시 새 공지로 교체**한다. (문구만 슬쩍 고치지 않는다)
- 공지는 한 번에 하나. 겹치는 기간에 두 소식이 생기면 **더 중요한 하나를 고르고** 나머지는 기간을 미룬다.

- [ ] 필수 요소(뱃지·제목·본문·CTA·게시기간·닫기)가 다 있나?
- [ ] 게시 종료일을 정했나? (영구 노출 금지)
- [ ] 뱃지 유형이 소식 성격과 맞나? 뱃지는 하나뿐인가? 무채색인가?
- [ ] 본문이 기능 나열이 아니라 "사용자가 얻는 것"인가? 가르치는 톤이 아닌가?
- [ ] CTA가 Slot 유무와 무관하게 항상 열리는 곳으로 가나?
- [ ] 강조가 CTA 한 곳뿐인가? (뱃지·그라디언트·부양효과로 강조를 분산하지 않았나)
