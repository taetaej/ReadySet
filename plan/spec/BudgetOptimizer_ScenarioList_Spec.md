## 1. 화면 개요

### 1.1 기능 정의
특정 Slot에 속한 **Budget Optimizer 시나리오 목록**을 조회·관리하는 화면임. 시나리오를 검색·필터·정렬해 찾고, 완료된 시나리오는 결과 화면으로 진입하며, 복제·이동·삭제 같은 관리 작업을 수행함.

**기획 의도**: 한 Slot에서 생성한 여러 예산 최적화 시나리오를 한눈에 비교·관리하게 함. 완료 여부·KPI·예산·기간을 목록에서 바로 파악하고, 완료 시나리오는 클릭 한 번으로 결과로 진입하게 함. 관리 작업(이동/삭제)은 Reach Caster 시나리오 목록과 동일한 인터랙션을 제공해 학습 비용을 낮춤.

### 1.2 문서 활용처
- **개발 참고**: 프론트엔드 구현 시 화면 동작·규칙·표기 기준 문서로 활용됨.
- **제품 Docs**: 본 정의서의 기능 설명·의도가 사용자 대상 기능 문서의 기반이 됨.
- **AI 기반 TC 생성**: 검색·필터·정렬·선택·관리 작업 규칙(Section 4~7)이 테스트 케이스의 원천 데이터가 됨. 각 규칙은 조건 → 기대 결과로 검증 가능하게 작성함.

### 1.3 진입 경로
- SNB(사이드바) Budget Optimizer 클릭, SlotHome 솔루션 카드, SlotBoard 등에서 진입함.
- URL: /budgetoptimizer
- Breadcrumb: SlotBoard / {Slot명} / Budget Optimizer

### 1.4 화면 구조 (세로 흐름)
Slot 헤더(SlotHeader, Reach Caster 공용)
→ 타이틀("Budget Optimizer") + New Scenario 버튼
→ 액션바(좌: 시나리오 개수 / 우: 선택 시 일괄작업 · 검색 · 필터)
→ 시나리오 테이블
→ 페이지네이션

## 2. 레이아웃

- 상단은 Reach Caster와 공용인 SlotHeader(광고주·Slot 정보)를 사용함.
- 본문(workspace-content): 타이틀 라인 → 액션바 → 테이블 → 페이지네이션 순의 세로 흐름임.
- 타이틀 라인 좌측에 "Budget Optimizer" 제목과 원형 New Scenario 버튼(＋)을 둠. 클릭 시 /budgetoptimizer/scenario/new로 이동함.
- 관리 작업 결과는 우상단 토스트로 안내함(성공/실패, 3초 자동 닫힘).

## 3. 액션바

좌측에 현재 필터 적용된 시나리오 개수("N Scenarios")를 표시하고, 우측에 액션(선택 시 일괄작업 → 검색 → 필터)을 배치함.

| 요소 | 노출 조건 | 동작 |
|---|---|---|
| N Scenarios | 항상 | 검색·필터 적용 후 결과 개수(filteredScenarios 기준) |
| N개 선택됨 | 1개 이상 선택 시 | 현재 선택된 시나리오 수 |
| 이동 버튼 | 1개 이상 선택 시 | 이동 다이얼로그 열기(Section 7.1) |
| 삭제 버튼 | 1개 이상 선택 시 | 선택 항목을 삭제 대상으로 삭제 다이얼로그 열기(Section 7.2) |
| 검색 | 항상 | 클릭 시 검색 입력창 확장(Section 4) |
| 필터 | 항상 | 클릭 시 필터 드롭다운 열기, 적용 개수 배지 표시(Section 5) |

## 4. 검색

| 항목 | 규칙 |
|---|---|
| 트리거 | 검색 버튼 클릭 시 입력창(폭 300px)으로 확장, autoFocus |
| 검색 대상 | 시나리오명 + 생성자(creator) 동시 |
| 매칭 방식 | 부분 일치(substring), **대소문자 무시** |
| 공백 처리 | 입력값 앞뒤 공백을 트리밍(trim) 후 비교. 공백만 입력한 경우 검색 미적용(전체 표시) |
| 타이밍 | onChange 실시간 필터(디바운스 없음) |
| placeholder | "시나리오명, 생성자 검색" |
| 결과 없을 때 | 별도 "검색 결과 없음" 문구는 두지 않고, 테이블 빈 상태(Section 7.3)로 빠짐 |
| 닫힘 | 입력값이 빈 상태에서 blur 시 버튼으로 축소. X 버튼 클릭 시 검색어 초기화 + 축소 |

- **기획 의도**: 시나리오명뿐 아니라 생성자로도 즉시 찾게 해, 협업 환경에서 "누가 만든 시나리오"를 빠르게 탐색하게 함.

## 5. 필터

필터 버튼 클릭 시 드롭다운을 열며, 적용된 항목 수를 버튼에 배지로 표시함. 3개 그룹(상태/KPI/업종) 모두 다중 선택 체크박스임. UI 톤앤매너는 Reach Caster 시나리오 목록 필터와 동일함.

| 그룹 | 항목 | 매칭 |
|---|---|---|
| 상태 | Completed / Processing / Pending / Error | 선택한 상태만 노출(OR) |
| KPI | 노출(Impression) / 클릭(Click) / 조회(View) / 도달(Reach) | 선택한 KPI만 노출(OR) |
| 업종 | 시나리오 데이터에서 수집한 고유 업종 목록 | 선택한 업종만 노출(OR). 목록이 길면 영역 내 스크롤 |

- **다중 그룹 조합**: 서로 다른 그룹 간에는 AND로 적용됨(예: 상태=Completed AND KPI=클릭).
- **적용 개수 배지**: 상태+KPI+업종 선택 수의 합(activeFilterCount).
- **필터 초기화**: 드롭다운 하단 버튼으로 세 그룹 모두 해제함(항상 노출).
- **스크롤**: 드롭다운과 업종 목록 스크롤은 톤온톤(custom-scrollbar) 스타일을 사용함.

## 6. 정렬

정렬 가능한 컬럼 헤더 클릭으로 정렬함. 같은 컬럼을 다시 클릭하면 방향이 토글됨(오름/내림). 다른 컬럼 클릭 시 해당 컬럼 기준 **내림차순**으로 시작함.

체크박스·컨텍스트 메뉴를 제외한 **모든 데이터 컬럼이 정렬 대상**임(Reach Caster 시나리오 목록과 동일).

| 컬럼 | 정렬 필드 | 정렬 방식 |
|---|---|---|
| ID | id | 숫자 비교 |
| 시나리오 | name | 문자열 비교 |
| 업종 | industry | 문자열 비교 |
| KPI | kpi(KPI_LABELS 기준) | 문자열 비교 |
| 총 예산 | totalBudget | 숫자 비교 |
| 기간 | 시작일(startDate) | 일시 비교 |
| 상태 | status | 문자열 비교 |
| 생성자 | creator | 문자열 비교 |
| 생성일시 | created | 일시 비교(초기 정렬 기준) |

- **초기 상태**: 생성일시(created) **내림차순** — 최신 생성 시나리오가 위로 옴.
- **토글 규칙**: 같은 컬럼 재클릭 시 방향 토글(오름↔내림). 다른 컬럼 클릭 시 그 컬럼 기준 **내림차순**으로 시작함.
- **방향 표시**: 활성 정렬 컬럼 헤더에만 화살표 아이콘 표시(오름=위, 내림=아래).
- **정렬 적용 시점**: 검색·필터가 적용된 결과에 정렬을 적용하고, 그 뒤 페이지네이션으로 분할함.
- **기간 정렬 기준**: 시작일(startDate) 기준으로 정렬함.
- **KPI 정렬 기준**: 표시 라벨(KPI_LABELS) 문자열 기준으로 정렬함.

## 7. 테이블

### 7.1 컬럼

| 컬럼 | 내용 | 비고 |
|---|---|---|
| 체크박스 | 행 선택 | 헤더 체크박스는 현재 페이지 전체 선택/해제 |
| ID | #{id} | muted 표기 |
| 시나리오 | 시나리오명 | 완료 상태만 강조(진입 가능), 그 외는 흐리게 |
| 업종 | industry | muted |
| KPI | 한글+영문 라벨(KPI_LABELS) | primary 톤 뱃지 |
| 총 예산 | 금액(원) | 정수 + "원", 천 단위 콤마(축약 없음) |
| 기간 | 시작일 → 종료일 | 각 yyyy-mm-dd, 2줄 표기 |
| 상태 | 상태 뱃지 | Processing은 진행 단계 표기(아래) |
| 생성자 | creator | 이메일은 마스킹(maskEmail) |
| 생성일시 | created | **yyyy-mm-dd hh:mm** 형식(초 미표기) |
| (컨텍스트 메뉴) | ⋮ | 행별 복제/이동/삭제(Section 7.4) |

### 7.2 행 클릭 · 상태별 동작

| 상태 | 행 클릭 | 표시 |
|---|---|---|
| Completed | 결과 화면으로 이동(/budgetoptimizer/scenario/{id}/result) | 시나리오명 정상 강조, 커서 pointer |
| Processing | 진입 불가 | 진행 단계 설명 + 진행률(5단계) 표시 |
| Pending | 진입 불가 | 대기 상태 뱃지 |
| Error | 진입 불가 | Error 뱃지 |

- **Processing 단계 설명(5단계)**: 1 입력 조건 분석 중 / 2 예산 배분 최적화 중 / 3 최적 배분 성과 예측 중 / 4 결과 시각화 중 / 5 완료.
- 완료가 아닌 시나리오는 이름을 흐리게(opacity) 처리해 진입 불가를 시각적으로 알림.

### 7.3 빈 상태
- 조건: 현재 페이지에 표시할 시나리오가 없음.
- 문구: "아직 생성된 시나리오가 없습니다." + "새 시나리오를 생성하여 최적 예산 배분을 탐색하세요."

### 7.4 행 컨텍스트 메뉴 (⋮)

| 항목 | 동작 |
|---|---|
| 복제 | 복제 처리 후 성공 토스트 |
| 이동 | 해당 시나리오를 선택 상태로 두고 이동 다이얼로그 열기 |
| 삭제 | 해당 시나리오를 삭제 대상으로 두고 삭제 다이얼로그 열기(destructive 색) |

- 메뉴 외부 클릭 시 닫힘.

## 8. 선택 및 관리 작업 (이동/삭제 다이얼로그)

일괄 작업(액션바 버튼)과 행 컨텍스트 메뉴 모두 동일한 다이얼로그를 사용함. Reach Caster 시나리오 목록과 동일한 패턴임.

### 8.1 이동 다이얼로그
- 제목: "시나리오 이동", 설명: "선택한 N개 시나리오를 다른 Slot으로 이동합니다."
- 이동 대상 Slot을 select로 선택함(광고주 동일 Slot 목록). **미선택 시 이동 버튼 비활성**.
- 확정 시: (시뮬레이션) 처리 후 성공 토스트 "N개 시나리오가 성공적으로 이동되었습니다.", 선택 해제. 실패 시 오류 토스트.
- 취소/닫기 시: 선택한 대상 Slot 값 초기화.

### 8.2 삭제 다이얼로그
- 제목: "시나리오를 삭제하시겠습니까?", 설명: "선택한 N개 시나리오를 삭제하면 복원할 수 없습니다. 정말로 삭제하시겠습니까?"
- 확정(삭제, destructive) 시: 목록에서 해당 시나리오 제거 + 성공 토스트 "N개 시나리오가 성공적으로 삭제되었습니다.", 선택 해제. 실패 시 오류 토스트.
- 취소 시: 삭제 대상 초기화, 목록 변화 없음.

### 8.3 토스트
- 성공/오류 2종. 우상단 노출, 3초 후 자동 닫힘. 닫기 버튼 제공.

## 9. 페이지네이션
- **페이지당 표시 개수 선택**: 10 / 20 / 50 중 선택(기본 10). 변경 시 첫 페이지로 이동함.
- 정렬·필터 적용 후 결과 기준으로 페이지 분할함.
- 처음/이전/페이지 번호/다음/마지막 이동을 제공함. 첫 페이지·마지막 페이지에서는 해당 방향 버튼이 비활성됨.
- 페이지 정보 표기: "{시작}-{끝} / {전체}개"(결과 0건이면 0으로 표기).
- 전체 선택 체크박스는 **현재 페이지** 항목 기준으로 동작함.

## 10. 검증 포인트 (TC 도출)
- 검색어에 시나리오명 일부/생성자 일부 입력 → 해당 항목만 노출되는가(대소문자 무시).
- 상태=Completed AND KPI=클릭 필터 → 두 조건을 모두 만족하는 시나리오만 노출되는가.
- 필터 배지 숫자 = 선택한 상태+KPI+업종 항목 수와 일치하는가.
- 생성일시 헤더 재클릭 시 오름/내림이 토글되는가. 초기 진입 시 생성일시 내림차순인가.
- ID/시나리오/업종/KPI/총 예산/기간/상태/생성자/생성일시 각 헤더 클릭 시 해당 기준으로 정렬되는가(다른 컬럼 클릭 시 내림차순으로 시작).
- ID/총 예산은 숫자, 나머지는 문자열/일시 기준으로 정렬되는가.
- Completed 행 클릭 → 결과 화면으로 이동하는가. Processing/Pending/Error 행 클릭 → 이동하지 않는가.
- 시나리오 1개 이상 선택 → 이동/삭제 버튼이 노출되는가. 0개면 숨는가.
- 이동 다이얼로그에서 대상 Slot 미선택 시 이동 버튼이 비활성인가.
- 삭제 확정 시 해당 시나리오가 목록에서 제거되고 성공 토스트가 뜨는가.
- 페이지당 10개 초과 시 페이지네이션이 동작하고, 전체 선택이 현재 페이지 기준인가.
- 빈 목록에서 안내 문구("아직 생성된 시나리오가 없습니다.")가 노출되는가.
- 검색·필터로 결과가 0건이 된 경우에도 빈 상태 문구가 노출되는가(별도 "검색 결과 없음" 문구는 없음).
- 검색어 앞뒤에 공백을 넣어도 트리밍되어 공백 없는 검색과 동일한 결과가 나오는가. 공백만 입력 시 전체가 표시되는가.
- 페이지당 표시 개수를 10→20→50으로 바꾸면 페이지 분할이 반영되고 첫 페이지로 이동하는가.
- 이동/삭제 처리 실패 시 오류 토스트가 뜨는가 — 이동: "시나리오 이동에 실패했습니다. 다시 시도해주세요.", 삭제: "시나리오 삭제에 실패했습니다. 다시 시도해주세요."
- 삭제 다이얼로그에서 취소 시 목록이 그대로 유지되고 선택이 해제되지 않는가.
- 이동 다이얼로그를 취소/닫기 하면 선택한 대상 Slot 값이 초기화되는가.

## 11. 데이터 개념 및 용어 매핑
- 시나리오 데이터: BOScenario(구현 파일 types.ts). 주요 필드 — name, industry, kpi(impression/click/view/reach), totalBudget, startDate/endDate, status(Pending/Processing/Completed/Error), processStep/totalSteps, created, creator/creatorId.
- KPI 라벨: KPI_LABELS(한글+영문 혼용). 상태 뱃지 스타일: STATUS_STYLES.
- **날짜/시간 표기**: 생성일시·완료일시는 **yyyy-mm-dd hh:mm**(초 미표기), 기간의 시작일·종료일은 **yyyy-mm-dd**로 표기함. 원본 데이터는 초까지 보유하나 화면에서는 분까지만 노출함.
- 정확한 타입·필드는 구현 파일을 참조함.

## 12. 개선 제안 (이 화면 한정)

에이전트 제안 → 기획자 채택 결정 구조. 이 목록 화면 범위 안의 개선만 다룸.

| 제안 | 내용 | 사용자 가치 | 상태 |
|---|---|---|---|
| 페이지당 개수 선택 | 페이지당 표시 개수를 10/20/50 중 선택 | 대량 시나리오 탐색 효율 | **구현 완료**(Section 9) |
| 검색 공백 트리밍 | 검색어 앞뒤 공백을 트리밍 후 매칭 | 실수 공백으로 결과가 비는 혼란 방지 | **구현 완료**(Section 4) |
| 검색 결과 없음 전용 문구 | "생성된 시나리오 없음"과 "검색 결과 없음"을 구분 표기 | 빈 상태 원인을 명확히 인지 | 검토 필요 |
| 정렬/필터 상태 URL 유지 | 정렬·필터 상태를 URL 쿼리로 유지해 새로고침·공유 시 복원 | 링크 공유·재진입 시 컨텍스트 보존 | 미채택 |
| 복제 결과 반영 | 복제 시 토스트만이 아니라 목록에 신규 항목 즉시 추가 | 복제 결과를 바로 확인 | 검토 필요 |
