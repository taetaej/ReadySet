## 1. 화면 개요

### 1.1 기능 정의
Budget Optimizer에서 새 시나리오를 생성하는 3단계 위자드 화면. 기본 정보 입력 → 상세 설정(매체/예산) → 검토 및 실행 순서로 진행한다.

**기획 의도**: 사용자가 KPI 목표와 총 예산, 분석 대상 매체/상품을 설정하면, 모델이 **매체·상품 간 최적 예산 배분안**을 도출한다. 일부 예산을 사용자가 직접 "잠금(고정)"하고 나머지만 최적화하는 부분 최적화를 지원하는 것이 이 화면의 핵심 가치다.

### 1.2 문서 활용처
- **개발 참고**: 프론트엔드 구현 시 화면 동작·규칙·제약의 기준 문서로 활용된다.
- **제품 Docs**: 본 정의서의 기능 설명·의도가 사용자 대상 기능 문서의 기반이 된다.
- **AI 기반 TC 생성**: 유효성 규칙(Section 5)과 인터랙션 규칙(Section 12)이 테스트 케이스의 원천 데이터가 된다. 각 규칙은 `조건 → 기대 결과`로 검증 가능하게 작성한다.

### 1.3 진입 경로
- SlotBoard → Slot Home → "Budget Optimizer" 선택 → "New Scenario"
- URL: `/budgetoptimizer/scenario/new`

### 1.4 위자드 구조

```
Step 1: 기본 정보 → Step 2: 상세 설정 → Step 3: 검토 및 실행
```

| 2 | 설명 | ❌ | Textarea | 최대 200자, 우측 하단 카운터(n/200), 세로 리사이즈 가능 | — |

- 업종 선택 안내 문구: "업종별 특화 최적화 모델(Meridian 활용)로 시나리오를 생성합니다."

### 3.2 업종 선택 방식

| 방식 | 설명 | 용도 |

**22개 업종 목록**:
화장품, 자동차, 식품, 건강식품, 전자제품, 패션, 여행, 게임, 이커머스, 금융, 교육, 부동산, 통신, 유통, 엔터테인먼트, 스포츠, 의료, 가전, 주류, 생활용품, 가구/인테리어, 반려동물

### 3.3 KPI 선택 카드

각 카드: 아이콘 + KPI명 + 설명. 선택 시 primary border + `primary/0.1` 배경.

| KPI | 아이콘 (lucide) | 설명 |
|------|--------|------|
| 노출 (Impression) | Eye | 노출 수 최대화 |
| 클릭 (Click) | MousePointerClick | 클릭 수 최대화 |
| 조회 (View) | Play | 조회 수 최대화 |
| 도달 (Reach) | Users | 도달률 최대화 |

- 안내 문구: "최적화할 KPI를 1개 선택하세요. 선택한 KPI를 극대화하는 방향으로 예산이 배분됩니다."

### 3.4 브랜드 드롭다운

- 검색 필드 포함 (Search 아이콘, autoFocus)
- **검색 방식**: 브랜드명 부분 일치(substring), 대소문자 무시, 실시간 필터
- 각 항목: 브랜드명 + 업종 뱃지
- 선택 시 업종 자동 세팅 → 드롭다운 우측에 "업종 | {업종명}" 읽기 전용 뱃지 표시
- 선택 후 검색어 초기화, 드롭다운 닫힘
- 샘플 브랜드 → 업종 매핑: 설화수/이니스프리→화장품, 현대자동차→자동차, CJ제일제당→식품, 종근당건강→건강식품, 삼성전자→전자제품, 나이키코리아→패션, 하나투어→여행, 넥슨→게임, 쿠팡→이커머스

### 3.4.1 업종 직접 선택 드롭다운

- 22개 업종 단순 리스트 (검색 필드 없음)

## 4. Step 2: 상세 설정

### 4.1 화면 구성

```
┌──────────────────────────────────────────────────────────────────┐
│  총 예산 입력 (고정폭)                                             │
├──────────────────────────────────────────────────────────────────┤
│  [매체 · 상품 추가] (총 예산 미입력 시 disabled)                    │
├──────────────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────────────────┐│
│  │ 예산 잠금 설정 테이블 (매체 / 상품 | 잠금 | 잠금 금액 | 삭제)  ││
│  │ ┌────────┬──────────┬──────────┬────────────────┐            ││
│  │ │ 매체   │ 잠금     │ 잠금 금액 │ 삭제           │            ││
│  │ ├────────┼──────────┼──────────┼────────────────┤            ││
│  │ │ Google │ Lock     │          │ ×              │            ││
│  │ │  상품A │ Lock     │ 5,000,000│ ×              │            ││
│  │ │  상품B │ Unlock   │ 최적화대상│ ×              │            ││
│  │ └────────┴──────────┴──────────┴────────────────┘            ││
│  └──────────────────────────────────────────────────────────────┘│
├──────────────────────────────────────────────────────────────────┤
│  Summary: 총 예산 / 잠금 예산 합계 / 잔여 예산 (최적화 대상 N개)     │
└──────────────────────────────────────────────────────────────────┘
```

- 잠금 토글은 lucide-react `Lock`/`Unlock` 아이콘 사용 (이모지 미사용)
- 비잠금 행의 잠금 금액 칸에는 "최적화 대상" 텍스트 표시
- Empty State: 상품 미추가 시 "분석할 매체와 상품을 추가해주세요" 안내 박스 표시

### 4.2 입력 필드

| # | 필드 | 필수 | 타입 | 제한 |
|---|------|------|------|------|
| 1 | 총 예산 | ✅ | Text (천 단위 콤마) | > 0, 원 단위, **최대 11자리(99,999,999,999원 = 999억)**, 고정폭 입력 필드 |
| 2 | 매체/광고상품 선택 | ✅ | Dialog (복수 선택) | 최소 2개 상품 |
| 3 | 예산 잠금 토글 | ❌ | Toggle (Lock/Unlock 아이콘) | 행별 ON/OFF |
| 4 | 잠금 금액 | 조건부 | Text (천 단위 콤마) | 잠금 ON 시 필수, > 0, **최대 11자리(999억)** |

> 총 예산 입력 필드는 콘텐츠 변화에 따라 축소되지 않도록 고정폭 사용 (정확한 폭은 구현 코드 기준)
> 금액 입력(총 예산·잠금 금액)은 숫자만 허용하며 11자리 초과 입력은 차단됨
> 잠금 토글은 이모지가 아닌 lucide-react `Lock`/`Unlock` 아이콘 사용

### 4.2.1 매체·상품 추가 버튼 제어

- 총 예산 미입력(≤ 0) 시 "매체 · 상품 추가" 버튼 **비활성화**
- 비활성 시 안내 문구: "총 예산을 먼저 입력해주세요."

### 4.3 매체/상품 추가 다이얼로그 (BOMediaDialog)

- 다이얼로그 타이틀: "매체 및 상품 선택", 설명: "분석에 포함할 매체와 상품을 선택하세요"
- 상단 안내(Info 아이콘): "Step1에서 선택한 업종의 모델 학습 결과가 있는 광고상품만 표시됩니다."
- 8개 매체 리스트: Google Ads, Meta, NAVER 보장형 DA, NAVER 성과형 DA, kakao 모먼트, TikTok, SMR, Targetpick
- 매체 > 광고상품 2depth 아코디언 구조 (매체 펼침/접힘)
- 매체 단위 선택 시 해당 매체의 모든 상품을 개별 행으로 추가
- 상품 단위 개별 선택 가능
- **검색 필터**:
  - 대상: 매체명 + 상품명 동시 검색
  - 방식: **부분 일치(substring)**, **대소문자 무시**, 공백 트리밍 없음(입력 그대로 비교)
  - 실시간(onChange) 필터링, 디바운스 없음
  - 매체명이 검색어와 일치하면 해당 매체의 모든 상품 노출, 상품명이 일치하면 해당 상품만 노출
  - 검색 결과 없는 매체는 리스트에서 숨김
- **매체 행 전체 선택/해제**: 버튼 라벨은 현재 검색 필터 결과 기준으로 "전체 선택"/"전체 해제" 토글. 필터된 상품만 대상
- **검색 결과 전체 선택**: 상단 버튼, 현재 필터된 모든 매체·상품 대상 토글
- **개별 상품 선택**: 체크박스(label) 클릭 토글
- **매체 아코디언**: 매체 행 또는 +/- 버튼 클릭 시 펼침/접힘
- **선택 카운트**: 매체 행에 선택 수 뱃지, 하단에 "선택됨: {선택}/{전체}" 표시
- **초기화(Reset)**: 선택/펼침/검색 상태 전체 리셋
- **기존 선택 복원**: 다이얼로그 재오픈 시 기존 선택 상품 상태 복원 (오픈 시 1회 초기화)
- **잠금 상태 유지**: 확인 시 이미 추가된 상품의 잠금(isFixed/fixedAmount) 상태 보존, 신규 상품은 `isFixed: false, fixedAmount: 0`
- **취소/오버레이 클릭**: 변경 취소 후 닫힘, 검색어 초기화

### 4.4 테이블 계층 구조

```
매체 (Parent Row)
  ├── 광고상품 1 (Child Row)
  ├── 광고상품 2 (Child Row)
  └── 광고상품 3 (Child Row)
```

- 매체 행: 하위 상품을 그룹핑하는 부모 행
- 매체 행에 잠금을 걸면 → 매체 전체에 고정 금액 배정 (하위 상품은 그 안에서 최적화)
- 상품 행에 잠금을 걸면 → 해당 상품에만 고정 금액 배정

### 4.5 잔여 예산 (배분 가능 예산) 계산

```
배분 가능 예산 = 총 예산
  - Σ(잠금된 매체의 잠금 금액)
  - Σ(상위 매체가 잠금되지 않은 상품의 잠금 금액)
```

**중복 차감 방지 규칙**:
- 매체 행이 잠금된 경우, 해당 매체 하위 상품의 잠금 금액은 이미 매체 잠금 금액에 포함된 것으로 간주
- 따라서 하위 상품의 잠금 금액을 별도로 차감하지 않음

### 4.6 잔여 예산 표시

| 상태 | 표시 |
|------|------|
| 정상 (≥ 0) | `배분 가능 예산: {금액} 원` (primary 색상) |
| 초과 (< 0) | `배분 가능 예산: -{금액} 원` (destructive 색상 + 경고 아이콘) |

## 5. Step 2: 유효성 검증 규칙

### 5.0 규칙 번호 체계

규칙은 검증 대상에 따라 5개 그룹(A~E)으로 분류하고, 그룹 내에서 순차 번호(V1~V10)를 부여한다. 소통 시 "V6"처럼 번호로 지칭한다.

| 그룹 | 분류 | 포함 규칙 | 에러 레벨 |
|------|------|-----------|-----------|
| A | 기본 입력 | V1, V2 | 글로벌/필드 |
| B | 잠금 금액 입력 | V3 | 필드 (행 인라인) |
| C | 매체-상품 계층 (매체 잠금 시) | V4, V5, V6 | 매체 행 인라인 |
| D | 매체 미잠금 조합 | V7 | 매체 행 인라인 |
| E | 예산 배분 전역 | V8, V9, V10 | 글로벌 |

> 참고: "중복 차감 방지"는 에러 규칙이 아닌 계산 규칙이므로 번호를 부여하지 않는다 (4.5절 참조).

### 5.1 규칙 요약

| # | 그룹 | 규칙명 | 조건 | 에러 레벨 |
|---|------|--------|------|-----------|

| V10 | E | 잔여 예산 수령처 존재 | 배분 가능 예산 > 0 + 비잠금 매체 없음 | 글로벌 |

### 그룹 B · 잠금 금액 입력

#### V3: 잠금 금액 필수

**조건**: `row.isFixed === true && (!row.fixedAmount || row.fixedAmount <= 0)` (매체 행/상품 행 공통)
**에러 메시지**: `"잠금 금액을 입력해주세요."`
**표시 위치**: 해당 행의 잠금 금액 입력 필드 하단

### 그룹 C · 매체-상품 계층 (매체 잠금 시)

**기획 의도**: 매체를 잠그면 그 매체 전체에 고정 예산이 배정되고, 하위 상품은 **그 매체 잠금 금액 범위 안에서** 배분된다. 따라서 하위 상품 잠금의 합이 매체 잠금 금액과 논리적으로 모순되지 않아야 한다(초과 불가, 남는 예산 없이 배분 불가한 상태 방지). 매체가 잠금된 경우 하위 상품의 잠금 상태에 따라 V4~V6로 분기한다. (표시 위치 공통: 매체 행 하단 인라인)

#### V4: 하위 잠금 합계 초과

**조건**:
```
매체.isFixed === true
&& Σ(하위 잠금 상품의 잠금 금액) > 매체.fixedAmount
```
**에러 메시지**: `"하위 상품 잠금 금액 합계({합계}원)가 매체 잠금 금액({매체금액}원)을 초과합니다."`
**정상 통과 예**: 매체 잠금 100만, 하위 잠금 합계 60만 (< 100만) → 통과 (나머지 40만은 비잠금 하위에 배분)

#### V5: 하위 비잠금 상품 배분 불가

**조건**:
```
매체.isFixed === true
&& 비잠금 하위 상품 존재
&& Σ(하위 잠금 상품의 잠금 금액) >= 매체.fixedAmount
```
**에러 메시지**: `"하위 비잠금 상품에 배분할 예산이 없습니다. 매체 잠금 금액을 늘리거나 상품 잠금을 해제해주세요."`
**왜**: 비잠금 하위 상품이 있는데 잠금 합계가 매체 금액과 같거나 크면, 최적화할 예산이 0 이하가 되어 최적화 대상이 무의미해진다.
**경계값**: 합계 = 매체 금액 → 위반 / 합계 < 매체 금액 → 통과

#### V6: 하위 전부 잠금 + 합계 불일치

**조건**:
```
매체.isFixed === true
&& 하위 상품 전부 잠금
&& Σ(하위 잠금 상품의 잠금 금액) ≠ 매체.fixedAmount
```
**에러 메시지**: `"모든 상품이 잠금되어 있으나 합계({합계}원)가 매체 잠금 금액({매체금액}원)과 다릅니다. 비잠금 상품을 추가하거나, 잠금 금액 합계를 매체 금액과 동일하게 맞춰주세요."`
**왜**: 하위가 전부 잠금이면 배분할 최적화 여지가 없으므로, 하위 잠금 합계가 매체 잠금 금액과 정확히 일치해야만 예산이 어긋나지 않는다.
**경계값**: 합계 = 매체 금액 → 통과 / 합계 ≠ 매체 금액 → 위반

---

### 그룹 D · 매체 미잠금 조합

#### V7: 매체 미잠금 + 하위 전부 잠금

**조건**:
```
media.isFixed === false
&& media.children.length > 0
&& media.children.every(c => c.isFixed === true)
```
**에러 메시지**: `"[매체명]의 모든 상품이 잠금되어 있습니다. 매체도 잠금하거나, 일부 상품의 잠금을 해제해주세요."`
**표시 위치**: 해당 매체 행 하단 인라인
**왜**: 매체가 잠금이 아닌데 하위 상품이 전부 잠금이면, 그 매체는 최적화에 기여하지 못하면서 의도(매체 잠금)도 불명확해진다. 의도를 명확히 하도록 안내한다.
**정상 통과 예**: 하위 3개 중 1개라도 비잠금이면 통과

---

### 그룹 E · 예산 배분 전역

#### V8: 잔여 예산 ≥ 0

**조건**: `배분가능예산 < 0`
**에러 메시지**: `"잠금 예산 합계가 총 예산을 초과합니다."`
**표시 위치**: 잔여 예산 표시 영역 (글로벌)
**왜**: 잠금 예산 합이 총 예산을 넘으면 배분 자체가 불가능하다.
**경계값**: 배분가능예산 = 0 → 통과(단, V9/V10과 조합 확인) / < 0 → 위반

#### V9: 최적화 대상 ≥ 2

**카운트 방식**: 매체 잠금 여부와 무관하게, 모든 비잠금 상품(상품 레벨)을 카운트한다.
```typescript
const unlockedProductCount = allProducts.filter(p => !p.isFixed).length
// V9 위반: unlockedProductCount < 2
```
**에러 메시지**: `"최적화를 위해 잠금되지 않은 항목이 2개 이상 필요합니다."`
**표시 위치**: 테이블 하단 글로벌 영역
**왜**: 최적화는 여러 항목 간 예산을 재분배하는 것이므로, 비교·배분 대상이 최소 2개는 있어야 의미가 있다.
**경계값**: 비잠금 상품 2개 → 통과 / 1개 이하 → 위반

#### V10: 잔여 예산 수령처 존재

**조건**:
```
배분가능예산 > 0
&& 비잠금 매체가 0개 (모든 매체가 잠금)
```
**에러 메시지**: `"잔여 예산을 배분할 비잠금 매체가 없습니다. 매체를 추가하거나 잠금을 해제해주세요."`
**표시 위치**: 테이블 하단 글로벌 영역
**왜**: 잔여 예산이 남았는데 이를 받을 비잠금 매체가 없으면(모든 매체 잠금), 남은 예산이 어디에도 배분되지 못하고 공중에 뜬다.
**정상 통과 예**: 비잠금 매체가 1개 이상 존재하면 잔여 예산 배분 가능 → 통과

### 7.1 위치 및 스타일

- 우측 고정폭 패널, 스크롤 시 sticky로 상단 고정
- 좌측 폼 영역과 세로 구분선으로 분리
- 모든 스텝에서 실시간 반영

### 7.2 표시 항목

| 섹션 | 항목 |
|------|------|
| Step 1 · Basic Information | 시나리오명, 업종, 브랜드(선택 시), KPI, 캠페인 기간 |
| Step 2 · Media & Budget | 선택 상품 수, 총 예산, 예산 잠금 상품 수, 매체별 상품 그룹 |
| Step 3 · Review & Execute | Step 3 도달 시 "검토" + "확인 완료" 표시 |

### 7.3 매체별 상품 그룹 표시

- 선택된 상품을 **매체명으로 그룹핑**하여 표시
- 매체명 헤더 + 하위 상품 칩 나열
- **매체 잠금 시**: 매체명 앞에 Lock 아이콘 표시
- **상품 잠금 시**: 상품 칩을 primary 강조색 + Lock 아이콘으로 표시
- **비잠금 상품**: 기본(muted) 칩, 아이콘 없음
- 자물쇠 이모지(🔒) 사용하지 않음 — lucide-react `Lock` 아이콘 사용

### 7.4 미입력 항목 표시

- 미입력 필드: `—`
- 입력 완료 필드: 실제 값 표시

### 8.1 버튼 활성화 조건

### 8.2 버튼 스타일 (Reach Caster 동일)

| 버튼 | 클래스 | 아이콘 |
|------|--------|--------|
| 취소 | `btn btn-ghost btn-lg` | — |
| 이전 | `btn btn-secondary btn-lg` | ChevronLeft (좌측) |

- 네비게이션 버튼 영역 **상단 구분선 없음** (폼과 여백만 두고 배치)
- 좌측 폼과 우측 Configuration Summary 사이의 세로 구분선은 유지

### 8.3 화면 이탈 방지 (Exit Guard)

**기획 의도**: 위자드는 입력 단계가 많아 실수로 이탈하면 작성 내용이 유실된다. 입력 중 이탈 시 확인 절차를 두어 데이터 유실을 방지한다. (Reach Caster / DataShot 시나리오 생성과 동일한 공통 훅 `useExitGuard` 사용)

**활성 조건 (isDirty)**: 입력값이 하나라도 존재하면 활성화. 단, 업종 선택 방식의 기본값(`브랜드 선택`)은 사용자 입력으로 보지 않는다.

| 이탈 경로 | 동작 |
|-----------|------|
| 브라우저 새로고침/탭 닫기 | `beforeunload` 브라우저 기본 경고 |
| 브라우저 뒤로가기 | `popstate` 가로채기 → 확인 다이얼로그 |
| 취소 버튼 / 사이드바 워크스페이스 이동 | 확인 다이얼로그 |
| 시나리오 생성 요청 성공 후 | Guard 해제 (경고 없이 이동) |

**확인 다이얼로그**:
- 타이틀: "페이지를 떠나시겠습니까?"
- 본문: "작성 중인 내용은 저장되지 않습니다."
- 버튼: [계속 작성] (머무름) / [나가기] (이탈 진행)

**TC 참고**: 입력 없음 → 이탈 시 다이얼로그 미표시(통과) / 입력 있음 → 이탈 시 다이얼로그 표시(위반 아님, 정상 동작) / 제출 성공 후 이동 → 다이얼로그 미표시

## 9. 에러 메시지 스타일

에러 표시 원칙 (구체 수치·색상 값은 디자인 시스템 토큰 / 구현 코드 기준):

- 모든 유효성 에러/경고는 **단일 destructive(에러) 스타일**로 통일 — warning 색상이나 이모지 미사용
- 에러 메시지는 해당 필드/영역 하단에 작은 텍스트로 표시
- 에러가 있는 입력 필드는 **테두리를 에러 색으로 강조**
- 색상은 `--destructive` 토큰 사용

## 10. 데이터 개념 및 용어 매핑

> 상세 타입 정의(인터페이스)는 구현 코드가 단일 진실 공급원이다 (`src/components/budgetoptimizer/types.ts`, `BOCreateScenario.tsx`). 여기서는 규칙·플로우 이해에 필요한 개념과 용어 매핑만 정리한다.

### 10.1 구조적 특징

- 선택된 광고상품은 **flat 배열**로 관리하고, 매체 레벨 잠금은 **별도 상태**로 관리한다.
- 매체-상품 계층은 매체 식별자(`mediaId`)로 연결한다. (매체 행은 하위 상품을 그룹핑하는 부모 역할)

### 10.2 UI 용어 ↔ 데이터 필드 매핑

| UI 용어 | 데이터 필드 | 비고 |
|---------|------------|------|
| 예산 잠금 (ON/OFF) | `isFixed` | UI는 "잠금", 데이터는 `isFixed`로 통일 |
| 잠금 금액 | `fixedAmount` | 잠금 시 필수, > 0 |
| 매체 잠금 | 매체 레벨 `isFixed` / `fixedAmount` | 매체 전체 고정 금액 |
| 상품 잠금 | 상품 레벨 `isFixed` / `fixedAmount` | 개별 상품 고정 금액 |

> 유효성 규칙(Section 5)에서 사용하는 `isFixed`, `fixedAmount`는 위 매핑을 따른다.

## 12. 인터랙션 플로우

### 12.1 정상 플로우

```
1. SlotBoard → Slot Home → "Budget Optimizer" 선택 → "New Scenario" → 위자드 진입
2. Step 1: 기본 정보 입력 → "다음" 클릭
3. Step 2: 매체/상품 추가 → 예산 입력 → 잠금 설정 (선택) → "다음" 클릭
4. Step 3: 설정 검토 → "시나리오 생성 요청" 클릭
5. 비동기 API 호출 → 성공 토스트 → Slot Home으로 이동
```

### 12.2 에러 플로우 예시

```
사용자가 총 예산 10,000,000원 입력
→ Google Ads 매체 잠금: 6,000,000원
→ Meta 매체 잠금: 5,000,000원
→ 배분 가능 예산 = 10,000,000 - 6,000,000 - 5,000,000 = -1,000,000
→ V8 발동: "잠금 예산 합계가 총 예산을 초과합니다." (destructive)
→ "다음" 버튼 disabled
```

### 12.3 V7 시나리오 (매체 미잠금 + 하위 전부 잠금)

```
사용자가 Google Ads 매체 추가 (잠금 OFF)
→ 하위 상품 A 잠금 ON
→ 하위 상품 B 잠금 ON
→ 하위 상품 C (마지막 상품) 잠금 ON
→ V7 발동: "Google Ads의 모든 상품이 잠금되어 있습니다. 매체도 잠금하거나, 일부 상품의 잠금을 해제해주세요." (destructive)
→ "다음" 버튼 disabled
```

### 12.4 V10 시나리오 (잔여 예산 수령처 부재)

```
총 예산 10억, 매체는 NAVER 성과형 DA 1개만 추가
→ 매체 잠금 1,000만원
→ 배분 가능 예산 = 10억 - 1,000만 = 9억 9,000만 (> 0)
→ 그러나 비잠금 매체가 없어 9억 9,000만을 배분할 곳이 없음
→ V10 발동: "잔여 예산을 배분할 비잠금 매체가 없습니다. 매체를 추가하거나 잠금을 해제해주세요."
→ "다음" 버튼 disabled
```

### 12.5 V6 시나리오 (하위 전부 잠금 + 합계 불일치)

```
매체 잠금 100,000원
→ 하위 상품 4개 전부 잠금, 각 10,000원 (합계 40,000원)
→ 합계 40,000 ≠ 매체 잠금 100,000
→ V6 발동: "모든 상품이 잠금되어 있으나 합계(40,000원)가 매체 잠금 금액(100,000원)과 다릅니다. ..."
→ "다음" 버튼 disabled
```

## 13. 공통 입력/인터랙션 규칙

개발 시 추측이 필요 없도록 공통 동작을 명시한다. (TC 생성의 직접 입력이 되므로 동작 결과를 명확히 기재)

### 금액 입력 (총 예산 / 잠금 금액)

| 항목 | 규칙 |
|------|------|
| 입력 타입 | `type="text"` (number 아님) |
| 표시 포맷 | 천 단위 콤마 자동 삽입 (`toLocaleString`) |
| 파싱 | 입력값에서 콤마 제거 후 `parseInt`, 숫자 아니면 `0` |
| 입력 제한 | 숫자만 허용(비숫자 입력 무시), **최대 11자리(999억) 초과 입력 차단** |
| 단위 | 원, 입력 필드 우측에 "원" 접미사 표시 |
| 총 예산 보조 | 값 > 0일 때 한글 금액 표기 병기 (`numberToKorean`) |
| 소수점 | 미허용 (정수 원 단위) |
| 적용 대상 | 총 예산, 매체 잠금 금액, 상품 잠금 금액 (동일 규칙) |

### 검색 (공통)

| 항목 | 규칙 |
|------|------|
| 매칭 방식 | 부분 일치(substring), 대소문자 무시 |
| 타이밍 | onChange 실시간, 디바운스 없음 |
| 초기화 | 항목 선택/다이얼로그 닫힘 시 검색어 리셋 |

### 텍스트 입력 제한

| 필드 | 규칙 |
|------|------|
| 시나리오명 | `maxLength=30`, 초과 입력 차단, 카운터 표시 |
| 설명 | `maxLength=200`, 초과 입력 차단, 카운터 표시, 세로 리사이즈 허용 |

### 토글/삭제

| 항목 | 규칙 |
|------|------|
| 잠금 토글 OFF 전환 | 잠금 해제 시 해당 행 `fixedAmount`를 0으로 초기화 |
| 매체 삭제 | 해당 매체의 모든 하위 상품 + 매체 잠금 상태 함께 제거 |
| 상품 삭제 | 해당 상품 행만 제거 |
| 매체 추가 시 | 새로 추가된 매체는 자동 펼침(expand) |

## 14. 개선 제안 (이 화면 한정)

> 시나리오 생성 위자드 **화면 자체**에 대한 개선 후보다. 목록/결과/솔루션 레벨 기능(시나리오 복사, What-If, AI 배분 추천 등)은 이 화면의 범위가 아니므로 각 해당 화면 정의서에서 다룬다.
> 아래는 에이전트가 제안하는 항목이며, 채택 여부는 기획자가 결정한다.

| 제안 | 내용 | 사용자 가치 | 상태 |
|------|------|-------------|------|
| 임시 저장(Draft) | 위자드 진행 상태를 임시 저장하고 이어서 작성 | 긴 설정 작업 중단/재개 지원 | 미채택 |
| 예산 잠금 프리셋 | Step2에서 자주 쓰는 잠금 구성을 저장/재적용 | 반복 설정 시간 절감 | 미채택 |
| 총 예산 대비 잠금 비율 표시 | 잠금 예산이 총 예산에서 차지하는 %를 실시간 표기 | 배분 감각 향상, V8 사전 인지 | 검토 필요 |

> 채택되어 구현된 항목: **페이지 이탈 방지** → Section 8.3으로 승격 (v1.8)

> 제안 추가/변경 시 위 표에 행으로 관리한다.
