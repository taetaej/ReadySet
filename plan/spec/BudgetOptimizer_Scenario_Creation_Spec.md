## 1. 화면 개요

Budget Optimizer에서 새 시나리오를 생성하는 3단계 위자드 화면. 기본 정보 입력 → 매체/예산 설정 → 검토 및 실행 순서로 진행한다.

- Slot 상세 화면 → 시나리오 생성 → "Budget Optimizer" 선택

```
Step 1: 기본 정보 → Step 2: 매체/예산 설정 → Step 3: 검토 및 실행
```

## 4. Step 2: 상세 설정

폼 영역 너비 900px.

### 4.1 화면 구성

```
┌──────────────────────────────────────────────────────────────────┐
│  총 예산 입력 (너비 400px 고정)                                    │
├──────────────────────────────────────────────────────────────────┤
│  [매체 · 상품 추가] (총 예산 미입력 시 disabled)                    │
├──────────────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────────────────────┐│
│  │ 예산 잠금 설정 테이블 (매체 / 상품 | 잠금 | 잠금 금액 | 삭제)  ││
│  │ ┌────────┬──────────┬──────────┬────────────────┐            ││
│  │ │ 매체   │ 잠금     │ 잠금 금액 │ 삭제           │            ││
│  │ ├────────┼──────────┼──────────┼────────────────┤            ││
│  │ │ Google │ Lock     │          │ ×              │            ││
│  │ │  상품A │ Lock     │ 5,000,000│ ×              │            ││
│  │ │  상품B │ Unlock   │ 최적화대상│ ×              │            ││
│  │ └────────┴──────────┴──────────┴────────────────┘            ││
│  └──────────────────────────────────────────────────────────────┘│
├──────────────────────────────────────────────────────────────────┤
│  Summary: 총 예산 / 잠금 예산 합계 / 잔여 예산 (최적화 대상 N개)     │
└──────────────────────────────────────────────────────────────────┘
```

- 잠금 토글은 lucide-react `Lock`/`Unlock` 아이콘 사용 (이모지 미사용)
- 비잠금 행의 잠금 금액 칸에는 "최적화 대상" 텍스트 표시
- Empty State: 상품 미추가 시 "분석할 매체와 상품을 추가해주세요" 안내 박스 표시

### 4.2 입력 필드

| # | 필드 | 필수 | 타입 | 제한 |
|---|------|------|------|------|
| 1 | 총 예산 | ✅ | number (천 단위 콤마) | > 0, 원 단위, 입력 필드 너비 400px 고정 |
| 2 | 매체/광고상품 선택 | ✅ | 다이얼로그 (복수 선택) | 최소 2개 상품 |
| 3 | 예산 잠금 토글 | ❌ | toggle (Lock/Unlock 아이콘) | 행별 ON/OFF |
| 4 | 잠금 금액 | 조건부 | number (천 단위 콤마) | 잠금 ON 시 필수, > 0 |

> 총 예산 입력 필드는 `width: 400px` 고정 (콘텐츠 변화에 따라 축소되지 않음)
> 잠금 토글은 이모지가 아닌 lucide-react `Lock`/`Unlock` 아이콘 사용

### 4.2.1 매체·상품 추가 버튼 제어

- 총 예산 미입력(≤ 0) 시 "매체 · 상품 추가" 버튼 **비활성화**
- 비활성 시 안내 문구: "총 예산을 먼저 입력해주세요."

### 4.3 매체/상품 추가 다이얼로그 (BOMediaDialog)

- 다이얼로그 타이틀: "매체 및 상품 선택", 설명: "분석에 포함할 매체와 상품을 선택하세요"
- 상단 안내(Info 아이콘): "Step1에서 선택한 업종의 모델 학습 결과가 있는 광고상품만 표시됩니다."
- 8개 매체 리스트: Google Ads, Meta, NAVER 보장형 DA, NAVER 성과형 DA, kakao 모먼트, TikTok, SMR, Targetpick
- 매체 > 광고상품 2depth 아코디언 구조 (매체 펼침/접힘)
- 매체 단위 선택 시 해당 매체의 모든 상품을 개별 행으로 추가
- 상품 단위 개별 선택 가능
- **검색 필터**:
  - 대상: 매체명 + 상품명 동시 검색
  - 방식: **부분 일치(substring)**, **대소문자 무시**, 공백 트리밍 없음(입력 그대로 비교)
  - 실시간(onChange) 필터링, 디바운스 없음
  - 매체명이 검색어와 일치하면 해당 매체의 모든 상품 노출, 상품명이 일치하면 해당 상품만 노출
  - 검색 결과 없는 매체는 리스트에서 숨김
- **매체 행 전체 선택/해제**: 버튼 라벨은 현재 검색 필터 결과 기준으로 "전체 선택"/"전체 해제" 토글. 필터된 상품만 대상
- **검색 결과 전체 선택**: 상단 버튼, 현재 필터된 모든 매체·상품 대상 토글
- **개별 상품 선택**: 체크박스(label) 클릭 토글
- **매체 아코디언**: 매체 행 또는 +/- 버튼 클릭 시 펼침/접힘
- **선택 카운트**: 매체 행에 선택 수 뱃지, 하단에 "선택됨: {선택}/{전체}" 표시
- **초기화(Reset)**: 선택/펼침/검색 상태 전체 리셋
- **기존 선택 복원**: 다이얼로그 재오픈 시 기존 선택 상품 상태 복원 (오픈 시 1회 초기화)
- **잠금 상태 유지**: 확인 시 이미 추가된 상품의 잠금(isFixed/fixedAmount) 상태 보존, 신규 상품은 `isFixed: false, fixedAmount: 0`
- **취소/오버레이 클릭**: 변경 취소 후 닫힘, 검색어 초기화

### 4.4 테이블 계층 구조

```
매체 (Parent Row)
  ├── 광고상품 1 (Child Row)
  ├── 광고상품 2 (Child Row)
  └── 광고상품 3 (Child Row)
```

- 매체 행: 하위 상품을 그룹핑하는 부모 행
- 매체 행에 잠금을 걸면 → 매체 전체에 고정 금액 배정 (하위 상품은 그 안에서 최적화)
- 상품 행에 잠금을 걸면 → 해당 상품에만 고정 금액 배정

### 4.5 잔여 예산 (배분 가능 예산) 계산

```
배분 가능 예산 = 총 예산
  - Σ(잠금된 매체의 잠금 금액)
  - Σ(상위 매체가 잠금되지 않은 상품의 잠금 금액)
```

**중복 차감 방지 규칙**:
- 매체 행이 잠금된 경우, 해당 매체 하위 상품의 잠금 금액은 이미 매체 잠금 금액에 포함된 것으로 간주
- 따라서 하위 상품의 잠금 금액을 별도로 차감하지 않음

### 4.6 잔여 예산 표시

| 상태 | 표시 |
|------|------|
| 정상 (≥ 0) | `배분 가능 예산: {금액} 원` (primary 색상) |
| 초과 (< 0) | `배분 가능 예산: -{금액} 원` (destructive 색상 + 경고 아이콘) |

## 5. Step 2: 유효성 검증 규칙

### 5.0 규칙 번호 체계

규칙은 검증 대상에 따라 5개 그룹(A~E)으로 분류하고, 그룹 내에서 순차 번호(V1~V10)를 부여한다. 소통 시 "V6"처럼 번호로 지칭한다.

| 그룹 | 분류 | 포함 규칙 | 에러 레벨 |
|------|------|-----------|-----------|
| A | 기본 입력 | V1, V2 | 글로벌/필드 |
| B | 잠금 금액 입력 | V3 | 필드 (행 인라인) |

| V1 | A | 총 예산 입력 | 총 예산 미입력 또는 ≤ 0 | 필드 (총 예산) |

### 그룹 A · 기본 입력

#### V1: 총 예산 입력

**조건**: `!totalBudget || totalBudget <= 0`
**에러 메시지**: `"총 예산을 입력해주세요."`
**표시 위치**: 총 예산 입력 필드 하단

#### V2: 최소 상품 수

**조건**: `products.length < 2`
**에러 메시지**: `"최소 2개 이상의 상품을 추가해주세요."`
**표시 위치**: 테이블 상단 글로벌 영역

---

### 그룹 B · 잠금 금액 입력

#### V3: 잠금 금액 필수

**조건**: `row.isFixed === true && (!row.fixedAmount || row.fixedAmount <= 0)` (매체 행/상품 행 공통)
**에러 메시지**: `"잠금 금액을 입력해주세요."`
**표시 위치**: 해당 행의 잠금 금액 입력 필드 하단

---

### 그룹 C · 매체-상품 계층 (매체 잠금 시)

매체가 잠금된 경우, 하위 상품의 잠금 상태에 따라 V4~V6로 분기한다. (표시 위치 공통: 매체 행 하단 인라인)

#### V4: 하위 잠금 합계 초과

**조건**:
```
매체.isFixed === true
&& Σ(하위 잠금 상품의 잠금 금액) > 매체.fixedAmount
```
**에러 메시지**: `"하위 상품 잠금 금액 합계({합계}원)가 매체 잠금 금액({매체금액}원)을 초과합니다."`

#### V5: 하위 비잠금 상품 배분 불가

**조건**:
```
매체.isFixed === true
&& 비잠금 하위 상품 존재
&& Σ(하위 잠금 상품의 잠금 금액) >= 매체.fixedAmount
```
**에러 메시지**: `"하위 비잠금 상품에 배분할 예산이 없습니다. 매체 잠금 금액을 늘리거나 상품 잠금을 해제해주세요."`

#### V6: 하위 전부 잠금 + 합계 불일치

**조건**:
```
매체.isFixed === true
&& 하위 상품 전부 잠금
&& Σ(하위 잠금 상품의 잠금 금액) ≠ 매체.fixedAmount
```
**에러 메시지**: `"모든 상품이 잠금되어 있으나 합계({합계}원)가 매체 잠금 금액({매체금액}원)과 다릅니다. 비잠금 상품을 추가하거나, 잠금 금액 합계를 매체 금액과 동일하게 맞춰주세요."`

---

### 그룹 D · 매체 미잠금 조합

#### V7: 매체 미잠금 + 하위 전부 잠금

**조건**:
```
media.isFixed === false
&& media.children.length > 0
&& media.children.every(c => c.isFixed === true)
```
**에러 메시지**: `"[매체명]의 모든 상품이 잠금되어 있습니다. 매체도 잠금하거나, 일부 상품의 잠금을 해제해주세요."`
**표시 위치**: 해당 매체 행 하단 인라인

---

### 그룹 E · 예산 배분 전역

#### V8: 잔여 예산 ≥ 0

**조건**: `배분가능예산 < 0`
**에러 메시지**: `"잠금 예산 합계가 총 예산을 초과합니다."`
**표시 위치**: 잔여 예산 표시 영역 (글로벌)

#### V9: 최적화 대상 ≥ 2

**카운트 방식**: 매체 잠금 여부와 무관하게, 모든 비잠금 상품(상품 레벨)을 카운트한다.
```typescript
const unlockedProductCount = allProducts.filter(p => !p.isFixed).length
// V9 위반: unlockedProductCount < 2
```
**에러 메시지**: `"최적화를 위해 잠금되지 않은 항목이 2개 이상 필요합니다."`
**표시 위치**: 테이블 하단 글로벌 영역

#### V10: 잔여 예산 수령처 존재

**조건**:
```
배분가능예산 > 0
&& 비잠금 매체가 0개 (모든 매체가 잠금)
```
**에러 메시지**: `"잔여 예산을 배분할 비잠금 매체가 없습니다. 매체를 추가하거나 잠금을 해제해주세요."`
**표시 위치**: 테이블 하단 글로벌 영역

## 10. 데이터 구조

> 실제 구현(`BOCreateScenario.tsx`)은 상품을 flat 배열(`products`)로 관리하고, 매체 레벨 잠금은 별도 배열(`mediaFixed`)로 관리한다. 매체-상품 계층은 `mediaId`로 연결한다.

### 10.1 BOFormData

```typescript
interface BOFormData {
  // Step 1
  scenarioName: string;              // 최대 30자
  description: string;               // 최대 200자
  industryMode: 'brand' | 'direct' | '';
  brand: string;                     // industryMode === 'brand' 시
  industry: string;                  // 22개 업종 중 1
  period: { start: string; end: string };
  kpi: string;                       // 'impression' | 'click' | 'view' | 'reach' | ''

  // Step 2
  totalBudget: number;
  products: BOProductEntry[];        // 선택된 광고상품 (flat)
  mediaFixed: BOMediaFixed[];        // 매체 레벨 잠금 상태
}
```

### 10.2 BOProductEntry / BOMediaFixed

```typescript
interface BOProductEntry {
  mediaId: string;                   // 매체명 (Google Ads, Meta, ...)
  productName: string;               // 광고상품명
  isFixed: boolean;                  // 상품 예산 잠금 여부
  fixedAmount: number;               // 잠금 금액 (잠금 시 필수, > 0)
}

interface BOMediaFixed {
  mediaId: string;                   // 매체명
  isFixed: boolean;                  // 매체 예산 잠금 여부
  fixedAmount: number;               // 매체 잠금 금액 (잠금 시 필수, > 0)
}
```

> 용어 참고: 데이터 필드명은 `isFixed`/`fixedAmount`를 사용하나, UI 노출 용어는 모두 "잠금"으로 통일한다.

### 10.3 유효성 상태 (개념)

```typescript
interface BOStep2ValidationState {
  groupCErrors: { mediaId: string; message: string }[];   // V4·V5·V6 (매체 계층)

  v7Errors: { mediaId: string; message: string }[];       // V7 매체 미잠금 + 하위 전부 잠금
  v8Error: string | null;                                 // 잔여 예산 < 0
  v9Error: string | null;                                 // 최적화 대상 < 2
  v10Error: string | null;                                // 잔여 예산 수령처 부재
  isValid: boolean;
}
```

## 12. 인터랙션 플로우

### 12.1 정상 플로우

```
1. Slot 상세 → 시나리오 생성 → "Budget Optimizer" 선택 → 위자드 진입
2. Step 1: 기본 정보 입력 → "다음" 클릭
3. Step 2: 매체/상품 추가 → 예산 입력 → 잠금 설정 (선택) → "다음" 클릭
4. Step 3: 설정 검토 → "실행" 클릭
5. 비동기 API 호출 → 성공 토스트 → Slot 상세로 이동
```

### 12.2 에러 플로우 예시

```
사용자가 총 예산 10,000,000원 입력
→ Google Ads 매체 잠금: 6,000,000원
→ Meta 매체 잠금: 5,000,000원
→ 배분 가능 예산 = 10,000,000 - 6,000,000 - 5,000,000 = -1,000,000
→ V8 발동: "잠금 예산 합계가 총 예산을 초과합니다." (destructive)
→ "다음" 버튼 disabled
```

### 12.3 V7 시나리오 (매체 미잠금 + 하위 전부 잠금)

```
사용자가 Google Ads 매체 추가 (잠금 OFF)
→ 하위 상품 A 잠금 ON
→ 하위 상품 B 잠금 ON
→ 하위 상품 C (마지막 상품) 잠금 ON
→ V7 발동: "Google Ads의 모든 상품이 잠금되어 있습니다. 매체도 잠금하거나, 일부 상품의 잠금을 해제해주세요." (destructive)
→ "다음" 버튼 disabled
```

### 12.4 V10 시나리오 (잔여 예산 수령처 부재)

```
총 예산 10억, 매체는 NAVER 성과형 DA 1개만 추가
→ 매체 잠금 1,000만원
→ 배분 가능 예산 = 10억 - 1,000만 = 9억 9,000만 (> 0)
→ 그러나 비잠금 매체가 없어 9억 9,000만을 배분할 곳이 없음
→ V10 발동: "잔여 예산을 배분할 비잠금 매체가 없습니다. 매체를 추가하거나 잠금을 해제해주세요."
→ "다음" 버튼 disabled
```

### 12.5 V6 시나리오 (하위 전부 잠금 + 합계 불일치)

```
매체 잠금 100,000원
→ 하위 상품 4개 전부 잠금, 각 10,000원 (합계 40,000원)
→ 합계 40,000 ≠ 매체 잠금 100,000
→ V6 발동: "모든 상품이 잠금되어 있으나 합계(40,000원)가 매체 잠금 금액(100,000원)과 다릅니다. ..."
→ "다음" 버튼 disabled
```

## 12.6 공통 입력/인터랙션 규칙

개발 시 추측이 필요 없도록 공통 동작을 명시한다.

### 금액 입력 (총 예산 / 잠금 금액)

| 항목 | 규칙 |
|------|------|
| 입력 타입 | `type="text"` (number 아님) |
| 표시 포맷 | 천 단위 콤마 자동 삽입 (`toLocaleString`) |
| 파싱 | 입력값에서 콤마 제거 후 `parseInt`, 숫자 아니면 `0` (`parseInt(v.replace(/,/g,'')) || 0`) |
| 단위 | 원, 입력 필드 우측에 "원" 접미사 표시 |
| 총 예산 보조 | 값 > 0일 때 한글 금액 표기 병기 (`numberToKorean`) |
| 소수점 | 미허용 (정수 원 단위) |

### 검색 (공통)

| 항목 | 규칙 |
|------|------|
| 매칭 방식 | 부분 일치(substring), 대소문자 무시 |
| 타이밍 | onChange 실시간, 디바운스 없음 |
| 초기화 | 항목 선택/다이얼로그 닫힘 시 검색어 리셋 |

### 텍스트 입력 제한

| 필드 | 규칙 |
|------|------|
| 시나리오명 | `maxLength=30`, 초과 입력 차단, 카운터 표시 |
| 설명 | `maxLength=200`, 초과 입력 차단, 카운터 표시, 세로 리사이즈 허용 |

### 토글/삭제

| 항목 | 규칙 |
|------|------|
| 잠금 토글 OFF 전환 | 잠금 해제 시 해당 행 `fixedAmount`를 0으로 초기화 |
| 매체 삭제 | 해당 매체의 모든 하위 상품 + 매체 잠금 상태 함께 제거 |
| 상품 삭제 | 해당 상품 행만 제거 |
| 매체 추가 시 | 새로 추가된 매체는 자동 펼침(expand) |
