## A. 화면 개요

### A.1 기능 정의 · 기획 의도

광고상품 조회(상세) 화면 상단에 **"Benchmark Analytics"** 영역으로 차트 2종을 나란히 제공함. 선택한 업종의 과거 집행 실적을 집계해, 사용자가 "다음 캠페인을 짤 때 참고"하도록 도움. **순수 참고용**이며, 이 차트의 데이터로 어떤 액션(배분 조정 등)을 강제하지 않음. "아~ 이 업종은 이렇구나" 수준의 디깅.

- **차트 1 — Cost Share**: "이 업종에선 돈을 **어디에 어떻게 나눠** 썼나?" (미디어믹스 배분 참고) — 상세 §C.1
- **차트 2 — Efficiency Map**: "그렇게 나눠 담았을 때, **내가 고른 것들 중 뭐가 효율적**이었나?" (선택 상품 간 효율 비교) — 상세 §C.2

두 차트는 **한 세트**임. 같은 대상(선택 매체/상품)을 "배분(비중)"과 "효율" 두 각도로 봄. 그래서 **"많이 쓴 것 ≠ 효율 좋은 것"**이라는 엇갈림이 두 차트를 오가며 자연스럽게 읽히는 것이 핵심 가치임.

- **지표 전제**: 두 차트의 지표는 데이터셋 생성 시 사용자가 고른 지표와 무관하게 **매체 공통 지표(9종)로 고정**됨(매체 간 비교가 성립하려면 지표 기준이 통일돼야 하므로). 상세·근거는 §B.4. (하단 Extracted 로우 데이터 테이블은 이 공통 지표 고정의 **대상이 아님** — 거긴 선택 지표를 그대로 노출.)

### A.2 문서 활용처

- **개발 참고**: 프론트엔드 구현 시 차트 동작·계산·표기 기준. 구현 파일은 §H.
- **제품 Docs**: 차트가 "무엇을 보여주고 어떻게 읽는가"의 사용자 설명 기반.
- **AI 기반 TC 생성**: 유효성 규칙(§D)·표시 규칙이 테스트 케이스 원천. 각 규칙은 `조건 → 기대 결과`로 검증 가능하게 작성.

### A.3 진입 경로

| 화면 | 위치 | 진입 조건 |
|---|---|---|
| Benchmark Analytics | `/datashot/:id`(광고상품 상세) 상단 | 추출 기준 `광고상품` + 제공 조건(§B.1) 충족 업종 존재 |

- 조건 조합 상세에는 이 영역이 없음. 광고상품 다매체 결과 전용임.

## B. 레이아웃 · 공통 컨트롤

### B.1 제공 조건

- 업종 단위 기준 **광고상품 3개 이상**인 업종만 Benchmark Analytics 영역을 제공함.
  - 매체 수는 제공 조건에 포함하지 않음(매체 뷰 토글 활성 여부에만 영향 — §B.3).
  - **왜 3개 이상인가**: 상품 2개면 도넛 2조각·산점도 2점이라 분석 가치가 낮음. 비교로 의미가 나오는 최소선을 3개로 둠.
- **제공 가능 업종이 하나도 없을 때(= 차트 영역 전체 미달)**:
  - Benchmark Analytics 영역에 **안내 배너**만 표시하고, 업종 드롭다운·매체/상품 뷰 토글·클릭/조회 탭 등 모든 컨트롤을 숨김.
  - **안내 문구**: Benchmark Analytics는 한 업종에 광고상품이 3개 이상 집행된 경우에만 표시됩니다.
- **강제 미달 플래그(`chartInsufficient`)**: 
  - 특정 데이터셋이 결과 차트 제공 조건에 못 미치는 **엣지 케이스를 재현**하기 위한 플래그. 플래그가 켜지면 실데이터 집계 결과와 무관하게 위 "차트 영역 전체 미달" 안내 배너만 표시함. (데모/엣지 확인용.)
  - **차트2 엣지 데모 플래그(`chartEdgeDemo`)**: 한 데이터셋에서 **업종 드롭다운 전환만으로 차트 엣지들을 모두 확인**하도록, 엣지 전용 업종 세트를 쓰게 하는 플래그. 모든 엣지 업종은 **상품 3개 이상**이라 제공 조건(R1)을 통과해 드롭다운에 노출되며, 매체 수 / 클릭(>0) 상품 수 / 조회(>0) 상품 수 분포만 달리해 각 엣지를 드러냄. (목록 샘플 `id: 17` = `[엣지] 차트 케이스 모음`.)

  | 업종(데모) | 구성 | 드러나는 규칙 |
  |---|---|---|
  | 패션 | 상품 3 · 매체 2개↑ · 클릭·조회 모두 ≥2 | (정상) 두 차트 다 정상 렌더 |
  | 식품 | 상품 3 · **고유 매체 1개** | V4·V5 — '매체' 토글 비활성 + 상품 뷰 강제 |
  | 화장품및보건용품 | 상품 3 · **클릭(>0) 1개**, 조회(>0) ≥2 | V7 — 진입 시 조회 탭 자동 선택, 클릭 탭 누르면 블러 플레이스홀더("클릭 성과…") |
  | 컴퓨터및정보통신 | 상품 3 · **조회(>0) 1개**, 클릭(>0) ≥2 | V8 — 진입 시 클릭 탭 자동 선택, 조회 탭 누르면 블러 플레이스홀더("조회 성과…") |
  | 금융보험및증권 | 상품 3 · **클릭(>0) ≤1 그리고 조회(>0) ≤1** | E5 — 클릭/조회 토글 숨김 + 블러 플레이스홀더(통합 문구 "클릭·조회 성과…") |

  > 엣지4(둘 다 부족)는 상품 3개를 "클릭만 / 조회만 / 둘 다 0(인지형)"으로 구성함. 둘 다 0인 상품도 노출·비용은 있어 **차트1(비중)엔 등장**하지만, 차트2는 클릭·조회 모두 대상 ≤1이라 E5로 빠짐.

### B.2 공통 컨트롤 (두 차트 공유)

| 컨트롤 | 범위 | 동작 |
|---|---|---|
| 업종 드롭다운 | 두 차트 공유 | 제공 조건 충족 업종만 노출. 선택 업종을 두 차트가 공유 |
| 매체 / 상품 뷰 토글 (우상단) | 두 차트 공유 | "매체 단위" ↔ "상품 단위" 전환 (§B.3 비활성 규칙) |
| 클릭 / 조회 탭 | **차트 2 전용** | 차트 1에는 영향 없음 (§C.2.2) |
| "분석 차트 제공 기준" 팝업 (돋보기) | 제목 옆 | 돋보기(`SearchCheck`) 클릭 → 제공 기준 안내 + 공통 지표 매핑표 팝업 (§B.4) |

### B.3 매체 뷰 토글 비활성 규칙 (단일 매체 업종)

매체/상품 뷰 토글은 **두 차트 공유** 컨트롤이므로, 이 비활성 규칙도 **차트1·차트2 모두**에 적용됨(단일 매체 업종이면 두 차트 다 상품 단위로 묶임).

- **조건**: 선택 업종의 매체 종류 수(고유 매체 수)가 **1개 이하**이면 '매체' 토글을 **비활성**.
- **왜**: 매체가 하나뿐이면 매체별 비중은 100% 1조각이라 비교 가치가 없음. 상품 단위 비교만 의미.
- **동작**: hover 시 title "단일 매체 업종은 매체별 보기를 제공하지 않습니다". 클릭해도 전환 안 됨.
- **강제 상품 뷰 (부수효과)**: 비활성인데 현재 뷰가 '매체'면(다매체 업종 보다가 단일 매체로 전환 시) 자동으로 '상품' 뷰로 되돌림. (차트2 매체 뷰 산출 §C.2.7도 이 규칙 때문에 단일 매체에선 열리지 않음.)

### B.4 공통 지표 기준 (차트 지표 고정 + 안내 팝업)

**왜 공통 지표인가**: 광고상품 추출은 여러 매체를 가로질러 비교하는 화면임. 그런데 매체마다 원본 지표의 이름·정의가 다름(예: 광고비 = Meta "광고 소진금액" / kakao "비용"). 매체 간 비교가 성립하려면 지표 기준이 하나로 통일돼야 하므로, 두 차트는 **매체 공통 지표로 고정**해 그림.

- **적용 범위**: **차트(Benchmark Analytics)에만** 적용됨. 데이터셋 생성 시 사용자가 어떤 지표를 골랐든, 또 업종에 매체가 하나뿐이거나 데이터셋 자체가 단일 매체여도, 차트 지표는 공통 지표 기준으로 구현됨.
- **대상 아님**: 하단 **Extracted 로우 데이터 테이블**은 공통 지표 고정의 대상이 **아님**(선택 지표를 그대로 노출). 사용자가 "차트 지표 ≠ 내가 고른 지표"로 혼동하지 않도록 아래 안내 팝업으로 기준을 밝힘.
- **공통 지표 구성(9종)**: 원본 4종(광고비·노출수·클릭수·조회수) + 계산 5종(CPC·CPV·CTR·VTR 등). 각 매체 원본 지표 ↔ 공통 지표 매핑과 계산식은 매핑표로 제공(생성·결과가 공유하는 공통 지표 매핑이 기준, 구현은 §H).

**안내 팝업 — "분석 차트 제공 기준"**:
- **트리거**: 제목("Benchmark Analytics") 옆 **돋보기 아이콘**(`SearchCheck`). (구 명세의 hover Info 툴팁을 대체 — 클릭 팝업으로 통합)
- **구성**:
  1. **제공 기준 안내**: 제공 조건(업종 기준 광고상품 3개 이상) · 업종 목록(조건 충족 업종만 드롭다운) · **지표 기준(차트는 아래 공통 지표를 기준으로 구현)**.
  2. **공통 지표 매핑표**: 공통 지표 ↔ 매체별 원본 지표 라벨(원본 4종) + 계산식(계산 지표, 매체 공통 1식).
- **공용 컴포넌트**: 이 매핑표는 생성 플로우 지표 선택의 "공통 지표 기준" 다이얼로그와 **동일 컴포넌트를 공유**함. 생성과 결과에서 같은 기준을 보게 해 혼동을 막음.

## C. 영역별 상세

### C.1 차트 1 — Cost Share (광고비 비중)

> 상태: **구현 완료**. (구현은 §H)

#### C.1.0 컨셉

- 질문(제목): **"광고비는 어디에 집중됐을까?"** / 서브: **"매체·상품별 광고비 배분 비중"**
- 주어: **선택한 업종의 전체 집행 실적** (매체 또는 매체>상품 단위 비중)
- 성격: **순수 참고 + 배분(쏠림) 조망.** "이 업종에선 돈이 어디에 몰렸나"를 한눈에 봄.
- **차트 2와의 세트**: 차트 2(효율)와 짝을 이뤄 "많이 쓴 것 ≠ 효율 좋은 것" 엇갈림을 드러냄. 차트 1이 **배분(비중)**, 차트 2가 **효율**을 맡음.

#### C.1.1 차트 정의

> 제목·서브 문구는 §C.1.0 컨셉 참조.

| 항목 | 정의 |
|---|---|
| 형태 | 도넛 + 범례 |
| 시리즈/단위 | "매체" 또는 "매체>상품" 광고비 **비중(%)** |
| 표시 상한 | 비중 상위 **6개** + 나머지 '기타' 합산 |
| 강조(그린) | 비중 1위 1개(시그니처 그린), 나머지 무채색 opacity 단계 |
| 툴팁 | 조각 전체명 + 비중(%) |

- **광고비 비공개**: 절대 금액은 노출하지 않고 **비중(%)만** 제공. (외부 노출 고려 — 절대수 역산 불가)
- **색 규칙**: 비중 1위만 시그니처 그린, 나머지는 무채색 opacity. (강조 한 곳)

#### C.1.2 뷰 토글 (매체/상품)

- **상품 뷰**: 매체>상품 단위 광고비 합산 비중.
- **매체 뷰**: 매체별 광고비 합산 비중.
- 이 토글은 **두 차트 공유** 컨트롤임. 단일 매체 업종에서의 '매체' 토글 비활성·강제 상품 뷰 규칙은 공통 컨트롤 §B.3 참조.

#### C.1.3 정렬 규칙

- **정렬 기준**: 조각(매체 또는 매체>상품)을 **광고비 비중(%) 내림차순**으로 정렬함. 가장 많이 쓴 조각이 맨 앞(그린 강조 1위), 적게 쓴 순으로 뒤따름.
- **상위 6개 + 기타**: 내림차순 정렬 후 **상위 6개만 개별 조각**으로 두고, 7위 이하는 모두 **'기타'로 합산**함(표시 상한).
- **'기타'는 항상 마지막**: '기타'는 비중 크기와 무관하게 **정렬 순서상 맨 뒤에 고정**함. (설령 '기타' 합산 비중이 상위 6개 중 일부보다 커도 앞으로 올라오지 않음.)
- 도넛 조각·범례 모두 이 순서를 따름.


### C.2 차트 2 — Efficiency Map (효율 포지셔닝 맵)

#### C.2.0 컨셉

- 질문(제목): **"어떤 상품이 효율적이었을까?"** / 서브: **"매체·상품별 반응률·단가 비교"**
- 주어: **내가 선택한 매체/상품** (업종 전체 평균 아님 — §C.2.5)
- 성격: **순수 참고 + 상대 비교.** 차트 1(비중)과 짝을 이뤄 "많이 쓴 것 ≠ 효율 좋은 것" 엇갈림을 드러냄.
- **테이블과의 차별화**: 하단 Extracted Table은 값(숫자)의 나열임. 이 차트는 **배치(포지셔닝)와 선택 평균 대비 상대 위치**를 보여줌 — 테이블로는 못 보는 뷰.

#### C.2.1 차트 정의

> 제목·서브 문구는 §C.2.0 컨셉 참조.

| 항목 | 정의 |
|---|---|
| 형태 | 2축 포지셔닝 맵. 효율 영역 = **좌상단** |
| X축 | 단가 (**정방향**: 왼쪽=저렴 → 오른쪽=비쌈) |
| Y축 | 반응 (위=높음) |
| 표시 대상 | **차트 1의 상위 상품(‘기타’ 제외)과 동일 집합** (매체/상품 뷰 공유) |
| 버블 크기 | 광고비 비중 |
| 강조(그린) | **효율 포인트 1개**만 그린 + 외곽링. 나머지 무채색 (강조 한 곳) |
| 영역 틴트 | 좌상(효율 영역) 그린 틴트 + 우하(비효율 영역) 연한 그레이 틴트. **각 한 겹**, 영역 라벨 텍스트 없음 (색 토큰은 §F) |
| 기준선 | **선택 상품 가중평균** 십자선. 차트엔 라벨 **"평균"**만 짧게 표기(정의는 Info 팝업) |
| 영역 라벨 | **없음** ("효율 스타" 등 영역 텍스트 미표기 — 군더더기 제거). "효율 포인트"는 그린 점 + Info 설명으로 전달 |
| 토글 위치 | **클릭/조회 토글은 제목 행 우측** |
| 축 스타일 | muted-foreground, 축선·눈금선 없음 (BO 패턴) |
| 툴팁 | 이름 + 반응/단가/비중 |

- **표기 자릿수** (축·툴팁·라벨 공통, DataShot 전역 정책):
  - **비율(CTR·VTR): 소수 둘째 자리까지** (셋째 자리에서 반올림, `toFixed(2)`). 예: `3.42%`, `48.07%`. 단, **차트 축 눈금만 소수 1자리로 표시**(공간 절약, 실제값·툴팁·효율 포인트 계산은 2자리 유지).
  - 단가(CPC·CPV): 정수(원), 천 단위 콤마.
  - 비중: 소수 1자리(%) — 차트 1과 동일.
- **축 도메인(범위) 규칙**: **X축(단가)·Y축(반응) 모두 최소를 0으로 고정**함.
  - 즉 축이 항상 원점(0,0)에서 시작함. 0 기준으로 봐야 "절대적으로 싼지/반응이 좋은지"가 왜곡 없이 읽힘. (최소를 데이터 최솟값으로 잡으면 작은 차이가 과장돼 보임)
  - 축 최대는 데이터 최대 + 여유 패딩(패딩 수치는 구현 코드 위임).

#### C.2.2 클릭 / 조회 탭 (차트 2 전용)

광고상품마다 측정 지표가 다름(클릭 중심 / 조회 중심). 이를 **탭으로 분리**해, 각 탭 안에서는 단위가 통일된 두 지표(비율×단가)만 씀.

| 탭 | X축 (단가) | Y축 (반응) |
|---|---|---|
| **클릭** | 클릭당 비용 (CPC) | 클릭률 (CTR) |
| **조회** | 조회당 비용 (CPV) | 조회율 (VTR) |

- 각 탭은 **비율(%) 1개 + 단가(원) 1개** 짝. 둘 다 외부 노출 가능 지표(절대수 아님).
- **표시 대상**: 그 탭의 지표를 **가진 상품만** 등장. (클릭 탭 = 클릭 데이터 있는 상품만, 조회 탭 = 조회 데이터 있는 상품만)

#### C.2.3 탭 전환 규칙 + 데이터 부족 플레이스홀더

**원칙**: 탭은 비활성으로 막지 않음(항상 클릭 가능). 선택한 탭에 비교 가능한 항목이 부족하면 그 자리에 **블러 플레이스홀더**를 띄워 "왜 비었는지"를 직접 확인하게 함(비활성보다 친절). 단 **두 탭 모두** 부족하면 고를 탭이 없으므로 **탭 토글 자체를 숨김**.

- **판정 단위 = 현재 뷰 단위**: 충분 판정은 **매체/상품 토글이 가리키는 단위**로 셈. **상품 뷰**면 상품 각각의 지표(그 상품의 클릭수·조회수)로, **매체 뷰**면 매체 단위 합산 지표(그 매체에 속한 상품들의 클릭수·조회수 합)로 판정함. 아래 '항목'은 이 뷰 단위의 1개(점 1개)를 뜻함(= §C.2.7의 매체 단위 집계와 동일 기준).
- **데이터 충분 판정**: 그 탭 지표를 가진 **항목(매체 또는 상품)이 2개 이상**(클릭 탭 = 클릭수 > 0 항목 ≥ 2, 조회 탭 = 조회수 > 0 항목 ≥ 2)이면 차트를 그림. **0·1개면 플레이스홀더.**
  - **왜 2개 이상인가**: 차트 2는 상대 비교(포지셔닝) 차트라 점이 1개뿐이면 비교·평균 대비 위치 판단이 불가함(§C.2 산출 전제).

**부족 상태별 분기** (현재 뷰 단위의 탭 지표 보유 항목 수 기준):

| 상태 | 탭 토글 | 차트 영역 | 안내 문구(개행 `/`) |
|---|---|---|---|
| 양쪽 다 ≥ 2 | 유지 | 정상 렌더 | — |
| 한쪽만 부족 (선택 탭 ≤ 1, 반대 탭 ≥ 2) | **유지**(클릭 가능) | 선택 탭 누르면 블러 플레이스홀더 | 클릭 탭: "…**클릭 성과**가 있는 항목이 2개 이상일 때 표시됩니다." / 조회 탭: "…**조회 성과**가 …" |
| 둘 다 부족 (양쪽 ≤ 1) | **숨김** | 블러 플레이스홀더 | "…**클릭·조회 성과**가 있는 항목이 2개 이상일 때 표시됩니다."(통합) |

- 공통 접두: "매체·상품별 반응률·단가 비교 차트는 /". '광고상품' 대신 **'항목'**(매체·상품 뷰 포괄). 폰트는 SpinX 해석과 동일 12.5px.
- **"비활성 안 함"과 "숨김"은 별개**: 비활성 처리를 쓰지 않는 건 모든 경우 공통이고(과거 "부족 탭 비활성" 규칙 폐기), **숨김은 '둘 다 부족'일 때만**의 미렌더 처리임.

**블러 플레이스홀더 구성** (빈 박스가 아니라 더미 차트를 흐리게 깔아 "차트 들어올 자리"임을 전달 — 좌우 비대칭의 "고장난 느낌" 방지):
- **뒤 레이어**: 정상 차트 2와 같은 유형·크기의 더미 산점도(버블 + 효율 영역 틴트 + 평균 십자선)를 흐리게(블러) 깔되 불투명도는 높게. 실데이터 오해 방지로 **축 눈금·숫자 없음**(넘침 숨김). (크기 수치는 구현 위임)
- **중간**: 가독성용 옅은 card 베일 한 겹.
- **앞 오버레이**(선명, 중앙): `Info` 아이콘 + 위 표의 안내 문구.
- **하단 SpinX 자리 유지**: 정상 차트처럼 SpinX 블록을 두되, 해석 대신 공통 보류 1문장: "이 차트는 비교 항목이 부족해 SpinX 분석을 제공하지 않습니다." (차트 위 안내가 이미 조건을 말하므로 조건을 반복하지 않고 상태만 담백하게 닫음.)

- **업종 변경 시 자동 탭 보정(1회)**: 진입/업종 전환 직후 사용자가 빈 탭(플레이스홀더)을 먼저 마주치지 않게, 데이터 있는 탭을 대신 띄워 줌. **왜**: 사용자는 업종을 바꾼 직후 "이 업종엔 데이터가 없나?"로 오해하기 쉬운데, 반대 탭에 멀쩡한 데이터가 있으면 그쪽을 먼저 보여 주는 게 맞음.

  | 항목 | 내용 |
  |---|---|
  | **보정 시점** | 업종이 바뀌는 순간에만 1회. 뷰(매체/상품) 전환이나 탭 클릭만으로는 보정이 일어나지 않음. |
  | **보정 조건** | 현재 보고 있는 탭이 비어 있고(그 탭의 비교 항목 부족), **반대 탭에는 비교 항목이 충분(2개 이상)**할 때. |
  | **동작** | 데이터가 있는 반대 탭으로 자동 전환. (클릭 탭이 비고 조회 탭에 데이터가 있으면 조회 탭으로, 그 반대면 클릭 탭으로.) |
  | **비전환 — 현재 탭에 데이터 있음** | 현재 탭에 비교 항목이 충분하면 그대로 유지(전환 안 함). |
  | **비전환 — 양쪽 다 부족** | 두 탭 모두 비면 옮겨 갈 탭이 없음 → 탭 토글을 숨기고 통합 플레이스홀더만 노출(위 '부족 상태별 분기'). |
  | **최초 진입** | 기본 선택은 클릭 탭. 처음 화면에 들어올 때도 이 보정이 1회 적용되므로, 클릭 탭이 비어 있으면 진입하자마자 조회 탭이 선택됨(= 데이터 있는 탭 우선). |
  | **수동 선택 존중** | 사용자가 **직접** 빈 탭을 눌러 보는 것은 막지 않음(그 경우 플레이스홀더 노출). 자동 보정이 사용자의 수동 탭 선택을 되돌리지는 않음. |

#### C.2.4 집계 대상 항목 선별 (모든 계산의 전제)

차트 2의 모든 계산(점 표시·기준선·효율 포인트)은 아래를 통과한 매체 또는 상품만 씀. 순서대로 거름.

1. **차트 1 상위 집합** (후보 범위): 차트 1(Cost Share)에 표시된 상위 매체 또는 상품(‘기타’ 제외)만을 후보로 삼음. — 두 차트가 **같은 집합을 보도록** 세트를 동기화하는 것이 대전제임. 차트 1에 없는(비중 낮아 ‘기타’로 묶인) 매체 또는 상품은 차트 2에도 등장하지 않음.
2. **탭 지표 보유** (후보 중 탈락 거름): 위 후보 중, 선택한 탭의 두 지표를 모두 측정한 매체 또는 상품만 남김.
   - 클릭 탭 → **클릭수 > 0** 인 매체 또는 상품 (CTR·CPC 계산 가능)
   - 조회 탭 → **조회수 > 0** 인 매체 또는 상품 (VTR·CPV 계산 가능)
   - 클릭수(또는 조회수)가 **0이거나 값이 없는 매체 또는 상품은 제외**함. (이들을 넣으면 분모 0 또는 평균 왜곡 발생)
   - 제외는 **세 곳 모두에 일괄 적용**(§D의 E2): 점 표시·기준선 합계(§C.2.5)·효율 포인트 후보(§C.2.6). 한 곳이라도 넣으면 평균·정규화가 왜곡되므로 "거른 집합"을 모든 계산에서 공유함.

> 이렇게 거른 묶음을 아래에서 **"대상 항목"**이라 부름(현재 뷰 단위에 따라 매체 또는 상품). 즉 **"차트 1에 보이는 매체/상품" 중 "선택한 탭 지표가 계산되는 것"**임. 대상 항목이 1개 이하이면 비교 의미가 없으므로 효율 포인트 강조는 생략함(점만 표시 — §D의 E1).

#### C.2.5 기준선 (선택 평균) — 가중평균

기준 십자선은 **대상 항목(매체 또는 상품)의 가중평균**임. 단순 평균이 아니라, 규모(노출·클릭)가 큰 항목이 평균에 더 반영되도록 **합계끼리 나눔.**

**클릭 탭:**
```
평균 반응(CTR, %)  = (대상 항목들의 클릭수 합계) ÷ (노출수 합계) × 100
평균 단가(CPC, 원) = (대상 항목들의 광고비 합계) ÷ (클릭수 합계)
```
**조회 탭:**
```
평균 반응(VTR, %)  = (조회수 합계) ÷ (노출수 합계) × 100
평균 단가(CPV, 원) = (광고비 합계) ÷ (조회수 합계)
```
- "합계"는 **대상 항목(§C.2.4를 통과한 것)만** 더함. 제외된 항목(클릭/조회 0)은 합계에도 넣지 않음.
- 이 평균이 X축·Y축 교차점(십자선)이 됨. **차트 위 라벨은 "평균"** 한 단어만 짧게.
- **정의는 Info(ⓘ) 팝업에** 적음: "선택한 매체/상품들의 반응·단가를 집행 규모로 가중평균한 값(업종 전체가 아닌 선택 기준)". 차트 면엔 긴 설명을 두지 않음.
- **"업종 평균"으로 표기 금지** — 업종 전체가 아니라 선택 항목들의 평균이므로 정직하게 표기함.
- 절대수(노출·클릭·광고비)는 이 평균 계산에만 쓰고 화면엔 결과값(CTR %·CPC 원)만 노출 — 공통 규칙 §F.
- **향후**: 업종 전체 집행 평균 데이터를 확보하면 기준선을 "업종 평균"으로 승격 검토.

#### C.2.6 효율 포인트 산출 (그린 강조 1개)

대상 항목(매체 또는 상품) 중 **딱 1개**를 "효율 포인트"로 골라 그린 + 외곽링으로 강조함. 나머지는 전부 무채색. 아래 순서대로 계산함.

**1단계 — 두 지표의 최소·최대 구하기** (대상 항목 기준):
```
반응최소 = 대상 항목들의 반응값 중 가장 작은 값   (클릭 탭이면 CTR, 조회 탭이면 VTR)
반응최대 = 가장 큰 값
단가최소 = 대상 항목들의 단가값 중 가장 작은 값   (CPC 또는 CPV)
단가최대 = 가장 큰 값
```

**2단계 — 각 항목의 값을 "좋을수록 높은" 0~100점으로 바꾸기 (정규화):**
```
반응점수 = (그 항목 반응 − 반응최소) ÷ (반응최대 − 반응최소) × 100
단가점수 = (단가최대 − 그 항목 단가) ÷ (단가최대 − 단가최소) × 100
```
- 뜻: 두 점수 모두 **"좋을수록 높다"**로 방향을 통일함. 반응은 **높을수록** 100점(가장 높은 반응=100, 가장 낮은 반응=0). 단가는 **쌀수록** 100점(가장 싼 단가=100, 가장 비싼 단가=0) — 분자에서 `단가최대 − 그 항목 단가`로 **뒤집어** 정규화하므로, 3단계에서 따로 `100 −`로 되집을 필요가 없음.
- **분모가 0일 때**(모든 항목의 반응이 같거나 단가가 같아서 최대=최소): 나누기를 하지 말고 그 값은 **50점으로 둠.**
- 이 점수는 **효율 포인트를 고르기 위한 내부 계산 전용**임. 차트·툴팁·Info 팝업 어디에도 점수를 노출하지 않음(그린 점 선택에만 씀).

**3단계 — 효율점수 구하기 (가중합, 0~100점):**
```
효율점수 = 0.5 × 반응점수 + 0.5 × 단가점수
```
- 뜻: 2단계에서 둘 다 "좋을수록 높은" 점수로 맞춰놨으므로, **반반 섞어 그냥 더하면** 효율점수(0~100점)가 됨. 반응이 높을수록, 단가가 쌀수록 효율점수가 커짐.
- 반응과 단가를 **똑같이 중요하게**(50:50) 봄. (한쪽에 가중치를 더 주지 않음.)
- **왜 가중합인가**: 효율의 정의("싸고 반응 좋은 것")를 **한 줄 덧셈**으로 그대로 표현함. 거리·제곱 같은 중간 개념 없이 "반응 점수 + 저렴함 점수"를 더할 뿐이라, 사용자·개발자 모두 설명 없이 이해하고 결과도 직관과 어긋나지 않음.

**4단계 — 효율점수가 가장 큰 1개 선택:**
```
효율 포인트 = 효율점수가 최댓값인 항목 1개
```
- **대상 항목 전체에서** 고름. 항목이 어느 사분면(좌상/우하 등)에 있는지는 **따지지 않음.** 좌상(효율 영역) 밖의 항목이 효율 포인트가 될 수도 있으며, 이는 "이 선택 중 상대적으로 가장 효율에 가까운 1개"라는 의도된 동작임.
- **동점일 때**(효율점수가 완전히 같은 항목이 둘 이상): **반응값이 더 높은 항목**을 우선. 그래도 같으면 단가가 더 싼 항목, 그래도 같으면 목록 순서상 먼저인 항목.

> **효율 영역(좌상 그린 틴트) ≠ 효율 포인트(그린 점)**: 좌상 영역은 "싸고 반응 좋은 구역"이라는 **공간 안내**이고, 효율 포인트는 "시스템이 고른 가장 효율적인 1개"라는 **판단**임. 보통 그린 점은 좌상 영역 안에 떨어지지만, 안 그럴 수도 있음(그 경우 "이 선택엔 뚜렷한 효율 포인트가 좌상에 없다"는 것 자체가 참고 정보).

### C.3 SpinX 분석 (두 차트 공통)

각 차트 하단에 SpinX 심볼 + 타이핑 해석을 둠. 벤치마크·참고 성격이라 **액션 제안 없음**.

#### C.3.1 차트 분석 생성

- 각 차트 하단에 SpinX가 생성한 분석 결과를 인라인으로 제공(약 2~3줄).
- **생성 시점**: 결과 화면 진입 또는 업종·뷰 변경 시, 현재 노출된 차트 중 저장된 분석 결과가 없는 차트에 한해 분석 요청
  - 생성 완료된 차트 분석 결과는 저장하여, 이후 동일 차트 노출시 저장된 결과를 불러와서 사용

| 상태 | 처리 |
|---|---|
| 생성 성공 | 분석 결과 저장 후, 이후 조회 화면에서 **동일 결과로 제공**(재생성 없음) |
| 생성 중 | (생성 실패 후, 데이터셋 조회 진입 또는 조회 화면 새로고침 시 재생성 시도) 심볼 회전 + analyzing... |
| 생성 실패 | 대체 텍스트 "SpinX 분석을 생성하지 못했습니다. 페이지를 새로고침하거나 데이터샷 결과 화면을 다시 열면 분석을 다시 시도합니다." |

- **차트가 제공되는 경우에만 분석 표시**(차트 미제공 시 해석도 미제공 — 제공 조건 §B.1, 플레이스홀더 §C.2.3).

**프런트 구현 상태(생성 API 연동 전)**: 현재는 생성 백엔드가 없어, 각 SpinX 블록이 **진입 시 짧은 '생성 중(analyzing…)' 단계를 거쳐 성공(타이핑)으로 전이**하는 방식으로 생성 흐름을 시뮬레이션함. 분석 텍스트는 업종별 고정 해석 또는 템플릿 폴백. 생성 API 연동 시 이 '생성 중' 지연을 실제 요청으로 교체하고, 성공 결과를 저장·재사용함.

**생성 실패 재현(`spinxFailDemo`)**: 생성 실패 케이스를 재현하기 위한 데이터셋 데모 플래그. 플래그가 켜지면 두 차트 하단 SpinX가 **생성 실패 대체 텍스트**를 표시함(생성 실패 상태로 고정). `chartInsufficient`(§B.1)과 동일한 "엣지/QA 확인용 플래그" 패턴. (목록 샘플 `id: 18` = `[엣지] SpinX 분석 생성 실패`.)
- 실패 대체 텍스트(원문): "이 차트에 대한 SpinX 분석을 생성하지 못했습니다. 새로고침하거나 결과에 다시 들어오면 분석을 다시 시도합니다."
- 이 "생성 실패"는 §C.2.3의 "데이터 부족 보류"("…비교 항목이 부족해 SpinX 분석을 제공하지 않습니다.")와 **다른 상태**임: 전자는 생성 시도가 실패한 것(재시도 유도), 후자는 데이터가 부족해 애초에 분석을 안 하는 것.

## E. 인터랙션 플로우

**정상 플로우**
1. 광고상품 상세 진입 → 제공 조건 충족 업종이 드롭다운에 채워지고 첫 업종이 선택됨.
2. 두 차트가 같은 업종으로 렌더. 차트 1(도넛)에서 비중 1위가 그린, 차트 2(산점도)에서 효율 포인트가 그린.
3. 매체/상품 토글로 단위 전환 → 두 차트 동시 갱신.
4. 차트 2에서 클릭/조회 탭 전환 → 해당 탭 지표로 축·점·평균·효율 포인트 재계산.

**주요 분기·엣지 흐름**
- 제공 업종이 하나도 없음 → 영역 전체가 안내 문구 + 컨트롤 숨김(R2).
- 단일 매체 업종 선택 → '매체' 토글 비활성, 상품 뷰 강제(V4·V5).
- 선택 업종이 클릭형만(조회 1개 이하) → 진입 시 클릭 탭 자동 선택. 사용자가 조회 탭을 눌러보면 블러 플레이스홀더("조회 성과…")(V8·V8a).
- 두 탭 다 항목(현재 뷰 단위) 1개 이하 → **클릭/조회 토글이 숨겨지고** 블러 플레이스홀더(통합 문구 "클릭·조회 성과…")만 노출. 차트 1은 정상(E5).
- 대상 항목이 1개(차트1 교집합 후) → 점만 표시, 효율 포인트 생략(E1).

## F. 공통 입력/인터랙션 규칙

- **비활성 패턴**: 차트1 '매체' 토글만 비활성(흐리게 + 금지 커서 + hover title). **차트2 클릭/조회 탭은 비활성화하지 않음**(선택 탭 데이터 부족 시 블러 플레이스홀더로 안내 — §C.2.3). 단 **두 탭 모두 부족할 때는 토글 자체를 숨김**(비활성이 아니라 미렌더 — §C.2.3·E5). "비활성 안 함"과 "숨김"은 별개 개념.
- **색 규칙**: 시그니처 그린(`--bo-accent`)은 "시스템이 짚은 정답"(차트1 비중 1위 / 차트2 효율 포인트) **한 곳에만**. 나머지는 무채색.
- **절대수 비노출**: 노출/클릭/조회/광고비 절대수는 내부 계산(가중평균·비중·효율점수)에만 쓰고 화면엔 비율(%)·단가(원)·비중(%)만 노출.
- **스타일 위임**: 모든 px/hsl/grid 수치는 구현 코드 + 디자인 토큰이 단일 진실 공급원. 본 문서는 의도·토큰명만 서술.

## G. 데이터 개념 및 용어 매핑

### G.1 UI 용어 ↔ 데이터/계산

| UI 용어 | 데이터 / 계산 | 화면 노출 |
|---|---|---|
| 비중(%) | 조각 광고비 ÷ 전체 광고비 × 100 | O (차트1) |
| 반응(클릭 탭) | CTR = 클릭수 ÷ 노출수 × 100 | O (차트2 Y) |
| 반응(조회 탭) | VTR = 조회수 ÷ 노출수 × 100 | O (차트2 Y) |
| 단가(클릭 탭) | CPC = 광고비 ÷ 클릭수 | O (차트2 X) |
| 단가(조회 탭) | CPV = 광고비 ÷ 조회수 | O (차트2 X) |
| 평균(기준선) | 대상 항목 가중평균(합계 ÷ 합계) | O (라벨 "평균") |
| 효율 포인트 | `0.5 × 반응점수 + 0.5 × 단가점수` 최댓값 1개 | O (그린 점, 점수는 미노출) |

### G.2 상품 1개가 가져야 할 필드 (차트 계산 입력)

| 필드 | 용도 | 화면 노출 |
|---|---|---|
| 매체명 | 매체 뷰 집계·색 그룹 | O |
| 상품명(label) | 상품 뷰 라벨 | O |
| 광고비 | 가중평균·비중·버블 크기 계산 | X (내부 계산만) |
| 노출수 | 가중평균(반응) 분모 | X (내부 계산만) |
| 클릭수 | CTR·CPC 계산, 클릭 탭 포함 판정(>0) | X (내부 계산만) |
| 조회수 | VTR·CPV 계산, 조회 탭 포함 판정(>0) | X (내부 계산만) |
| CTR / VTR (%) | 차트2 Y축 | O |
| CPC / CPV (원) | 차트2 X축 | O |

- 클릭수·조회수는 "탭 포함 판정"에도 쓰임(0이면 그 탭에서 제외 — §C.2.4·E2).
- **데이터 소스**: 현재 `ResultCharts` 내부 샘플(업종별 상품 실적). 실데이터 연동 시 백엔드 응답으로 교체(화면 규칙·표기는 유지). 정확한 타입은 `ResultCharts.tsx`의 `Row` 인터페이스가 단일 진실 공급원.
