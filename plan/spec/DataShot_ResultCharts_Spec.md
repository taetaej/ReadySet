## A. 화면 개요

### A.1 기능 정의 · 기획 의도

광고상품 조회(상세) 화면 상단에 **"Benchmark Analytics"** 영역으로 차트 2종을 나란히 제공한다. 선택한 업종의 과거 집행 실적을 집계해, 사용자가 "다음 캠페인을 짤 때 참고"하도록 돕는다. **순수 참고용**이며, 이 차트의 데이터로 어떤 액션(배분 조정 등)을 강제하지 않는다. "아~ 이 업종은 이렇구나" 수준의 디깅.

- **차트 1 — Cost Share**: "이 업종에선 돈을 **어디에 어떻게 나눠** 썼나?" (미디어믹스 배분 참고)
- **차트 2 — Efficiency Map**: "그렇게 나눠 담았을 때, **내가 고른 것들 중 뭐가 효율적**이었나?" (선택 상품 간 효율 비교)

두 차트는 **한 세트**다. 같은 대상(선택 매체/상품)을 "배분(비중)"과 "효율" 두 각도로 본다. 그래서 **"많이 쓴 것 ≠ 효율 좋은 것"**이라는 엇갈림이 두 차트를 오가며 자연스럽게 읽히는 것이 핵심 가치다.

### A.2 문서 활용처

- **개발 참고**: 프론트엔드 구현 시 차트 동작·계산·표기 기준. 구현은 `ResultCharts.tsx`.
- **제품 Docs**: 차트가 "무엇을 보여주고 어떻게 읽는가"의 사용자 설명 기반.
- **AI 기반 TC 생성**: 유효성 규칙(§D)·표시 규칙이 테스트 케이스 원천. 각 규칙은 `조건 → 기대 결과`로 검증 가능하게 작성.

### A.3 진입 경로

| 화면 | 위치 | 진입 조건 |
|---|---|---|
| Benchmark Analytics | `/datashot/:id`(광고상품 상세, `DatasetResult`) 상단 | 추출 기준 `광고상품` + 제공 조건(§B.1) 충족 업종 존재 |

- 조건 조합 상세(`DatasetDetail`)에는 이 영역이 없다. 광고상품 다매체 결과 전용이다.

## B. 레이아웃 · 공통 컨트롤

### B.1 제공 조건

- 업종 최소 단위 기준 **고유 상품 3개 이상**인 업종만 제공한다. 매체 수는 제공 조건에 포함하지 않는다(매체 뷰 토글 활성 여부에만 영향 — §C.1.2).
  - **왜 3개 이상인가**: 상품 2개면 도넛 2조각·산점도 2점이라 분석 가치가 낮다. 비교로 의미가 나오는 최소선을 3개로 둔다.
- **제공 가능 업종이 하나도 없을 때(= 차트 영역 전체 미달)**: Benchmark Analytics 영역에 **안내 배너**만 표시하고, **업종 드롭다운·매체/상품 뷰 토글·클릭/조회 탭 등 모든 컨트롤을 숨긴다.** (보여줄 업종이 없는데 빈 컨트롤을 두지 않는다 — 군더더기 제거)
  - **안내 UI**: 에러가 아니라 **정보성 안내**이므로, 빈 결과(SearchX)가 아니라 **생성 플로우의 Info 배너와 동일 스타일**(muted 배경 한 겹 + 1px border + `Info` 아이콘 + muted 텍스트)로 표시한다. destructive(빨강)·큰 빈 박스는 "고장난 느낌"을 주므로 쓰지 않는다. (스타일 원천: `MediaProductSelect`의 안내 배너)
  - **안내 문구**: **"Benchmark Analytics는 한 업종에 광고상품이 3개 이상 집행된 경우에만 표시됩니다."** — "왜 안 보이는지 + 제공 조건"을 사용자 관점으로 한 줄 서술(DataShot 안내 배너 톤 "~만 표시됩니다"와 통일, 경어체 `~됩니다.`).
- **강제 미달 플래그(`chartInsufficient`)**: 특정 데이터셋이 결과 차트 제공 조건에 못 미치는 **엣지 케이스를 재현**하기 위한 플래그. `true`이면 실데이터 집계 결과와 무관하게 위 "차트 영역 전체 미달" 안내 배너만 표시한다. (상세로는 `DatasetResult` → `ResultCharts`의 `forceInsufficient` prop으로 전달. 데모/엣지 확인용이며 실데이터 집계를 거치지 않는다.)
- **차트2 엣지 데모 플래그(`chartEdgeDemo` → `edgeDemo` prop)**: 한 데이터셋에서 **업종 드롭다운 전환만으로 차트2 엣지들을 모두 확인**하도록, 엣지 전용 업종 세트를 쓰게 하는 플래그. 모든 엣지 업종은 **상품 3개 이상**이라 제공 조건(R1)을 통과해 드롭다운에 노출되며, 매체 수 / 클릭(>0) 상품 수 / 조회(>0) 상품 수 분포만 달리해 각 엣지를 드러낸다. (목록 샘플 `id: 17` = `[엣지] 차트2 케이스 모음`.)

  | 업종(데모) | 구성 | 드러나는 규칙 |
  |---|---|---|
  | 패션 | 상품 3 · 매체 2개↑ · 클릭·조회 모두 ≥2 | (정상) 두 차트 다 정상 렌더 |
  | 식품 | 상품 3 · **고유 매체 1개** | V4·V5 — '매체' 토글 비활성 + 상품 뷰 강제 |
  | 화장품및보건용품 | 상품 3 · **클릭(>0) 1개**, 조회(>0) ≥2 | V7 — 진입 시 조회 탭 자동 선택, 클릭 탭 누르면 블러 플레이스홀더("클릭 성과…") |
  | 컴퓨터및정보통신 | 상품 3 · **조회(>0) 1개**, 클릭(>0) ≥2 | V8 — 진입 시 클릭 탭 자동 선택, 조회 탭 누르면 블러 플레이스홀더("조회 성과…") |
  | 금융보험및증권 | 상품 3 · **클릭(>0) ≤1 그리고 조회(>0) ≤1** | E5 — 어느 탭이든 블러 플레이스홀더(선택 탭 문구) |

  > 엣지4(둘 다 부족)는 상품 3개를 "클릭만 / 조회만 / 둘 다 0(인지형)"으로 구성한다. 둘 다 0인 상품도 노출·비용은 있어 **차트1(비중)엔 등장**하지만, 차트2는 클릭·조회 모두 대상 ≤1이라 E5로 빠진다.

### B.2 공통 컨트롤 (두 차트 공유)

| 컨트롤 | 범위 | 동작 |
|---|---|---|
| 업종 드롭다운 | 두 차트 공유 | 제공 조건 충족 업종만 노출. 선택 업종을 두 차트가 공유 |
| 매체 / 상품 뷰 토글 (우상단) | 두 차트 공유 | "매체 단위" ↔ "상품 단위" 전환 (§C.1.2 비활성 규칙) |
| 클릭 / 조회 탭 | **차트 2 전용** | 차트 1에는 영향 없음 (§C.2.2) |
| Info 툴팁 | 제목 옆 | 제공 기준 안내 |

- 영역 전체 레이아웃: 차트 2종을 가로로 나란히(좌 Cost Share · 우 Efficiency Map). 각 차트는 `ChartCard`(제목 + Info + titleRight 슬롯 + 본문 + SpinX)로 감싼다. 정확한 폭/간격은 구현 코드·디자인 토큰 위임.

| 표시 상한 | 비중 상위 **6개** + 나머지 '기타' 합산 |
| 강조(그린) | 비중 1위 1개(`--bo-accent`), 나머지 무채색 opacity 단계 |
| 툴팁 | 조각 전체명 + 비중(%) |

- **광고비 비공개**: 절대 금액은 노출하지 않고 **비중(%)만** 제공. (외부 노출 고려 — 절대수 역산 불가)
- **색 규칙**: 비중 1위만 시그니처 그린, 나머지는 무채색 opacity. (강조 한 곳)

#### C.1.1 뷰 토글 (매체/상품)

- **상품 뷰**: 매체>상품 단위 비중.
- **매체 뷰**: 매체별 광고비 합산 비중.

#### C.1.2 매체 뷰 토글 비활성 규칙 (단일 매체 업종)

- **조건**: 선택 업종의 매체 종류 수(고유 매체 수)가 **1개 이하**이면 '매체' 토글을 **비활성(disabled)**.
- **왜**: 매체가 하나뿐이면 매체별 비중은 100% 1조각이라 비교 가치가 없다. 상품 단위 비교만 의미.
- **동작**: 비활성 토글은 opacity 낮춤 + `cursor: not-allowed`, hover 시 title "단일 매체 업종은 매체별 보기를 제공하지 않습니다". 클릭해도 전환 안 됨.
- **강제 상품 뷰 (부수효과)**: 비활성인데 현재 뷰가 '매체'면(다매체 업종 보다가 단일 매체로 전환 시) 자동으로 '상품' 뷰로 되돌림.

#### C.1.3 정렬 규칙

- **정렬 기준**: 조각(매체 또는 매체>상품)을 **광고비 비중(%) 내림차순**으로 정렬한다. 가장 많이 쓴 조각이 맨 앞(그린 강조 1위), 적게 쓴 순으로 뒤따른다.
- **상위 6개 + 기타**: 내림차순 정렬 후 **상위 6개만 개별 조각**으로 두고, 7위 이하는 모두 **'기타'로 합산**한다(표시 상한).
- **'기타'는 항상 마지막**: '기타'는 비중 크기와 무관하게 **정렬 순서상 맨 뒤에 고정**한다. (설령 '기타' 합산 비중이 상위 6개 중 일부보다 커도 앞으로 올라오지 않는다.)
  - **왜 고정하나**: '기타'는 "나머지 묶음"이라는 성격이라, 개별 조각들과 같은 선상에서 크기순으로 섞이면 "7위 묶음"이라는 의미가 흐려진다. 항상 끝에 둬서 "상위 6개 + 그 외" 구조를 시각적으로 유지한다.
- 도넛 조각·범례 모두 이 순서를 따른다. 비중 1위(= 첫 조각, '기타' 아님)만 시그니처 그린, 나머지는 무채색.

#### C.1.4 조각 라벨 텍스트 색 (다크모드 고정)

- 도넛 **조각 위에 얹히는 비중(%) 라벨**은 조각 색이 항상 어두운 계열(1위=그린, 그 외=어두운 무채색)이라, 모드와 무관하게 **라이트모드 기준 색을 고정**한다.
  - **1위 조각(그린) 위**: 어두운 글씨(라이트모드 `--foreground` 실제값 `hsl(0 0% 3.9%)`).
  - **그 외 조각 위**: 흰 글씨(`hsl(0 0% 100%)`).
- **왜 고정인가**: `--background`/`--foreground` 토큰을 쓰면 **다크모드에서 토큰이 뒤집혀** 어두운 조각 위에 어두운 글씨가 되어 대비가 깨진다. 조각 색은 모드와 무관하게 어두우므로, 라벨도 모드 불변 고정색이 맞다. (조각 라벨 한정 규칙 — 범례·축 등 일반 텍스트는 토큰 그대로)

### C.2 차트 2 — Efficiency Map (효율 포지셔닝 맵)

> 상태: 차트 1 완료, **차트 2는 산출식·탭 규칙 재설계 반영 완료** (`ResultCharts.tsx`).

#### C.2.0 컨셉

- 질문(제목): **"어떤 상품이 효율적이었을까?"** / 서브: **"매체·상품별 반응률·단가 비교"**
- 주어: **내가 선택한 매체/상품** (업종 전체 평균 아님 — §C.2.5)
- 성격: **순수 참고 + 상대 비교.** 차트 1(비중)과 짝을 이뤄 "많이 쓴 것 ≠ 효율 좋은 것" 엇갈림을 드러낸다.
- **테이블과의 차별화**: 하단 Extracted Table은 값(숫자)의 나열이다. 이 차트는 **배치(포지셔닝)와 선택 평균 대비 상대 위치**를 보여준다 — 테이블로는 못 보는 뷰.

#### C.2.1 차트 정의

| 항목 | 정의 |
|---|---|
| 형태 | 2축 포지셔닝 맵(ScatterChart). 효율 영역 = **좌상단** |
| X축 | 단가 (**정방향**: 왼쪽=저렴 → 오른쪽=비쌈) |
| Y축 | 반응 (위=높음) |
| 표시 대상 | **차트 1의 상위 상품(‘기타’ 제외)과 동일 집합** (매체/상품 뷰 공유) |
| 버블 크기 | 광고비 비중 |
| 강조(그린) | **효율 포인트 1개**만 그린 + 외곽링. 나머지 무채색 (강조 한 곳) |
| 영역 틴트 | 좌상(효율 영역) 그린 틴트(`--primary`) + 우하(비효율 영역) 연한 그레이 틴트(`--foreground` 매우 옅게). **각 한 겹**, 영역 라벨 텍스트 없음 |
| 기준선 | **선택 상품 가중평균** 십자선. 차트엔 라벨 **"평균"**만 짧게 표기(정의는 Info 팝업) |
| 영역 라벨 | **없음** ("효율 스타" 등 영역 텍스트 미표기 — 군더더기 제거). "효율 포인트"는 그린 점 + Info 설명으로 전달 |
| 토글 위치 | **클릭/조회 토글은 제목 행 우측**(ChartCard `titleRight` 슬롯) |
| 축 스타일 | muted-foreground, axisLine/tickLine 없음 (BO 패턴) |
| 툴팁 | 이름 + 반응/단가/비중 |

> steering 정합: 강조 한 곳(효율 포인트 1개 그린), 틴트 한 겹씩(좌상 그린·우하 그레이), 영역 라벨 제거(군더더기↓), "그린 = 시스템이 짚은 정답".
> **용어·정의 노출**: 차트 위에는 "평균" 한 단어만. **"평균"과 "효율 포인트"의 정의는 제목 옆 Info(ⓘ) 호버 팝업**에 적는다 (차트 면을 깨끗하게 유지).

- **Info(ⓘ) 팝업 구성** (제목 옆 호버. 간결·명사형 위주, 축/버블 등 자명한 범례성 항목은 넣지 않는다 — 차트가 스스로 말하게):
  - 리드 문장: "선택한 {단위}을 반응률·단가 두 축에 놓아, 어느 {단위}이 효율적인 자리에 있는지 보여줍니다. 왼쪽 위(저단가·고반응)로 갈수록 효율적입니다." ({단위} = 뷰 토글에 따라 '상품'/'매체')
  - **탭(클릭·조회)**: 하위 2줄로 분리 서술 — "클릭 탭은 클릭률·클릭당 비용(CPC)으로 비교", "조회 탭은 조회율·조회당 비용(CPV)으로 비교".
  - **평균**: "선택한 {단위}들의 반응률·단가를 집행 규모로 가중평균한 값" (명사형 종결, 라벨 콜론형).
  - **효율 포인트**: 라벨 콜론형이 아니라 **문장 안에 녹여** 서술 — "반응이 높고 단가가 낮을수록 효율적이며, 이를 점수화해 가장 높은 {단위}을 **효율 포인트**로 짚습니다." (산출식의 50:50 가중 등 세부 수치는 팝업에 노출하지 않는다 — 계산은 §C.2.6, 팝업은 '무엇을 짚는지'만.)
  - **노출하지 않는 항목**: 가로축/세로축 방향·버블 크기 의미는 축 라벨·버블로 자명하므로 팝업에서 **제외**(군더더기 제거). 효율 포인트 라벨 텍스트 색은 그린이 아니라 **일반 `--foreground`**(다른 항목과 동일 — 팝업 안에서 색 강조를 분산시키지 않음).

- **표기 자릿수** (축·툴팁·라벨 공통, DataShot 전역 정책):
  - **비율(CTR·VTR): 소수 둘째 자리까지** (셋째 자리에서 반올림, `toFixed(2)`). 예: `3.42%`, `48.07%`. 단, **차트 축 눈금만 소수 1자리로 표시**(공간 절약, 실제값·툴팁·효율 포인트 계산은 2자리 유지).
  - 단가(CPC·CPV): 정수(원), 천 단위 콤마.
  - 비중: 소수 1자리(%) — 차트 1과 동일.
  - (기존 "VTR 소수 1자리" 정책은 폐기 → CTR·VTR 모두 2자리로 통일. `DataShot_DatasetDetail_Spec.md` §5.4도 동일 갱신.)
- **축 도메인(범위) 규칙**: **X축(단가)·Y축(반응) 모두 최소를 0으로 고정**한다.
  - 즉 축이 항상 원점(0,0)에서 시작한다. 0 기준으로 봐야 "절대적으로 싼지/반응이 좋은지"가 왜곡 없이 읽힌다. (최소를 데이터 최솟값으로 잡으면 작은 차이가 과장돼 보임)
  - 축 최대는 데이터 최대 + 여유 패딩(패딩 수치는 구현 코드 위임).

#### C.2.2 클릭 / 조회 탭 (차트 2 전용)

광고상품마다 측정 지표가 다르다(클릭 중심 / 조회 중심). 이를 **탭으로 분리**해, 각 탭 안에서는 단위가 통일된 두 지표(비율×단가)만 쓴다.

| 탭 | X축 (단가) | Y축 (반응) |
|---|---|---|
| **클릭** | 클릭당 비용 (CPC) | 클릭률 (CTR) |
| **조회** | 조회당 비용 (CPV) | 조회율 (VTR) |

- 각 탭은 **비율(%) 1개 + 단가(원) 1개** 짝. 둘 다 외부 노출 가능 지표(절대수 아님).
- **표시 대상**: 그 탭의 지표를 **가진 상품만** 등장. (클릭 탭 = 클릭 데이터 있는 상품만, 조회 탭 = 조회 데이터 있는 상품만)

#### C.2.3 탭 전환 규칙 + 데이터 부족 플레이스홀더

> 핵심: **탭은 비활성화하지 않는다(항상 클릭 가능).** 대신 **선택된 탭에 비교 가능한 항목(2개↑)이 없으면 그 탭 자리에 "블러 플레이스홀더"**를 보여준다. 사용자가 눌러서 "왜 비었는지"를 직접 확인할 수 있게 하는 것이 비활성(disabled)보다 친절하고, 둘 다 부족한 경우까지 하나의 UI로 통일된다.

- **데이터 충분 판정**: 그 탭 지표를 가진 상품이 **2개 이상**이면 차트를 그린다(클릭 탭 = 클릭수 > 0 상품 ≥ 2, 조회 탭 = 조회수 > 0 상품 ≥ 2). **2개 미만(0·1개)이면 그 탭 선택 시 플레이스홀더.**
  - **왜 2개 이상인가**: 차트 2는 **상대 비교(포지셔닝)** 차트다. 점이 1개뿐이면 비교·평균 대비 위치 판단이 불가해 차트로서 의미가 없다(§C.2 산출의 전제). 그래서 2개부터 그린다.
- **탭 비활성 없음**: 두 탭 모두 항상 클릭 가능. `disabled`·`cursor: not-allowed`·hover title을 쓰지 않는다. (과거 "부족 탭 비활성" 규칙 폐기.)
- **업종 변경 시 자동 탭 보정(1회)**: 업종이 바뀔 때, **현재 선택 탭이 비었고 반대 탭엔 데이터가 있으면** 데이터 있는 탭으로 자동 전환한다. (진입 시 빈 탭을 먼저 보지 않게.) 단 **사용자가 직접 빈 탭을 눌러보는 것은 막지 않는다**(그 경우 플레이스홀더 노출). → 자동 전환은 `industry` 변경에만 반응, 사용자 수동 탭 선택은 유지.
- **데이터 부족 플레이스홀더(선택 탭에 2개 미만)**: 빈 박스가 아니라 **그럴싸한 더미 포지셔닝 맵을 흐리게(blur) 깔고 그 위에 안내를 얹는다.** 구성:
  - **뒤 레이어**: 정상 차트 2와 **같은 유형·같은 크기**(그리드 칸 폭 × height 250px)의 더미 산점도(버블 + 효율 영역 틴트 + 평균 십자선)를 `blur` + 높은 opacity로. 실데이터 오해 방지를 위해 **더미 축은 눈금·숫자 없음**, 영역 밖으로 blur가 번지지 않게 `overflow: hidden`.
  - **중간**: 가독성용 옅은 card 베일 한 겹.
  - **앞 오버레이**(선명, 중앙): `Info` 아이콘 + 안내 문구. 문구는 **선택 탭에 따라 분기**:
    - 클릭 탭 → "매체·상품별 반응률·단가 비교 차트는 / 클릭 성과가 있는 항목이 2개 이상일 때 표시됩니다."
    - 조회 탭 → "매체·상품별 반응률·단가 비교 차트는 / 조회 성과가 있는 항목이 2개 이상일 때 표시됩니다."
    - (개행 포함. '광고상품' 대신 **'항목'** — 매체 뷰·상품 뷰 모두 포괄. 폰트는 SpinX 해석과 동일 12.5px.)
  - **하단 SpinX 자리 유지**: 정상 차트와 동일하게 `SpinXInsight`를 둔다. 비교 불가라 해석 대신 **업종 무관 공통 1문장**: "비교할 수 있는 항목이 아직 충분하지 않아 차트 해석은 잠시 접어둘게요. 항목이 충분히 모이면 가장 효율적인 지점을 짚어 드릴게요."
  - **왜 블러 플레이스홀더인가**: 2열 중 한 칸만 빈 박스/안내 텍스트로 비면 "고장난 느낌"을 준다. 더미 차트를 흐리게 깔면 "차트가 들어올 자리"임이 전달돼 **좌우 비대칭이 자연스러워지고**, 옆 Cost Share와 질감·높이가 맞는다. (단, 더미를 실데이터로 오해하지 않도록 축 숫자 제거 + 안내 문구로 제공 조건을 분명히.)
- **둘 다 부족**: 위 규칙의 자연스러운 귀결 — 어느 탭을 눌러도 그 탭이 비었으므로 **양쪽 다 플레이스홀더**가 된다(별도 분기 없음).

#### C.2.4 집계 대상 상품 선별 (모든 계산의 전제)

차트 2의 모든 계산(점 표시·기준선·효율 포인트)은 아래를 통과한 상품만 쓴다. 순서대로 거른다.

1. **차트 1 상위 집합** (후보 범위): 차트 1(Cost Share)에 표시된 상위 상품(‘기타’ 제외)만을 후보로 삼는다. — 두 차트가 **같은 집합을 보도록** 세트를 동기화하는 것이 대전제다. 차트 1에 없는(비중 낮아 ‘기타’로 묶인) 상품은 차트 2에도 등장하지 않는다.
2. **탭 지표 보유** (후보 중 탈락 거름): 위 후보 중, 선택한 탭의 두 지표를 모두 측정한 상품만 남긴다.
   - 클릭 탭 → **클릭수 > 0** 인 상품 (CTR·CPC 계산 가능)
   - 조회 탭 → **조회수 > 0** 인 상품 (VTR·CPV 계산 가능)
   - 클릭수(또는 조회수)가 **0이거나 값이 없는 상품은 제외**한다. (이들을 넣으면 분모 0 또는 평균 왜곡 발생)

> 이렇게 거른 상품 묶음을 아래에서 **"대상 상품"**이라 부른다. 즉 **"차트 1에 보이는 매체/상품" 중 "선택한 탭 지표가 계산되는 것"**이다. 대상 상품이 1개 이하이면 비교 의미가 없으므로 효율 포인트 강조는 생략한다(점만 표시 — §D의 E1).
> 참고: 두 조건은 교집합이라 **거르는 순서가 결과를 바꾸지는 않지만**, "차트 1 집합이 후보 범위다"라는 대전제를 먼저 세워야 의도가 분명해지므로 이 순서로 서술한다.

#### C.2.5 기준선 (선택 평균) — 가중평균

기준 십자선은 **대상 상품의 가중평균**이다. 단순 평균이 아니라, 규모(노출·클릭)가 큰 상품이 평균에 더 반영되도록 **합계끼리 나눈다.**

**클릭 탭:**
```
평균 반응(CTR, %)  = (대상 상품들의 클릭수 합계) ÷ (노출수 합계) × 100
평균 단가(CPC, 원) = (대상 상품들의 광고비 합계) ÷ (클릭수 합계)
```
**조회 탭:**
```
평균 반응(VTR, %)  = (조회수 합계) ÷ (노출수 합계) × 100
평균 단가(CPV, 원) = (광고비 합계) ÷ (조회수 합계)
```
- "합계"는 **대상 상품(§C.2.4를 통과한 것)만** 더한다. 제외된 상품(클릭/조회 0)은 합계에도 넣지 않는다.
- 이 평균이 X축·Y축 교차점(십자선)이 된다. **차트 위 라벨은 "평균"** 한 단어만 짧게.
- **정의는 Info(ⓘ) 팝업에** 적는다: "선택한 매체/상품들의 반응·단가를 집행 규모로 가중평균한 값(업종 전체가 아닌 선택 기준)". 차트 면엔 긴 설명을 두지 않는다.
- **"업종 평균"으로 표기 금지** — 업종 전체가 아니라 선택 상품들의 평균이므로 정직하게 표기한다.
- 참고: 노출수·클릭수·광고비 같은 **절대수는 이 평균을 구하는 내부 계산에만** 쓰고, 화면에는 노출하지 않는다. 화면에 보이는 건 평균 CTR(%)·CPC(원) 결과값뿐이다.
- **향후**: 업종 전체 집행 평균 데이터를 확보하면 기준선을 "업종 평균"으로 승격 검토.

#### C.2.6 효율 포인트 산출 (그린 강조 1개)

대상 상품 중 **딱 1개**를 "효율 포인트"로 골라 그린 + 외곽링으로 강조한다. 나머지는 전부 무채색. 아래 순서대로 계산한다.

**1단계 — 두 지표의 최소·최대 구하기** (대상 상품 기준):
```
반응최소 = 대상 상품들의 반응값 중 가장 작은 값   (클릭 탭이면 CTR, 조회 탭이면 VTR)
반응최대 = 가장 큰 값
단가최소 = 대상 상품들의 단가값 중 가장 작은 값   (CPC 또는 CPV)
단가최대 = 가장 큰 값
```

**2단계 — 각 상품의 값을 "좋을수록 높은" 0~100점으로 바꾸기 (정규화):**
```
반응점수 = (그 상품 반응 − 반응최소) ÷ (반응최대 − 반응최소) × 100
단가점수 = (단가최대 − 그 상품 단가) ÷ (단가최대 − 단가최소) × 100
```
- 뜻: 두 점수 모두 **"좋을수록 높다"**로 방향을 통일한다. 반응은 **높을수록** 100점(가장 높은 반응=100, 가장 낮은 반응=0). 단가는 **쌀수록** 100점(가장 싼 단가=100, 가장 비싼 단가=0) — 분자에서 `단가최대 − 그 상품 단가`로 **뒤집어** 정규화하므로, 3단계에서 따로 `100 −`로 되집을 필요가 없다.
- **분모가 0일 때**(모든 상품의 반응이 같거나 단가가 같아서 최대=최소): 나누기를 하지 말고 그 값은 **50점으로 둔다.**
- 이 점수는 **효율 포인트를 고르기 위한 내부 계산 전용**이다. 차트·툴팁·Info 팝업 어디에도 점수를 노출하지 않는다(그린 점 선택에만 쓴다).

**3단계 — 효율점수 구하기 (가중합, 0~100점):**
```
효율점수 = 0.5 × 반응점수 + 0.5 × 단가점수
```
- 뜻: 2단계에서 둘 다 "좋을수록 높은" 점수로 맞춰놨으므로, **반반 섞어 그냥 더하면** 효율점수(0~100점)가 된다. 반응이 높을수록, 단가가 쌀수록 효율점수가 커진다.
- 반응과 단가를 **똑같이 중요하게**(50:50) 본다. (한쪽에 가중치를 더 주지 않는다.)
- **왜 가중합인가**: 효율의 정의("싸고 반응 좋은 것")를 **한 줄 덧셈**으로 그대로 표현한다. 거리·제곱 같은 중간 개념 없이 "반응 점수 + 저렴함 점수"를 더할 뿐이라, 사용자·개발자 모두 설명 없이 이해하고 결과도 직관과 어긋나지 않는다.

**4단계 — 효율점수가 가장 큰 1개 선택:**
```
효율 포인트 = 효율점수가 최댓값인 상품 1개
```
- **대상 상품 전체에서** 고른다. 상품이 어느 사분면(좌상/우하 등)에 있는지는 **따지지 않는다.** 좌상(효율 영역) 밖의 상품이 효율 포인트가 될 수도 있으며, 이는 "이 선택 중 상대적으로 가장 효율에 가까운 1개"라는 의도된 동작이다.
- **동점일 때**(효율점수가 완전히 같은 상품이 둘 이상): **반응값이 더 높은 상품**을 우선. 그래도 같으면 단가가 더 싼 상품, 그래도 같으면 목록 순서상 먼저인 상품.

- **명칭·정의**: 이 그린 점을 **"효율 포인트"**라 부른다. 차트 위엔 라벨을 달지 않고(점만), **정의는 Info(ⓘ) 팝업**에 적는다: "선택 매체/상품 중 반응이 높고 단가가 낮은, 가장 효율적인 1개. 반응 점수와 저렴함 점수를 반반(50:50) 더해 산출."

> **효율 영역(좌상 그린 틴트) ≠ 효율 포인트(그린 점)**: 좌상 영역은 "싸고 반응 좋은 구역"이라는 **공간 안내**이고, 효율 포인트는 "시스템이 고른 가장 효율적인 1개"라는 **판단**이다. 보통 그린 점은 좌상 영역 안에 떨어지지만, 안 그럴 수도 있다(그 경우 "이 선택엔 뚜렷한 효율 포인트가 좌상에 없다"는 것 자체가 참고 정보).

#### C.2.7 매체 뷰일 때

매체 뷰에선 상품이 아니라 **매체 1개가 점 1개**가 된다. 매체 안의 상품들을 먼저 합쳐서 매체 단위 값을 만든다.

- **집계 전제**: §C.2.4와 동일하게, 선택한 탭의 지표를 가진 상품(클릭 탭이면 클릭수 > 0)만 합친다. 클릭/조회 0 상품은 그 매체 합계에서도 제외.
- **매체 단위 값** (클릭 탭 예시, 조회 탭도 동일 구조로 조회수·CPV 사용):
```
매체 반응(CTR, %)  = (그 매체 상품들의 클릭수 합계) ÷ (노출수 합계) × 100
매체 단가(CPC, 원) = (그 매체 상품들의 광고비 합계) ÷ (클릭수 합계)
매체 광고비 비중    = (그 매체 광고비 합계) ÷ (전체 광고비 합계)   // 버블 크기용
```
- 이렇게 만든 **매체 점들**을 대상으로 기준선(§C.2.5)·효율 포인트(§C.2.6)를 **그대로 다시 계산**한다. (상품 → 매체로 단위만 바뀔 뿐 계산 방식 동일)
- 매체가 1개뿐이면 §C.1.2에 따라 '매체' 토글이 비활성이므로 이 뷰 자체가 안 열린다.

### C.3 SpinX 인사이트 (두 차트 공통)

- 각 차트 하단에 `SpinXSymbol` + 타이핑 해석.
- **수치 요약이 아니라 '발견' 서술.** (예: "광고비 1위 디맨드젠은 선택 평균보다 비싸고 반응도 낮았고, 적게 쓴 YouTube 셀렉트가 효율 포인트였어요.")
- 벤치마크·참고 성격이라 **액션 제안 없음.**

| V10 | V 차트2 | 축 최소 0 고정 | 임의 데이터 | X·Y축 모두 0에서 시작 | 동작 |
| V11 | V 차트2 | 효율 포인트 그린 | 대상 상품 ≥ 2 | 효율점수 최댓값 1개만 그린 + 외곽링, 나머지 무채색 | 동작 |
| V12 | V 차트2 | 비율 자릿수 | CTR/VTR 값 | 툴팁·계산 2자리, 축 눈금만 1자리 | 동작 |
| E1 | E 엣지 | 대상 ≤ 1 | 탭 활성(지표 보유 ≥ 2)이나 차트 1 교집합 후 대상 상품 ≤ 1 | 효율 포인트 강조 **생략**(점만 표시) | 동작 |
| E2 | E 엣지 | 지표 0·결측 제외 | 클릭수(또는 조회수) 0·결측 상품 | 그 탭의 점·기준선 합계·효율 포인트에서 모두 제외 | 동작 |
| E3 | E 엣지 | 효율점수 동점 | 효율점수가 같은 상품 둘 이상 | 반응값 높은 상품 우선 → 단가 싼 상품 → 목록 순 | 동작 |
| E4 | E 엣지 | 정규화 분모 0 | 모든 상품 반응(또는 단가) 동일 | 해당 축 점수 50점 고정, 효율점수 계산 그대로 반영 | 동작 |
| E5 | E 엣지 | 두 탭 모두 부족 | 클릭·조회 탭 모두 지표 보유 상품 ≤ 1 | 어느 탭을 눌러도 블러 플레이스홀더(선택 탭에 맞춰 "클릭/조회 성과…" 문구). 2열 유지, 차트 1은 정상 | 동작 |

### D.2 규칙 상세 (보충)

- **E2가 핵심**: 클릭/조회 0 상품은 **점에서도 빠지고, 기준선 합계에서도 빠지고, 효율 포인트 후보에서도 빠진다.** 한 군데라도 넣으면 평균·정규화가 왜곡된다.
- **두 종류 미달의 문구·UI 구분** (모두 destructive 아닌 정보성 안내, 경어체 "~표시됩니다."):
  - ① **영역 전체 미달(R2/R2a)**: 두 차트 다 못 그림(업종 상품 < 3 등) → **상단 Info 안내 배너** "Benchmark Analytics는 한 업종에 광고상품이 3개 이상 집행된 경우에만 표시됩니다." + 모든 컨트롤 숨김. (차트 1도 안 그림)
  - ② **차트 2 선택 탭 부족(V7/V8/E5)**: 차트 1은 정상 유지, **차트 2 자리에만 블러 플레이스홀더**. 탭은 비활성화하지 않으며(항상 클릭 가능), 선택한 탭에 맞춰 문구가 "클릭 성과…"/"조회 성과…"로 분기. 둘 다 부족이면 어느 탭이든 플레이스홀더(E5).
- **V7/V8/E5는 동일 메커니즘**: "선택된 탭에 비교 가능 항목(2개↑)이 없으면 블러 플레이스홀더" 하나로 통합된다. 과거 "탭 disabled" 방식은 폐기.
- **경계값(TC용)**: 제공 조건 상품 2개↔3개, 탭 활성 상품 1개↔2개, 대상 상품 1개↔2개, 매체 수 1개↔2개를 양방향으로 도출.

## E. 인터랙션 플로우

**정상 플로우**
1. 광고상품 상세 진입 → 제공 조건 충족 업종이 드롭다운에 채워지고 첫 업종이 선택됨.
2. 두 차트가 같은 업종으로 렌더. 차트 1(도넛)에서 비중 1위가 그린, 차트 2(산점도)에서 효율 포인트가 그린.
3. 매체/상품 토글로 단위 전환 → 두 차트 동시 갱신.
4. 차트 2에서 클릭/조회 탭 전환 → 해당 탭 지표로 축·점·평균·효율 포인트 재계산.

**주요 분기·엣지 흐름**
- 제공 업종이 하나도 없음 → 영역 전체가 안내 문구 + 컨트롤 숨김(R2).
- 단일 매체 업종 선택 → '매체' 토글 비활성, 상품 뷰 강제(V4·V5).
- 선택 업종이 클릭형만(조회 1개 이하) → 진입 시 클릭 탭 자동 선택. 사용자가 조회 탭을 눌러보면 블러 플레이스홀더("조회 성과…")(V8·V8a).
- 두 탭 다 상품 1개 이하 → 어느 탭을 눌러도 블러 플레이스홀더(선택 탭 문구). 차트 1은 정상(E5).
- 대상 상품이 1개(차트1 교집합 후) → 점만 표시, 효율 포인트 생략(E1).

## F. 공통 입력/인터랙션 규칙

- **비활성 패턴**: 차트1 '매체' 토글만 비활성(opacity 낮춤 + `cursor: not-allowed` + hover title). **차트2 클릭/조회 탭은 비활성화하지 않는다**(선택 탭 데이터 부족 시 블러 플레이스홀더로 안내 — §C.2.3).
- **색 규칙**: 시그니처 그린(`--bo-accent`)은 "시스템이 짚은 정답"(차트1 비중 1위 / 차트2 효율 포인트) **한 곳에만**. 나머지는 무채색.
- **절대수 비노출**: 노출/클릭/조회/광고비 절대수는 내부 계산(가중평균·비중·효율점수)에만 쓰고 화면엔 비율(%)·단가(원)·비중(%)만 노출.
- **스타일 위임**: 모든 px/hsl/grid 수치는 구현 코드 + 디자인 토큰이 단일 진실 공급원. 본 문서는 의도·토큰명만 서술.

## G. 데이터 개념 및 용어 매핑

### G.1 UI 용어 ↔ 데이터/계산

| UI 용어 | 데이터 / 계산 | 화면 노출 |
|---|---|---|
| 비중(%) | 조각 광고비 ÷ 전체 광고비 × 100 | O (차트1) |
| 반응(클릭 탭) | CTR = 클릭수 ÷ 노출수 × 100 | O (차트2 Y) |
| 반응(조회 탭) | VTR = 조회수 ÷ 노출수 × 100 | O (차트2 Y) |
| 단가(클릭 탭) | CPC = 광고비 ÷ 클릭수 | O (차트2 X) |
| 단가(조회 탭) | CPV = 광고비 ÷ 조회수 | O (차트2 X) |
| 평균(기준선) | 대상 상품 가중평균(합계 ÷ 합계) | O (라벨 "평균") |
| 효율 포인트 | `0.5 × 반응점수 + 0.5 × 단가점수` 최댓값 1개 | O (그린 점, 점수는 미노출) |

### G.2 상품 1개가 가져야 할 필드 (차트 계산 입력)

| 필드 | 용도 | 화면 노출 |
|---|---|---|
| 매체명 | 매체 뷰 집계·색 그룹 | O |
| 상품명(label) | 상품 뷰 라벨 | O |
| 광고비 | 가중평균·비중·버블 크기 계산 | X (내부 계산만) |
| 노출수 | 가중평균(반응) 분모 | X (내부 계산만) |
| 클릭수 | CTR·CPC 계산, 클릭 탭 포함 판정(>0) | X (내부 계산만) |
| 조회수 | VTR·CPV 계산, 조회 탭 포함 판정(>0) | X (내부 계산만) |
| CTR / VTR (%) | 차트2 Y축 | O |
| CPC / CPV (원) | 차트2 X축 | O |

- 클릭수·조회수는 "탭 포함 판정"에도 쓰인다(0이면 그 탭에서 제외 — §C.2.4·E2).
- **데이터 소스**: 현재 `ResultCharts` 내부 샘플(업종별 상품 실적). 실데이터 연동 시 백엔드 응답으로 교체(화면 규칙·표기는 유지). 정확한 타입은 `ResultCharts.tsx`의 `Row` 인터페이스가 단일 진실 공급원.

## H. 개선 제안 (이 화면 한정)

> 에이전트 제안 → 기획자 채택 결정. 차트 영역 범위 안의 것만 담는다.

| 제안 | 내용 | 사용자 가치 | 상태 |
|---|---|---|---|
| 효율 포인트 호버 시 근거 노출 | 효율 포인트에 마우스 올리면 "반응 상위·단가 하위" 같은 선정 근거를 툴팁에 한 줄 | "왜 이게 효율 포인트인지" 납득 (있어 보임 = 근거) | 검토 필요 |
| 가중치 조절(반응:단가) | Info 팝업 또는 토글로 50:50 외 비율(예: 반응 중시) 선택 | 캠페인 목적(반응형/효율형)에 맞춘 효율 해석 | 미채택 |
| 차트 1↔2 조각 hover 연동 | 차트 1 조각 hover 시 차트 2의 같은 상품 점을 강조 | 두 차트가 한 세트임을 인터랙션으로 체감 | 미채택 |

> 업종 벤치마크 실데이터 연동, SpinX 해석 고도화 등은 상위 문서/솔루션 레벨이라 여기서 다루지 않는다.
