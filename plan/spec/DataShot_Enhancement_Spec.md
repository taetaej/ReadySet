## A. 화면 개요

### A.1 기능 정의 · 기획 의도

DataShot 데이터셋 생성·조회를 **"광고상품 기준 다매체 추출"**로 확장함. 기존은 단일 매체 기준으로 조회 조건을 조립했으나, 이번 고도화는 **여러 매체를 한 번에 선택하고 매체별 광고상품·지표를 조합**해 추출할 수 있게 함. 결과 화면에는 매체·상품 단위 비교를 돕는 **차트 2종**을 추가함.

- **왜 "광고상품 기준"인가**: 사용자는 매체 하나하나의 저수준 옵션보다 "어떤 광고상품에 얼마를 쓰고 어떤 효율이 났나"를 상품 단위로 비교하고 싶어 함. ReadySet 표준 광고상품을 축으로 삼으면 매체를 가로질러 비교가 가능해짐.
- **왜 "추출 기준" 택1을 두나**: 기존 조건 조합 방식을 쓰고 싶은 사용자도 있음. 그래서 진입점에서 `광고상품`(정돈된 표준 상품 기준) / `조건 조합`(기존 세밀 조합)을 **택1**하게 해, 기존 플로우를 보존하면서 새 플로우를 추가함.

### A.2 문서 활용처

- **개발 참고**: 프론트엔드 구현 시 화면 동작·규칙·표기 기준. 각 변경 항목에 구현 파일을 명시(§E.1).
- **제품 Docs**: 본 정의서의 기능 설명·의도가 사용자 대상 기능 문서의 기반이 됨.
- **AI 기반 TC 생성**: 유효성 규칙(§B.4·§C.5)·표시 규칙이 테스트 케이스 원천. 각 규칙은 `조건 → 기대 결과`로 검증 가능하게 작성.

## B. 데이터셋 목록 (`/datashot`)

> 상태: **구현 완료** (`DatasetList.tsx`, `types.ts`).

### B.1 레이아웃 — 컬럼 순서

```
체크박스 · ID · 데이터셋명 · 매체 · 업종 · 조회 기간 · 지표 구성 · [추출 기준]★ · 상태 · 생성자 · 생성일시 · ⋮
```

- ★ = 신규 컬럼. "지표 구성" 바로 뒤에 배치. 기존 컬럼 순서/정렬 동작은 그대로 유지.
- **왜 이 위치인가**: 사용자가 훑는 순서(식별 → 데이터 범위[매체·업종·기간] → 추출 성격[추출 기준·지표 구성])에 맞춰, 추출 성격 묶음의 앞에 둠.

### B.2 추출 기준 컬럼 (신규)

목록 테이블의 "지표 구성" 컬럼 뒤에 "추출 기준" 컬럼을 신설함.

- **왜 추가하나**: 고도화로 데이터셋 추출 방식이 두 갈래(광고상품 / 조건 조합)로 나뉨. 목록에서 각 데이터셋이 어느 방식으로 뽑혔는지 한눈에 식별해야, 사용자가 결과 형상(단일 매체 vs 다매체)을 예측하고 들어갈 수 있음.
- **표시 값** (두 케이스 모두 노출):
  - `광고상품` — 추출 기준이 광고상품인 데이터셋.
  - `조건 조합` — 기존 방식(미지정 포함). 기존 데이터와 동일.
- **정렬·필터**: 미지원 (식별용 표시 전용).

### B.3 매체 컬럼 표시·필터·정렬 분기

"매체" 컬럼은 추출 기준과 선택한 매체 수에 따라 표시가 달라짐.

- **왜 분기하나**: 매체가 하나면 이름으로 바로 식별하고, 여러 개면 개수로 요약해 선택 범위를 전달함. 광고상품은 매체를 가로지르는 다매체 추출이라 매체명 하나로 대표할 수 없고, 개수 요약이 "여러 매체를 묶었다"는 사실을 정확히 전달함.

| 추출 기준 | 매체 수 | 표시 (`getMediaDisplay`) |
|---|---|---|
| 광고상품 | 1개 | 해당 **매체명** (예: `Google Ads`) |
| 광고상품 | 2개 이상 | **"N개 매체"** 요약 (예: `3개 매체`). N = `mediaCount` |
| 조건 조합 | — | 기존과 동일 **단일 매체명** 1개 (예: `Google Ads`) |

**필터**
- 표시 문구와 관계없이 데이터셋에 포함된 **실제 매체**를 기준으로 적용함(필드 매핑은 §B.6).
- 매체를 여러 개 선택하면, 선택한 매체 중 **하나라도 포함된** 데이터셋을 표시함(OR 매칭).

**정렬 (매체 컬럼 기준)**
- 오름차순: **단일 매체 데이터셋을 먼저, 복수 매체 데이터셋을 뒤에** 둠.
  - 단일 매체끼리는 기존 매체명 오름차순.
  - 복수 매체끼리는 **매체 수가 적은 순**, 매체 수가 같으면 **데이터셋명 오름차순**.
- 내림차순: 위 순서를 반대로 적용함.
- **동률 처리(엣지)**: 위 비교 키가 모두 같아도(단일에서 매체명 동일, 복수에서 매체 수·데이터셋명 모두 동일) 순서가 흔들리지 않도록 **최종 타이브레이커로 `id` 오름차순**을 적용함(안정 정렬). 내림차순에서도 `id` 타이브레이커는 오름차순 고정으로 두어, 같은 묶음의 표시 순서가 토글 간 일관되게 유지됨.

| L7 | L 목록 | 업종 레벨 제약 | `extractMode === 'product'` 데이터 | 업종 분류 레벨이 항상 대분류(`industryLevel: 'major'`) | 동작 |

| L9 | L 목록 | 매체 필터 비매칭 | 위 데이터셋, 필터 `TikTok`만 선택 | 해당 데이터셋 숨김(미포함) | 동작 |
| L10 | L 목록 | 매체 정렬 단일/복수 경계 | 매체 오름차순 정렬 | 단일 매체 그룹이 복수 매체 그룹보다 앞 | 동작 |
| L11 | L 목록 | 매체 정렬 복수 동률 | 복수 매체 2건의 매체 수가 동일 | 데이터셋명 오름차순으로 정렬 | 동작 |

### B.5 업종 제약 (참고)

광고상품 기준은 **대분류 업종만** 선택 가능하므로, 목록의 광고상품 데이터셋은 업종 레벨이 항상 대분류(`industryLevel: 'major'`)임(L7). 업종 표시 함수는 기존과 공유(레벨·개수 그대로 표기). 제약 자체는 §C.2.1에서 규정.

## C. 데이터셋 생성 (`/datashot/new`)

> 추출 기준 분기 흐름. `CreateDataset.tsx`가 `currentStep===2`에서 `formData.extractMode==='product'`면 `CreateDatasetStep2Product`, 아니면 기존 `CreateDatasetStep2`를 렌더. Step3도 동일하게 분기.

### C.1 레이아웃 — 추출 기준 분기 흐름

```
Step1 (기본 정보)
 ├─ 데이터셋명
 ├─ 지표 구성 (종합/성과)
 ├─ 조회기간
 ├─ 추출 기준 ★신규  [광고상품 | 조건 조합] 택1
 └─ 업종              ← 추출 기준 선택 후에만 노출 / 광고상품이면 대분류만

Step2 (상세 설정) — 추출 기준에 따라 분기
 ├─ extractMode='condition' → 기존 CreateDatasetStep2 (매체 단일 → 광고분류 → 타겟팅 → 지표)
 └─ extractMode='product'   → CreateDatasetStep2Product
       ├─ 매체 · 광고상품 (다매체 체크 + 매체별 상품 다이얼로그)

       ├─ 상세 조건 (선택, 매체 1개일 때만)
       │    ├─ 협력 광고 파트너사 (Meta 전용)
       │    └─ 타겟팅 옵션
       │    └─(구분선)
       └─ 지표 (매체 1개=매체 지표 / 2개↑=공통 지표)

Step3 (검토 및 추출)  ← extractMode별 분기(§C.2.6)

우측: Configuration Summary (BASIC INFORMATION / QUERY SETTINGS / REVIEW)
       └ extractMode별 QUERY SETTINGS 분기

### C.2 영역별 상세

#### C.2.1 추출 기준 선택 (Step1)

> 상태: **구현 완료** (`CreateDatasetStep1.tsx`, `createDatasetTypes.ts`, `CreateDataset.tsx`).

- **배치 위치**: Step1(기본 정보)의 **조회기간 블록 아래 · 업종 블록 위**.
- **왜 Step1인가**: 추출 기준은 이후 전 단계(매체·업종·지표)의 선택지를 가르는 **최상위 분기**임. 가장 먼저 정해야 뒤 입력이 일관되므로 기본 정보 단계에서 결정함.
- **선택지**: `광고상품` / `조건 조합` **택1**(아이콘 + 제목 + 2줄 설명 카드, 택1 필수 선택 버튼 패턴).

  - 조건 조합 카드 설명: "매체별 상세 옵션을 직접 조합해 세밀하게 데이터를 추출 ⏎ (업종 대·중분류 선택 가능)"
  - 상단 안내: "데이터를 어떤 기준으로 추출할지 선택하세요. 선택한 기준에 따라 설정할 업종·매체·지표 항목이 달라집니다."
- **버튼 동작**: 같은 버튼 재클릭은 무시(동일 값). 다른 버튼 클릭 시 전환하되 "기준 변경 시 초기화" 규칙을 거침.
- **업종 블록 노출 제어**: 추출 기준이 선택되기 전에는 업종 블록을 숨김. 선택되면 바로 아래에 나타남. (추출 기준이 업종 선택 가능 레벨을 결정하므로 순서를 강제)
- **업종 레벨 제약**:
  - `광고상품` → 업종 **대분류만** 선택 가능
  - `조건 조합` → 업종 **대분류·중분류** 선택 가능
  - 다이얼로그 반영: `IndustryDialog`에 추출 기준을 전달해 `광고상품`이면 "중분류" 레벨 토글을 **비활성화(disabled)**하고, 토글 아래에 "추출 기준이 광고상품인 경우 대분류 업종만 선택할 수 있습니다."를 표시.
- **기준 변경 시 초기화 (중분류만, 사전 확인)**: `광고상품`으로 바꾸는데 현재 선택 업종이 **중분류**이고 1개 이상이면 → 즉시 바꾸지 않고 **확인 다이얼로그**를 띄움. 현재 선택이 대분류이거나 선택 업종이 없으면 확인 없이 즉시 변경(잃을 입력 없음). (파괴적 변경 사전 확인 원칙은 §C.3)

  | 항목 | 내용 |
  |---|---|
  | 제목 | "선택한 업종 초기화" |
  | 본문 | "광고상품 기준은 대분류 업종만 선택할 수 있습니다. 변경하면 선택한 업종이 초기화됩니다. 계속 진행하시겠습니까?" |
  | 변경 | `extractMode = 'product'` + 업종 초기화(`industries: []`, `industryLevel: null`) |
  | 취소 | 아무것도 바뀌지 않음(추출 기준도 그대로) |

  - **문구 참조**: 제목 "선택한 업종 초기화"는 `IndustryDialog`의 분류 레벨 변경 확인 다이얼로그 제목과 **동일 문구** 재사용(톤앤매너 통일). 본문만 광고상품 전환 맥락으로 조정.
  - **알림 방식**: 플랫폼 표준 확인 다이얼로그. CreateDataset이 다이얼로그를 렌더하고, Step1은 `onConfirmResetForProduct()` 콜백으로 상위에 확인을 요청함.
- **용어**: 생성 폼 `extractMode` 값은 `'product' | 'condition' | ''`(미선택). 목록과 동일하게 `'condition'` 사용.

#### C.2.2 매체·상품 선택 (광고상품 기준)

> 상태: **구현 완료** (`CreateDatasetStep2Product.tsx`, `MediaProductSelect.tsx`, `ProductDialog.tsx`).

- **매체 목록**: `Google Ads`, `Meta`, `kakao모먼트`, `NAVER 성과형 DA`, `NAVER 보장형 DA`, `TikTok`.
- **매체 선택**: 체크박스로 다매체 선택. 선택 시 "상품 추가" 버튼 노출, 선택 상품 수 뱃지 표시함.
- **매체·상품 선택 인터랙션 세부** (추측 방지):
  - **매체 체크 ON**: `mediaProducts[media] = []`(빈 상품 배열 등록). "상품 추가" 버튼 + 빈 상태 힌트("'상품 추가' 버튼을 클릭하여 상품을 추가하세요") 노출.
  - **매체 체크 OFF**: 해당 매체 키 제거 → **그 매체의 선택 상품도 함께 삭제**(연관 데이터 제거).
  - **개별 상품 제거(X 아이콘)**: 리스트에서 해당 상품만 제거(다이얼로그 거치지 않음).
  - **상품 수 뱃지**: "상품 추가" 버튼에 선택 상품 수를 뱃지로 표기(0개면 미표기).
- **상품 선택 다이얼로그** (`ProductDialog`):
  - 상단 안내: "Step1에서 선택한 기간·업종의 집행 데이터가 있는 상품만 표시됩니다."
  - 상품 소스: `scenario/constants`의 `mediaData.DIGITAL`. DataShot 매체명 ↔ 키 표기 차이는 공백 제거 정규화로 보정. (2026 1~6월 범위면 집행 데이터 있는 상품만 노출)
  - **검색**: 상품명 **부분 일치(substring)**, **대소문자 무시**, onChange 실시간(디바운스 없음), 공백 트리밍 없이 입력 그대로 비교.
  - **전체 선택/해제**: **검색 필터 결과(filteredProducts) 기준**. 필터된 상품이 모두 선택돼 있으면 "전체 해제"(필터 결과만 해제, 그 외 선택 유지), 아니면 "전체 선택"(기존 선택 + 필터 결과 합집합).
  - **선택 카운트**: "선택됨: {선택 수}/{전체 상품 수}"(검색과 무관하게 전체 기준).

  - **취소/오버레이 클릭/닫기**: 변경 **폐기**(해당 매체 상품은 열기 전 상태 그대로).
- **데이터 모델**: `FormData.mediaProducts: { [media]: string[] }`(매체→선택 상품 배열).

#### C.2.3 상세 조건 선택 (광고상품 기준)

> 상태: **구현 완료** (`CreateDatasetStep2Product.tsx`, `CollaborativePartnerSelect.tsx`, 타겟팅 공유 `TargetingSelector`).

- **상세 조건 그룹** (협력 광고 파트너사 + 타겟팅 옵션을 묶는 선택 섹션):
  - 상세 조건은 **선택 사항**이며, 미선택해도 다음 단계로 진행 가능.
  - 매체가 **1개**일 때만 매체·광고상품과 지표 사이에 표시함.
  - 내부 순서: 협력 광고 파트너사(Meta 전용) → 타겟팅 옵션.
  - 각 아코디언은 기본 닫힘이며, 선택값이 있으면 스텝 재진입 시 해당 아코디언을 펼쳐 표시함.
  - 매체 수가 1개가 아니게 바뀌면 선택된 타겟팅 옵션 값(`targetingCategory`/`targetingOptions`)과 협력 광고 파트너사 값을 초기화함.
  - **왜 매체 1개일 때만인가**: 상세 조건(타겟팅·파트너사)은 단일 매체의 세밀 조건임. 다매체 추출에서는 매체마다 옵션 체계가 달라 하나의 상세 조건으로 묶을 수 없으므로 노출하지 않음.
- **협력 광고 파트너사** (Meta 단일 선택 전용, `CollaborativePartnerSelect`):
  - Meta 단일 선택 시 제공. 옵션 소스는 조건 조합과 동일(`adProductStructureByMedia['Meta'].collaborativePartner`).
  - 광고상품 미선택 시 아코디언 헤더는 유지하고, 내부에 "광고상품을 먼저 선택해주세요."를 표시.
  - 선택한 기간·업종·광고상품에 집행 데이터가 있는 파트너사만 제공. 여러 상품을 선택하면 파트너사 목록은 합집합으로 구성.
  - 선택 가능한 파트너사가 없으면 "선택 가능한 협력 광고 파트너사가 없습니다."를 표시.
  - 광고상품 변경으로 제공 목록에서 제외된 파트너사는 자동 해제.
  - 데이터 모델: `FormData.productCollaborativePartners: string[]`.
- **타겟팅 옵션**: 선택한 매체의 타겟팅 옵션을 제공. 카테고리·옵션 선택 및 해제 규칙은 기존 조건 조합 방식을 따름.
- **상호 배제 — Meta** (왜: 협력 광고 데이터와 기기유형 분해는 동시에 성립하지 않아 한쪽만 허용):

  | 트리거 | 결과 | 안내 문구 |
  |---|---|---|
  | 협력 광고 파트너사 선택 | 타겟팅 '기기유형' 비활성화 | (드롭다운) "협력 광고 파트너사 선택 중에는 사용할 수 없습니다" |
  | 타겟팅 '기기유형' 선택 | 협력 광고 파트너사 아코디언 닫고 비활성화 | (헤더) "타겟팅 옵션에서 '기기 유형' 사용 중에는 선택할 수 없습니다" |
  | 파트너사 전체 해제 | '기기유형' 다시 활성화 | — |
  | 타겟팅 '선택 안 함' 전환 | 협력 광고 파트너사 다시 활성화 | — |
- **데이터 모델**: 타겟팅은 조건 조합과 공유하는 `targetingCategory`/`targetingOptions` 재사용.

#### C.2.4 지표 선택 (광고상품 기준)

> 상태: **구현 완료** (`MetricSelect.tsx`). 매체 선택 후에만 노출.

- **매체 1개**: 해당 매체 지표 전체 제공(조건 조합과 동일 소스).
- **매체 2개 이상**: **공통 지표** 제공. 단, Step1의 **지표 구성(purpose)**에 따라 범위가 달라진다:
  - `종합 지표`(internal) → 공통 지표 **전체 9종**(광고비/노출수/클릭수/조회수/CPM/CPC/CPV/CTR/VTR)
  - `성과 지표`(external) → 공통 지표 중 **계산 지표 5종만**(CPM/CPC/CPV/CTR/VTR). 원본 4종(광고비/노출수/클릭수/조회수) 제외.
  - **왜 다른가**: 성과 지표는 효율·비용 지표에 집중하고, 원본 볼륨 지표는 종합 분석 맥락에서만 의미가 있음.
- **타겟팅 선택에 따른 지표 제외** (매체 1개일 때만): 선택한 타겟팅에 따라 조회 불가 지표를 제외함. 조건 조합 Step2와 **동일 규칙**을 공용 함수 `applyTargetingExclusions(base, media, targetingCategory)`로 공유. 제외 후 빈 그룹은 숨김.
  - **Meta + 기기유형**: `post_reaction`, `post_engagement`, `cost_per_post_engagement`, `link_click`, `cost_per_link_click`, `link_ctr`, `complete_registration`, `cost_per_registration` 제외 + "협력 광고" 그룹 전체 비움.
  - **kakao모먼트 + 디바이스**: `conversions`, `message_send`, `message_open`, `message_click`, `message_open_rate`, `message_click_rate`, `channel_add_cpa`, `channel_add_cvr` 제외.
  - **NAVER 보장형 DA + 노출영역**: `cost`, `cost_guaranteed`, `cpc`, `cpm`, `cpv` 제외.
  - 그 외 조합은 제외 없음. **매체 2개 이상(공통 지표)에는 미적용.**
- **공통 지표(9종)**: `common_cost`(광고비), `common_impressions`(노출수), `common_clicks`(클릭수), `common_views`(조회수), `common_cpm`(CPM), `common_cpc`(CPC), `common_cpv`(CPV), `common_ctr`(클릭률(CTR)), `common_vtr`(조회율(VTR)).
- **공통 지표 기준 매핑 다이얼로그**: 안내 영역의 "공통 지표 기준"(SearchCheck 아이콘) 클릭 시 매핑 표 다이얼로그 제공.
  - **원본 지표 4종**은 매체별 라벨로 매핑:

    | 공통 지표 | Google Ads | Meta | kakao모먼트 | NAVER 성과형 DA | NAVER 보장형 DA | TikTok |
    |---|---|---|---|---|---|---|
    | 광고비 | 광고비 | 광고 소진금액 | 비용 | 매출(소진금액) | 집행금액 | 광고 소진금액 |
    | 노출수 | 노출수 | 노출수 | 노출수 | 노출수 | 노출수 | 노출수 |
    | 클릭수 | 클릭수 | 클릭(전체) | 클릭수 | 클릭수 | 클릭수 | 클릭수 |
    | 조회수 | 조회수 | 동영상 3초 이상 재생수 | 재생수 | 비디오 재생 횟수 | 동영상 조회수 | 재생수 |

  - **계산 지표 5종**은 매체 구분 없이 계산식 1개로 표기(테이블에서 매체 열 colspan 병합):

    | 공통 지표 | 계산식 |
    |---|---|
    | 1,000회 노출당 비용(CPM) | 광고비 / 노출수 * 1,000 |
    | 클릭당 비용(CPC) | 광고비 / 클릭수 |
    | 조회당 비용(CPV) | 광고비 / 조회수 |
    | 클릭률(CTR) | 클릭수 / 노출수 * 100 |
    | 조회율(VTR) | 조회수 / 노출수 * 100 |
- **그룹 UI**: 접기/펼치기 + 검색(부분 일치, 대소문자 무시) + 그룹별 전체 선택/해제. (CreateDatasetStep2의 MetricGroupList 로직 복제)
- **매체 수 변경 시 지표 초기화 (사전 확인)**: 매체 선택이 **지표 소스 경계**(단일 매체 지표 `≤1개` ↔ 공통 지표 `≥2개`)를 넘고 이미 선택한 지표가 있으면 → 즉시 반영하지 않고 **확인 다이얼로그**를 띄움. 2→3, 3→2처럼 **둘 다 공통 지표(≥2) 영역**이면 소스가 안 바뀌므로 다이얼로그 없이 유지(초기화 안 함). (파괴적 변경 사전 확인 원칙은 §C.3)

  | 항목 | 내용 |
  |---|---|
  | 제목 | "선택한 지표 초기화" |
  | 본문 | "매체 수가 바뀌어 선택 가능한 지표가 달라집니다. 변경하면 선택한 지표가 초기화됩니다. 계속 진행하시겠습니까?" |
  | 변경 | 매체 반영 + 지표 초기화(+ 매체가 1개가 아니게 되면 타겟팅/파트너사도 초기화) |
  | 취소 | 매체 변경 자체를 되돌림 |

  - **문구 참조**: 제목·본문은 `CreateDataset.tsx`의 실제 다이얼로그 문구를 그대로 사용하며, 업종 초기화 다이얼로그(§C.2.1)와 **동일한 "선택한 {항목} 초기화" 패턴**으로 통일함.
- **데이터 모델**: `FormData.productMetrics: string[]`.

#### C.2.5 우측 요약 (Configuration Summary)

> 상태: **구현 완료** (`ConfigurationSummary.tsx`).

- **BASIC INFORMATION 블록에 "추출 기준" 항목 추가**:
  - 위치: 조회기간 아래 · 업종 위(Step1 입력 순서와 동일).
  - 값: `광고상품` / `조건 조합` / 미선택 시 `—`.
- **QUERY SETTINGS 블록 광고상품 분기** (`ProductQuerySettings`):
  - `광고상품` 기준이면 **매체 N개 · 매체별 상품 수(+총 상품 수) · 상세 조건(선택 시만) · 선택 지표**로 요약. 매체 미선택 시 `Pending`.
  - **상세 조건 요약**은 매체 1개일 때만 노출하며, 지표 블록과 동일 레이아웃: "상세 조건 {합계}개" 헤더(합계 = 파트너사 수 + 타겟팅 옵션 수) 아래 그룹 칩 묶음(muted 박스)에 `협력 광고 파트너사 › 값들` / `{타겟팅 카테고리명} › 값들`을 각 그룹 행으로 표시. 선택한 것만 행으로 노출.
  - `조건 조합` 기준은 기존 요약(매체·광고분류·타겟팅·지표) 유지.
  - 분기 기준은 추출 기준이며, 광고상품은 단일 매체가 아닌 매체별 상품 구성을 참조함(필드 매핑은 §C.6).

#### C.2.6 검토 및 추출 (Step3)

> 상태: **구현 완료** (`CreateDatasetStep3Product.tsx`). 광고상품 기준일 때 Step3를 분기.

Step3(미리보기·추출)의 규칙은 **조건 조합 Step3와 동일**함 — 컬럼 노출(선택한 항목만 컬럼으로, 미선택 미노출)·업종 레벨대로 노출·"전체 컬럼 보기" 공용 모달·데이터 없음 안내·추출 버튼 비활성이 모두 공통. (상세는 `DataShot_CreateDataset_Spec.md`)

- **유일한 차이 — 행 구성**: 미리보기 행을 **선택한 매체 × 광고상품 × 업종 조합으로 flatten**해 만듦(조건 조합의 단일 매체 조합과 다른 점). 타겟팅·파트너사 행값은 선택 옵션 순환(샘플), 미리보기는 **상위 5행**만 표시.
- **업종**: §C.2.1에 따라 광고상품은 **대분류만**이므로 항상 업종(대)만 노출(값은 Step1에서 고른 실제 업종, 미선택이면 "전체"). 업종 레벨대로 노출된다는 원리 자체는 조건 조합과 동일하며, 광고상품은 선택이 대분류로 고정될 뿐임.
- **데이터 없음 / 추출 버튼**: 행=0 또는 지표=0이면 안내 문구 노출 + "데이터셋 생성 요청" 버튼 비활성(§C.5 V18). 문구·동작은 조건 조합과 동일.

### C.3 공통 입력/인터랙션 규칙 (생성)

- **검색(상품/지표)**: 부분 일치(substring) · 대소문자 무시 · onChange 실시간(디바운스 없음) · 공백 트리밍 없음.
- **다이얼로그 상태**: 열 때 기존 선택 복원, 확인 시 덮어쓰기, 취소/오버레이 폐기. 전체 선택/해제는 **검색 필터 결과 기준**.
- **파괴적 변경은 사전 확인**: 업종 초기화(C.2.1)·지표 초기화(C.2.4)·추출 기준 전환(§C.5 V17)은 모두 확인 다이얼로그로 사전 동의를 받음.
- **스타일 위임**: 모든 px/hsl/grid 수치는 구현 코드 + 디자인 토큰이 단일 진실 공급원. DataShot은 인라인 스타일 모듈 규칙(토큰 값을 인라인으로 사용)을 따름.

### C.4 인터랙션 플로우 (생성)

**정상 플로우 (광고상품 기준)**
1. Step1에서 데이터셋명·지표 구성·조회기간 입력 → 추출 기준 `광고상품` 선택 → 업종(대분류) 선택 → 다음.
2. Step2에서 매체 체크(예: Meta 1개) → "상품 추가"로 상품 선택(복원→체크→확인) → (매체 1개이므로) 상세 조건에서 타겟팅/파트너사 선택 → 지표 선택 → 다음.
3. Step3 미리보기 확인(상위 5행) → "데이터셋 생성 요청" → 생성.

**주요 에러·분기 시나리오**
- Step1에서 추출 기준 미선택 → "추출 기준을 선택해주세요." + 다음 비활성(§C.5 V1).
- 중분류 업종 선택 상태에서 `광고상품`으로 전환 → "선택한 업종 초기화" 확인 다이얼로그(§C.5 V12).
- 매체 2개 선택 후 지표 선택 → 매체를 1개로 줄이면 "선택한 지표 초기화" 확인(§C.5 V13).
- Meta에서 파트너사 선택 → 타겟팅 '기기유형' 비활성화(§C.5 V7), 반대 방향도 상호 배제(V8).

**종합 진행 조건 (의사코드)**

// Step1 (추출 기준 포함) — isStep1Valid
datasetName.trim() && 조회기간 유효 && extractMode !== '' && industries.length > 0 && industryLevel

// Step2 (광고상품 기준) — isStep2Valid (extractMode === 'product')
medias = Object.keys(mediaProducts)
medias.length > 0 && medias.every(m => mediaProducts[m].length > 0) && productMetrics.length > 0

// Step3 (추출 버튼) — isStep3HasData
// 광고상품: 매체×상품 행 > 0 && productMetrics > 0
// 조건 조합: products > 0 && metrics > 0
```

> 경계값(TC용): 매체 0개 ↔ 1개, 매체 1개(상품 0 ↔ 1), 매체 1개 ↔ 2개(지표 소스 전환), 지표 0개 ↔ 1개를 양방향으로 도출.

### C.6 데이터 개념 및 용어 매핑 (생성)

| UI 용어 | 데이터 / 소스 | 비고 |
|---|---|---|
| 추출 기준 | `FormData.extractMode: 'product' \| 'condition' \| ''` | `''` = 미선택 |
| 매체별 상품 | `FormData.mediaProducts: { [media]: string[] }` | 매체→선택 상품 배열 |
| 선택 지표 | `FormData.productMetrics: string[]` | 매체/공통 지표 |
| 협력 파트너사 | `FormData.productCollaborativePartners: string[]` | Meta 단일 선택 시 |
| 타겟팅(공유) | `FormData.targetingCategory` / `targetingOptions` | 조건 조합과 공유 |

> 용어 통일: 추출 기준은 `'product'`(광고상품) / `'condition'`(조건 조합) 두 값으로 목록·생성이 동일하게 씀. "상세 옵션"/`'detail'` 라벨은 폐기. 타입 전문은 `createDatasetTypes.ts` 참조.

## D. 데이터셋 상세/결과 (`/datashot/:id`)

> 기존 "Extracted Data" 테이블 위에 결과 차트 2종 영역을 신설함.

### D.1 목록 → 상세 분기 (추출 기준별)

> 상태: **구현 완료** (`DatasetDetailRouter.tsx` → `DatasetResult.tsx`).

목록에서 데이터셋을 클릭하면 추출 기준에 따라 상세 화면이 분기됨(`/datashot/:id` → `DatasetDetailRouter`).

- 추출 기준이 **광고상품**이면 → **다매체 통합 결과 화면**(`DatasetResult`: 상단 차트 2종 + Extracted Data 테이블).
- 그 외/미지정(**조건 조합**)이면 → **기존 상세 화면**(`DatasetDetail`).
- **왜 분기하나**: 광고상품은 다매체·상품 교차 데이터라 비교 차트가 필요하고, 조건 조합은 기존 단일 매체 상세로 충분함. 추출 방식에 맞는 분석 뷰를 제공함.
- 분기 입력: 목록 클릭 시 넘긴 데이터셋 정보의 추출 기준. (상태 유실 시 조건 조합 상세로 폴백)

### D.2 헤더 (광고상품 상세)

- **헤더 데이터**: `DatasetResult`는 `location.state.datasetData`에서 데이터셋명·매체 수("N개")·업종·조회기간·브레드크럼을 받아 표시. (광고상품·지표 수치, 모달 내용은 실데이터 영역이라 샘플 유지)
- **요약 항목 + 돋보기 모달** (조건 조합 상세와 같은 패턴이되 광고상품 기준):
  - 순서: **매체 · 광고상품(`N개 · N개`) · 조회기간 · 업종 N개 · 지표 N개**. (조건 조합 상세의 "조회조건" 자리를 **"매체 · 광고상품"**으로 교체)
  - **매체와 광고상품은 하나의 요약 항목으로 묶어** `N개 · N개`(매체 수 · 광고상품 총합) 형식으로 표시함. 광고상품은 매체에 종속된 데이터라 한 항목으로 묶어 "매체별 선택 상품"을 한 모달에서 함께 보여주는 편이 맥락 파악에 유리함.
  - **돋보기(SearchCheck 아이콘)**: 매체·광고상품(묶음) · 업종 · 지표 항목에 노출. 클릭 시 상세 모달을 엶. (조회기간은 돋보기 없음)
    - **매체·광고상품 돋보기 → `ProductListModal`**(`DatasetDetailModals` 공용 재사용): 다매체 추출의 "매체별 선택 광고상품" 구조를 읽기전용으로 표시.
    - **업종 돋보기 → `IndustryModal`**(공용 재사용): 대분류 업종 목록 표시.
    - **지표 돋보기 → `MetricsModal`**(공용 재사용): 지표 그룹 읽기전용 표시.
- **헤더 액션 버튼** (조건 조합 상세와 동일 동작):
  - **공유(Share2)**: Copy Link(현재 URL 복사 + 토스트 "현재 URL이 복사되었습니다.") / Export to Excel.
  - **정보(Info, hover)**: 설명 · Dataset ID · 생성일시/생성자(이메일은 `maskEmail` 마스킹) 툴팁.
  - **더보기(MoreVertical)**: 복제 / 이동 / 삭제. 삭제는 확인 다이얼로그(한글 조사 을/를 자동) → 성공 토스트 후 `/datashot` 이동. `id === 10`(종합 지표 데이터셋)은 복제 시 "복제 불가 안내" 다이얼로그.
  - 모달·유틸(`DatasetDetailModals`, `maskEmail`)은 조건 조합 상세와 공용하며, DatasetResult는 추가 분리 없이 재사용함(조건 조합 상세 `DatasetDetail`은 미변경).
  - **문구 참조**: 공유 토스트 "현재 URL이 복사되었습니다.", 삭제 확인 다이얼로그, 정보 툴팁 문구는 모두 **조건 조합 상세(`DatasetDetail`)와 동일 문구** 재사용(두 화면이 같은 헤더 패턴을 공유하므로 톤앤매너·문장 구조를 통일). 신규 문구를 새로 지어내지 않음.
