## 1. 화면 개요

### 1.1 기능 정의
Budget Optimizer 시나리오의 최적화 결과를 확인하는 화면임. 모델이 도출한 **매체·상품별 예산 배분안과 예상 성과(보장 KPI 등)**를 스코어카드·차트·테이블로 제공하고, SpinX 기반 해석을 함께 제공함.

**기획 의도**: 사용자가 "얼마를 어디에 배분했고(투입), 그래서 어떤 성과가 예상되는가(산출)"를 한 화면에서 직관적으로 이해하도록 함. 시나리오 생성 시 **예산 잠금**을 사용한 경우, 잠금이 반영된 결과와 잠금 없이 모델이 자유롭게 최적화한 결과(순수 최적화)를 **비교**할 수 있게 하여, 사용자 개입이 성과에 미친 영향을 확인하게 하는 것이 핵심 가치임.

### 1.2 문서 활용처
- **개발 참고**: 프론트엔드 구현 시 화면 동작·규칙·표기 기준 문서로 활용됨.
- **제품 Docs**: 본 정의서의 기능 설명·의도가 사용자 대상 기능 문서의 기반이 됨.
- **AI 기반 TC 생성**: 표시 규칙(Section 6)·인터랙션 규칙(Section 7)이 테스트 케이스의 원천 데이터가 됨. 각 규칙은 조건 → 기대 결과로 검증 가능하게 작성함.

### 1.3 진입 경로
- 시나리오 목록에서 완료 상태 시나리오 선택 → 결과 화면
- URL: /budgetoptimizer/scenario/:id/result
- **진입 조건**: 시나리오 상태가 완료(Completed)인 경우에만 결과 활성화

### 1.4 화면 구조 (세로 흐름)
결과 상태 띠배너(잠금 시나리오 한정)
→ 스코어카드(4종)
→ Optimization Analytics (차트 4종: Budget Input 2 + Performance Output 2)
→ Budget Allocation Detail (매체>상품 테이블)
→ Reach Caster 간편 생성 CTA

- **CTA**: 테이블 하단에 "Reach Caster로 이 예산안의 도달 성과 예측하기" 버튼을 둠. 클릭 시 간편 생성 중간 설정 레이어를 엶(상세는 Section 9).

## 3. 결과 상태 띠배너 (잠금/순수 모드)

### 3.1 노출 조건
- **잠금이 1개 이상인 시나리오**에서만 노출함. 잠금이 하나도 없으면 이 배너 대신 기본 타이틀(Optimized Budget Allocation + 설명)만 표시함.
- **기획 의도**: 잠금이 없으면 결과는 곧 모델의 순수 최적화이므로 비교 대상이 없음. 비교가 의미 있는 경우(잠금 존재)에만 모드 전환 UI를 제공함.

### 3.2 구성
화면 폭을 가로지르는 풀블리드 띠임. 자물쇠/열린 자물쇠 아이콘 + 모드명 + 설명 + 우측 모드 전환 버튼으로 구성함.

| 모드 | 모드명(영문) | 설명 문구(실제 노출) |
|---|---|---|
| 잠금 반영 | Locked Budget Allocation | "시나리오 생성 시 설정한 예산 잠금이 반영된 최적화 결과입니다." |
| 순수 최적화 | Fully Optimized Allocation | "예산 잠금 없이 모델이 전체 예산을 자유롭게 최적 배분한 결과입니다." |

### 3.3 모드 전환 버튼

| 현재 뷰 | 버튼 문구 | 아이콘 |
|---|---|---|
| 잠금 반영 | 순수 최적화 결과 보기 | 열린 자물쇠 |
| 순수 최적화 | 잠금 반영 최적화 결과 보기 | 자물쇠 |

- **동작**: 클릭 시 스코어카드·테이블·차트 전체가 해당 모드 데이터로 전환됨.
- **순수 최적화 뷰 부수효과**: 예산 잠금(Lock) 표시를 모두 숨김(잠금이 없는 결과이므로).

## 4. 화면 내 KPI 변수 처리 (KPI 파생 표기 규칙)

시나리오 생성 시 선택한 **1개의 KPI**(노출/클릭/조회/도달)가 결과 화면 전반의 라벨·차트 제목·부제·툴팁에 일관되게 파생 반영됨. 화면에 하드코딩된 "노출" 같은 값은 없으며, **선택 KPI에 따라 표기가 전부 바뀜.** 이 규칙은 스코어카드·차트·테이블을 아우르는 전역 규칙이라, 개별 화면 요소를 설명하기 전에 먼저 둠.

### 4.1 KPI 원천 값과 매핑
- **원천**: 시나리오 결과 데이터의 KPI 종류(kpi) — impression / click / view / reach 중 하나임.
- **매핑 테이블**(UI ↔ 데이터, 구현: KPI_META):

| KPI 코드(kpi) | 한글 라벨(label) | 영문 라벨(labelEn) | 단위(unit) |
|---|---|---|---|
| impression | 노출 | Impression | 회 |
| click | 클릭 | Click | 회 |
| view | 조회 | View | 회 |
| reach | 도달 | Reach | 회 |

- **한글↔영문 파생**: 차트 컴포넌트는 한글 라벨을 받아 영문으로 역매핑함(노출→Impression, 클릭→Click, 조회→View, 도달→Reach). 매핑에 없는 값이 들어오면 입력값을 그대로 표기함(fallback).

### 4.2 KPI에 따라 치환되는 요소
({KPI} = 한글 라벨, {KPIEn} = 영문 라벨)

| 위치 | 표기 패턴 | 예시(KPI=클릭) |
|---|---|---|
| 스코어카드 1번 카드 제목 | Guaranteed {KPIEn} | Guaranteed Click |
| Incremental 영문 차트명(제목 옆) | Incremental {KPIEn} | Incremental Click |
| Response Curve 부제 | 예산 투입 대비 보장 {KPI} 반응 | 예산 투입 대비 보장 클릭 반응 |
| Incremental 부제 | 균등 배분 대비 채널별 {KPI} 증감 | 균등 배분 대비 채널별 클릭 증감 |
| 차트 Info 툴팁 | "…채널별 {KPI} 창출·감소…", "최적화 후 도달하는 총 {KPI}", "…주차별 {KPI} 기여 패턴…" 등 | …채널별 클릭… |
| Budget Allocation Detail 테이블 | Guaranteed {KPIEn} 컬럼이 선택 KPI로 치환됨(컬럼 상세 규칙은 Section 8) | Guaranteed Click 컬럼 |

- **KPI 무관 고정**: 4개 차트의 **한글 질문형 대표 제목**(예: "최적화로 성과가 얼마나 늘어날까?")은 KPI와 무관하게 항상 고정임. Budget Share·Weekly Contribution 부제도 KPI를 표기하지 않음(각각 예산·매체 기여 기반).
- **의도**: 사용자가 시나리오에서 무엇을 KPI로 잡았는지를 화면 어디서든 즉시 인지하게 함. 한글 대표 제목은 차트의 목적(질문)을 전달하는 역할이라 KPI에 의존하지 않게 고정하고, 선택 KPI 맥락은 영문 차트명·부제·컬럼에서 드러냄.

### 4.3 단위 처리 규칙
- **모든 KPI(노출/클릭/조회/도달)**: 값은 정수 + 회로 표기함. 도달(Reach)도 비율(%)이 아니라 **도달 수(명 단위이나 표기는 회)** 개념으로 다룸.

### 4.4 검증 포인트 (TC 도출)
- KPI=노출로 진입 → 1번 카드 제목이 "Guaranteed Impression", Incremental 영문 차트명이 "Incremental Impression", Response Curve 부제가 "예산 투입 대비 보장 노출 반응"인가.
- KPI=도달로 진입 → 위 파생 표기가 모두 도달/Reach로 바뀌고, 스코어카드·테이블 Reach 컬럼 단위가 모두 회인가(%가 아닌가).
- KPI 종류와 무관하게 Avg. CPM은 노출 합계 기준으로 계산되는가(클릭/조회/도달 KPI에서도 CPM 산출식 동일).
- KPI를 어떤 값으로 바꿔도 4개 차트의 한글 대표 제목(질문형)은 모두 **불변**인가.

## 5. 스코어카드

### 5.1 구성 (4종)
| 카드 | 값 | 비고 |
|---|---|---|
| Guaranteed {KPI} | 보장 KPI 합계 | KPI는 시나리오 설정값(노출/클릭/조회/도달) |
| Total Budget | 총 예산 | 정수(원), 축약 없이 전체 표기 |
| Avg. CPM | 평균 CPM | 총예산 ÷ (총노출/1000) |
| Locked Budget | 잠금 예산 합계 + 비중(%) | 잠금 있는 시나리오에서 의미 |

- **디자인 기조**: Reach Caster의 Reach Predictor 스코어카드와 동일함(값 강조, hover 시 떠오름, 아이콘 배경 없음). 다크모드 대응함.
- **KPI 라벨**: 한글+영문 혼용 표기를 원칙으로 함(예: "노출 (Impression)"). 단, 결과 테이블 컬럼명은 영문만 사용함.

### 5.2 스코어카드 산출식 (검증용)
각 카드 값은 **현재 표시 중인 모드(잠금 반영/순수 최적화)의 배분 데이터**를 기준으로 계산함. 모드를 전환하면 아래 값도 해당 모드 데이터로 재계산됨.

| 카드 | 산출식 | 표기 규칙 |
|---|---|---|
| Guaranteed {KPI} | 배분별 보장 KPI 값(kpiValue)의 합계 | 정수 + 회. 도달(Reach)도 도달 수(명) 개념이므로 회로 표기 |
| Total Budget | 시나리오 총 예산 | 정수(원), 축약 없이 전체 표기 |
| Avg. CPM | 총노출 > 0이면 총예산 ÷ (총노출 ÷ 1000)을 반올림, 총노출 = 0이면 0 | 정수(원). KPI 종류와 무관하게 항상 **노출(impression) 합계** 기준으로 계산 |
| Locked Budget | 잠금(isFixed=true) 배분 예산의 합계 + 비중 | 잠금 예산 > 0이면 "{금액}원 ({비중}%)", 잠금이 없으면 값 0·비중 표기 없음. 비중 = 잠금예산 ÷ 총예산 × 100(소수점 2자리, 예: 52.20%) |

- **경계 케이스**: 총노출 = 0 → Avg. CPM은 0(0으로 나눔 방지). 잠금 예산 = 0 → Locked Budget 값 0, 단위/비중 미표기.

## 6. Optimization Analytics (차트 4종)

### 6.1 섹션 구조
- 상위 제목 Optimization Analytics + "최적화 원리 알아보기"(SpinX 트리거) + 매체/상품 공통 토글이 동일 선상에 위치함.
- **차트 헤더 구조**: 각 차트는 (1) 한글 질문형 제목(차트 목적을 즉시 이해하도록) + (2) 제목 옆 작은 **영문 차트명**(Budget Share / Response Curve / Weekly Contribution / Incremental {KPIEn}) + (3) 그 아래 **한글 부제**로 구성함. 부제는 **한글 설명구만** 두며 영문을 넣지 않음(제목 옆 영문 차트명과 중복 방지). 4개 차트 부제 톤앤매너를 한글 명사구로 통일함.

| 차트 | 한글 부제 |
|---|---|
| Budget Share | 매체·상품별 예산 배분 비중 |
| Response Curve | 예산 투입 대비 보장 {KPI} 반응 |
| Weekly Contribution | 업종 모델이 학습한 주차별 매체(또는 상품) 기여 패턴 |
| Incremental | 균등 배분 대비 채널별 {KPI} 증감 |
- 4개 차트는 2×2 그리드임. 상단 2개 = 예산 투입 관점, 하단 2개 = 성과 산출 관점임.

| 위치 | 차트 | 한글 질문 제목 | 영문명 |
|---|---|---|---|
| 상단 좌 | Budget Share | 예산은 어디에 배분되었을까? | Budget Share |
| 상단 우 | Response Curve | 예산을 더 넣으면 성과가 오를까? | Response Curve |
| 하단 좌 | Weekly Contribution | 업종 내 매체별 기여는 어떤 흐름일까? | Weekly Contribution |
| 하단 우 | Incremental | 최적화로 성과가 얼마나 늘어날까? | Incremental {KPIEn} |

> **제목 워딩 규칙(중요)**: 결과 화면의 수치는 실제 집행 성과가 아니라 **모델이 예측한 최적 배분안**임. 따라서 차트 제목은 완료형("늘었을까?")이 아닌 **예측/전망형("늘어날까?")**으로 통일함. 완료형은 "이미 캠페인을 집행해 성과가 확정된" 인상을 주어 예측 결과라는 성격을 오해하게 하므로 지양함. 나머지 제목("배분되었을까?"는 이미 산출된 배분안을 설명하므로 유지, "오를까?"도 전망형).

### 6.2 매체/상품 공통 토글
- 하나의 토글(매체 / 상품)이 **4개 차트 전체**에 동시 적용됨.
- 매체 뷰: 매체 단위 집계임. 상품 뷰: 매체 > 상품 단위임.
- **표시 상한**: 각 차트는 기여/비중 상위 5개 항목만 표시함(그 외는 차트별 규칙에 따라 기타 묶음 또는 제외함).

### 6.3 Budget Share

| 항목 | 정의 |
|---|---|
| 차트 형태 | 100% Stacked Bar |
| 축 | 단일 막대(축 없음). 매체(또는 상품)별 예산 비중을 가로로 분할 |
| 시리즈 | 매체(또는 상품)별 예산 비중 |
| 표시 상한 | 상위 5개 개별 표시, 나머지는 기타(Others)로 합산 |
| 색상 | 비중 1위만 강조색, 나머지는 무채색 opacity 단계(모노톤) |

- **Info 툴팁**: "선택된 매체/상품별 예산 배분 비중을 시각화합니다. 상위 5개 항목까지 개별 표시되며, 나머지는 '기타(Others)'로 합산됩니다."
- **의도**: 예산이 어디에 얼마나 배분되었는지 비중을 한눈에 보여줌.

### 6.4 Response Curve

| 항목 | 정의 |
|---|---|
| 차트 형태 | 라인(선형 렌더) |
| X축 | 예산 투입액. 캠페인 총예산 기준으로 고정(줌 토글 없음) |
| Y축 | 보장 KPI |
| 시리즈 | 매체(또는 상품), KPI 기여 상위 5개 |
| 곡선 생성 | 포화 함수 y=a×(1−e^(−b×x))로 데이터 생성(오버슈팅/꺾임 방지) |
| 마커 | Current spend — 각 시리즈 현재 배분 예산 지점에 점 1개 |
| 범례 | 우측. 클릭 시 시리즈 표시/숨김 토글(숨김 시 흐림 + 취소선) |

- **Info 툴팁**: "매체별 예산 투입 대비 KPI 반응 곡선입니다." + 항목 설명 — ●점(Current Spend)=현재 배분된 예산 지점 / 점 왼쪽=이미 투입된 예산 구간의 성과 / 점 오른쪽=추가 투입 시 예상 성과(곡선이 완만할수록 효율 포화) / KPI 기여 상위 5개 항목만 표시.
- **주요 참고(구현 논의 중)**: 곡선의 진실 공급원 — 현재는 프론트가 포화함수 계수(satA/satB)로 곡선을 생성하나, 백엔드가 포인트 배열을 내려주고 선형보간하는 방식도 검토 대상임. 상품 뷰의 maxSpend는 현재 프론트가 예산×3으로 임의 산정 중 → 모델 제공값으로 대체 필요. currentSpend 마커 Y값은 곡선 계산값이 아니라 실제 예측 KPI와 일치하는지 검증 필요. (상세는 Section 12 예정 기능)
- **의도**: "지금보다 예산을 더 넣으면 효율이 더 나오는지(포화 여부)"를 판단하게 함.

### 6.5 Weekly Contribution

| 항목 | 정의 |
|---|---|
| 차트 형태 | 누적 영역(monotone 곡선) |
| X축 | 주차(week) 시계열 |
| Y축 | 주차별 KPI 기여 |
| 시리즈 | 매체(또는 상품), 기여 상위 5개 |
| 조회 구간 토글 | 최근 1년(52주) / 최근 2년(전체 104주). X축 우측(범례 하단, X축 선상)에 배치 |
| 동기간 음영 밴드 | 내 캠페인 기간의 전년·전전년 동기간을 보라색 음영(ReferenceArea) + "{연도} 동기간" 라벨. 표시 구간과 겹치는 부분만 클램프 |

- **성격(중요)**: 이 시나리오의 미래 예측이 아니라, **해당 업종 모델이 학습한 과거 기간의 주차별 기여 패턴**임(브랜드 모델이 아닌 업종 모델 기준).
- **Info 툴팁**: "해당 업종 모델이 학습한 과거 기간의 매체별(또는 상품별) 주차별 KPI 기여 패턴입니다. 이 시나리오의 미래 예측이 아니라, 업종 데이터에서 관측된 매체별 기여 경향을 보여줍니다." + 항목 설명 — 최근 1년=가장 최근 52주 / 최근 2년=모델 학습 전체 기간(104주) / 보라색 음영=내 캠페인 기간의 전년·전전년 동기간(같은 시기 업종 매체 기여 참고) / 기여 상위 5개만 표시.
- **의도**: "내 캠페인 시기(예: 7~9월)에 업종에서는 과거에 어떤 매체 기여가 높았나"를 벤치마크로 참고하게 함.
- **오해 방지**: "캠페인 종료 후 잔존 효과 추정" 등 미래 예측 프레임 문구는 쓰지 않음.

### 6.6 Incremental (KPI 증분 워터폴)

| 항목 | 정의 |
|---|---|
| 차트 형태 | 워터폴 |
| X축 | 균등 배분(기준) → 채널(또는 상품)별 증감 → 최적화(최종) 순. 항목명이 길면 한 줄 10자·최대 2줄 말줄임(전체는 툴팁) |
| Y축 | 총 KPI (0부터 표시) |
| 막대 색 | 최적화(최종)=강조색, 균등 배분(기준)=진한 무채색, 증감 막대=흐린 무채색 |
| 값 라벨 색 | 증가(+)=초록, 감소(−)=빨강 (테이블 delta 색과 통일) |
| 연결선 | 이전 막대 누적 상단 → 다음 막대를 잇는 점선 |

- **Info 툴팁**: "균등 배분에서 최적화까지, 채널별 KPI 창출·감소 기여를 누적해 보여줍니다." + 항목 설명 — 최적화(보라)=최적화 후 도달하는 총 KPI / 균등 배분(진한 회색)=최적화 전 기준 총 KPI / +초록 값=예산 증액으로 창출된 KPI / −빨강 값=예산 감액으로 감소한 KPI / 얻은 KPI가 잃은 KPI보다 크면 최종값이 더 높아짐.
- **의도**: "균등하게 나눴을 때보다 최적화로 성과가 얼마나 순증하는지"를 잃은 것 vs 얻은 것 대비로 보여줌.

### 6.7 차트 공통 규칙

두 종류의 툴팁을 구분함.

| 툴팁 종류 | 트리거 | 내용 |
|---|---|---|
| Info 툴팁 | 각 차트 제목 옆 Info 아이콘 hover | 차트 해석 방법 안내(각 차트 6.3~6.6의 Info 툴팁 문구) |
| 데이터 호버 툴팁 | 차트 요소(막대/점/영역) hover | 해당 지점의 값. 축약 없이 전체 숫자(천 단위 콤마)로 표기 |

- **축 틱 라벨**: Y/X축 틱만 축약(억/천만/만) 허용. (데이터 값 자체는 축약 금지)
- **표시 상한(공통)**: 4개 차트 모두 상위 5개 항목만 표시함. 초과분은 차트별 규칙에 따라 기타(Others) 묶음 또는 제외함.
- **매체/상품 토글 연동**: 6.2 공통 토글이 4개 차트에 동시 적용됨.

## 7. SpinX 인사이트 (차트별 해석)

> **범위 한정**: 이 섹션은 **결과 화면에서의 SpinX 노출·인터랙션 정의**만 다룸. SpinX의 프롬프팅·응답 생성 로직·모델 연동 등 기능 상세는 별도 SpinX 문서에서 관할하며 여기서 다루지 않음.

### 7.1 구성
- 각 차트 하단에 SpinX 해석 블록을 둠. 상단 헤어라인으로 차트와 구분함(카드/보더 박스 없이 미니멀).
- 헤더에 SpinX 심볼 + "SpinX for Budget Optimizer" 워드마크를 둠. 로딩 중 타이핑 효과(심볼 회전 + analyzing…)를 줌.
- 본문: 해당 차트에 대한 해석 텍스트(약 300자 내외)임.

### 7.2 "이어서 질문하기"
- 해석 블록 하단 텍스트 링크임. **클릭 시 질문을 자동 전송하지 않고**, SpinX 패널을 열어 입력창에 해당 차트 멘션("@{차트명} ")을 프리필함.
- **의도**: 사용자가 해당 차트를 컨텍스트로 두고 이어서 자유롭게 질문하게 함.

### 7.3 SpinX @멘션
- SpinX 입력창에서 @ 입력 시 결과 화면의 차트 목록(Budget Share / Response Curve / Weekly Contribution / Incremental) 자동완성 드롭다운이 뜸.
- 선택 시 "@{차트명} " 텍스트가 삽입됨. 키보드(↑↓ 이동, Enter/Tab 선택, Esc 닫기) 및 클릭을 지원함.
- **의도**: 차트를 대화 컨텍스트로 첨부해, 해당 차트 데이터 기반 답변을 유도함. (실제 데이터 주입은 백엔드 연동 시)

### 7.4 최적화 원리 트리거 (헤더 레벨)
- Optimization Analytics 제목 옆 "최적화 원리 알아보기"(SpinX 심볼) 클릭 시, SpinX 패널이 열리며 최적화 원리 질문을 **자동 전송**함.
- 잠금 여부와 무관하게 항상 노출함(차트 존 제목 라인에 위치).

## 8. Budget Allocation Detail (테이블)

### 8.1 구성
매체 > 상품 1-2뎁스 아코디언(Expand/Collapse)임. Reach Caster Estimated Performance 테이블 톤앤매너를 따름. 지표 컬럼명은 **영문만** 사용하고, 숫자 뒤에 작고 흐린 단위를 붙임. 0값은 하이픈(-)으로 표기함.

| 컬럼 | 단위/표기 | Estimated Total 행 |
|---|---|---|
| 매체>상품 | 한글명 | (라벨) |
| Budget | 정수(원) | 개별 행 합계 |
| Share | 소수점 2자리 % | 100% |
| Guaranteed {KPI} | 정수(회) | 개별 행 합계 |
| Impression | 정수(회) | 개별 행 합계 |
| Click | 정수(회) | 개별 행 합계 |
| View | 정수(회) | 개별 행 합계 |
| Reach | 정수(회) | 모델 제공 총 도달값(아래 참조) |
| CPM | 정수(원) | 전체 평균 |
| CPC | 정수(원) | 전체 평균 |
| CPV | 정수(원) | 전체 평균 |

- **잠금 표시**: 예산(Budget) 셀에 자물쇠 아이콘을 표시함(금액 기준이 정확함).
- **Estimated Total의 Reach**: 매체 간 도달은 중복되므로 프론트에서 단순 합산하지 않음. **모델(데이터사이언티스트)이 중복 제거해 계산한 총 도달 값을 그대로 표시**함(잠금 반영/순수 최적화 뷰 각각 별도 값). 해당 값이 내려오지 않으면 하이픈(-)으로 표기함.

### 8.2 순수 최적화 뷰 delta 표시
- 순수 최적화 뷰(잠금 해제)로 볼 때, 잠금 반영 결과 대비 값 차이를 **Budget / Share / Guaranteed {KPI}** 컬럼에 delta로 표시함(증가 초록, 감소 빨강). Estimated Total 행도 동일함.
- 순수 최적화 뷰에서는 잠금 아이콘을 표시하지 않음.

## 9. Reach Caster 간편 생성 (Easy Create)

결과 화면의 최적 예산 배분안을 Reach Caster 도달 예측으로 끊김 없이 연결하는 기능임. 완료 상태 결과 화면 하단 CTA에서 진입함. **구현 완료.**

### 9.1 진입
- 위치: Budget Allocation Detail 테이블 하단 CTA. 문구 "Reach Caster로 이 예산안의 도달 성과 예측하기" + 보조문구 "최적화된 매체별 예산·예상 노출 기반".
- 클릭 시 중간 설정 레이어(다이얼로그)를 엶. 여기서 타겟 GRP·예상 노출 전달 방식을 확정한 뒤 Reach Caster 시나리오 생성(Step2)으로 예산·매체를 프리필하며 이동함.

### 9.2 중간 설정 레이어

| 항목 | 정의 |
|---|---|
| 시나리오명 | 프리셋 "(BO-{시나리오ID}) {원본 시나리오명}", **변경 불가**(원본 추적용) |
| 업종·기간 | 원본 시나리오 값 승계(표시) |
| 타겟 GRP | 남/여 성별 섹션으로 선택. 기본값 **전체 선택**. 성별별 전체 선택/해제 지원. 최소 1개 이상 선택해야 생성 가능 |
| 예상 노출 전달 모드 | 3택 — 미전달(none) / 필수 상품만(required) / 전부(all). **기본값 전부(all)** |
| 매핑 가능/불가 | Reach Caster 미지원(매핑 불일치) 항목은 별도로 분리해 안내. 매핑 가능 항목만 프리필 대상 |

- **예상 노출 필수 상품**: CPT/보장형/예약형 상품(상품명 패턴 `_CPT` / 예약형 / 보장형)은 예상 노출 확정 입력이 필요한 항목으로 판별함. required 모드일 때 이 항목만 노출을 전달함.
- **생성 가능 조건**: 타겟 GRP 1개 이상 선택 AND 매핑 가능 항목이 1개 이상. 매핑 가능 항목이 0이면 생성 불가.

### 9.3 확정 시 동작
- Reach Caster 시나리오 생성 Step2로 이동하며, 매핑 가능한 매체·상품의 예산을 프리필함.
- 예상 노출 전달: none=미전달 / required=CPT 등 필수 상품만 전달 / all=전부 전달. 전달 대상 상품에 예상 노출값을 함께 넘김.
- 원본 정보(시나리오명·업종·브랜드·기간·타겟 GRP·노출 모드)를 함께 승계함.

### 9.4 데이터 매핑(용어)
- 미지원 판별: 현재 mock 기준 Targetpick 매체 및 "디스플레이_방문" 상품을 미지원으로 간주함(실제 매핑 규칙은 연동 시 확정).
- 구현: `BOReachCasterEasyCreateModal.tsx`, 진입 CTA·이동 로직은 `BOResult.tsx`.

## 11. 데이터 개념 및 용어 매핑

결과 데이터는 **매체·상품 배분(allocations)** 을 기본으로, 잠금 반영/순수 최적화 두 세트를 가짐. UI 용어와 데이터 필드 매핑은 아래와 같음.

| UI 용어 | 데이터 필드 |
|---|---|
| 잠금 반영 결과 | 기본 allocations (일부 isFixed=true) |
| 순수 최적화 결과 | pureAllocations (모두 잠금 해제) |
| 잠금 | 필드 isFixed |
| 총 도달(잠금 반영 / 순수) | totalReach / pureTotalReach |

차트별 데이터 소스:

| 차트 | 데이터 소스 |
|---|---|
| Budget Share / Response Curve / Incremental | allocations 기반 |
| Weekly Contribution | 업종 모델 학습 주간 시계열(별도 소스) |

- 정확한 타입·필드는 구현 파일(resultSampleData.ts)을 참조함.

## 12. 예정 기능 (이 화면 한정)

| 항목 | 내용 | 사용자 가치 | 상태 |
|---|---|---|---|
| Export (Excel/PDF) | 결과 데이터 다운로드 | 결과 공유·보고 활용 | **완료** (헤더 Export 버튼 구현됨) |
| Reach Caster 간편 생성(Easy Create) | 결과 화면 CTA → 중간 설정 → Reach Caster Step2 예산 프리필 | 최적화 예산안을 도달 예측까지 끊김 없이 연결 | **구현 완료** (상세는 Section 9) |
| 최적화 원리 안내 (KPI 역전 설명 포함) | "최적화 원리 알아보기"에 최적화 동작 원리 + 순수 최적화가 잠금 결과보다 낮게 나올 수 있는 이유(효율 포화·매체 우선 배분)를 함께 설명 | 최적화 신뢰도 오해 방지 | 채택 (BO-001 이슈 연계) — 구현 예정 |

### 12.1 최적화 원리 안내 (구현 방향 검토 중)

- **배경**: 순수 최적화 결과가 사용자의 잠금 반영 결과보다 보장 KPI가 낮게 나오는 경우가 있음(BO-001). 이는 순수 최적화가 효율 포화 지점을 넘지 않게 배분하고, 매체 우선 배분(Meridian 모델 권장)을 하기 때문으로, 오해를 방지하려면 원리 설명이 필요함.
- **통합 방향(검토 중)**: 별도 "KPI 역전 안내" UI를 두기보다, **"최적화 원리 알아보기"에 이 설명을 함께 녹이는** 방향을 검토 중임. 하나의 진입점에서 최적화 동작 원리와 역전 현상 원인을 함께 이해하게 하는 편이 산만하지 않음.
- **표현 형식(검토 중)**: 현재 "최적화 원리 알아보기"는 SpinX 패널을 여는 트리거이나, 이를 **다이얼로그 팝업**으로 만드는 방안도 검토 중임.
  - SpinX 진입: 이어서 자유 질문이 가능함(대화형). 단, 원리 설명이 매번 생성 답변에 의존함.
  - 다이얼로그 팝업: 정제된 원리 설명을 일관되게 노출함. 단, 후속 질문 연결은 별도 처리가 필요함.
  - 🚩 최종 형식은 상세 확정 시 결정함.
