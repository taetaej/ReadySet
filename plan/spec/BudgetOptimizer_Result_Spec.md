## 1. 화면 개요

### 1.1 기능 정의
Budget Optimizer 시나리오의 최적화 결과를 확인하는 화면. 모델이 도출한 **매체·상품별 예산 배분안과 예상 성과(보장 KPI 등)**를 스코어카드·차트·테이블로 제공하고, SpinX 기반 해석을 함께 제공한다.

**기획 의도**: 사용자가 "얼마를 어디에 배분했고(투입), 그래서 어떤 성과가 예상되는가(산출)"를 한 화면에서 직관적으로 이해하도록 한다. 시나리오 생성 시 **예산 잠금**을 사용한 경우, 잠금이 반영된 결과와 잠금 없이 모델이 자유롭게 최적화한 결과(순수 최적화)를 **비교**할 수 있게 하여, 사용자 개입이 성과에 미친 영향을 확인하게 하는 것이 핵심 가치다.

### 1.2 문서 활용처
- **개발 참고**: 프론트엔드 구현 시 화면 동작·규칙·표기 기준 문서로 활용된다.
- **제품 Docs**: 본 정의서의 기능 설명·의도가 사용자 대상 기능 문서의 기반이 된다.
- **AI 기반 TC 생성**: 표시 규칙(Section 5)·인터랙션 규칙(Section 6~7)이 테스트 케이스의 원천 데이터가 된다. 각 규칙은 `조건 → 기대 결과`로 검증 가능하게 작성한다.

### 1.3 진입 경로
- 시나리오 목록에서 완료 상태 시나리오 선택 → 결과 화면
- URL: `/budgetoptimizer/scenario/:id/result`
- **진입 조건**: 시나리오 상태가 `완료(Completed)`인 경우에만 결과 활성화

### 1.4 화면 구조 (세로 흐름)
```
결과 상태 띠배너(잠금 시나리오 한정)
  → 스코어카드(4종)
  → Optimization Analytics (차트 4종: Budget Input 2 + Performance Output 2)
  → Budget Allocation Detail (매체>상품 테이블)
```

## 3. 결과 상태 띠배너 (잠금/순수 모드)

### 3.1 노출 조건
- **잠금이 1개 이상인 시나리오**에서만 노출한다. 잠금이 하나도 없으면 이 배너 대신 기본 타이틀(`Optimized Budget Allocation` + 설명)만 표시한다.
- **기획 의도**: 잠금이 없으면 결과는 곧 모델의 순수 최적화이므로 비교 대상이 없다. 비교가 의미 있는 경우(잠금 존재)에만 모드 전환 UI를 제공한다.

### 3.2 구성
- 화면 폭을 가로지르는 풀블리드 띠. 자물쇠/열린 자물쇠 아이콘 + 모드명 + 설명 + 우측 모드 전환 버튼.
- 모드명(영문):
  - 잠금 반영: `Locked Budget Allocation`
  - 순수 최적화: `Fully Optimized Allocation`
- 설명 문구(실제 노출):
  - 잠금 반영: "시나리오 생성 시 설정한 예산 잠금이 반영된 최적화 결과입니다."
  - 순수 최적화: "예산 잠금 없이 모델이 전체 예산을 자유롭게 최적 배분한 결과입니다."

### 3.3 모드 전환 버튼
- 잠금 반영 뷰: "순수 최적화 결과 보기" (열린 자물쇠 아이콘)
- 순수 최적화 뷰: "잠금 반영 최적화 결과 보기" (자물쇠 아이콘)
- **동작**: 클릭 시 스코어카드·테이블·차트 전체가 해당 모드 데이터로 전환된다.
- **순수 최적화 뷰 부수효과**: 예산 잠금(Lock) 표시를 모두 숨긴다(잠금이 없는 결과이므로).

## 4. 스코어카드

### 4.1 구성 (4종)
| 카드 | 값 | 비고 |
|---|---|---|
| Guaranteed {KPI} | 보장 KPI 합계 | KPI는 시나리오 설정값(노출/클릭/조회/도달) |
| Total Budget | 총 예산 | 정수(원), 축약 없이 전체 표기 |
| Avg. CPM | 평균 CPM | 총예산 ÷ (총노출/1000) |
| Locked Budget | 잠금 예산 합계 + 비중(%) | 잠금 있는 시나리오에서 의미 |

- **디자인 기조**: Reach Caster의 Reach Predictor 스코어카드와 동일(값 강조, hover 시 떠오름, 아이콘 배경 없음). 다크모드 대응.
- **KPI 라벨**: 한글+영문 혼용 표기 원칙(예: "노출 (Impression)"). 단, 결과 테이블 컬럼명은 영문만.

## 5. Optimization Analytics (차트 4종)

### 5.1 섹션 구조
- 상위 제목 `Optimization Analytics` + "최적화 원리 알아보기"(SpinX 트리거) + 매체/상품 공통 토글이 동일 선상에 위치.
- 각 차트 제목은 **한글 질문형**(사용자가 차트 목적을 즉시 이해하도록) + 작은 영문 차트명 병기.
- 4개 차트는 2×2 그리드. 상단 2개 = 예산 투입 관점, 하단 2개 = 성과 산출 관점.

| 위치 | 차트 | 한글 질문 제목 | 영문명 |
|---|---|---|---|
| 상단 좌 | Budget Share | 예산은 어디에 배분되었을까? | Budget Share |
| 상단 우 | Response Curve | 예산을 더 넣으면 성과가 오를까? | Response Curve |
| 하단 좌 | Weekly Contribution | 업종 내 매체별 기여는 어떤 흐름일까? | Weekly Contribution |
| 하단 우 | Incremental | 최적화로 성과가 얼마나 늘었을까? | Incremental {KPI} |

### 5.2 매체/상품 공통 토글
- 하나의 토글(`매체` / `상품`)이 **4개 차트 전체**에 동시 적용된다.
- 매체 뷰: 매체 단위 집계. 상품 뷰: `매체 > 상품` 단위.
- **표시 상한**: 각 차트는 기여/비중 상위 5개 항목만 표시(그 외는 차트별 규칙에 따라 기타 묶음 또는 제외).

### 5.3 Budget Share
- 100% Stacked Bar. 매체(또는 상품)별 예산 비중을 시각화.
- 상위 5개 개별 표시, 나머지는 `기타(Others)`로 합산.
- **컬러 규칙**: 비중 1위만 강조색, 나머지는 무채색 opacity 단계(모노톤).

### 5.4 Response Curve
- 예산 투입(X) 대비 보장 KPI(Y) 반응 곡선. 매체(또는 상품) KPI 기여 상위 5개.
- **X축**: 캠페인 총예산 기준 고정. (초기 검토했던 전체 예산 범위 줌 토글은 모델 제공 값과 큰 차이가 없어 **제거**함)
- **곡선 형태**: 포화 함수 `y=a*(1-e^(-b*x))`로 데이터 생성(오버슈팅/꺾임 방지), `type="linear"` 렌더.
- **Current spend 마커**: 각 매체 현재 배분 예산 지점에 점 1개.
- **우측 범례**: 클릭 시 해당 시리즈 표시/숨김 토글(숨김 시 흐림 + 취소선).
- **의도**: "지금보다 예산을 더 넣으면 효율이 더 나오는지(포화 여부)"를 판단하게 한다.

### 5.5 Weekly Contribution
- **성격(중요)**: 이 차트는 이 시나리오의 미래 예측이 아니라, **해당 업종 모델이 학습한 과거 기간의 매체(또는 상품)별 주차 기여 패턴**이다. (브랜드 모델이 아닌 업종 모델 기준)
- **데이터**: 주간(week) 시계열, 누적 영역(monotone 곡선). 기여 상위 5개.
- **조회 구간 토글**: `최근 1년`(최근 52주) / `최근 2년`(전체 104주). X축 우측(범례 하단, X축 선상)에 배치.
- **동기간 음영 밴드**: 내 캠페인 기간의 **전년·전전년 동기간**을 보라색 음영(ReferenceArea)으로 표시하고 `{연도} 동기간` 라벨을 단다. 현재 표시 구간과 겹치는 부분만 클램프하여 노출.
  - **의도**: "내 캠페인 시기(예: 7~9월)에 업종에서는 과거에 어떤 매체 기여가 높았나"를 벤치마크로 참고하게 한다.
- **오해 방지**: "캠페인 종료 후 잔존 효과 추정" 등 미래 예측 프레임 문구는 쓰지 않는다.

### 5.6 Incremental (KPI 증분 워터폴)
- **형태**: 워터폴. `균등 배분`(기준 총 KPI) → 채널(또는 상품)별 증감 누적 → `최적화`(최종 총 KPI).
- **막대 색**: 최적화(최종 결과)=강조색, 균등 배분(기준)=진한 무채색, 증감 막대=흐린 무채색(동일).
- **값 라벨 색**: 증가(+)=초록, 감소(−)=빨강 (결과 테이블 delta 색과 통일). Y축은 0부터 표시.
- **막대 간 연결선**: 이전 막대 누적 상단 → 다음 막대를 잇는 점선.
- **X축 라벨**: 항목명이 길면 한 줄 10자·최대 2줄로 말줄임, 전체 이름은 툴팁에서 확인.
- **의도**: "균등하게 나눴을 때보다 최적화로 성과가 얼마나 순증했는지"를 잃은 것 vs 얻은 것 대비로 보여준다.

### 5.7 차트 공통 규칙
- **툴팁**: 값은 축약 없이 전체 숫자(천 단위 콤마) 표기. 축(Y/X) 틱 라벨만 축약(억/천만/만) 허용.
- **Info 툴팁**: 각 차트 제목 옆 `Info` 아이콘 hover 시 차트 해석 방법을 안내.

## 6. SpinX 인사이트 (차트별 해석)

### 6.1 구성
- 각 차트 하단에 SpinX 해석 블록. 상단 헤어라인으로 차트와 구분(카드/보더 박스 없이 미니멀).
- 헤더에 SpinX 심볼 + `SpinX for Budget Optimizer` 워드마크. 로딩 중 타이핑 효과(심볼 회전 + `analyzing…`).
- 본문: 해당 차트에 대한 해석 텍스트(약 300자 내외).

### 6.2 "이어서 질문하기"
- 해석 블록 하단 텍스트 링크. **클릭 시 질문을 자동 전송하지 않고**, SpinX 패널을 열어 입력창에 해당 차트 멘션(`@{차트명} `)을 프리필한다.
- **의도**: 사용자가 해당 차트를 컨텍스트로 두고 이어서 자유롭게 질문하게 한다.

### 6.3 SpinX @멘션
- SpinX 입력창에서 `@` 입력 시 결과 화면의 차트 목록(Budget Share / Response Curve / Weekly Contribution / Incremental) 자동완성 드롭다운이 뜬다.
- 선택 시 `@{차트명} ` 텍스트가 삽입된다. 키보드(↑↓ 이동, Enter/Tab 선택, Esc 닫기) 및 클릭 지원.
- **의도**: 차트를 대화 컨텍스트로 첨부해, 해당 차트 데이터 기반 답변을 유도한다. (실제 데이터 주입은 백엔드 연동 시)

### 6.4 최적화 원리 트리거 (헤더 레벨)
- `Optimization Analytics` 제목 옆 "최적화 원리 알아보기"(SpinX 심볼) 클릭 시, SpinX 패널이 열리며 최적화 원리 질문을 **자동 전송**한다.
- 잠금 여부와 무관하게 항상 노출(차트 존 제목 라인에 위치).

## 7. Budget Allocation Detail (테이블)

### 7.1 구성
- 매체 > 상품 1-2뎁스 아코디언(Expand/Collapse). Reach Caster Estimated Performance 테이블 톤앤매너.
- **컬럼**: 매체>상품(한글) / Budget / Share / Guaranteed {KPI} / Impression / Click / View / Reach / CPM / CPC / CPV
  - 지표 컬럼명은 **영문만** 사용.
- **단위 표기**: 숫자 + 작고 흐린 단위. 돈은 전부 정수(원), Share만 소수점 2자리 %, 수량은 정수(회).
- **0값**: 하이픈(`-`)으로 표기.
- **잠금 표시**: 예산(Budget) 셀에 자물쇠 아이콘(금액 기준이 정확).
- **Estimated Total 행**: CPM/CPC/CPV는 전체 평균으로 채운다.

### 7.2 순수 최적화 뷰 delta 표시
- 순수 최적화 뷰(잠금 해제)로 볼 때, 잠금 반영 결과 대비 값 차이를 **Budget / Share / Guaranteed {KPI}** 컬럼에 delta로 표시한다(증가 초록, 감소 빨강). Estimated Total 행도 동일.
- 순수 최적화 뷰에서는 잠금 아이콘을 표시하지 않는다.

## 9. 데이터 개념 및 용어 매핑

- 결과 데이터는 **매체·상품 배분(allocations)** 을 기본으로, 잠금 반영/순수 최적화 두 세트를 갖는다.
  - UI "잠금 반영 결과" = 기본 `allocations` (일부 `isFixed=true`)
  - UI "순수 최적화 결과" = `pureAllocations` (모두 잠금 해제)
- UI "잠금" = 필드 `isFixed`.
- 차트별 데이터: Budget Share/Response Curve/Incremental은 allocations 기반, Weekly Contribution은 **업종 모델 학습 주간 시계열**(별도 소스).
- 정확한 타입·필드는 구현 파일(`resultSampleData.ts`) 참조.

## 10. 예정 기능 (이 화면 한정)

아래 3개 항목은 모두 **진행 예정(채택)**이다. 세부 구현 방식은 하위 항목에 정리한다.

| 항목 | 내용 | 사용자 가치 | 상태 |
|---|---|---|---|
| Export (Excel/PDF) | 결과 데이터 다운로드 | 결과 공유·보고 활용 | **완료** (헤더 Export 버튼 구현됨) |
| Reach Caster 간편 생성(Easy Create) | 결과 화면 CTA → 중간 설정(타겟 GRP·매핑 불일치) → Reach Caster Step2 예산 프리필 진입 | 최적화 예산안을 도달 예측까지 끊김 없이 연결 | 채택 (P1, 정책서 §4) — 구현 예정 |
| 최적화 원리 안내 (KPI 역전 설명 포함) | "최적화 원리 알아보기"에 최적화 동작 원리 + 순수 최적화가 잠금 결과보다 낮게 나올 수 있는 이유(효율 포화·매체 우선 배분)를 함께 설명 | 최적화 신뢰도 오해 방지 | 채택 (BO-001 이슈 연계) — 구현 예정 |

### 10.1 최적화 원리 안내 (구현 방향 검토 중)

- **배경**: 순수 최적화 결과가 사용자의 잠금 반영 결과보다 보장 KPI가 낮게 나오는 경우가 있다(BO-001). 이는 순수 최적화가 효율 포화 지점을 넘지 않게 배분하고, 매체 우선 배분(Meridian 모델 권장)을 하기 때문으로, 오해를 방지하려면 원리 설명이 필요하다.
- **통합 방향(검토 중)**: 별도 "KPI 역전 안내" UI를 두기보다, **"최적화 원리 알아보기"에 이 설명을 함께 녹이는** 방향을 검토 중이다. 하나의 진입점에서 최적화 동작 원리와 역전 현상 원인을 함께 이해하게 하는 편이 산만하지 않다.
- **표현 형식(검토 중)**: 현재 "최적화 원리 알아보기"는 SpinX 패널을 여는 트리거이나, 이를 **다이얼로그 팝업**으로 만드는 방안도 검토 중이다.
  - SpinX 진입: 이어서 자유 질문 가능(대화형). 단, 원리 설명이 매번 생성 답변에 의존.
  - 다이얼로그 팝업: 정제된 원리 설명을 일관되게 노출. 단, 후속 질문 연결은 별도 처리 필요.
  - 🚩 최종 형식은 상세 확정 시 결정.
