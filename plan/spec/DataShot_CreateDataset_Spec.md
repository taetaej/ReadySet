## 1. 화면 개요

### 1.1 기본 정보

| 항목 | 내용 |
|---|---|
| 화면명 | 데이터셋 생성 (Create Dataset) |
| 경로 | `/datashot/new` |
| 진입 경로 | DataShot 목록 → "New Dataset" 버튼 |
| 접근 권한 | Admin, Marketer |
| 주요 기능 | 3단계 스텝 폼으로 조회 조건을 설정하고 데이터 추출을 요청 |

### 1.2 기능 정의 및 기획 의도

데이터셋 생성은 **"어떤 데이터를 뽑을지"를 조건으로 조립하는 마법사**다. 기간·업종(1단계) → 매체·광고분류·타겟팅·지표(2단계) → 미리보기 확인(3단계) 순으로, 넓은 조건에서 좁은 조건으로 좁혀 나가며 추출 요청을 완성한다.

- **왜 3단계로 나누나**: 조건이 많아 한 화면에 다 담으면 압도된다. "무엇을(1) → 어디서·어떻게(2) → 확인(3)"의 인지 순서로 쪼개 부담을 낮춘다.
- **왜 스텝마다 하위를 초기화하나**: 앞 단계 선택(기간·업종·매체)이 뒤 단계의 선택지를 결정한다. 앞을 바꾸면 뒤 선택이 유효하지 않을 수 있어, 매체를 바꾸면 광고상품·지표·타겟팅을 리셋해 잘못된 조합을 원천 차단한다.
- **왜 "0건 예방"을 하나**: 실제 집행 데이터가 없는 조건을 고르면 추출 결과가 빈다. 그래서 앞 단계 조건에 실데이터가 있는 선택지만 노출해 헛수고를 막는다.

### 1.3 문서 활용처

- **Docs**: 각 단계의 목적을 사용자 관점으로 서술 → 제품 문서로 재가공
- **TC**: §13 유효성 규칙 + §14 검증 포인트가 그대로 테스트 케이스 소스

### 4.2 설명 (선택)

| 요소 | 스펙 |
|---|---|

| 글자수 표시 | `{현재}/200` (우측) |

### 4.3 지표 구성 (purpose)

**의도**: 데이터셋에 담을 지표 범위를 고른다. 종합 지표는 비용·효율 전체를, 성과 지표는 순수 효율·성과 지표만 담는다. Shared Slot 대외 공유 맥락에서 종합 지표는 제한 대상이므로 생성 시점에 유형을 명시하게 한다.

| 요소 | 스펙 |
|---|---|
| 라벨 | "지표 구성" + 필수(*) |
| 안내 | "종합 지표는 Private 또는 Internal Slot에서만 선택할 수 있습니다." |
| 선택 | 두 카드 중 단일 선택 (`Layers` 종합 지표 / `TrendingUp` 성과 지표) |
| 종합 지표(internal) | "전체 성과 흐름을 통합적으로 확인할 수 있도록 모든 효율 및 비용 지표를 제공" |
| 성과 지표(external) | "CTR, CPC 등 순수 효율과 성과 트렌드 분석에 최적화된 데이터셋" |

**유효성**:
| 조건 | 에러 메시지 |
|---|---|
| purpose 미선택 | "지표 구성을 선택해주세요." |

> **구현-정합 주의**: (1) 두 옵션 모두 항상 활성이며, 슬롯 타입(Shared)에 따른 종합 지표 Disabled 처리는 안내 문구로만 존재하고 실제 비활성화는 없다. (2) 지표 구성은 UI상 필수(에러 문구 노출)이나, "다음" 버튼 활성 조건(`isStep1Valid`)에는 purpose가 포함돼 있지 않다 — 즉 purpose 미선택이어도 다음 단계로 넘어갈 수 있다. (§13 V-그룹에 그대로 반영)

### 4.4 조회기간

| 요소 | 스펙 |
|---|---|
| 라벨 | "조회기간" + 필수(*) |
| 안내 | "최근 2년치 데이터를 조회할 수 있습니다." |
| 기간 유형 | radio: 월별 / 분기별 (기본 월별) |
| 선택 UI | MonthRangePicker |
| 유형 변경 시 | 기간 값(시작/종료 연·월) 전부 초기화 |

**유효성** (validateDateRange):
| 조건 | 에러 메시지 |
|---|---|
| 시작·종료 중 하나라도 미선택 | "조회기간을 선택해주세요." |
| endTotal < startTotal | "종료일은 시작일보다 이후여야 합니다." |
| endTotal − startTotal > 24 (개월) | "조회기간은 최대 2년까지 설정 가능합니다." |

- 월별은 개월 단위, 분기별은 3개월 배수로 환산해 비교(24개월 = 2년 상한). 시작=종료 동일 기간 허용, 역순 불가.

#### 4.4.1 월별 / 분기별 Picker (공통 동작)

### 4.6 Step 1 유효성 활성화 조건

- 다음 중 하나라도 입력/선택되면 유효성 검사 활성화: datasetName / description / period.startYear·startMonth / industries.

### 4.7 Step 1 완료 조건 (다음 버튼 활성)

```
datasetName.trim() !== '' &&
period.startYear && period.startMonth && period.endYear && period.endMonth &&
dateValidation.valid &&
industries.length > 0 &&
industryLevel !== null
```

> purpose(지표 구성)는 이 조건에 포함되지 않는다(§4.3 주의 참조).

## 15. 데이터 개념 및 용어 매핑

| UI 용어 | 데이터 필드 | 비고 |
|---|---|---|
| 지표 구성 | `purpose` (`'internal'`=종합 지표, `'external'`=성과 지표) | Shared Slot 제한 판단 기준 |
| 조회기간 | `period.{start,end}{Year,Month}` + `periodType` | quarter는 3개월 배수 환산 |
| 업종 | `industries[]` + `industryLevel` | "대 > 중 > 소" 표기 |
| 매체 | `media` | 값에 따라 광고상품·타겟팅·지표 구조 결정 |
| 광고상품 | `products[0]`에 `{fieldKey: string[]}` JSON 직렬화 | 첫 필드 필수 |
| 타겟팅 | `targetingCategory` + `targetingOptions[]` | 카테고리 있으면 옵션 필수 |
| 지표 | `metrics[]` (지표 id 배열) | 타겟팅 조합으로 일부 제외 |

> 타입 정의는 구현이 진실 공급원: `createDatasetTypes.ts`(`FormData`), `types.ts`, `sampleData.ts`.

## 16. 개선 제안 (이 화면 한정)

| 제안 | 내용 | 사용자 가치 | 상태 |
|---|---|---|---|
| 지표 구성 완료 조건 정합 | purpose를 isStep1Valid에 포함할지 결정(현재 필수 문구와 진행 조건 불일치) | 필수 표기와 실제 동작의 일관성 | 검토 필요 |
| 슬롯 타입별 종합 지표 Disabled | Shared Slot에서 종합 지표 옵션 실제 비활성화 | 정책과 UI 일치, 잘못된 선택 예방 | 검토 필요 |
| 예상 데이터 크기 동적화 | 고정 표기 대신 조건 기반 실제 추정 | 추출 규모 예측 정확도 | 미채택 |
