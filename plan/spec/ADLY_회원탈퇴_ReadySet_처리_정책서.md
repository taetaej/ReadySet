## 1. 배경

ReadySet은 ADLY SSO를 통해 사용자 인증을 수행하며, 자체 회원가입 체계를 갖고 있지 않음. ADLY에서 회원이 탈퇴하면 ReadySet 로그인이 불가해지므로, ReadySet 내 잔류 데이터 및 개인정보에 대한 후처리 정책이 필요함.

### 1.1 전제 조건

- ReadySet은 ADLY의 하위 서비스(Sub-platform)로서 SSO 인증에 의존함
- ADLY 탈퇴 = ReadySet 접근 영구 불가
- ReadySet은 유저의 이름, 이메일 등 PII를 자체 DB에 캐싱/저장하고 있음
- 개인정보 보호법에 따라, 탈퇴 시 PII의 파기 또는 비식별화가 의무임

## 2. 핵심 원칙

| # | 원칙 | 설명 |
|---|------|------|
| 1 | **공유 자산은 삭제하지 않음** | Internal/Shared 슬롯 및 하위 결과물은 다른 유저가 함께 사용 중이므로, 탈퇴 유저가 생성했더라도 삭제하지 않음 |
| 2 | **개인정보는 익명화함** | 생성자명, 이메일 등 탈퇴 유저를 식별할 수 있는 정보는 비식별 처리함 |
| 3 | **비공유 자산은 즉시 삭제함** | Private 슬롯은 본인 외 접근 불가한 자산이므로, 탈퇴 시점에 즉시 삭제함 |
| 4 | **즉시 접근 차단** | 탈퇴 이벤트 수신 즉시 세션/토큰을 무효화하여 서비스 접근을 차단함 |

## 3. 처리 구분

### 3.1 즉시 처리 (탈퇴 이벤트 수신 시점)

| 항목 | 조치 |
|------|------|
| 활성 세션 | 즉시 만료 (모든 디바이스) |
| Access Token / Refresh Token | 즉시 폐기 |
| SpinX 활성 세션 | 즉시 종료 |

### 3.2 공유 자산 — 유지 + 익명화

아래 자산은 삭제하지 않고 유지하되, 탈퇴 유저의 PII를 익명화 처리함.

| 자산 | 유지 | 익명화 대상 필드 |
|------|------|-----------------|
| Internal/Shared Slot | ✅ 유지 | owner(생성자명), owner_email |
| 시나리오 (Reach Caster) | ✅ 유지 | 작성자명, 작성자 이메일 |
| 데이터셋 (DataShot) | ✅ 유지 | 생성자명, 생성자 이메일 |
| Final Set 결과물 | ✅ 유지 | 선택자 정보 (해당 시) |
| Resources 파일 | ✅ 유지 | 업로더명 |
| Activity Log | ✅ 유지 | 작업자명, 이메일 |
| SpinX 대화 이력 | ✅ 유지 | 질문자 정보 |

### 3.3 비공유 자산 — 즉시 삭제

| 자산 | 처리 |
|------|------|
| Private Slot | 즉시 삭제 |
| Private Slot 내 시나리오 | 함께 삭제 |
| Private Slot 내 데이터셋 | 함께 삭제 |
| Private Slot 내 Resources | 함께 삭제 |
| Private Slot 내 SpinX 세션 | 함께 삭제 |

## 5. 소유권(Owner) 처리

### 5.1 Internal/Shared Slot

| 상황 | 처리 |
|------|------|
| 같은 광고주 내 다른 Marketer 존재 | owner 필드를 `NULL`로 변경함. 해당 광고주 권한 가진 모든 Marketer가 수정/삭제 가능 |
| 해당 광고주의 유일한 Marketer가 탈퇴 | ⚠️ 관리 불능 위험 — 아래 5.2 참조 |

### 5.2 유일한 Marketer 탈퇴 시

**선택지 (결정 필요)**

| 옵션 | 설명 | 장점 | 단점 |
|------|------|------|------|
| A. 탈퇴 차단 | 해당 유저가 유일한 Marketer인 광고주가 있으면 탈퇴 불가 안내 | 데이터 안전 | ADLY 측 탈퇴 플로우 개입 필요 |
| B. 시스템 Owner 이관 | 시스템 관리자 계정으로 자동 이관 | 무중단 | 관리 책임 소재 모호 |
| C. ADLY Admin 알림 | ADLY 관리자에게 알림 → 수동 Owner 재지정 | 유연 | 대응 지연 가능 |

> **추천: B + C 병행** — 시스템 Owner로 임시 이관 후, ADLY Admin에게 재지정 요청 알림 발송

## 6. ADLY 탈퇴 사용자 처리를 위한 ADLY SSO 연동 확인사항

ReadySet이 탈퇴 처리를 수행하려면, ADLY 측에서 아래 항목을 지원해야 함. ADLY 팀과 사전 협의 필요.

### 6.1 탈퇴 이벤트 전달 방식

| 확인 항목 | 설명 | 비고 |
|-----------|------|------|
| 이벤트 전달 방식 | Webhook(Push) vs Polling(Pull) 중 어떤 방식을 제공하는지? | Webhook 선호 |
| Webhook Endpoint 등록 | ADLY에서 ReadySet Webhook URL을 등록할 수 있는 관리 기능이 있는지? | — |
| Payload 스펙 | 탈퇴 이벤트에 어떤 정보가 포함되는지? (user_id, email, 탈퇴 시각, 사유 등) | 최소 user_id 필수 |
| 이벤트 발행 시점 | 탈퇴 확정 즉시인지? 유예 기간이 있는지? | ReadySet은 수신 즉시 처리 예정 |
| 재시도 정책 | Webhook 전송 실패 시 재시도 여부 및 횟수 | 데이터 정합성 확보 |

### 6.2 탈퇴 전 영향도 조회 (선택 — ADLY UX 개선용)

| 확인 항목 | 설명 |
|-----------|------|
| ReadySet 영향도 API 호출 가능 여부 | ADLY 탈퇴 플로우에서 ReadySet API를 호출하여 "이 유저가 ReadySet에 보유한 자산 수"를 조회할 수 있는지? |
| API 예시 | `GET /api/readyset/user/{user_id}/withdrawal-impact` → 보유 Slot 수, 공유 자산 수, 유일한 Marketer 여부 반환 |
| 화면 반영 | ADLY 탈퇴 화면에서 "ReadySet에 N개의 공유 자산이 있습니다" 등 안내 문구 노출 가능 여부 |

### 6.3 탈퇴 화면 고지 문구 삽입 가능 여부

| 확인 항목 | 설명 |
|-----------|------|
| 하위 서비스 고지 영역 | ADLY 탈퇴 확인 화면에 하위 서비스(ReadySet 등)별 데이터 처리 안내를 삽입할 수 있는 영역이 있는지? |
| 요청 문구 예시 | "ADLY 탈퇴 시 ReadySet 내 개인정보가 삭제되며, 본인이 생성한 비공개(Private) 자산은 즉시 삭제됨. 공유 중인 자산은 유지되나, 생성자 정보가 익명 처리됨." |

### 6.4 탈퇴 취소(복구) 시나리오

| 확인 항목 | 설명 |
|-----------|------|
| 탈퇴 취소 가능 여부 | ADLY에서 탈퇴 후 일정 기간 내 복구를 지원하는지? |
| 복구 시 ReadySet 알림 | 복구 이벤트도 Webhook으로 전달 가능한지? |
| ReadySet 복구 범위 | Private 자산은 즉시 삭제이므로 복구 불가함을 ADLY 측에 사전 안내 필요 |

### 6.5 기타 확인사항

| 확인 항목 | 설명 |
|-----------|------|
| SSO 토큰 자동 만료 | ADLY 탈퇴 시 발급된 토큰이 ADLY 측에서 자동으로 revoke 되는지? 아니면 ReadySet이 자체 폐기해야 하는지? |
| 탈퇴 사유 활용 | reason_code를 ReadySet 로그에 기록해도 되는지? (내부 통계용) |
| 테스트 환경 | 탈퇴 Webhook을 테스트할 수 있는 Staging/Sandbox 환경이 제공되는지? |

## 7. 처리 플로우

```
ADLY 탈퇴 요청
  │
  ▼
[ADLY] 탈퇴 Webhook → ReadySet 수신
  │
  ▼
[즉시] 세션/토큰 무효화
  │
  ▼
[즉시] PII 익명화 (user_name, user_email, profile_image)
  │
  ├─ Internal/Shared 자산: owner → NULL, 표시명 → "탈퇴한 사용자"
  │
  ├─ Activity Log / SpinX 이력: 작업자 → "탈퇴한 사용자"
  │
  └─ Private Slot + 하위 전체: 즉시 영구 삭제
```

## 8. 엣지 케이스

| 케이스 | 처리 |
|--------|------|
| 탈퇴 유저가 최근 수정자인 경우 | 최근 수정자 표시도 "탈퇴한 사용자"로 변환함 |
| 탈퇴 유저가 Shared Slot의 공유 대상(Client/Agency)인 경우 | 접근 차단만 하고 Slot 자체는 유지함 (다른 공유 대상은 영향 없음) |
| 동일 이메일로 재가입 | 신규 유저로 간주함. 이전 자산과 연결하지 않음 |
| 탈퇴 유저가 시나리오 이동 중이었던 경우 | 이동 완료 처리 후 익명화함 (진행 중 작업은 완료 우선) |

## 10. 구현 영향 범위 (참고)

| 영역 | 영향 |
|------|------|
| Backend — Auth | 세션/토큰 폐기 로직, Webhook 수신 엔드포인트 |
| Backend — User | PII 익명화 배치/즉시 처리 |
| Backend — Slot | owner NULL 처리, Private Slot 즉시 삭제 로직 |
| Frontend — UI | "탈퇴한 사용자" 표시 분기, Avatar fallback |
| Frontend — Info 툴팁 | 이메일 필드 조건부 숨김 |
| ADLY 연동 | Webhook 수신, (선택) 영향도 조회 API |
