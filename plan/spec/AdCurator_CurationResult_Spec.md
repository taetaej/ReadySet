## 1. 화면 개요

### 1.1 기능 정의
생성이 완료된 큐레이션의 **결과를 확인하는 화면**임. 캠페인 조건에 맞춰 선별된 매체·상품을 적합도 그룹(Best Fit / Good Fit)으로 보여주고, 각 매체·상품의 결론 구절·근거와 프로모션 정보를 제공함. 사용자는 마음에 드는 매체·상품을 **컬렉션**에 담아 BudgetOpt 2.0 시나리오 생성으로 이어갈 수 있음.

**기획 의도**
- 이 화면은 숫자를 나열하는 화면이 아니라 "이번 캠페인에 무엇이 맞는가"라는 **결론을 먼저 말하는 화면**임. 위에서 아래로 결론(Best Match 등 카드) → 근거(평가 축별 점수 차트·목록의 결론 구절과 근거) → 상세(목록) → 다음 행동(컬렉션 → BudgetOpt 2.0) 순서로 읽히게 함.
- 결과는 **생성 시점 기준으로 고정**되고 다시 계산하지 않음(정책서 4.2). 조건을 바꾸려면 복제 후 다시 생성해야 하므로, 화면은 "무엇이 어떤 조건으로 나온 결과인지"를 항상 확인할 수 있어야 함.
- 큐레이션 결과는 수정할 수 없으나, **컬렉션만 예외**(정책서 6.2.1). 결과를 읽는 데서 멈추지 않고 "담기"로 다음 단계(예산 배분)의 입력을 만들게 함. 이때 업종·기간·담은 매체·상품이 BudgetOpt 2.0으로 그대로 이어져 세션이 끊기지 않게 함.
- 어려운 선별 과정(후보 선정 → 적합도 평가 → 그룹핑)은 평가 축 점수 차트와 SpinX 해석 뒤로 접어 두고, 사용자는 결론을 먼저 보고 필요할 때만 근거를 펼침.

### 1.2 문서 활용처
- **개발 참고**: 프론트엔드 구현 시 화면 동작·규칙·표기 기준 문서로 활용됨.
- **제품 Docs**: 본 정의서의 기능 설명·의도가 사용자 대상 기능 문서의 기반이 됨.
- **AI 기반 TC 생성**: 규칙 요약(Section 10)과 검증 포인트(Section 12)가 테스트 케이스의 원천 데이터가 됨. 각 규칙은 조건 → 기대 결과로 검증 가능하게 작성함.

### 1.3 진입 경로
- 큐레이션 목록에서 **Completed** 상태 행 클릭(AdCurator_CurationList_Spec.md 6.2)
- URL: /adcurator/curation/{id}/result
- **진입 조건**: 처리 상태가 Completed인 큐레이션만 결과를 열 수 있음. Pending·Processing·Error는 목록에서 진입이 막힘(V1).
- 이 화면에서 이어지는 곳: BudgetOpt 2.0 시나리오 생성(Section 8), 큐레이션 복제(큐레이션 생성 화면 Step 1, 프리필), 큐레이션 목록(삭제·이동 후)

### 1.4 화면 구조 (세로 흐름)
헤더(큐레이션명 · 메타 요약 · 액션 아이콘, 한 줄 — 다른 솔루션 결과 화면과 동일 구성)
→ (조건부) 조건 완화 안내 줄
→ 상단 2분할: 좌 **Curation Highlights**(개수 요약 + 왕중왕 카드 2~3개, 세로) / 우 **Campaign Fit**(평가 축 점수 막대 차트 + SpinX 해석)
→ 목록 영역: Best Fit 구역(검색·필터 + 매체·상품 목록 + 더 보기) + 접이식 `이런 선택지도 있어요` 구역(Good Fit) / 우측 **컬렉션 패널**(sticky)
→ 우하단 ActionDock(SpinX 입력 바 + 컨텍스트 액션)

- 공통 레이아웃(AppLayout, Breadcrumb)과 권한 매트릭스는 공통 정의서를 따름. 이 문서는 결과 화면 고유 규칙만 다룸.

### 1.5 역할별 노출

공통 권한 매트릭스를 따라 큐레이션 목록과 같은 기준을 적용함(AdCurator_CurationList_Spec.md 1.5).

| 요소 | Admin / Marketer | Agency / Client |
|---|---|---|
| 결과 조회(헤더·카드·차트·목록·컬렉션 내용) | 가능 | 가능 |
| Good Fit 구역 펼치기 · 검색 · 필터 · 더 보기 | 가능 | 가능 |
| 공유 메뉴(Copy Link, Export to Excel) · 정보 툴팁 | 노출 | 노출 |
| 더보기 메뉴(복제 · 이동 · 삭제) | 노출 | 미노출 |
| 목록의 `+ 담기` 버튼 | 노출 | 미노출 (담긴 항목은 `✓ 담았어요` 표시만) |
| 컬렉션 패널의 빼기(×) · `저장` · BudgetOpt 연계 CTA | 노출 | 미노출 |
| ActionDock ＋ 런처(컨텍스트 액션) | 노출 | 미노출 (액션이 없으므로 ＋ 자체를 숨김) |
| ActionDock SpinX 입력 바 · SpinX 패널 | 가능 | 가능 (기존 SpinX 이용 권한·사용량 정책 준수) |

- Agency/Client는 Shared Slot에서만 이 화면에 접근함(공통 정책). Shared Slot에서는 프로모션 "포함"으로 큐레이션을 만들 수 없으므로(AdCurator_CurationCreate_Spec.md 3.6), Shared Slot의 결과에는 프로모션 요소가 없음.
- **기획 의도**: 외부 사용자는 결과 열람과 공유만 하게 하고, 데이터를 바꾸거나 다음 작업을 만드는 모든 진입점은 비활성이 아니라 **미노출**로 처리해 "왜 못 누르지?"라는 혼란을 없앰(목록 화면과 동일 원칙).

## 2. 레이아웃

### 2.1 구조

```
┌ Breadcrumb ─────────────────────────────────────────────────────────┐
│ {큐레이션명}  업종 • 기간 • 목적 • 프로모션 • 상세 조건 n개 🔍 │ ⤴ ⓘ ⋮ │
├─────────────────────────────────────────────────────────────────────┤
│ (조건부) ⓘ 상세 조건 N개를 완화해 매체·상품을 확보했습니다. 어떤 조건인지 보기 │
├───────────────────────────┬─────────────────────────────────────────┤
│ Curation Highlights  이번 캠페인엔 이 매체·상품이 맞아요 │ 내 캠페인에 어떤 매체·상품이 잘 맞을까?  Campaign Fit │
│ ┌ Best Fit 24개 · 전체 214개 중 ┐ │ █▇▆▅▅▄▃▃▂▂▂▁ (막대 = 매체·상품, 칸 = 평가 축) │
│ ├ Best Match (강조) ────┤ │ 막대 = 점수 합 · 그린 = 이번 캠페인 1위 · 점수 합 순 → │
│ ├ Industry Favorite ────┤ │ SpinX 해석 + 이어서 질문하기 │
│ └ Top Performer ────────┘ │ │
├───────────────────────────┴───────────────────┬─────────────────────┤
│ Best Fit n                       [검색] [필터]  │ 컬렉션  n / 30      │
│ 안내 줄(SpinX 정리 · 생성 시점 기준)            │ 담은 항목 목록       │
│ 매체·상품 행 …                                  │ BudgetOpt 2.0 CTA   │
│ 더 보기                                         │ (sticky)            │
│ ── 이런 선택지도 있어요  Good Fit n  펼치기 ↓ ──│                     │
└───────────────────────────────────────────────┴─────────────────────┘
                                          ActionDock (우하단 고정)
```

- 위 도식은 카드 3개가 모두 표시되는 예시임. 실제로는 Best Match 1개 + 조건부 대안 카드 0~2개이며(4.1), 카드 묶음 높이가 우측 차트 높이에 맞춰짐. 묶음 맨 위의 개수 요약(4.1)은 카드가 아님.

### 2.2 영역별 의도
- **상단 2분할(좌 카드 / 우 차트)**: Reach Caster 결과 화면의 "좌 스코어카드 + 우 차트" 구성과 같은 패턴임. 좌측에서 결론을, 우측에서 그 근거를 한 시선 안에서 확인하게 함. 폭 비율은 좌 5 : 우 5. 두 열의 하단이 맞도록 차트 높이를 카드 묶음에 맞춤.
- **목록 + 컬렉션 패널**: 목록에서 고른 항목이 같은 화면의 컬렉션 패널에 바로 쌓이게 해 "고르고 → 확인하고 → 이어간다"가 한 화면에서 끝나게 함. 컬렉션 패널은 스크롤해도 상단에 고정(sticky).
- **ActionDock**: BudgetOpt 2.0·Reach Caster 결과 화면과 같은 공통 컴포넌트(`ActionDock`). 우하단 고정이므로 화면 우측 끝에 다른 액션을 붙이지 않음.
- **SpinX 패널**: 열리면 본문이 우측 패널 폭만큼 밀리고 ActionDock은 숨김(BudgetOpt 2.0 결과 화면과 동일).

## 3. 헤더

한 줄 레이아웃으로 좌→우: 큐레이션명 / 메타 요약(인라인) / 세로 구분선 / 액션 버튼.

- **기획 의도**: 결과 화면은 솔루션이 달라도 "이름 → 조건 → 액션"을 같은 자리에서 읽을 수 있어야 사용자가 헤더를 솔루션마다 다시 학습하지 않음.

### 3.1 큐레이션명

| 요소 | 내용 / 스타일 (의도) |
|---|---|
| 텍스트 | 큐레이션명 (제목급·medium, Paperlogy) |
| overflow | 한 줄 말줄임(ellipsis) — 긴 이름 처리 |
| 솔루션 뱃지 | 두지 않음. 솔루션은 Breadcrumb(SlotBoard / {Slot명} / Ad Curator / {큐레이션명})으로 구분함 |

### 3.2 메타 요약 (인라인)

각 항목은 `•` 구분자로 연결하고, muted 톤 소형 텍스트로 "라벨(medium) + 값" 형식으로 표시함. 칩·뱃지 형태로 만들지 않음.

| 항목 | 표시 형식 | 클릭 동작 |
|---|---|---|
| 업종 | 브랜드를 선택해 만든 큐레이션: "업종 {브랜드} / {업종}", 업종을 직접 선택한 큐레이션: "업종 {업종}" | 없음 |
| 기간 | "기간 {yyyy-mm-dd} → {yyyy-mm-dd}" (캠페인 기간) | 없음 |
| 목적 | 1개: "목적 {목적명}". 2개 이상: "목적 {목적1} / {목적2}". 목적은 "인지 → 조회 → 트래픽 → 전환" 고정 순서에서 가장 앞선 목적. | 없음 |
| 상세 조건 | "상세 조건 {N}개" + `SearchCheck` 아이콘. **N > 0일 때만 표시**(DataShot 상세 조건과 동일) | "큐레이션에 반영된 조건" 모달 오픈(3.3) |

- **상세 조건 N**: 큐레이션 생성 Step 2에서 입력한 선별 기준 항목 수(속성 기준 + 특성 기준). 같은 항목의 포함·제외는 1개로 셈(AdCurator_CurationCreate_Spec.md 4.8과 동일). 조건 완화로 제외된 항목도 입력한 항목이므로 N에 포함됨.
- **라벨 표기**: 입력 화면의 "캠페인 기간"·"캠페인 목적"은 헤더에서 다른 솔루션과 같은 짧은 라벨 "기간"·"목적"으로 표기함. 정식 명칭은 반영된 조건 모달에서 확인함.
- **기획 의도**: 프로모션 포함 여부를 항상 명시해, 미포함 큐레이션에서 프로모션 표시가 없는 이유를 사용자가 바로 이해하게 함. 목적은 다중 선택이라 목록 화면과 같은 "대표 외 N" 요약으로 헤더 한 줄의 폭을 유지함.

### 3.3 조건 완화 안내(조건부)와 "반영된 조건" 모달

**조건 완화 안내 줄**

| 항목 | 규칙 |
|---|---|
| 노출 조건 | 후보 선정 결과가 0개여서 상세 조건 일부가 제외된 큐레이션(정책서 3.3.1)에만 표시. 완화가 없으면 줄 자체를 표시하지 않음(빈 자리 없음) |
| 위치 | 헤더 바로 아래 본문 최상단 한 줄. DataShot의 "Data Limit Warning"처럼 조건부로 헤더 아래에 놓이는 안내와 같은 위치 |
| 구성 | `Info` 아이콘(muted) + `상세 조건 {N}개를 완화해 매체·상품을 확보했습니다.` + 텍스트 링크 `어떤 조건인지 보기`. {N}은 완화로 제외된 항목 수 |
| 톤 | 오류가 아니라 정책에 따른 정상 처리 결과이므로 경고색(destructive)을 쓰지 않음 |
| 링크 동작 | 헤더의 `상세 조건 {N}개` 돋보기와 **같은 모달**을 엶 |

**"큐레이션에 반영된 조건" 모달** (`md` 크기, ui-dialog-policy. 제목·버튼 영역은 고정하고 본문만 스크롤)

큐레이션 생성 때 입력한 내용을 **읽기 전용**으로 다시 보여줌. 구역 구성과 행 표기는 큐레이션 생성 화면(AdCurator_CurationCreate_Spec.md 3장 Step 1, 4.5 선별 기준 목록, 4.6 조건 분류)과 같게 맞춤.

| 구역 | 내용 |
|---|---|
| 설명 | "큐레이션을 만들 때 입력한 조건입니다. 생성 시점 기준으로 고정됩니다." |
| 기본 정보 (생성 Step 1) | 업종(헤더와 같은 표기: `{브랜드} / {업종}` 또는 `{업종}`) · 캠페인 기간(`yyyy-mm-dd → yyyy-mm-dd`) · 캠페인 목적(선택한 목적 전체를 "인지 → 조회 → 트래픽 → 전환" 고정 순서, 가운뎃점 구분) · 프로모션(`포함` / `미포함`). 큐레이션명·설명은 헤더와 정보 툴팁에 있으므로 제외 |
| 속성 기준 `{N}개` (생성 Step 2) | 속성 라벨 조건(예: 구매 방식, 지면, 소재 포맷, 예산). 행 표기는 아래 "행 표기 규칙". 항목이 없으면 이 그룹은 표시하지 않음 |
| 특성 기준 `{N}개` (생성 Step 2) | 근거 라벨 조건(예: 단가 추세, 집행 경험, 매체 규모). 항목이 없으면 이 그룹은 표시하지 않음 |
| 버튼 | [닫기] 1개. 오버레이 클릭·Esc도 닫힘 |

- 속성 기준·특성 기준이 모두 없으면 "상세 설정" 구역 자체를 표시하지 않음. 다만 이 모달은 `상세 조건 {N}개`(N > 0) 항목에서만 열리므로 실제로는 둘 중 하나 이상 존재함.

**행 표기 규칙** (생성 화면 Step 2 "선별 기준" 목록과 동일, 삭제(×)와 편집은 없음)

| 항목 | 규칙 |
|---|---|
| 왼쪽 | 조건 값. 복수 값은 가운뎃점으로 결합(예: `YouTube · 네이버 메인`). 말로 받은 제외 조건은 포함 조건과 **별도 행**으로 `{값} 제외`(예: `TikTok 제외`). 예산은 `{금액}만 원`(천 단위 콤마, 예: `3,000만 원`) |
| 오른쪽 | 조건 이름(muted, 예: `매체·지면`) |
| 행 순서 | 사용자가 고른 순서와 무관하게 조건 정의(카탈로그) 순서 |
| 그룹 숫자 | `{N}`은 **항목 수**이며 같은 항목의 포함 행·제외 행은 1개로 셈. 속성 기준 수 + 특성 기준 수 = 헤더 `상세 조건 {N}개`의 N |
| 완화로 제외된 항목 | 행은 그대로 보이되 muted 톤으로 낮추고 조건 이름 옆에 muted `완화로 제외`를 붙임. 완화가 있을 때만 모달 하단에 안내 `매체·상품이 0개가 되지 않도록, 영향이 가장 적은 상세 조건을 제외했습니다.`를 표시함. 완화가 없으면 표시도 안내도 없음 |

- **기획 의도**: 사용자가 생성할 때 넣은 조건(Step 1·Step 2)을 그대로 다시 보게 해 "내가 넣은 조건이 이 결과로 이어졌다"를 확인하게 함. 생성 화면과 같은 구역·표기를 써서 새로 배울 것이 없게 하고, 값은 "입력한 사실"로서 모두 보여주되 완화로 제외된 항목은 결과에 반영되지 않았음을 한눈에 구분함(정책서 3.3.1 "제외된 조건을 기준 요약에 표시"). 구역 이름도 생성 화면과 같은 "속성 기준·특성 기준"을 써 사용자가 입력 때의 용어로 읽게 함.
- **적합도 평가 기준**: 평가 축은 Campaign Fit 막대 툴팁(5.3)과 상품 팝업 레이더(6.10.1)에서 보여 주므로 이 모달에 두지 않음.
- **기획 의도(헤더 항목·안내 줄·모달 역할 분담)**: 조건 전체를 항상 펼치면 화면이 무거워지므로 평소에는 헤더 항목과 조건부 안내 줄만 두고 상세는 모달로 접어 둠(DataShot 결과 헤더의 돋보기 모달 패턴과 같은 접근). 완화는 결과가 입력 조건과 다르게 나왔다는 뜻이라 사용자가 놓치지 않도록 조건부 안내 줄을 따로 둠.

## 4. Curation Highlights (왕중왕 카드, 2~3개)

### 4.1 구성
- 섹션 제목 "Curation Highlights"(영문 h3 제목 규칙, BudgetOpt 2.0·Reach Caster 결과와 동일).
- 제목 오른쪽에 muted 한 줄 캡션 `이번 캠페인엔 이 매체·상품이 맞아요`(고정 문구)를 둠. 오른쪽 차트는 BudgetOpt 2.0 결과 차트와 같은 헤더 구성(한글 질문 제목 + 영문 차트명 + 한글 부제, 5.1)을 따름.
- **기획 의도**: 헤더는 다른 솔루션과 통일하되(3장), "결론을 먼저 말하는 화면"이라는 Ad Curator 결과의 정체성은 본문 첫 영역에서 드러냄.

**왕중왕 정의**
- 왕중왕은 **Best Fit(최대 30개) 중 가장 먼저 검토할 매체·상품**을 뜻하는 기획 용어임. 화면에는 "왕중왕"이라는 말을 쓰지 않고 카드명(Best Match 등)만 표기함.
- 구성은 **정답 1개 + 다를 때만 대안**임. Good Fit은 왕중왕 대상이 아님.

| 구분 | 카드 | 관점 | 표시 조건 |
|---|---|---|---|
| 정답 | Best Match | 종합 적합도 | 항상 1개(Best Fit이 1개 이상일 때) |
| 대안 | Industry Favorite | 같은 업종 집행 | 이 관점의 1등이 Best Match와 **다른 상품**일 때만 |
| 대안 | Top Performer | 평가 KPI 효율 | 이 관점의 1등이 Best Match와 **다른 상품**일 때만 |

- 표시되는 카드는 **항상 2~3개**(Best Match 1개 + 대안 1~2개)임. 카드가 1개가 되는 경우(Best Match가 두 관점 모두에서 1등, 관점 데이터 산출 불가 등)는 산정 단계에서 발생하지 않도록 함(데이터사이언티스트 확정).
- **기획 의도**: 정답이 여러 개이면 정답이 흐려지고, 같은 상품이 카드 여러 장에 반복됨. 그래서 정답은 하나로 두고, "다른 우선순위를 더 중시한다면 이쪽"이라는 대안은 **실제로 다른 선택지가 있을 때만** 보여줌.

**타일 배치** (Reach Caster 결과 Key Metrics Summary와 같은 2×2 타일)
- 개수 요약 1개와 카드 2~3개를 **2열 2행 타일**로 둠: 좌상 개수 요약 → 우상 Best Match → 아래 행 대안 카드. 대안이 1개(카드 총 2개)이면 마지막 타일이 두 칸을 씀.
- 타일 구성은 Reach Caster 스코어카드와 같음: 상단에 영문 카드명 + 한글 부제(왼쪽)와 아이콘(오른쪽, 배경 없이 muted), 하단에 값. 개수 요약의 값은 `{N}개`, 카드의 값은 매체명(작게) + 상품명(굵게, 최대 2줄)이며 그 아래 한 줄 설명(최대 2줄)을 둠. 넘치는 문구는 말줄임하고 전체 문구는 hover 툴팁(title)으로 확인함.
- **Best Match 타일만 muted 배경**으로 강조하고, **그린은 Best Match 상품명 밑줄 한 곳에만** 사용함. 대안 카드는 무채색임. hover 시 부양·그림자 효과는 두지 않음(테두리만 진해짐).
- **기획 의도**: 결과 화면의 상단 좌측을 다른 솔루션과 같은 스코어카드 문법으로 맞춰 처음 보는 사용자도 "핵심 결론 카드"로 읽게 함. 그린은 "시스템이 짚은 정답"의 언어이므로 정답인 Best Match에만 씀.

**개수 요약**
- 타일 배치의 **첫 타일(좌상)**에 요약 1개를 둠. 카드가 아니므로 카드 수(2~3)에 포함하지 않음.
- 구성: 라벨 `Best Fit` + 부제 `이번 캠페인에 닿은`, 큰 숫자 `{Best Fit 수}개`, 보조 문장 `전체 매체·상품 {전체 풀}개 중에서 골랐어요`.
- 값: Best Fit 수는 결과의 Best Fit 개수, 전체 풀은 입력 조건을 적용하기 전 큐레이션 대상 전체 매체·상품 수(정책서 4.4.2 1단계)임. 정수이며 천 단위 콤마를 씀. 결과 스냅샷 값이므로 검색·필터·컬렉션 조작·Good Fit 구역 펼침으로 바뀌지 않음.
- 그린을 쓰지 않고(그린은 Best Match 카드 한 곳), hover·클릭 동작과 숫자 카운트 모션이 없음.
- **Best Fit은 0개가 되지 않음.** 조건으로 걸러낸 결과가 0개이면 일부 조건을 제외(완화)해 다시 선별하며, 어떤 조건을 제외할지는 데이터사이언티스트가 정의함(완화 안내는 3.3).
- **기획 의도**: 사용자는 "전체 매체·상품 중 내 캠페인에 닿은 것이 몇 개인가"를 먼저 알고 싶어 함. 규모감을 한 줄로 주면 Best Fit이 많은 선택지에서 가려낸 결과임이 전달되고, 가려낸 과정(퍼널)을 펼쳐 보이지 않아도 됨.

### 4.2 카드 정의 (정책서 4.3 변경)

| 카드 | 한글 부제 | 선정 기준 | 한 줄 설명 |
|---|---|---|---|
| Best Match | 이번 캠페인에 딱 맞는 | **Best Fit 중** 종합 적합도가 가장 높은 매체·상품(목록 1위와 같음) | 해당 매체·상품의 결론 구절(6.3, 같은 문장 재사용) + 함께 1등 문구(아래). 근거 문장은 타일에 두지 않고 목록 행에서 확인함 |
| Industry Favorite | 같은 업종에서 많이 쓴 | **Best Fit 중** 동일 업종에서 집행된 캠페인 수가 가장 많은 매체·상품 | "Best Fit 중 {업종} 업종 캠페인 {N}건으로 가장 많이 집행되었습니다." |
| Top Performer | 효율이 가장 좋은 | **Best Fit 중** 이번 캠페인의 평가 KPI 기준 과거 집행 효율이 가장 좋은 매체·상품 | "Best Fit 중 {평가 KPI} 기준 과거 {효율 지표}가 가장 우수했습니다." |

- 각 카드는 라벨(영문 카드명 + 한글 부제) → 매체명(작게) → 상품명(크게) → 한 줄 설명 순서로 구성함. 병합 카드의 한글 부제는 두 부제를 가운뎃점으로 이음(`같은 업종에서 많이 쓴 · 효율이 가장 좋은`).
- 한 줄 설명은 **비교 대상("Best Fit 중")을 명시**하고 과거 실적을 미래 성과로 단정하지 않음(정책서 8.6 상대 표현 원칙).
- {N}은 천 단위 콤마 정수. {평가 KPI}·{효율 지표}의 매핑은 정책서 3.4 확정 후 반영(15.1 Q2).

**판정 규칙** (V18·V19)
1. Best Match = Best Fit 중 종합 적합도 1위.
2. 관점별 1등을 Best Fit 안에서 각각 산정함(같은 업종 집행 1등, 평가 KPI 효율 1등).
3. 관점의 1등이 **Best Match와 같은 상품이면** 그 관점의 대안 카드는 만들지 않음.
4. 관점의 1등이 Best Match와 다르면 그 관점의 대안 카드를 만듦. **두 관점의 1등이 서로 같은 상품이면 카드 하나로 병합**하고 라벨을 함께 표기함(예: `Industry Favorite · Top Performer`). 한 줄 설명은 두 문장을 이어서 표시함.

**함께 1등 문구 (Best Match 카드)**
- 대안 카드가 생략된 관점(Best Match가 1등인 관점)이 있으면 Best Match 카드 한 줄 설명 아래에 muted 톤으로 표시함. 관점명은 `같은 업종 집행`, `{평가 KPI} 효율`임.

| 생략된 관점 수 | 문구 |
|---|---|
| 1개 | `{관점명}에서도 1등입니다.` (예: `같은 업종 집행에서도 1등입니다.`) |
| 0개 | 문구 없음 |

- **기획 의도**: 대안 카드를 만들지 않아도 "Best Match가 다른 관점에서도 1등"이라는 정보는 잃지 않게 함.

### 4.3 산정 경계
- 동점이면 **목록 순위(6.2)가 앞선 매체·상품**을 선택함(15.1 Q2 확정 전 임시 기준).
- 관점에 필요한 데이터(업종 내 집행 건수, 효율 지표)를 산출할 수 없으면 **그 관점은 대안 판정에서 제외**함. 대안 카드도, 함께 1등 문구의 관점명도 만들지 않음(해당 관점을 비교할 근거가 없으므로 "1등"이라고 말하지 않음).
- **Best Fit은 0개가 되지 않음.** 조건으로 걸러낸 결과가 0개이면 일부 조건을 제외(완화)해 다시 선별하며, 어떤 조건을 제외할지는 데이터사이언티스트가 정의함(완화 안내는 3.3).

### 4.4 카드 클릭
- 카드의 상품명을 클릭하면 **목록의 해당 행으로 이동**함: 검색·필터 초기화(왕중왕은 항상 Best Fit이므로 Good Fit 구역은 건드리지 않음) → 그 행이 보이는 위치까지 목록을 펼침 → 행 위치로 스크롤 → 행을 약 1.6초간 강조 후 원래대로.
- **기획 의도**: 카드는 결론이고 목록은 상세이므로, 결론에서 근거(결론 구절·근거 문장·프로모션)와 담기로 한 번에 내려가게 함.

## 5. Campaign Fit

### 5.1 구성
- **차트 헤더**(BudgetOpt 2.0 결과 6.1과 같은 구성): (1) 한글 질문형 제목 `내 캠페인에 어떤 매체·상품이 잘 맞을까?` + (2) 제목 옆 작은 영문 차트명 `Campaign Fit` + (3) 그 아래 한글 부제 `매체·상품별 다축 적합도 분석`. 부제는 한글 명사구만 두고 영문을 넣지 않음.
- **막대 차트**(5.3) 아래에 1px 구분선을 두고 SpinX 해석 블록(5.4)을 둠. 차트는 별도 테두리 카드로 감싸지 않음.
- 선별 과정 수치(전체 풀 → 후보 선정 → 적합도 통과 → Best Fit)와 진입 연출은 이 영역에 두지 않음. 후보 선정·적합도 통과 수치는 이 화면에 표시하지 않음.
- **기획 의도**: 이 차트가 답하는 질문은 "내 캠페인에 어떤 매체·상품이 잘 맞을까?"이므로 시스템이 후보를 어떻게 걸렀는지(퍼널)가 아니라 **왜 이 상품들이 앞서는지**를 보여줌. 막대는 평가 축 점수를 그대로 합친 높이(일반적으로 좋은 정도)이고, 그린은 이번 캠페인의 종합 적합도 1위(Best Match)임. 두 기준이 같으면 그린이 가장 높은 막대이고, 다르면 "점수만 높은 상품과 내 캠페인에 맞는 상품은 다르다"를 차트가 직접 보여 줌(Reach Caster 리치 커브에서 최대 도달이 아니라 최적점을 짚는 것과 같은 방식).

### 5.2 평가 축과 점수
- 평가 축은 **5개 또는 6개**이며, **어떤 축으로 평가할지는 큐레이션 생성 시 입력한 캠페인 설명에 따라 정해짐**(생성 정의서 3.9, 정책서 3.4). 캠페인마다 축 구성이 달라질 수 있으므로 화면 규칙은 특정 축 이름에 의존하지 않음.
- 캠페인 설명은 선택 입력이므로, 설명 없이 만든 큐레이션은 **기본 평가 축**(5개 또는 6개)으로 평가함. 기본 평가 축의 구성은 데이터사이언티스트가 정의하며 화면은 정의하지 않음.
- 축별 점수와 **종합 적합도(순위)**는 데이터사이언티스트가 정의해 결과로 제공하며, 화면은 산출 방식을 정의하지 않음. 한 큐레이션 안의 모든 매체·상품은 같은 축으로 점수를 받음.
- 목록 순위(6.2)·Best Match(4.2)·카드 판정은 모두 **종합 적합도 순위**를 따름.
- **막대 높이 = 축별 점수의 단순 합**(화면 표시 규칙)임. 종합 적합도는 축 점수의 단순 합과 다를 수 있으므로 막대 순서와 목록 순위는 다를 수 있음.
- 점수 원값은 화면에 표시하지 않고 높이·칸·상대 표현(`상위 N%`)으로만 표현함(정책서 8.6 상대 표현).
- 축 이름과 표시 순서는 결과 데이터가 정하며, 막대의 칸·레이더(6.10.1)·툴팁이 모두 같은 순서를 씀. 차트에는 별도 범례를 두지 않음.
- **기획 의도**: 다른 도구는 조건에 맞는 상품을 걸러내는 데서 끝나지만, Ad Curator는 캠페인 설명을 읽고 **무엇으로 평가할지부터 캠페인에 맞춰 고름**. 같은 업종·목적이라도 브리프가 다르면 평가 축이 달라지는 것이 이 솔루션의 차별점이므로, 축 구성은 막대 툴팁·상품 팝업 레이더·SpinX 해석에서 드러냄. 막대를 축 점수의 단순 합으로 두면 사용자가 "높이 = 점수 합"이라는 한 문장으로 차트를 읽을 수 있고, 그린의 위치로 "이번 캠페인 기준"이 무엇을 바꿨는지 볼 수 있음.

### 5.3 차트 표시 규칙

| 항목 | 규칙 |
|---|---|
| 막대 | Best Fit 매체·상품마다 막대 1개(최대 30개). Good Fit은 차트에 표시하지 않음 |
| 정렬 | 점수 합 내림차순으로 왼쪽부터 배치. 합이 같으면 목록 순위가 앞선 쪽이 왼쪽(V20). 차트 아래 muted 안내 `점수 합이 높은 순 →` |
| 높이 | 점수 합에 비례하며 0에서 시작함(막대 간 차이를 과장하지 않음) |
| 칸 | 막대 안에 축별 점수만큼 쌓임. 축 순서는 결과 데이터가 정한 순서이며 모든 막대에서 같음. 칸은 색이 아니라 **명도 단계**로 구분함 |
| Best Match 표시 | Best Match 막대는 위치와 관계없이 시그니처 그린의 명도 단계로 칠하고 막대 위에 이름 필 `Best Match · 이번 캠페인 1위`를 붙임. 그린은 이 막대 한 곳에만 씀 |
| 나머지 막대 | 무채색 명도 단계. Industry Favorite·Top Performer 상품의 막대도 표식 없이 무채색(강조는 한 곳) |
| hover / 포커스 | 툴팁에 매체명, 상품명, `이번 캠페인 {n}위`(종합 적합도 순위 = 목록 순위), 축별 `상위 {N}%`를 칸 색 견본과 함께 쌓인 순서대로(맨 위 칸이 맨 위) 표시함. 다른 막대는 흐리게 함. 왼쪽 카드에 올리면 해당 막대가, 막대에 올리면 해당 카드가 서로 강조됨 |
| 클릭 | 막대에는 클릭 동작이 없음(hover·포커스로 읽기만 함). 목록 이동은 카드(4.4)에서, 컬렉션 담기는 목록의 `+ 담기` 버튼으로만 함 |
| 진입 모션 | 결과 화면에 진입할 때 막대가 바닥에서 순서대로 올라오는 모션을 1회 재생함. 시스템 "동작 줄이기" 설정이면 생략하고 최종 상태를 바로 표시함. 필터·검색·컬렉션 조작으로는 재생하지 않음 |

- `상위 {N}%` 임시 기준: 해당 축의 점수를 Best Fit 안에서 내림차순으로 순위(동점은 같은 순위) r, 전체 n개일 때 상위 `ceil(r / n × 100)`%(1~100 정수). 산출 방식은 15.1 Q6.
- **기획 의도**: 막대 하나가 상품 하나, 칸이 근거라는 단순한 규칙이라 처음 보는 사용자도 읽을 수 있음. 막대는 점수 합 순서로 두고 그린만 이번 캠페인 1위에 두어, 그린이 맨 왼쪽이 아니면 그 차이 자체가 "내 캠페인에 맞춘 평가"의 근거가 됨. 툴팁의 `이번 캠페인 {n}위`로 목록 순위와 연결함.

### 5.4 SpinX 차트 해석 (정책서 8.4 변경)

> **범위 한정**: 화면에서의 노출·인터랙션만 정의함. 프롬프팅·응답 생성 로직은 별도 SpinX 문서 관할.

| 항목 | 규칙 |
|---|---|
| 위치·구성 | 차트 하단. 헤더에 SpinX 심볼 + 워드마크 "SpinX for Ad Curator"(BudgetOpt 2.0 해석 블록과 같은 구성). 로딩 중 타이핑 효과(심볼 회전 + analyzing…) |
| 본문 | Best Match가 어떤 평가 축에서 강해 가장 높은 막대가 되었는지, 다음 순위와 비교해 어느 축이 차이를 만들었는지, 대안 카드가 있으면 어떤 축·우선순위에서 다른지를 설명. 점수 값을 단순 반복하지 않고 상대 표현으로 서술. 평가 축이 캠페인 설명의 어떤 내용을 반영했는지 한 문장 포함. Best Match가 점수 합 1위가 아니면, 이번 캠페인에서 중요한 축 덕분에 1위가 되었다는 점을 설명함. 완화된 조건이 있으면 그 사실을 한 문장 포함. 문장은 합니다체 |
| 이어서 질문하기 | 타이핑이 끝난 뒤 텍스트 링크 `이어서 질문하기 →`를 표시. 클릭하면 SpinX 패널을 열고 입력창에 `@Campaign Fit `를 프리필함. **자동 전송하지 않음**(BudgetOpt 2.0 결과 7.2와 동일) |
| 생성 실패 | 본문 `이 차트에 대한 SpinX 분석을 생성하지 못했습니다.` / 보조 `새로고침하거나 결과에 다시 들어오면 분석을 다시 시도합니다.` (BudgetOpt 2.0 결과 7.1.1과 동일 문구). muted 톤, 타이핑 효과·"이어서 질문하기" 미노출 |
| 사용량 | 결과 진입 시 자동 생성되는 해석은 사용자 대화 사용량에 포함하지 않음(정책서 8.6) |

- **기획 의도(자동 전송하지 않는 이유)**: 의도치 않은 클릭이 SpinX 사용량을 소모하지 않도록 함(ActionDock 제안 질문도 같은 이유로 자동 전송하지 않음).

## 6. 매체·상품 목록

### 6.1 구역 구성
- 목록은 **두 구역**으로 나뉨: ① `Best Fit` 구역(항상 펼침) ② `이런 선택지도 있어요` 구역(Good Fit, 접이식). 탭으로 동등하게 나누지 않음.
- **Best Fit 구역**: 헤더에 제목 `Best Fit` + 개수 `{N}` + muted 캡션 `이번 캠페인을 위해 고른 최고의 상품들이에요`, 그 아래에 검색·필터(6.6·6.7), 안내 줄(6.4), 행 목록, 더 보기(6.8). {N}은 **검색·필터와 무관하게 고정**됨.
- **`이런 선택지도 있어요` 구역**: Best Fit 목록(더 보기 포함) 아래에 1px 구분선을 두고 헤더 한 줄을 둠. 구성은 제목 `이런 선택지도 있어요` + muted `Good Fit {N} · 참고해 보면 좋아요` + 우측 `펼치기 ↓`(펼친 상태에서는 `접기 ↑`).
  - **기본은 접힘**이며 헤더 전체를 눌러 펼침·접힘을 토글함. 펼치면 Good Fit 행(6.3)을 10개씩 보여주고 `더 보기`로 10개씩 추가함. 접었다 펼치면 처음 10개로 돌아가고, 새로고침·재진입하면 접힌 상태로 돌아감.
  - Good Fit이 0개이면 이 구역을 표시하지 않음.
  - 검색·필터는 이 구역에도 같이 적용됨(6.6·6.7). 헤더의 `Good Fit {N}`은 전체 개수로 고정되고, 검색·필터가 적용 중이면 뒤에 ` · {M}개 일치`를 붙임. 접혀 있어도 적용되며 펼치면 일치하는 행만 보임.
- **Low Fit 구역은 두지 않음**(정책서 3.5: 결과 화면 미제공).
- **그룹당 최대 30개**를 전제로 설계함(정책서에 명시 없음, 15.1 Q1).
- **기획 의도**: Best Fit은 이 큐레이션이 먼저 검토하라고 고른 대상이고, 카드·차트·개수 요약도 모두 Best Fit을 기준으로 함. Good Fit을 탭으로 나란히 두면 두 그룹이 같은 무게로 읽히므로, 아래에 접어 두어 "먼저 볼 것"과 "참고로 볼 것"을 구분함. 그래도 Good Fit은 숨기지 않고 한 번의 클릭으로 열 수 있어 선택지를 넓히고 싶은 사용자의 길을 막지 않음.

### 6.2 순위
- 각 그룹 안에서 **종합 적합도 내림차순**으로 고정 정렬함. 정렬 변경 기능은 두지 않음.
- 행 왼쪽 순위 번호(01, 02…)는 **그룹 내 순위**이며, 검색·필터를 적용해도 번호가 바뀌지 않음.
- 적합도 점수 값은 화면에 표시하지 않음(점수 산출 방식 미정, 정책서 3.4. 15.1 Q2).
- **기획 의도**: 순위 자체가 곧 적합도 순서이므로 정렬 선택지를 주면 오히려 "무엇이 더 맞는가"가 흐려짐.

### 6.3 행 구성
행은 표의 열 구조가 아니라 **세로로 읽히는 리스트**임(열 헤더·열 구분선 없음, 행 사이 1px 구분선만). 가로로는 `순위` / `상품` / `이유` / `담기` 네 구역으로 나뉘고 이유 구역이 가장 넓음.

**Best Fit 행**

| # | 항목 | 화면 표시 | 데이터 출처 | 형식 · 규칙 |
|---|---|---|---|---|
| 1 | 순위 | 행 맨 앞 번호 | 종합 적합도 순위(산출 로직, 6.2) | 2자리(01~). **Best Match 행의 번호만 그린**, 나머지는 muted. 검색·필터를 적용해도 번호 유지 |
| 2 | 매체명 | 상품명 위 작은 글씨(muted) | 매체·상품 카탈로그 | 원문 그대로(예: `kakao 모먼트`, `NAVER 성과형 DA`, `Google Ads`, `Meta`) |
| 3 | 상품명 | 굵은 글씨. 누르면 상품 팝업 | 매체·상품 카탈로그 | **레디셋 광고상품명 원문 그대로**(예: `카카오톡비즈보드_전환_카카오톡채널_CPA`), 길면 줄바꿈. 누르면 상품 팝업(6.10)이 열림 |
| 4 | 상품 설명 | 상품명 아래 한 줄 | 상품 라벨 | 30자 이내(공백 포함) 명사구, 마침표 없음. **노출 지면을 포함**(예: 채팅 목록 최상단, 네이버 메인). 같은 라벨이면 같은 문장(정책서 8.3) |
| 5 | 프로모션 여부 | 상품 설명 뒤 `· 프로모션 있음` | 프로모션 데이터 | 큐레이션을 "프로모션 포함"으로 만들고 캠페인 기간과 겹칠 때만(6.5, V10). 누르면 상품 팝업의 프로모션 영역으로 열림(6.10) |
| 6 | 결론 구절 | 이유 구역 첫 줄, 굵게 | 가장 강한 평가 축 + 쉬운 말 사전 | 15~25자(공백 포함), 해요체 |
| 7 | 근거 | 결론 아래, 옅은 글씨 | 평가 축 결과 + 캠페인 입력값 + 상품 라벨 | 1~2문장, 결론 구절과 합쳐 150자 이내(공백 포함), **캠페인 입력값 연결 하나 필수**, 해요체(V23) |
| 8 | 담기 상태 | 행 오른쪽 `+ 담기` / `✓ 담았어요` | 컬렉션 | Admin/Marketer만 조작(Agency/Client는 `✓ 담았어요` 표시만, 1.5), 최대 30개(7.4) |

**예시 (Best Fit 행)**

> 매체명·상품명은 레디셋 카탈로그의 실제 표기이고, 설명·문구·평가 근거는 설명을 위한 예시임(실제 데이터 아님). 캠페인은 `업종 화장품 / 목적 전환 / 기간 12월 / 소재 영상`으로 가정함.

| 순위 | 매체명 | 상품명 | 상품 설명 | 프로모션 | 결론 구절 | 근거 | 연결한 입력값 |
|---|---|---|---|---|---|---|---|
| **01** | kakao 모먼트 | 카카오톡비즈보드_전환_카카오톡채널_CPA | 카카오톡 채팅 목록 최상단 배너 | · 프로모션 있음 | **화장품 캠페인에서 가장 꾸준히 선택됐어요** | 전환 효율도 상위권이라 믿고 먼저 담기 좋아요. 카카오톡을 여는 순간 보이는 자리라 12월 신제품 런칭처럼 짧은 기간에 빠르게 알릴 때 특히 잘 맞아요. | 목적(전환), 기간(12월) |
| 02 | NAVER 성과형 DA | 웹사이트 전환_네이버 메인_CPC | 네이버 메인 노출 성과형 디스플레이 | | **네이버 메인 지면에 넓게 닿아요** | 화장품 업종에서도 많이 쓰여 운영이 안정적이에요. 성과형으로 구매할 수 있어 전환 목적 캠페인의 비용을 관리하기 좋아요. | 업종(화장품), 목적(전환) |
| 03 | Google Ads | 건너뛸 수 없는 인스트림 광고_CPM | YouTube 영상 시청 중 건너뛸 수 없는 광고 | | **화장품 업종에서 많이 쓰인 영상 상품이에요** | 시청자 관심사로 타겟을 좁힐 수 있어 런칭 영상을 원하는 사람에게 보여 주기 좋아요. 이미 만든 영상 소재를 그대로 쓸 수 있어 준비 부담도 적어요. | 업종(화장품), 소재(영상) |
| 04 | Meta | 경매_트래픽_랜딩 페이지 조회수 극대화_facebook | 페이스북 피드에서 랜딩 페이지로 연결 | · 프로모션 있음 | **이번 캠페인에 넓게 닿는 상품이에요** | 화장품 업종에서도 자주 쓰였어요. 랜딩 페이지로 바로 연결돼 12월 신제품 소개를 보여 주기 좋아요. | 업종(화장품), 기간(12월) |

- 예시의 결론 구절은 각 상품에서 **가장 강한 평가 축**을 쉬운 말로 바꾼 것임(평가 축과 쉬운 말 사전은 15.1 Q2·Q8에서 확정). 근거는 결론을 반복하지 않고 "왜 이 캠페인에 맞는가"를 입력값과 연결해 설명함.
- **프로모션을 별도 열로 두지 않는 이유**: 프로모션 "미포함"으로 만든 큐레이션에서는 프로모션 요소가 전혀 없어야 하므로, 열을 만들면 미포함일 때 빈 열이 남음. 상품 설명 뒤 인라인으로 두면 미포함일 때 그 텍스트만 사라지고 **행 레이아웃은 포함·미포함이 완전히 같음**.
- 매체·상품 이름·상품 설명·결론 구절·근거는 모두 생성 시점 값이며 다시 계산하지 않음.
- 행에 hover하면 배경이 은은하게 바뀜(강조 효과 없음). 상품명과 `· 프로모션 있음`을 제외한 행 영역에는 클릭 동작이 없음.
- Good Fit 구역의 행은 같은 구성이되 상품명 굵기와 텍스트 대비를 낮춰 참고용임을 드러냄(색 강조 없음). 순위는 muted이며, 결론 구절·근거는 Best Fit 행과 같은 규칙(V23)을 따르고 **근거에 낮게 평가된 부분을 반드시 포함**함.
- **기획 의도**: 행을 `무엇(상품) | 왜(이유) | 담기`로 나누면 사용자가 상품을 확인하고 이유를 읽고 바로 담는 흐름이 한 줄에서 끝남. 결론 구절을 굵게 먼저 두어 이유를 한 줄만 읽어도 판단할 수 있고, 근거는 필요할 때 이어 읽게 함. 근거에 캠페인 입력값 연결을 필수로 두는 이유는 같은 상품 설명이 어느 캠페인에서나 똑같이 보이는 것을 막고 "내 캠페인을 위한 결과"임을 느끼게 하기 위함.

### 6.4 안내 줄
Best Fit 구역 헤더 바로 아래 한 줄. 목록의 성격을 한 번만 알려 주고 행마다 반복하지 않게 함.

| 위치 | 내용 |
|---|---|
| 좌측 | SpinX 심볼 + `선정 근거는 SpinX가 정리했습니다.` |
| 우측 | `생성 시점 기준 · yyyy-mm-dd` + Info 아이콘. hover 시 툴팁 |

- 우측 툴팁 문구(프로모션 포함): `결과는 생성 시점의 데이터·프로모션 기준입니다. 다시 계산하지 않으며, 최신 프로모션은 원문 링크에서 확인할 수 있습니다.`
- 우측 툴팁 문구(프로모션 미포함): `결과는 생성 시점의 데이터 기준입니다. 다시 계산하지 않으며, 최신 기준이 필요하면 복제 후 다시 생성해 주세요.`
- **기획 의도**: 정책서 4.2의 "결과 기준 데이터" 정책을 사용자가 오해하지 않게 함. 프로모션 정보가 시간이 지나 달라졌을 때 결과가 틀린 것으로 오해하지 않도록, 생성 시점 기준임을 목록 곁에 항상 둠.

### 6.5 프로모션 (정책서 5장)

| 구분 | 규칙 |
|---|---|
| 표시 조건 | 큐레이션이 프로모션 **포함**으로 생성되었고, 해당 매체·상품에 **캠페인 기간과 하루 이상 겹치는 프로모션**이 있을 때만 상품 설명 뒤에 `· 프로모션 있음` 표시(V10) |
| 미포함 | 목록·필터·안내 툴팁 어디에도 프로모션 요소를 표시하지 않음(V11) |
| 열기 | `· 프로모션 있음`을 누르면 상품 팝업(6.10)이 열리고 프로모션 영역이 보이는 위치로 스크롤됨. 행 안에서 펼치지 않음 |
| 안내 | 팝업의 프로모션 영역 하단에 `생성 시점(yyyy-mm-dd) 기준입니다. 최신 내용은 MTS 2.0 원문에서 확인해 주세요.` + 원문 링크(새 탭) |

**프로모션 영역 구성 (정책서 5.3, 상품 팝업에 표시)**

| 요소 | 내용 |
|---|---|
| 프로모션명 | 원문에 등록된 프로모션명 |
| 기간 | 프로모션 혜택이 적용되는 광고 집행 기간 |
| 혜택 | 추가 노출·할인 등 혜택과 규모를 원문 기준으로 표시 |
| 조건 | 최소 집행 금액, 대상 상품, 중복 적용 제한 등 |
| 이점 | 혜택으로 얻는 이점. **원문에 없는 성과 보장이나 금액 환산은 쓰지 않음** |

- 한 매체·상품에 캠페인 기간과 겹치는 프로모션이 둘 이상이면 **캠페인 기간과 겹치는 날이 가장 많은 프로모션 1개만** 표시함. 겹치는 날 수가 같으면 프로모션 시작일이 빠른 것을 표시함.

### 6.6 검색
- 버튼 `검색`을 누르면 입력창으로 확장되고 자동 포커스됨(큐레이션 목록 검색과 동일 방식).

| 항목 | 규칙 |
|---|---|
| 검색 대상 | 매체명 + 상품명 + 상품 설명을 동시에(결론 구절·근거 문장은 대상이 아님) |
| 매칭 방식 | 부분 일치(substring), **대소문자 무시** |
| 공백 처리 | 입력값 앞뒤 공백을 트리밍한 뒤 비교. 공백만 입력하면 검색 미적용 |
| 타이밍 | onChange 실시간(디바운스 없음) |
| 범위 | Best Fit 목록과 `이런 선택지도 있어요` 구역에 함께 적용 |
| placeholder | `매체·상품 검색` |
| 닫힘 | 입력값이 빈 상태에서 blur하면 버튼으로 축소. X 버튼은 검색어 초기화 + 축소 |

### 6.7 필터
- 버튼 `필터`를 누르면 드롭다운을 열고, 적용된 항목 수를 버튼에 배지로 표시함(활성 시 연한 배경). 큐레이션 목록 필터와 같은 UI 톤임.

| 그룹 | 항목 | 규칙 |
|---|---|---|
| 매체 | Best Fit·Good Fit 전체의 매체 목록 + 매체별 개수(두 구역 합계) | 다중 선택, 선택한 매체의 항목만 표시(OR) |
| 프로모션 | `프로모션 있는 것만` 스위치 | **프로모션 포함으로 만든 큐레이션에서만 이 그룹을 표시**. ON이면 `프로모션 있음` 항목만 표시 |
| 컬렉션 | `담은 것만` 스위치 | ON이면 컬렉션에 담긴 항목만 표시 |

- **그룹 간은 AND**, 매체 그룹 안은 OR임.
- **배지 숫자** = 선택한 매체 수 + ON인 스위치 수.
- 하단: `초기화`(검색어를 제외한 모든 필터 해제) + `{N}개 표시`(필터·검색 적용 후 두 구역의 결과 수 합계).
- 필터나 검색이 적용 중이면 Best Fit 헤더 아래에 `필터 {n}개 적용 · {N}개 표시` + `초기화` 링크를 표시함(필터 없이 검색어만 있어도 `{N}개 표시` + `초기화`). 초기화는 필터와 검색어를 모두 해제함.
- 바깥 클릭·Esc로 드롭다운이 닫힘.
- **기획 의도**: 그룹당 최대 30개를 훑을 때 "어떤 매체의 상품만", "프로모션 있는 것만", "내가 고른 것만"이 가장 흔한 좁히기이기 때문임. 프로모션 필터를 미포함 큐레이션에서 숨겨 미포함에서 의미 없는 선택지를 없앰.

### 6.8 더 보기
- 처음에는 **10개**를 표시하고, 남은 항목이 있으면 목록 하단 중앙에 `{M}개 더 보기 · {표시 수} / {전체} ` 텍스트 버튼을 표시함. M = min(10, 남은 개수). 누를 때마다 10개씩 추가됨.
- 검색·필터 변경 시 Best Fit 목록과 Good Fit 구역 모두 처음 10개로 초기화함. Good Fit 구역은 더 보기를 따로 가지며 접었다 펼치면 처음 10개로 돌아감.
- 모두 표시되면 버튼이 사라짐.
- **기획 의도**: 페이지네이션 컨트롤은 목록을 "표"처럼 보이게 해 피로도를 높이므로, 읽는 흐름을 끊지 않는 더 보기를 씀.

### 6.9 빈 상태
| 상황 | 표시 |
|---|---|
| 검색·필터 결과 0건 | `조건에 맞는 매체·상품이 없습니다.` + 줄바꿈 후 `필터 초기화` 링크(검색어도 함께 해제) |
| `이런 선택지도 있어요` 구역의 검색·필터 결과 0건 | 구역을 펼치면 `조건에 맞는 매체·상품이 없습니다.`를 표시(필터 초기화 링크는 Best Fit 쪽 하나만 둠). 헤더는 `Good Fit {N} · 0개 일치` |
| Good Fit이 0개 | `이런 선택지도 있어요` 구역을 표시하지 않음. Best Fit은 0개가 되지 않음(4.1) |

### 6.10 상품 팝업
- **열기**: 행의 상품명을 누르거나 `· 프로모션 있음`을 누르면 열림(후자는 프로모션 영역이 보이는 위치로 스크롤). Best Fit·Good Fit 행 모두 같음. 팝업 위에 다른 팝업을 열지 않음(중첩 없음).
- **크기**(ui-dialog-policy): Best Fit 상품은 `lg`(레이더 + 속성 2열), Good Fit 상품은 `md`(레이더 없음, 1열). 헤더·푸터는 고정하고 본문이 화면보다 길면 본문만 스크롤함.
- **닫기**: `닫기` 버튼, 오버레이 클릭, Esc. 다시 열면 스크롤은 맨 위에서 시작함.
- 팝업의 모든 값은 생성 시점 값이며 다시 계산하지 않음.

| 영역 | 내용 | 표시 조건 |
|---|---|---|
| 헤더 | 매체명(muted, 작게) / 상품명(굵게, 원문 그대로) / 상품 설명(행과 같은 문장, 지면 포함) | 항상 |
| 레이더 차트(왼쪽) | 6.10.1 | **Best Fit 상품만** |
| 속성(오른쪽) | 6.10.2 | 값이 있는 항목만 |
| 프로모션(하단) | 프로모션명·기간(한 줄) / 혜택 / 조건 / 이점 + 원문 링크 + 안내 문구(6.5). 프로모션이 둘 이상이면 캠페인 기간과 가장 많이 겹친 1개(6.5) | 6.5의 표시 조건을 만족할 때만 |
| 푸터 | `+ 담기` / `✓ 담았어요`(Admin/Marketer만, 7.3과 같은 규칙) + `닫기` | 항상 |

**6.10.1 레이더 차트 (Best Fit 상품)**
- 축은 이 큐레이션의 평가 축 전체(5개 또는 6개, 5.2)이며 순서는 Campaign Fit 막대 칸 순서와 같음.
- 두 도형: **이 상품**(면) + **Best Fit 평균**(점선). 평균은 Best Fit 전체(이 상품 포함)의 축별 점수 평균임. 이 상품이 Best Match이면 면을 그린 계열로, 그 밖에는 무채색으로 칠함(그린은 정답에만, 4.1).
- 점수 숫자는 표시하지 않음(정책서 8.6 상대 표현). 축 이름만 라벨로 표시하고, **해석 문구와 툴팁은 두지 않음**. 면과 점선의 비교만으로 강하고 약한 축이 읽히기 때문임.
- **기획 의도**: 막대 차트가 "합"을 보여 준다면 레이더는 "이번 캠페인의 평가 축 중 어디에서 강하고 어디가 약한가"를 보여 줌. Best Match도 약한 축이 있으면 숨기지 않아 결론을 신뢰하게 하고, 평균을 기준으로 삼아 점수 원값 없이도 상대 위치를 읽게 함. 차트가 쉬우므로 해석 문장을 덧붙이지 않음. Good Fit은 평균에 못 미치는 것이 당연하므로 차트를 두지 않고 근거 문장에서 설명함.

**6.10.2 속성**

값 | 항목명(muted) 읽기 전용 행으로 표시함(반영된 조건 모달 3.3과 같은 형식). 노출 지면은 상품 설명에 포함되므로 속성에 다시 쓰지 않음.

| 순서 | 항목 | 표시 값 |
|---|---|---|
| 1 | 구매 방식 + 과금 방식 | `{구매 방식} · {과금 방식}` (예: `성과형 · CPC`) |
| 2 | 소재 형식 | 지원하는 소재 형식을 가운뎃점으로 나열(예: `동영상 · 이미지`). 영상 상품은 영상 형식(길이·스킵 여부)을 병기(예: `동영상 (스킵 불가 · 15초)`) |
| 3 | 타게팅 지원 | 지원하는 옵션을 구체 항목으로 나열. 데모는 `연령 · 성별`로 풀어 씀(예: `연령 · 성별 · 지역 · 관심사`) |
| 4 | 추천 타겟 | 이 상품이 잘 닿는 대상(예: `20~30대 여성 · 뷰티 관심`). 상품 라벨 기준이며 입력 조건과 비교하지 않으므로 ✓를 붙이지 않음 |
| 5 | 디바이스 | `모바일 · PC` 등 지원 기기 |
| 6 | 보장 형태 | 보장형일 때만 표시(예: `노출 보장`) |
| 7 | 최소 집행 금액 | `{금액}만 원`(천 단위 콤마, 큐레이션 입력과 같은 표기) |

- **값이 없는 항목은 행 자체를 숨김**(빈 칸·`-` 표기 없음). 모든 항목이 비면 영역을 숨기고 레이더(또는 프로모션)만 표시함.
- 내가 입력한 속성 기준(생성 Step 2)과 맞는 항목은 값 옆에 `✓`를 붙이고, 영역 하단에 muted 한 줄 `✓ 내가 입력한 조건과 맞아요`를 표시함(✓가 하나도 없으면 한 줄도 표시하지 않음). **완화로 제외된 조건**에 해당하는 항목은 ✓ 대신 muted `조건 완화`로 표시함(3.3).
- 특성 기준(생성 Step 2)은 상품 속성이 아니라 평가와 관련된 기준이므로 이 영역에 표시하지 않고 레이더와 근거 문장에 반영함.
- **기획 의도**: 광고주·집행자가 담기 전에 확인할 것은 비용 구조(구매·과금), 만들어야 할 소재, 도달 대상(타게팅·추천 타겟·디바이스), 약속 조건(보장), 진입 장벽(최소 금액)임. 입력한 조건과의 일치를 ✓로 보여 "내 캠페인에서 쓸 수 있는 상품"임을 팝업에서도 이어서 확인하게 함.

## 7. 컬렉션

### 7.1 정의 (정책서 6장)
- 컬렉션은 사용자가 결과에서 매체·상품을 담아 만든 묶음이며 **큐레이션당 1개**임. **저장된 컬렉션**은 접근 가능한 모든 사용자가 같은 것을 봄. 저장하지 않은 담기·빼기는 지금 보고 있는 화면에만 있고 화면을 떠나면 사라짐(7.5).
- 담기·빼기는 Admin/Marketer만 가능하고, Agency/Client는 조회만 가능함.
- 최대 **30개**까지 담을 수 있음(BudgetOpt 2.0 시나리오의 상품 상한 30개와 같음).
- 큐레이션 결과는 불변이지만 컬렉션은 결과 위에 얹는 사용자 설정이므로 **불변성의 예외**임(정책서 6.2.1).

### 7.2 컬렉션 패널 (우측 sticky)

| 요소 | 규칙 |
|---|---|
| 헤더 | `컬렉션` + `{n} / 30` + 얇은 진행 바(n/30 비율) + 오른쪽 `저장` 버튼(Admin/Marketer만, 7.5) |
| 저장 안내 | 저장하지 않은 변경이 있으면 헤더 아래 muted 한 줄 `저장하지 않은 변경 사항이 있습니다.` |
| 담은 항목 | 담은 순서대로 나열: 상품명(위) + 매체명(아래, muted) + 적합도 그룹 `Best` / `Good` + 빼기(×, Admin/Marketer만). 항목이 많으면 목록 영역 안에서만 스크롤 |
| 빈 상태 | Admin/Marketer: `담은 매체·상품이 없습니다. 목록에서 담기를 누르면 이곳에 모입니다.` / Agency·Client: `담긴 매체·상품이 없습니다.` |
| CTA 영역 | Admin/Marketer만 노출(Section 8) |

- 컬렉션 패널은 필터·검색과 무관하게 **전체 컬렉션**(Good Fit 항목 포함)을 보여줌.

### 7.3 담기·빼기

| 동작 | 규칙 |
|---|---|
| 담기 | 목록 행의 `+ 담기`를 누르면 즉시 컬렉션에 담기고 패널에 항목이 추가됨(진행 바·개수 갱신) |
| 빼기 | `✓ 담았어요`를 다시 누르거나 패널의 ×를 누르면 즉시 빠짐. 별도 확인 다이얼로그 없음 |
| 중복 | 같은 매체·상품은 한 번만 담길 수 있음(V4). 담기 버튼이 토글이므로 중복 담기가 발생하지 않음 |
| 필터 연동 | `담은 것만` 필터가 켜진 상태에서 빼면 해당 행이 목록에서 즉시 사라짐 |
| 유지 | 담기·빼기는 화면에만 반영됨. `저장`을 눌러야 새로고침·재진입·다른 사용자 접속에서도 유지됨(7.5) |

- **기획 의도**: 담기는 "행 선택"이 아니라 "수집"이므로 확인 없이 즉시 반영하고(흐름을 끊지 않음), 실수는 같은 자리에서 바로 되돌릴 수 있게 함.

### 7.4 한도
- 컬렉션이 30개일 때: 담기지 않은 행의 `+ 담기`는 **비활성 스타일**(흐리게)이며 hover 시 안내 `컬렉션에는 최대 30개까지 담을 수 있습니다.`를 표시함. 비활성 버튼을 눌러도 토스트로 같은 안내를 표시하고 담기지 않음(V3).
- 이미 담긴 행의 `✓ 담았어요`는 활성이어서 빼기가 가능함. 하나를 빼면 다시 담을 수 있음.

### 7.5 저장
- 담기·빼기는 즉시 화면(행의 담기 상태·패널·개수)에 반영하지만 **서버에 저장하지 않음**(휘발성).
- 결과 화면에 진입하면 마지막으로 저장된 컬렉션을 불러옴. 저장된 적이 없으면 빈 컬렉션임.
- `저장` 버튼: 현재 컬렉션이 저장된 컬렉션과 다를 때만 활성(담았다가 다시 빼서 같아지면 비활성). 누르면 현재 컬렉션 전체를 저장하고 토스트 `컬렉션을 저장했습니다.`를 표시한 뒤 비활성으로 돌아감(V5).
- 저장 실패: 화면의 현재 컬렉션은 되돌리지 않고 그대로 두며, 토스트 `컬렉션 저장 중 일시적인 오류가 발생했습니다.`를 표시하고 버튼은 활성으로 남음(V5).
- 저장하지 않은 변경이 있는 상태에서 화면을 떠나면(다른 메뉴·목록 이동, 새로고침, 탭 닫기) 플랫폼 공통 이탈 확인(큐레이션·시나리오 생성 화면과 같은 방식)을 표시함(V26). 확인하면 변경은 사라지고, 취소하면 화면에 남음.
- BudgetOpt 2.0으로 이동할 때는 **현재 컬렉션**(저장 여부와 무관)이 넘어가며 이탈 확인을 표시하지 않음. 저장하지 않은 변경은 결과 화면에 남지 않음.
- 둘 이상의 사용자가 저장하면 **마지막에 저장한 컬렉션**이 이전 저장을 덮어씀.
- Agency/Client는 저장된 컬렉션만 보며 `저장` 버튼이 없음.
- **기획 의도**: 담기는 검토 중의 임시 선택이므로 누를 때마다 저장하면 여러 사람이 보는 컬렉션이 계속 흔들림. 확정한 묶음만 저장해 공유하고, 저장하지 않은 선택은 가볍게 버릴 수 있게 함.

## 8. BudgetOpt 2.0 연계 (정책서 7.2)

### 8.1 진입점
- 컬렉션 패널 CTA와 ActionDock ＋ 런처의 액션 `BudgetOpt 2.0으로 배분하기`. 두 경로는 같은 모달을 엶. Admin/Marketer만 노출(1.5).
- 같은 액션을 페이지 안(패널)과 ActionDock에 모두 두는 것은 BudgetOpt 2.0 결과 화면이 "도달 예측하기"를 페이지 CTA와 ActionDock에 모두 두는 패턴과 같음.

### 8.2 컬렉션 패널 CTA

| 요소 | 내용 |
|---|---|
| 제목 | `이 조합에 예산을 어떻게 나눌까요?` |
| 설명 | `매체별 예산 배분과 KPI 예측은 BudgetOpt 2.0에서 확인해요.` (BudgetOpt 2.0 결과 CTA와 같은 카피 톤) |
| 버튼 | Primary 표준 버튼(pill) `BudgetOpt로 이어서` + 우측 화살표 아이콘. hover 시 화살표만 살짝 이동 |
| 보조 문구 | 활성: `업종·기간·컬렉션을 그대로 가져갑니다.` / 비활성: `컬렉션에 2개 이상 담으면 이어갈 수 있습니다.` |

- **활성 조건**: 컬렉션 개수가 **2개 이상 30개 이하**(V12). BudgetOpt 2.0 시나리오는 최소 2개·최대 30개 상품이 필요하기 때문임(BudgetOptimizer_Scenario_Creation_Spec.md V2·V10). 0~1개일 때 버튼은 비활성이며 위 보조 문구를 표시함.
- **기획 의도**: 위에서 이미 본 개수·항목을 CTA에서 다시 나열하지 않고, "넘어가면 새로 얻는 것"과 "가져가는 맥락"만 말함.

### 8.3 간편 생성 모달 (`md` 크기)

버튼을 누르면 모달을 엶. 큐레이션 결과가 그대로 넘어가므로 사용자는 두 가지만 더 입력함.

| 항목 | 필수 | 규칙 |
|---|---|---|
| 시나리오명 | (자동) | 읽기 전용. `(B/O-{큐레이션 ID}) {큐레이션명}`(정책서 7.2 네이밍). 최대 길이 초과 시 처리는 BudgetOpt 2.0 생성 정의서를 따름 |
| 업종 · 기간 | (자동) | 읽기 전용. 큐레이션의 업종 결정 방식·브랜드·업종과 캠페인 기간을 그대로 승계 |
| 컬렉션 | (자동) | 읽기 전용 목록(상품명 · 매체명 · Best/Good). 항목이 많으면 목록 안에서 스크롤 |
| 총 예산 | 필수 | 원 단위 정수. 숫자만 입력, 천 단위 콤마 자동, 11자리(999억) 초과 입력 차단. BudgetOpt 2.0 총 예산 입력과 동일 규칙 |
| KPI | 필수 | 노출 / 클릭 / 조회 / 도달 중 **1개**(BudgetOpt 2.0 Step 1 KPI 선택과 동일 항목) |

- 하단 버튼: `취소` / `BudgetOpt로 이동`. 총 예산 > 0 **AND** KPI 선택 시에만 이동 버튼이 활성됨.
- 입력 오류 문구는 BudgetOpt 2.0 생성과 같은 문구를 씀(V13, V15). 사용자가 첫 입력을 시작한 뒤부터 표시함.
- 취소·오버레이 클릭·Esc로 닫으면 입력값은 폐기되고, 다시 열면 비어 있는 상태로 시작함.

### 8.4 확정 시 동작
- `BudgetOpt로 이동`을 누르면 **같은 Slot의 BudgetOpt 2.0 시나리오 생성 화면 Step 2**로 이동함. 시나리오명·업종·브랜드·캠페인 기간·KPI(Step 1 값)와 총 예산, 컬렉션의 매체·상품이 프리필됨.
- 프리필 값은 모두 생성 화면에서 수정할 수 있음(정책서 7.2).
- 이동해도 이 큐레이션의 컬렉션은 그대로 유지됨.
- 컬렉션 중 BudgetOpt 2.0이 지원하지 않는 매체·상품은 **넘기지 않고 지원하는 것만 넘김**. 모달에서 별도로 안내하거나 이동을 막지 않으며, 넘긴 뒤의 상품 수·기간(최대 90일) 검사는 BudgetOpt 2.0 생성 화면의 규칙을 따름.
- **기획 의도**: 결과 화면에서 두 번 걸러 막지 않고 흐름을 이어 줌. BudgetOpt의 입력 규칙은 BudgetOpt 생성 화면이 단일 기준으로 안내함.

## 9. SpinX

> **범위 한정**: 이 섹션은 결과 화면에서의 SpinX 노출·인터랙션만 정의함. 프롬프팅·응답 생성·모델 연동은 별도 SpinX 문서 관할.

### 9.1 SpinX가 맡는 영역(정책서 8.1)

| 영역 | 화면 위치 | 비고 |
|---|---|---|
| 매체·상품 설명 | 목록 행의 상품 설명(6.3) | 결과 생성 시점에 확정된 문장 |
| 결론 구절·근거 | 목록 행의 결론 구절·근거(6.3), Best Match 카드 한 줄(4.2) | 같은 문장을 재사용 |
| 차트 해석 | 차트 하단(5.4) | 진입 시 자동 생성 |
| 결과 상담 | ActionDock 입력 바 + SpinX 패널(9.2~9.4) | 사용자가 질문할 때만 |

### 9.2 ActionDock
- 우하단 고정 공통 컴포넌트. 입력 바(메인) + ＋ 런처(보조).
- **입력 바**: placeholder 롤링 힌트(제안 질문을 일정 간격으로 순환, 마우스가 바에 있으면 멈춤). 입력창에 포커스하면 제안 질문이 바 위로 펼쳐짐. 제안 질문을 누르면 **입력창에 채워지고 자동 전송되지 않음**. 입력 후 Enter 또는 전송 버튼으로 SpinX 패널이 열리며 질문이 전송됨.
- **제안 질문(예시)**: 모두 결과 상담 범위(9.4) 안의 질문이어야 함.
  1. `매체·상품이 많이 걸러진 이유가 뭔가요?`
  2. `Best Fit 1위와 2위를 비교해 주세요`
  3. `Best Match는 왜 이 상품인가요?`
- **＋ 런처 액션**(Admin/Marketer만): `BudgetOpt 2.0으로 배분하기`(8.3 모달 열기, 컬렉션이 2개 미만이면 모달을 열지 않고 토스트로 8.2 보조 문구를 안내), `큐레이션 복제`(3.4.3 복제와 동일).
- SpinX 패널이 열려 있는 동안 ActionDock은 숨김.

### 9.3 SpinX 패널
- 우측에서 열리며 본문이 패널 폭만큼 밀림(BudgetOpt 2.0 결과 화면과 동일).
- 질문 전송 시 사용자 메시지가 쌓이고 SpinX 답변이 이어짐.
- **@멘션**: 입력창에서 `@`를 입력하면 결과 화면의 해석 대상 목록(Campaign Fit) 자동완성이 뜸. 선택하면 `@{이름} `이 삽입됨(BudgetOpt 2.0 결과 7.3과 동일 방식).

### 9.4 결과 상담 범위(정책서 8.5)

| 구분 | 답변 범위 |
|---|---|
| 큐레이션 결과 이해 | 적용된 조건, 후보 선정 과정, 선별 과정 단계별 기준 |
| 매체·상품 설명 | 개별 매체·상품의 특성과 선정 근거, 해당 Fit에 포함된 이유 |
| 매체·상품 비교 | 후보 간 특성·조건 충족 여부·적합도 평가 근거의 차이 |
| 기본 광고 지식 | 광고 용어·지표 등 일반 개념 |

**수행하지 않는 요청**(안내 문장은 SpinX 문서 관할, 아래는 방향만 정의): 조건 변경에 따른 결과 수정·재산출·추정 → 복제 후 조건을 수정해 재생성하도록 안내 / 매체·상품별 예산 배분 → BudgetOpt 2.0 이용 안내 / 예상 도달 산출 → Reach Caster 이용 안내 / 결과 밖 매체·상품 추천 → 확인할 수 없는 범위 안내 / 최종 조합의 정답 판정 → 검토 근거 설명으로 대체.

- **기획 의도**: 제안 질문이 수행하지 않는 요청을 부추기면 사용자가 거절 답변을 먼저 경험하므로, 제안 질문은 항상 수행 범위 안에서 만듦(V17).

### 9.5 공통 원칙(정책서 8.6)
- **근거 준수**: 확인 가능한 사실만 설명하고 데이터가 부족하면 한계를 안내함.
- **상대 표현**: 비교 대상을 명시하고 "높은 편"·"낮은 편"으로 설명하며, 과거 실적을 미래 성과로 보장하지 않음.
- **사용 기준**: 기존 SpinX 이용 권한·사용량·제한 정책을 따름. 자동 생성되는 결과 설명은 사용자 대화 사용량에서 제외함.

### 10.2 규칙별 상세

**V1 진입 상태**
- 조건: 목록에서 Pending·Processing·Error 행 클릭(AdCurator_CurationList_Spec.md 6.2).
- 기대 결과: 이동하지 않음. URL을 직접 입력해 들어온 경우의 처리는 15.1 Q3.
- 왜: 결과가 생성되지 않았거나 오류 상태이면 보여줄 결과가 없음(정책서 2.1.4).

**V2 편집 권한**
- 조건: Agency/Client.
- 기대 결과: 목록의 `+ 담기` 버튼, 컬렉션 빼기(×)·`저장`, BudgetOpt 연계 CTA, ActionDock ＋ 런처, 더보기 메뉴가 모두 **화면에 없음**(비활성 아님). 이미 담긴 항목은 `✓ 담았어요` 표시만 보이고 누를 수 없음.
- 왜: 외부 사용자의 오조작·권한 에러를 원천 차단(1.5).

**V3 컬렉션 최대 개수**
- 조건: 컬렉션 개수 = 30에서 담기지 않은 행의 `+ 담기`를 누름(경계: 29 → 담기 가능 / 30 → 차단 / 30에서 1개 빼면 다시 담기 가능).
- 에러 메시지: `컬렉션에는 최대 30개까지 담을 수 있습니다.` (신규 문구. ui-validation-message-policy 6-1 "최소 {N}개 이상" 패턴의 상한 버전)
- 표시 위치: 토스트 + 비활성 담기 버튼 hover 안내
- 검증 타이밍: 클릭 시
- 왜: 정책서 6.2.2 최대 30개 + BudgetOpt 2.0 상품 상한 30개와 일치.

**V4 중복 금지**
- 조건: 이미 담긴 매체·상품의 `✓ 담았어요`를 누름.
- 기대 결과: 중복으로 담기지 않고 컬렉션에서 빠짐(토글).

**V5 저장**
- 조건: Admin/Marketer가 `저장`을 누름(버튼은 현재 컬렉션 ≠ 저장된 컬렉션일 때만 활성).
- 기대 결과(성공): 현재 컬렉션 전체가 저장되고 토스트 `컬렉션을 저장했습니다.`, 버튼 비활성, `저장하지 않은 변경 사항이 있습니다.` 사라짐.
- 에러 메시지(실패): `컬렉션 저장 중 일시적인 오류가 발생했습니다.` (ui-validation-message-policy 6-2 "실패" 패턴). 화면의 컬렉션은 되돌리지 않고 버튼은 활성 유지.
- 경계: 담았다가 다시 빼서 저장된 상태와 같아지면 버튼 비활성 / 다른 사용자가 먼저 저장했어도 마지막 저장이 덮어씀.

**V6 검색**: 6.6의 규칙(부분 일치, 대소문자 무시, 트리밍, 실시간, Best Fit·Good Fit 두 구역 범위)이 기대 결과임.

**V7 필터 조합**
- 조건: 매체 [Meta, Google Ads] 선택 + `프로모션 있는 것만` ON → (Meta 또는 Google Ads) AND 프로모션 있음.
- 배지 숫자 = 선택 매체 수 + ON 스위치 수(예: 매체 2 + 프로모션 ON → 3).

**V8 더 보기**: Best Fit 목록과 Good Fit 구역이 각각 독립적으로, 표시 수 10 → 클릭 시 20 → … 남은 개수가 10 미만이면 `{남은 개수}개 더 보기`. 모두 표시되면 버튼 없음.

**V9 결과 없음**
- 문구: `조건에 맞는 매체·상품이 없습니다.` + `필터 초기화` 링크.
- 링크 클릭 시 검색어·필터가 모두 해제되고 전체 목록이 표시됨.

**V10 프로모션 표시 조건**
- 조건: 프로모션 포함 AND 캠페인 기간과 하루 이상 겹치는 프로모션이 존재(경계: 겹침 0일 → 미표시 / 하루 → 표시).
- 기대 결과: 상품명 옆 `프로모션 있음`, 클릭 시 상품 팝업(6.10)의 프로모션 영역.

**V11 미포함 비노출**
- 조건: 프로모션 미포함으로 생성.
- 기대 결과: `프로모션 있음`, 팝업의 프로모션 영역, 필터의 프로모션 그룹, 안내 툴팁의 프로모션 문장이 없고, 헤더는 `프로모션 미포함`을 표시. 행 레이아웃은 포함일 때와 같음.

**V12 CTA 활성 개수**
- 조건: 컬렉션 개수 0 또는 1(경계: 1 → 비활성 / 2 → 활성 / 30 → 활성).
- 기대 결과: 버튼 disabled + 보조 문구 `컬렉션에 2개 이상 담으면 이어갈 수 있습니다.` ActionDock `BudgetOpt 2.0으로 배분하기`를 눌러도 모달이 열리지 않고 같은 문구를 토스트로 안내.

**V13 총 예산 필수**
- 조건: 미입력 또는 0.
- 에러 메시지: `총 예산을 입력해 주세요.` (BudgetOpt 2.0 시나리오 생성 V1과 동일 문구)

- 숫자만 허용(비숫자 무시), 천 단위 콤마 자동, **최대 11자리(999억)** — 12자리째 입력은 차단, 소수점 불가.

- 에러 메시지: `KPI를 선택해 주세요.` (BudgetOpt 2.0 시나리오 생성과 동일 문구)
- 표시 위치: KPI 선택 그룹 하단.

**V16 해석 생성 실패**: 5.4의 실패 문구 2개를 원문대로 표시, "이어서 질문하기"·타이핑 효과 미노출.

**V17 제안 질문 범위**: ActionDock 제안 질문 구성 시 9.4의 "수행하지 않는 요청"에 해당하는 질문(예산 배분·도달 산출 등)을 포함하지 않음.

**V18 대안 카드 표시 조건**
- 조건: 같은 업종 집행 1등(Industry Favorite 후보)과 평가 KPI 효율 1등(Top Performer 후보)을 **Best Fit 안에서** 각각 구함.
- 기대 결과: 1등이 Best Match와 **다른 상품**이면 해당 대안 카드를 표시. **같은 상품**이면 대안 카드를 만들지 않고 Best Match 카드에 `{관점명}에서도 1등입니다.`를 표시.
- 경계: 데이터 산출 불가 관점은 카드·문구 모두 제외 / 동점은 목록 순위가 앞선 상품이 1등 / 카드는 항상 2~3개(1개가 되는 경우는 산정에서 발생하지 않음).
- 왜: 정답은 하나로 두고, 실제로 다른 선택지가 있을 때만 대안을 보여 같은 상품의 반복과 정답 흐림을 막음(4.1).

**V19 대안 카드 병합**
- 조건: Industry Favorite 후보와 Top Performer 후보가 같은 상품이고 그 상품이 Best Match가 아님.
- 기대 결과: 카드 1개에 라벨 `Industry Favorite · Top Performer`를 함께 표시하고 한 줄 설명을 두 문장으로 이어서 표시. 카드 총 개수는 2개(Best Match + 병합 카드).

**V20 막대 높이·정렬·그린**
- 조건: Best Fit 매체·상품별 평가 축 점수(막대는 단순 합)와 결과로 제공된 종합 적합도 순위.
- 기대 결과: 막대 높이가 단순 합에 비례(0에서 시작)하고 단순 합 내림차순으로 왼쪽부터 정렬됨. 그린은 종합 적합도 1위(Best Match, 목록 1위)인 막대 하나이며 이름 필 `Best Match · 이번 캠페인 1위`가 붙음. 막대 hover 시 `이번 캠페인 {n}위`가 목록 순위와 같음.
- 경계: Best Match가 단순 합 1위이면 그린이 맨 왼쪽 / 아니면 그린이 맨 왼쪽이 아닌 자리에 있음(정상) / 단순 합이 같으면 목록 순위가 앞선 상품이 왼쪽 / 모든 막대의 칸 순서가 같음.
- 왜: 일반적인 점수 순서와 이번 캠페인 기준의 정답을 한 차트에서 함께 보여, 캠페인에 맞춘 평가라는 차별점을 형태로 전달함.

**V21 Best Fit 개수 요약**
- 조건: 결과 화면 진입.
- 기대 결과: Curation Highlights 맨 위에 `Best Fit` / `이번 캠페인에 닿은` / `{Best Fit 수}개` / `전체 매체·상품 {전체 풀}개 중에서 골랐어요`가 표시됨. 숫자는 정수·천 단위 콤마. 검색·필터·컬렉션 조작·Good Fit 펼침으로 값이 바뀌지 않음. 카드 수(2~3)에 포함하지 않음.
- 경계: Best Fit 1개 → `1개` / 전체 풀 1,000 이상 → `1,000` 형식 / Best Fit 0개는 발생하지 않음(4.1).
- 왜: 많은 선택지 중 몇 개가 이 캠페인에 닿았는지를 가려낸 과정 없이 규모감으로만 전달하기 위함.

**V22 Good Fit 구역**
- 조건: Good Fit 개수 확인(경계: 0 → 구역 없음 / 1 → 접힌 구역 표시).
- 기대 결과: 1개 이상이면 Best Fit 목록 아래에 접힌 상태로 `이런 선택지도 있어요` 헤더(`Good Fit {N} · 참고해 보면 좋아요`, `펼치기 ↓`)를 표시. 헤더를 누르면 펼쳐지고(`접기 ↑`) 다시 누르면 접힘. 펼치면 10개 표시 + 더 보기 10개씩. 접었다 펼치면 처음 10개로 돌아가고 새로고침하면 접힌 상태. 검색·필터가 함께 적용되고 적용 중이면 헤더에 ` · {M}개 일치`.
- 왜: 먼저 검토할 대상(Best Fit)과 참고용(Good Fit)의 비중을 구분하되, 선택지를 넓히고 싶은 사용자가 한 번의 클릭으로 볼 수 있게 함.

**V23 행 문구 길이·형식**
- 조건: Best Fit 행에 표시되는 문구(공백 포함 글자 수 기준).
- 기대 결과: 상품 설명은 30자 이내의 명사구이고 마침표가 없음(경계: 30자 → 허용 / 31자 → 규칙 위반). 결론 구절은 15~25자(경계: 14자·26자 → 규칙 위반, 15자·25자 → 허용). 근거는 1~2문장이고 결론 구절과 합쳐 150자 이내(경계: 150자 → 허용 / 151자 → 규칙 위반)이며 캠페인 입력값(업종·목적·기간·소재 등) 중 하나 이상과 연결됨. 이유 문구는 해요체. 같은 라벨의 상품 설명은 같은 문장.
- 경계: 근거가 3문장 이상이면 규칙 위반 / 입력값 연결이 없으면 규칙 위반. 위반 문구의 처리는 15.1 Q8.
- 왜: 한 줄 안에서 훑어 읽히도록 길이를 제한하고, 근거가 캠페인과 무관한 상투 문장이 되지 않게 함.

**V24 속성 표시**
- 조건: 상품 팝업의 속성 영역(6.10.2).
- 기대 결과: 구매·과금 → 소재 형식 → 타게팅 지원 → 추천 타겟 → 디바이스 → 보장 형태 → 최소 집행 금액 순서로, 값이 있는 항목만 행으로 표시. 값이 없는 항목은 행 자체가 없음(경계: 7개 모두 없음 → 영역 없음). 생성 Step 2 속성 기준과 맞는 항목에는 `✓`, 완화로 제외된 조건의 항목에는 `조건 완화`. 노출 지면은 속성 행에 없음.
- 경계: 보장 형태는 보장형이 아니면 표시하지 않음 / 타게팅의 데모는 `연령 · 성별`로 풀어서 표시 / ✓가 하나도 없으면 범례 한 줄도 없음.
- 왜: 빈 값을 채우려 자리를 차지하지 않고 확인할 수 있는 정보만 보여 팝업이 길어지지 않게 함.

**V25 레이더 표시**
- 조건: 상품 팝업 열기(Best Fit 상품 / Good Fit 상품).
- 기대 결과: Best Fit 상품에는 평가 축 전체(5개 또는 6개)의 레이더가 이 상품(면)과 Best Fit 평균(점선)으로 표시되고 축 이름만 라벨로 있음. 해석 문구·툴팁·점수 숫자가 없음. Good Fit 상품에는 레이더가 없음.
- 경계: 이 상품이 Best Match이면 면이 그린 계열, 그 밖에는 무채색.
- 왜: 도형 비교만으로 읽히는 차트에 해석을 덧붙이지 않고, 참고용인 Good Fit은 근거 문장으로 충분하게 함.

**V26 미저장 이탈**
- 조건: 저장하지 않은 컬렉션 변경이 있는 상태에서 다른 메뉴·목록 이동, 새로고침, 탭 닫기.
- 기대 결과: 플랫폼 공통 이탈 확인 표시. 확인 → 이동하고 변경은 사라짐 / 취소 → 화면에 남음.
- 경계: 변경이 없거나 저장 후 → 확인 없이 이동 / BudgetOpt로 이동 → 확인 없이 현재 컬렉션을 넘기고 이동.

## 11. 인터랙션 플로우

### 11.1 정상 플로우
1. 큐레이션 목록에서 Completed 행 클릭 → 결과 화면. 막대 차트가 올라오는 모션 뒤에 SpinX 해석이 타이핑됨.
2. 좌측 카드로 결론(Best Match 등)을 확인하고, 카드의 상품명을 눌러 목록의 해당 행으로 내려감.
3. 목록에서 결론 구절과 근거를 읽고, 프로모션이 있으면 `프로모션 있음`을 눌러 상세 확인. 필요하면 검색·필터로 좁힘.
4. 마음에 드는 매체·상품의 `+ 담기`를 눌러 컬렉션에 담음(우측 패널에 쌓임). 다른 사람과 공유하거나 나중에 다시 보려면 `저장`을 누름.
5. 컬렉션이 2개 이상이 되면 CTA 활성 → `BudgetOpt로 이어서` → 모달에서 총 예산·KPI 입력 → `BudgetOpt로 이동` → BudgetOpt 2.0 시나리오 생성 Step 2(프리필).

### 11.2 에러·경계 플로우
1. 컬렉션 30개에서 추가 담기 → `+ 담기` 비활성 + 안내 토스트. 하나를 빼면 다시 담을 수 있음.
2. 컬렉션 저장 실패 → 화면의 컬렉션은 그대로이고 오류 토스트. 다시 저장할 수 있음.
3. 모달에서 총 예산을 비우거나 KPI를 고르지 않으면 이동 버튼이 비활성이며 필드 아래에 에러 문구가 표시됨.
4. SpinX 해석 생성 실패 → 차트 아래에 실패 문구(차트·수치는 정상). 새로고침하면 다시 시도.

### 11.3 프로모션 미포함 큐레이션
1. 헤더에 `프로모션 미포함` 표시. 목록 행에는 `프로모션 있음`이 없고 필터에는 프로모션 그룹이 없음. 나머지 화면은 포함 큐레이션과 동일.

### 11.4 외부 사용자(Agency/Client)
1. Shared Slot 진입 → 결과 조회·검색·필터·공유(Copy Link, Export to Excel)·SpinX 질문만 가능.
2. `+ 담기` 버튼, 컬렉션 빼기, CTA, ＋ 런처, 더보기 메뉴는 화면에 없음. 이미 담긴 항목은 담김 표시로 확인.

## 12. 검증 포인트 (TC 도출)

**진입·권한**
- Completed 행 클릭 시 결과 화면(/adcurator/curation/{id}/result)으로 이동하는가. Pending/Processing/Error 행은 이동하지 않는가.
- Admin/Marketer로 진입 시 더보기 메뉴, `+ 담기` 버튼, 빼기(×), CTA, ＋ 런처가 모두 보이는가.
- Agency/Client로 진입 시 위 요소가 모두 **화면에 없는가**(비활성이 아님). 공유 메뉴·정보 툴팁·SpinX 입력 바는 보이는가. 이미 담긴 항목이 `✓ 담았어요` 표시로 보이고 누를 수 없는가.

**헤더**
- 헤더가 한 줄(큐레이션명 / 메타 요약 / 세로 구분선 / 공유·정보·더보기)로 구성되어 BudgetOpt 2.0·Reach Caster 결과 헤더와 같은 위치·형식인가. 솔루션 뱃지가 없고, 큐레이션명이 길면 말줄임으로 한 줄을 유지하는가.
- 메타 요약이 `•`로 연결되고 `업종 → 기간 → 목적 → 프로모션 → 상세 조건` 순서인가. 각 항목이 "라벨 + 값" 형식인가.
- 브랜드를 선택해 만든 큐레이션은 `업종 {브랜드} / {업종}`, 업종을 직접 선택한 큐레이션은 `업종 {업종}`으로 표시되는가.
- 기간이 `기간 yyyy-mm-dd → yyyy-mm-dd` 형식인가.
- 목적이 1개면 `목적 {목적명}`, 2개 이상이면 `목적 {대표 목적} 외 {N-1}`로 표시되는가(예: [전환, 인지] → "인지 외 1", 4개 → "인지 외 3"). 대표 목적이 선택 순서와 무관하게 고정 순서(인지 → 조회 → 트래픽 → 전환)의 첫 번째인가. 2개 이상일 때 hover/포커스 시 전체 목적이 고정 순서로 항목 아래쪽 툴팁에 표시되고, 1개일 때는 툴팁이 없는가.
- 프로모션이 `프로모션 포함` / `프로모션 미포함`으로 표시되는가.
- 상세 조건이 1개 이상일 때만 `상세 조건 {N}개` + 돋보기가 표시되고, 0개면 항목 자체가 없는가. 같은 항목의 포함·제외가 1개로 집계되는가. 돋보기 클릭 시 "큐레이션에 반영된 조건" 모달이 열리고 닫기·오버레이·Esc로 닫히는가(모달 상세는 아래 "반영된 조건 모달").
- 완화된 조건이 있을 때만 헤더 아래에 안내 줄 `상세 조건 {N}개를 완화해 매체·상품을 확보했습니다.`가 표시되고(경고색이 아닌 muted 톤), 없으면 줄 자체가 없는가. 링크 `어떤 조건인지 보기`가 헤더 돋보기와 같은 모달을 여는가.

**반영된 조건 모달**
- 모달에 기본 정보(업종·캠페인 기간·캠페인 목적·프로모션)와 상세 설정(속성 기준·특성 기준)이 읽기 전용으로 표시되고, 큐레이션명·설명은 없는가. 삭제(×)·편집 요소가 없는가.
- 업종이 헤더와 같은 표기(`{브랜드} / {업종}` 또는 `{업종}`)이고, 기간이 `yyyy-mm-dd → yyyy-mm-dd`이며, 목적이 선택 순서와 무관하게 고정 순서·가운뎃점으로 나열되는가.
- 속성 기준·특성 기준 그룹 헤더의 숫자가 항목 수이고, 두 숫자의 합이 헤더 `상세 조건 {N}개`의 N과 같은가. 같은 항목의 포함 행·제외 행이 1개로 집계되는가. 항목이 없는 그룹이 표시되지 않는가.
- 행이 왼쪽 값 / 오른쪽 조건 이름(muted)으로 표시되고, 복수 값이 가운뎃점으로 결합되며(예: `YouTube · 네이버 메인`), 제외 조건이 `{값} 제외` 별도 행이고, 예산이 `{금액}만 원`(천 단위 콤마)인가. 행 순서가 카탈로그 순서인가.
- 완화가 있는 큐레이션에서 완화로 제외된 행이 muted 톤 + `완화로 제외`로 표시되고 하단에 `매체·상품이 0개가 되지 않도록, 영향이 가장 적은 상세 조건을 제외했습니다.`가 표시되는가. 완화가 없으면 둘 다 없는가. 완화 안내 줄의 N이 `완화로 제외` 행의 항목 수와 같은가.
- Share 클릭 시 `Copy Link`, `Export to Excel` 2개만 표시되고 PDF 항목이 없는가. Copy Link 클릭 시 URL이 복사되고 `링크가 복사되었습니다.`가 표시되는가.
- Export to Excel 시 파일명이 `AC_Curation_Result_yyyymmdd`(오늘 일자)인 .xlsx로 다운로드되는가.
- Info hover 시 설명·Curation ID(#{id})·생성일시(아래 줄에 생성자와 마스킹된 이메일)·완료일시가 표시되고 날짜가 yyyy-mm-dd hh:mm:ss 형식인가. 설명이 없는 큐레이션에서 설명 항목이 표시되지 않는가.
- More 메뉴가 Admin/Marketer에게만 보이고 Agency/Client에게는 아이콘 자체가 없는가. 복제 클릭 시 프리필된 큐레이션 생성 Step 1로 이동하고 큐레이션명이 `(복제) {원본명}`, 캠페인 기간이 비어 있는가.
- 삭제 확정 시 성공 토스트 후 약 1.5초 뒤 목록으로 이동하는가. 취소 시 화면이 그대로인가.

**Curation Highlights**
- Best Match 카드가 항상 1개 표시되고 Best Fit 중 종합 적합도 1위(목록 1위)와 같은 상품인가. Best Match 타일만 muted 배경이고 그린이 Best Match 상품명 밑줄 한 곳뿐인가.
- 개수 요약과 카드가 2×2 타일(좌상 개수 요약, 우상 Best Match, 아래 대안)로 표시되는가. 카드가 2개이면 마지막 타일이 두 칸을 쓰는가. 상품명·한 줄 설명이 2줄을 넘으면 말줄임되고 hover 시 전체 문구가 보이는가. 아이콘에 배경이 없는가.
- 좌상 타일에 개수 요약(`Best Fit` / `이번 캠페인에 닿은` / `{N}개` / `전체 매체·상품 {전체 풀}개 중에서 골랐어요`)이 표시되고 카드 수(2~3)에 포함되지 않는가. 숫자가 천 단위 콤마이고 검색·필터·컬렉션 조작·Good Fit 펼침으로 바뀌지 않는가. 그린·hover·클릭 동작·카운트 모션이 없는가(V21).
- 모든 카드의 후보 풀이 Best Fit인가(Good Fit 항목이 어떤 카드에도 선정되지 않는가). 한 줄 설명에 비교 대상(`Best Fit 중`)이 명시되는가.
- 같은 업종 집행 1등이 Best Match와 **다른 상품**이면 Industry Favorite 카드가, **같은 상품**이면 카드 없이 Best Match 카드에 `같은 업종 집행에서도 1등입니다.`가 표시되는가. Top Performer도 같은 방식(`{평가 KPI} 효율에서도 1등입니다.`)인가.
- 두 관점의 1등이 서로 같은 상품(Best Match 아님)이면 카드 1개에 `Industry Favorite · Top Performer` 라벨이 함께 표시되는가(카드 총 2개).
- 어떤 관점의 데이터가 산출 불가일 때 그 관점의 대안 카드와 문구가 모두 없는가. 동점이면 목록 순위가 앞선 상품이 선택되는가.
- 카드 상품명 클릭 시 검색·필터가 초기화되고 해당 행으로 스크롤되어 일시 강조되는가. 해당 행이 11번째 이후여도 보이는 위치까지 펼쳐지는가.

**Campaign Fit**
- 차트 헤더가 한글 제목 `내 캠페인에 어떤 매체·상품이 잘 맞을까?` + 제목 옆 작은 영문 `Campaign Fit` + 아래 부제 `매체·상품별 다축 적합도 분석`로 표시되는가. 부제에 영문이 없는가.
- 차트에 평가 축 범례가 없는가. 막대 툴팁의 축 이름이 5개 또는 6개인가.
- 차트에 Best Fit 매체·상품마다 막대 1개가 표시되고 Good Fit이 표시되지 않는가. 막대 수가 Best Fit 수(최대 30)와 같은가.
- 막대가 점수 합 내림차순으로 왼쪽부터 정렬되고, 그린 막대가 위치와 관계없이 Best Match(목록 1위)이며 `Best Match · 이번 캠페인 1위` 이름 필이 붙는가(V20). 합이 같으면 목록 순위가 앞선 쪽이 왼쪽인가. 차트 아래에 `점수 합이 높은 순 →`가 표시되는가. 막대 hover 시 `이번 캠페인 {n}위`가 목록 순위와 같은가. 범례가 `캠페인 설명을 읽고 고른 평가 축`이고 칸이 범례 순서로 쌓이는가.
- 막대 높이가 0에서 시작해 점수 합에 비례하는가. 모든 막대에서 칸이 같은 축 순서로 쌓이고 색이 아니라 명도 단계로 구분되는가.
- Best Match 막대만 그린 계열이고 막대 위에 `Best Match` 이름 필이 붙는가. 나머지 막대(대안 카드의 상품 포함)가 무채색이고 표식이 없는가.
- 막대 hover/포커스 시 툴팁에 매체명·상품명·축별 `상위 {N}%`가 칸 색 견본과 함께 쌓인 순서대로 표시되고 다른 막대가 흐려지는가. 왼쪽 카드에 올리면 해당 막대가, 막대에 올리면 해당 카드가 서로 강조되는가.
- 막대를 클릭해도 이동·담기 등 어떤 동작도 일어나지 않는가. hover·키보드 포커스로는 툴팁이 표시되는가.
- 진입 시 막대가 바닥에서 올라오는 모션이 1회 재생되는가. "동작 줄이기" 설정에서는 모션 없이 최종 상태가 바로 표시되는가. 필터·검색·컬렉션 조작으로 재생되지 않는가.
- SpinX 해석이 타이핑되고, 끝난 뒤 `이어서 질문하기 →`가 나타나는가. 클릭 시 SpinX 패널이 열리고 입력창에 `@Campaign Fit `가 프리필되며 **전송되지 않는가**.
- 해석 생성 실패 시 `이 차트에 대한 SpinX 분석을 생성하지 못했습니다.` / `새로고침하거나 결과에 다시 들어오면 분석을 다시 시도합니다.`가 원문대로 표시되고 `이어서 질문하기`·타이핑 효과가 없는가.

**목록**
- Best Fit 구역 헤더에 `Best Fit {N}`과 캡션 `이번 캠페인을 위해 고른 최고의 상품들이에요`가 표시되고, 검색·필터를 적용해도 숫자가 바뀌지 않는가. 탭이 없고 Low Fit 구역이 없는가.
- 처음 10개가 표시되고 `{M}개 더 보기 · {표시} / {전체}`로 10개씩 추가되는가. 남은 개수가 10 미만이면 M이 남은 개수인가. 모두 표시되면 버튼이 사라지는가.
- 순위 번호가 그룹 내 순위이고, 필터·검색을 적용해도 번호가 유지되는가.
- Best Fit 행이 `순위` / `매체명(상품명 위 작은 글씨)` / `상품명(굵게)` / `상품 설명` / (`· 프로모션 있음`) / `결론 구절(굵게)` / `근거(옅게)` / `담기 상태`로 구성되는가. Best Match 행의 순위만 그린이고 나머지는 muted인가.
- 상품명이 카탈로그의 레디셋 광고상품명 원문 그대로 표시되고 길면 줄바꿈되는가. 상품명을 누르면 상품 팝업(6.10)이 열리고 상품명·`· 프로모션 있음` 이외의 행 영역을 눌러도 동작이 없는가.
- 상품 설명이 30자 이내 명사구이고 마침표가 없는가. 같은 라벨의 상품은 같은 설명인가. 결론 구절이 15~25자 해요체이고 굵게, 근거가 1~2문장 옅은 글씨이며 합쳐 150자 이내이고 캠페인 입력값 연결이 하나 이상인가(V23).
- Admin/Marketer: 행 오른쪽에 `+ 담기`가 있고 누르면 `✓ 담았어요`로 바뀌는가. Agency/Client: `+ 담기`가 없고 담긴 행에만 `✓ 담았어요`가 표시되는가.
- Good Fit 행에 강점과 낮게 평가된 부분이 함께 나오고 낮은 부분이 muted 톤인가. Best Fit 행은 강점만인가.
- Best Fit 목록 아래에 `이런 선택지도 있어요` 구역(`Good Fit {N} · 참고해 보면 좋아요`, `펼치기 ↓`)이 접힌 상태로 표시되는가. Good Fit이 0개이면 구역이 없는가(V22).
- 헤더를 누르면 펼쳐지고(`접기 ↑`) 다시 누르면 접히는가. 펼치면 10개가 표시되고 `더 보기`로 10개씩 추가되며, 접었다 펼치면 처음 10개로 돌아가는가. 새로고침하면 접힌 상태인가. 검색·필터가 이 구역에도 적용되고 헤더에 ` · {M}개 일치`가 붙는가. Good Fit 행의 `+ 담기`로 컬렉션에 담기·빼기가 되는가.
- 행에 프로모션 열이 따로 없고, 프로모션 있는 행만 상품 설명 뒤에 `· 프로모션 있음`이 있는가.
- `· 프로모션 있음` 클릭 시 상품 팝업이 열리고 프로모션 영역(프로모션명·기간·혜택·조건·이점)이 보이는가. 행 안에서 펼쳐지지 않는가.
- 팝업의 프로모션 영역 하단 문구와 원문 링크가 있고 링크가 새 탭에서 열리는가.
- 프로모션 미포함 큐레이션에서 `프로모션 있음`, 필터의 프로모션 그룹, 툴팁의 프로모션 문장이 없고 헤더가 `프로모션 미포함`인가. 행 레이아웃이 포함 큐레이션과 같은가.
- 캠페인 기간과 프로모션 기간이 겹치지 않는 매체·상품(경계: 겹침 0일)에 `프로모션 있음`이 없는가. 하루 겹치면 있는가.
- 검색: 매체명·상품명·상품 설명 일부(대소문자 무시)로 Best Fit·Good Fit 두 구역에서 함께 찾아지는가. 앞뒤 공백이 트리밍되는가. 공백만 입력하면 전체가 보이는가. 결론 구절·근거 문장 일부로는 검색되지 않는가.
- 검색 입력이 비어 있는 상태로 blur하면 버튼으로 축소되고, X로 검색어가 초기화되는가.
- 필터: 매체 선택(OR), `프로모션 있는 것만`, `담은 것만`이 그룹 간 AND로 적용되는가. 배지 숫자 = 선택 매체 수 + ON 스위치 수인가. 드롭다운에 매체별 개수(두 구역 합계)가 표시되는가. 프로모션 미포함 큐레이션에서 프로모션 스위치가 없는가.
- 필터·검색 결과 0건에서 `조건에 맞는 매체·상품이 없습니다.`와 `필터 초기화`가 표시되고, 클릭 시 전체가 복원되는가.
- 필터·검색이 적용 중일 때 Best Fit 헤더 아래에 `필터 {n}개 적용 · {N}개 표시` / `초기화`가 표시되는가.
- 안내 줄에 `선정 근거는 SpinX가 정리했습니다.`와 `생성 시점 기준 · yyyy-mm-dd`가 있고, Info hover 시 프로모션 포함·미포함에 따라 해당 툴팁 문구가 표시되는가.

**상품 팝업**
- 상품명 클릭 시 팝업이 열리고, `· 프로모션 있음` 클릭 시 같은 팝업이 프로모션 영역 위치로 열리는가. 팝업 위에 다른 팝업이 열리지 않는가. 닫기·오버레이 클릭·Esc로 닫히고 다시 열면 맨 위에서 시작하는가.
- Best Fit 상품은 `lg` 2열(왼쪽 레이더, 오른쪽 속성), Good Fit 상품은 `md` 1열(레이더 없음)인가. 본문이 길면 헤더·푸터는 고정되고 본문만 스크롤되는가.
- 헤더에 매체명·상품명·상품 설명이 행과 같은 값으로 표시되고 상품 설명에 노출 지면이 포함되는가.
- 속성이 구매·과금 → 소재 형식 → 타게팅 지원 → 추천 타겟 → 디바이스 → 보장 형태 → 최소 집행 금액 순서로 값 있는 항목만 표시되는가. 값이 없는 항목의 행이 없는가. 보장형이 아니면 보장 형태가 없는가. 타게팅이 `연령 · 성별 · 지역`처럼 구체 항목으로 표시되는가. 추천 타겟에는 ✓가 붙지 않는가(V24).
- 입력한 속성 기준과 맞는 항목에 `✓`가 있고 `✓ 내가 입력한 조건과 맞아요`가 표시되는가. 완화로 제외된 조건의 항목에 `조건 완화`가 표시되는가. 속성 영역이 비어 있으면 영역이 없는가.
- Best Fit 상품에 레이더(이 상품 면 + Best Fit 평균 점선, 축 5개 또는 6개, Campaign Fit 막대 칸과 같은 축 순서)가 표시되고 해석 문구·툴팁·점수 숫자가 없는가. Best Match 팝업만 면이 그린 계열인가. Good Fit 팝업에 레이더가 없는가(V25).
- 프로모션이 있는 상품에서 프로모션 영역(프로모션명·기간 한 줄 / 혜택 / 조건 / 이점 / 원문 링크 / 안내 문구)이 표시되고 없는 상품에서는 영역이 없는가. 겹치는 프로모션이 둘 이상이면 캠페인 기간과 겹치는 날이 가장 많은 1개만 표시되고, 같으면 시작일이 빠른 것이 표시되는가.
- Admin/Marketer에게 푸터의 `+ 담기` / `✓ 담았어요`가 있고 누르면 행의 상태와 컬렉션 패널이 함께 갱신되는가. Agency/Client에게는 담기 버튼이 없고 `닫기`만 있는가.

**컬렉션**
- `+ 담기`를 누르면 즉시 패널에 항목이 추가되고 `{n} / 30`과 진행 바가 갱신되는가. `✓ 담았어요` 또는 패널 ×로 즉시 빠지는가.
- 담기·빼기 후 저장하지 않고 새로고침·재진입하면 마지막으로 저장된 컬렉션으로 돌아가는가. `저장` 후에는 새로고침·재진입·다른 Admin/Marketer·Agency/Client 계정에서도 같은 컬렉션이 보이는가.
- `저장` 버튼이 변경이 있을 때만 활성이고, 담았다가 다시 빼서 저장 상태와 같아지면 비활성인가. 변경이 있으면 `저장하지 않은 변경 사항이 있습니다.`가 표시되는가. 저장 성공 시 `컬렉션을 저장했습니다.` 후 버튼이 비활성인가. Agency/Client에게 `저장` 버튼이 없는가.
- 저장하지 않은 변경이 있을 때 다른 메뉴 이동·새로고침·탭 닫기에서 이탈 확인이 표시되는가. BudgetOpt로 이동할 때는 확인 없이 현재 컬렉션이 넘어가는가(V26).
- 컬렉션 29개 → 담기 가능, 30개 → 담기지 않은 행의 `+ 담기`가 비활성이고 hover 시 `컬렉션에는 최대 30개까지 담을 수 있습니다.`가 표시되며 눌러도 담기지 않는가. 30개에서 1개를 빼면 다시 담을 수 있는가. 이미 담긴 행은 30개에서도 빼기가 되는가.
- `담은 것만` 필터가 켜진 상태에서 빼면 해당 행이 목록에서 사라지는가.
- 패널은 필터·검색과 무관하게 전체 컬렉션(Good Fit 항목 포함)을 보여주는가. 항목이 많으면 패널 목록 안에서만 스크롤되고 패널은 sticky인가.
- 빈 컬렉션 문구가 Admin/Marketer(`담은 매체·상품이 없습니다. 목록에서 담기를 누르면 이곳에 모입니다.`)와 Agency/Client(`담긴 매체·상품이 없습니다.`)에서 각각 다르게 표시되는가.
- 저장 실패(모의) 시 화면의 컬렉션이 그대로이고 `컬렉션 저장 중 일시적인 오류가 발생했습니다.`가 표시되며 버튼이 활성으로 남는가.
- 큐레이션 삭제 시 컬렉션도 함께 삭제되는가.

**BudgetOpt 2.0 연계**
- 컬렉션 0·1개에서 CTA가 disabled이고 `컬렉션에 2개 이상 담으면 이어갈 수 있습니다.`가 표시되는가. 2개·30개에서 활성인가. ActionDock 액션도 0·1개에서 모달을 열지 않고 안내하는가.
- 모달에서 시나리오명이 `(B/O-{큐레이션 ID}) {큐레이션명}`, 업종·기간·컬렉션 목록이 읽기 전용으로 프리필되는가. 브랜드를 선택해 만든 큐레이션은 브랜드도 승계되는가.
- 총 예산: 숫자만 입력되고 천 단위 콤마가 붙으며, 11자리까지 입력되고 12자리째는 차단되는가. 미입력(또는 0)이면 `총 예산을 입력해 주세요.`가 표시되는가.
- KPI 미선택이면 `KPI를 선택해 주세요.`가 표시되는가. 노출/클릭/조회/도달 중 1개만 선택되는가.
- 총 예산 > 0 AND KPI 선택 전에는 `BudgetOpt로 이동`이 비활성인가. 취소·Esc·오버레이 클릭 후 다시 열면 입력이 비어 있는가.
- 이동 시 BudgetOpt 2.0 생성 Step 2로 가고 시나리오명·업종·기간·KPI·총 예산·컬렉션 매체·상품이 프리필되며, 이 큐레이션의 컬렉션은 그대로 유지되는가. BudgetOpt 미지원 매체·상품은 안내·차단 없이 빠지고 지원 상품만 넘어가는가.

**SpinX**
- ActionDock 입력창에 포커스하면 제안 질문이 펼쳐지고, 누르면 입력창에 채워지고 **전송되지 않는가**. Enter 시 SpinX 패널이 열리고 본문이 밀리며 ActionDock이 숨겨지는가.
- 제안 질문에 예산 배분·도달 산출 같은 비수행 요청이 없는가.
- Agency/Client에서 ＋ 런처가 없고 입력 바만 있는가.
- 결과 진입 시 자동 생성된 해석이 사용자 대화 사용량에 반영되지 않는가.

## 13. 데이터 개념 및 용어 매핑

> 상세 타입은 구현 코드가 단일 진실 공급원임(`src/components/adcurator/types.ts`에 결과용 타입 추가 예정). 여기서는 규칙·플로우 이해에 필요한 개념과 용어 매핑만 정리함.

### 13.1 구조적 특징
- 결과는 **생성 시점 스냅샷**임(큐레이션 속성 + 선별 과정 단계 값 + 평가 축별 점수 + 적합도 그룹별 매체·상품 목록 + 왕중왕 카드 산정 결과 + SpinX 해석). 이후 다시 계산하지 않음.
- 적합도 그룹은 Best Fit·Good Fit만 화면에 노출함. Low Fit은 선별 과정 단계 값에만 영향을 주고 목록에는 포함되지 않음.
- 컬렉션은 결과와 **별도 데이터**이며 큐레이션당 1개임. `저장`을 눌렀을 때만 서버에 저장됨(마지막 저장 우선).

### 13.2 UI 용어 ↔ 데이터 개념

| UI 용어 | 데이터 개념 | 비고 |
|---|---|---|
| 결론 문구 | 고정 문구 | 데이터 아님. Curation Highlights 캡션(4.1) |
| 큐레이션명 / ID / 설명 | 큐레이션 속성 | 목록·생성 정의서와 동일 |
| 캠페인 목적 | 목적 배열(1~4개) | 표시는 고정 순서 |
| 프로모션 포함/미포함 | 프로모션 포함 여부(boolean) | 헤더·필터·행 표시를 결정 |
| 상세 조건 N개 / 속성 기준 · 특성 기준 | Step 2 선별 기준 항목 수(속성 기준 수 + 특성 기준 수, 같은 항목의 포함·제외는 1개) | 0개면 헤더 항목 미표시. 돋보기 → 반영된 조건 모달 |
| 완화된 조건 | 후보 선정 시 제외된 상세 조건 항목(입력한 항목 중 일부) | 0개면 안내 줄 미표시. 모달에서는 해당 행에 `완화로 제외` 표기 |
| 전체 풀 / 후보 선정 / 적합도 통과 / Best Fit | 선별 과정 4단계 값(정수). 3단계 = Best Fit 수 + Good Fit 수 | 전체 풀·Best Fit은 개수 요약(4.1)에 노출. 후보 선정·적합도 통과는 미노출. 정책서 4.4.2 정의 |
| 평가 축 / 축별 점수 / 종합 적합도 순위 | 결과로 제공되는 평가 축 목록(5개 또는 6개, 이름·표시 순서)과 매체·상품별 축 점수, 종합 적합도 순위(데이터사이언티스트 정의) | 막대 높이 = 축 점수 단순 합. 순위·Best Match는 종합 적합도 순위. 점수 원값은 노출하지 않음. 상위 N% 산출은 Q6 |
| Best Match / Industry Favorite / Top Performer | 카드별 선정 매체·상품 + 보조 값(집행 건수, 효율 지표) | Best Match는 항상, 나머지는 Best Match와 다른 상품일 때만 카드 생성. 산출 불가 관점은 제외(4.3) |
| Best Fit / Good Fit | 적합도 그룹 | Low Fit은 화면 미노출 |
| 순위 | 그룹 내 적합도 순위 | 점수 값은 노출하지 않음 |
| 상품 설명 | 상품 라벨 기반 설명(30자 이내 명사구) | 같은 라벨이면 같은 문장 |
| 결론 구절 / 근거 | 결론 구절 = 가장 강한 평가 축을 쉬운 말 사전으로 바꾼 문구, 근거 = 평가 축 결과 + 캠페인 입력값 + 상품 라벨로 만든 1~2문장(Good Fit은 낮게 평가된 부분 포함) | 생성 방식·주체는 Q8, Good Fit 규칙은 Q7 |
| 프로모션 있음 | 캠페인 기간과 겹치는 프로모션 존재 | 상세는 프로모션명·기간·혜택·조건·이점·원문 링크 |
| 컬렉션 | 큐레이션별 담은 매체·상품 목록(최대 30) | 불변성의 예외 |
| 평가 KPI / 효율 지표 | Top Performer 산정 기준 | 정책서 3.4 확정 후 매핑 |

## 14. 스타일·구현 지침

- 화면 고유 스타일은 **Tailwind 유틸리티 클래스**로 작성함. 막대 진입 모션처럼 Tailwind로 복잡한 경우에만 CSS Module을 쓰고, 인라인은 동적 값(막대 높이, 진행 바 비율)에만 씀(handoff-implementation-guide).
- `btn`, `input`, `card`, `dropdown`, `workspace-content`, `custom-scrollbar` 등 공통 클래스는 그대로 사용함.
- 색상은 디자인 토큰(`hsl(var(--...))`)만 사용함. 시그니처 그린은 `--bo-accent` 토큰이며 **정답 카드(Best Match)의 좌측 바와 차트의 Best Match 막대 두 곳**에만 씀. 에러는 `--destructive`.
- Primary 버튼은 프로덕트 표준 스펙(BOScenarioList의 New Scenario와 동일 pill)을 따름.
- 다이얼로그 크기는 ui-dialog-policy를 따름: 반영된 조건 `md`, BudgetOpt 간편 생성 `md`, 삭제·이동 `confirm`(기존 재사용).
- 같은 구조의 선례를 우선 재사용함: 헤더 액션(Reach Caster 결과), SpinX 해석 블록·원리 트리거 패턴(BudgetOpt 2.0 결과), 필터·검색·삭제·이동(AC 목록), ActionDock(common).
- 신규 컴포넌트는 `src/components/adcurator/`에 두고 접두사 `AC`를 씀.

### 15.2 구현 완료 후 문서 정합
화면정의서와 구현이 끝난 뒤 한 번에 처리함.

- 정책서 4.4·8.4: 시각화와 SpinX 차트 해석 대상을 퍼널에서 평가 축 점수 막대 차트(본 문서 5장)로 갱신. 4.4.2의 선별 과정 수치 중 화면 노출은 전체 풀·Best Fit뿐임을 반영.
- 정책서 6장: 컬렉션을 `저장`했을 때만 유지·공유하는 방식(본 문서 7.5)으로 갱신.

### 15.3 문구 톤 (문구 일관성 원칙)
- **결론 문구·섹션 캡션(Curation Highlights)·차트 질문 제목(Campaign Fit)·개수 요약·Good Fit 구역 문구·목록 행의 결론 구절·근거·CTA 카피**: 해요체 — BudgetOpt 2.0 결과 CTA 선례("…이어서 볼 수 있어요.").
