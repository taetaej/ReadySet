## 1. 화면 개요

### 1.1 기능 정의
생성이 완료된 큐레이션의 **결과를 확인하는 화면**임. 캠페인 조건에 맞춰 선별된 매체·상품을 적합도 그룹(Best Fit / Good Fit)으로 보여주고, 각 매체·상품의 선별 이유와 프로모션 정보를 제공함. 사용자는 검토하면서 마음에 드는 매체·상품을 **담고**, 간편 생성 다이얼로그에서 예산·KPI만 더 입력해 BudgetOpt 2.0 예산 최적화로 넘어갈 수 있음.

**기획 의도**
- 이 화면은 숫자를 나열하는 화면이 아니라 "이번 캠페인에 무엇이 맞는가"라는 **결론을 먼저 말하는 화면**임. 위에서 아래로 결론(Best Match 등 카드) → 근거(평가 축 점수 차트 + SpinX 해석) → 상세(목록의 선별 이유) → 다음 행동(담기 → BudgetOpt 2.0) 순서로 읽히게 함.
- 결과는 **생성 시점 기준으로 고정**되고 다시 계산하지 않음(정책서 4.2). 조건을 바꾸려면 복제 후 다시 생성해야 하므로, 화면은 "무엇이 어떤 조건으로 나온 결과인지"를 항상 확인할 수 있어야 함.
- 어려운 선별 과정(후보 선정 → 적합도 평가 → 그룹핑)은 차트와 SpinX 해석 뒤로 접어 두고, 사용자는 결론을 먼저 보고 필요할 때만 근거를 펼침.

### 1.2 문서 활용처
- **개발 참고**: 프론트엔드 구현 시 화면 동작·규칙·표기 기준 문서로 활용됨.
- **제품 Docs**: 본 정의서의 기능 설명·의도가 사용자 대상 기능 문서의 기반이 됨.
- **AI 기반 TC 생성**: 규칙 요약(Section 10)과 검증 포인트(Section 12)가 테스트 케이스의 원천 데이터가 됨. 각 규칙은 조건 → 기대 결과로 검증 가능하게 작성함.

### 1.3 진입 경로
- 큐레이션 목록에서 **Completed** 상태 행 클릭(AdCurator_CurationList_Spec.md 6.2)
- SNB의 Ad Curator 트리에서 완료된 큐레이션 클릭, 슬롯 홈 Ad Curator 컬럼의 결과물 클릭
- URL: /adcurator/curation/{id}/result
- **진입 조건**: 처리 상태가 Completed인 큐레이션만 결과를 열 수 있음. Pending·Processing·Error는 목록·SNB에서 진입이 막힘(V1).
- 이 화면에서 이어지는 곳: BudgetOpt 2.0 시나리오 생성(Section 8), 큐레이션 복제(큐레이션 생성 화면 Step 1, 프리필), 큐레이션 목록(삭제·이동 후)

### 1.4 화면 구조 (세로 흐름)
헤더(큐레이션명 · 메타 요약 · 액션 아이콘, 한 줄 — 다른 솔루션 결과 화면과 동일 구성)
→ (조건부) 조건 완화 안내 줄
→ 상단 2분할: 좌 **Curation Highlights**(가로형 카드 2~3개, 세로 스택) / 우 **Curation Fit**(평가 축 점수 막대 차트 + SpinX 해석)
→ 목록: `Best Fit List` 구역 + 접이식 `Good Fit List` 구역
→ 다음 단계 CTA(BudgetOpt 2.0 연계 → 간편 생성 다이얼로그)
→ 우하단 ActionDock(SpinX 입력 바 + 컨텍스트 액션)

- 공통 레이아웃(AppLayout, Breadcrumb)과 권한 매트릭스는 공통 정의서를 따름. 이 문서는 결과 화면 고유 규칙만 다룸.

### 1.5 역할별 노출

공통 권한 매트릭스를 따라 큐레이션 목록과 같은 기준을 적용함(AdCurator_CurationList_Spec.md 1.5).

|---|---|---|
| 결과 조회(헤더·카드·차트·목록·상품 팝업·속성 조건 모달) | 가능 | 가능 |
| `Good Fit List` 펼치기 · 검색 · 필터 · 더 보기 | 가능 | 가능 |

- **기획 의도**: 외부 사용자는 결과 열람과 공유만 하게 하고, 데이터를 바꾸는 진입점은 비활성이 아니라 **미노출**로 처리해 "왜 못 누르지?"라는 혼란을 없앰(목록 화면과 동일 원칙). 담기·BudgetOpt 연계는 BudgetOpt 시나리오 생성으로 이어지므로 외부 사용자 노출을 따로 정해야 함(Q9).

### 2.2 영역별 의도
- **상단 2분할(좌 카드 / 우 차트)**: Reach Caster 결과 화면의 "좌 스코어카드 + 우 차트" 구성과 같은 패턴임. 좌측에서 결론을, 우측에서 그 근거를 한 시선 안에서 확인하게 함. 폭 비율은 **좌 5 : 우 7**이며, 막대 수가 많은 차트에 폭을 더 줌. 긴 상품명이 있어도 비율은 밀리지 않음.
- **높이 기준은 왼쪽 카드 묶음**임. 오른쪽 차트 열은 높이 계산에서 빠지고, 왼쪽 묶음 높이 안에서 차트가 남는 높이를 모두 씀(최소 높이 보장). 정렬 규칙은 5.5.
- **목록**: 행마다 무엇(상품) → 왜(선별 이유) → 담기를 한 줄에 둠. 두 구역의 제목 위계를 같게 맞춰 구조가 한눈에 보이게 함(6.1).
- **다음 단계 CTA**: 목록 맨 아래에 1px 구분선으로 정보와 행동을 끊고 BudgetOpt 2.0으로 넘어가는 이유를 한 줄로 말함(8장, BudgetOpt 2.0 결과의 Reach Caster CTA와 같은 구성·여백). 왼쪽 정렬해 우하단 ActionDock과 겹치지 않게 함. 버튼은 간편 생성 다이얼로그를 엶(8.3).
- **ActionDock**: BudgetOpt 2.0·Reach Caster 결과 화면과 같은 공통 컴포넌트(`ActionDock`). 우하단 고정이므로 화면 우측 끝에 다른 액션을 붙이지 않음.
- **SpinX 패널**: 열리면 본문이 우측 패널 폭만큼 밀리고 ActionDock은 숨김(BudgetOpt 2.0 결과 화면과 동일).

## 3. 헤더

한 줄 레이아웃으로 좌→우: 큐레이션명 / 메타 요약(인라인) / 세로 구분선 / 액션 버튼.

- **기획 의도**: 결과 화면은 솔루션이 달라도 "이름 → 조건 → 액션"을 같은 자리에서 읽을 수 있어야 사용자가 헤더를 솔루션마다 다시 학습하지 않음.

### 3.1 큐레이션명

| 요소 | 내용 / 스타일 (의도) |
|---|---|
| 텍스트 | 큐레이션명 (제목급·medium, Paperlogy) |
| overflow | 한 줄 말줄임(ellipsis). hover 시 전체 이름을 툴팁(title)으로 보여 줌 |
| 솔루션 뱃지 | 두지 않음. 솔루션은 Breadcrumb으로 구분함 |

### 3.2 메타 요약 (인라인)

BudgetOpt 2.0 결과 헤더와 같은 형식임: 각 항목은 `•` 구분자로 연결하고, muted 톤 소형 텍스트로 "라벨(medium) + 값" 형식으로 표시함. 칩·뱃지 형태로 만들지 않음. 순서는 업종 → 기간 → 목적 → 속성 조건 → 특성 조건.

| 항목 | 라벨 | 값 | 표시 조건 · 동작 |
|---|---|---|---|
| 업종 | 브랜드를 선택해 만든 큐레이션: `브랜드/업종`, 업종을 직접 선택한 큐레이션: `업종` | `{브랜드} / {업종}` 또는 `{업종}` | 항상 |
| 기간 | `기간` | `{yyyy-mm-dd} → {yyyy-mm-dd}` (캠페인 기간) | 항상 |
| 목적 | `목적` | 선택한 목적 **전체**를 "인지 → 조회 → 트래픽 → 전환" 고정 순서로, 구분은 ` / ` (예: `인지 / 조회 / 트래픽`). 줄임·툴팁 없음 | 항상 |
| 속성 조건 | `속성 조건` | `{N}개` + `SearchCheck` 돋보기 | N > 0일 때만. 돋보기를 누르면 속성 조건 모달(3.3) |
| 특성 조건 | `특성 조건` | `{N}개` (개수만, 동작 없음) | N > 0일 때만. 0이면 항목 자체가 없음 |

- **N**: 큐레이션 생성 Step 2에서 입력한 기준 항목 수. 속성 조건 = 속성 기준 항목 수, 특성 조건 = 특성 기준 항목 수. 같은 항목의 포함·제외는 1개로 셈(AdCurator_CurationCreate_Spec.md 4.8과 동일). 완화로 제외된 항목도 입력한 항목이므로 N에 포함됨.
- 프로모션 포함 여부는 헤더에 표시하지 않음(v1.2에서 제거). 포함 여부는 목록의 `· 매체 프로모션`·`필터` 버튼 노출과 생성 시점 기준 툴팁 문구로 드러남.
- **기획 의도**: 결과 화면 헤더를 솔루션마다 같은 형식으로 맞춰 다시 학습할 것이 없게 함. 목적은 이 큐레이션의 평가 축을 정하는 핵심 입력이라 줄이지 않고 모두 보여 줌. 속성 조건은 결과를 거른 기준이라 돋보기로 내용을 확인할 수 있게 하고, 특성 조건은 순위에만 반영되므로 개수만 보여 줌.

### 3.3 조건 완화 안내(조건부)와 속성 조건 모달

**조건 완화 안내 줄**

| 항목 | 규칙 |
|---|---|
| 노출 조건 | 후보 선정 결과가 0개여서 상세 조건 일부가 제외된 큐레이션(정책서 3.3.1)에만 표시. 완화가 없으면 줄 자체를 표시하지 않음(빈 자리 없음) |
| 위치 | 헤더 바로 아래 본문 최상단 한 줄 |
| 구성 | `Info` 아이콘(muted) + `모든 조건을 충족하는 매체·상품이 없어 조건 {N}개를 제외하고 선별했습니다.` + 텍스트 링크 `제외한 조건 보기`. {N}은 완화로 제외된 항목 수(속성·특성 합계) |
| 톤 | 오류가 아니라 정책에 따른 정상 처리 결과이므로 경고색(destructive)을 쓰지 않음 |
| 링크 동작 | 헤더 `속성 조건 {N}개` 돋보기와 **같은 모달**을 엶 |

**속성 조건 모달** (`md` 크기, ui-dialog-policy. 제목·버튼 영역은 고정하고 본문만 스크롤)

| 영역 | 내용 |
|---|---|
| 제목 | `속성 조건` |
| 설명 | `큐레이션을 만들 때 입력한 속성 조건입니다. 생성 시점 기준으로 고정됩니다.` |
| 완화 알림 | 완화로 제외된 속성 조건이 있을 때만 표 위에 알림 상자(Info 아이콘 + 옅은 회색 상자, 생성 Step 2 단계 안내와 같은 형식): `모든 조건을 충족하는 매체·상품이 없어, 결과에 영향이 가장 적은 조건을 제외하고 선별했습니다.` |
| 표 | 열 헤더 `기준명` / `항목`. 속성 기준만 표시(특성 기준은 표시하지 않음) |
| 버튼 | `확인` 1개(primary, 공통 다이얼로그 하단). 오버레이 클릭·Esc도 닫힘 |

**행 표기 규칙** (읽기 전용, 삭제·편집 없음)

| 항목 | 규칙 |
|---|---|
| 기준명 | 조건 이름(muted, 예: `매체·지면`) |
| 항목 | 조건 값. 복수 값은 가운뎃점으로 결합(예: `동영상 · 이미지`). 제외 조건은 포함 조건과 **별도 행**으로 `{값} 제외`(예: `네이버 메인 제외`). 예산은 `{금액}만 원`(천 단위 콤마, 예: `3,000만 원`) |
| 행 순서 | 사용자가 고른 순서와 무관하게 조건 정의(카탈로그) 순서. 같은 항목은 포함 행 → 제외 행 |

- **기획 의도**: 결과를 거른 기준(속성 조건)을 "내가 넣은 값"과 같은 표기로 다시 보게 해, 결과가 어떤 조건으로 나왔는지 확인하게 함. 완화는 결과가 입력과 다르게 나왔다는 뜻이라 헤더 아래 안내 줄과 모달 알림 두 곳에서 같은 말로 알려 놓치지 않게 함.

## 4. Curation Highlights (왕중왕 카드, 2~3개)

### 4.1 구성
- 섹션 제목 "Curation Highlights"(영문 h3 제목 규칙, BudgetOpt 2.0·Reach Caster 결과와 동일). 제목 아래에 캡션을 두지 않음.
- 카드는 **세로로 쌓은 가로형 카드**임. 카드 1장이 가로로 긴 한 줄이며, 왼쪽에 라벨(영문 카드명 + 한글 부제), 오른쪽에 매체명(작게, muted) + 상품명(굵게, 최대 2줄)을 둠.
- 카드에는 **아이콘, 한 줄 설명, hover 효과, 클릭 동작이 없음**. 카드는 결론을 읽는 요약이며, 근거는 차트와 목록에서 확인함.
- **Best Match 카드만 muted 배경**으로 강조함. 대안 카드는 기본 카드 배경임. 카드에는 그린을 쓰지 않음(그린은 차트의 Best Match 막대 한 곳, 14장).
- Best Fit 개수는 카드 영역에 두지 않고 목록의 개수 줄(`Best Fit {N}개`, 6.4)에서 보여 줌.
- **기획 의도**: 상단 왼쪽은 "무엇을 먼저 볼지"만 말하고 군더더기(아이콘·설명·개수 타일)를 뺌. 가로형 카드를 세로로 쌓으면 긴 광고상품명이 넓게 읽히고, 카드 묶음 높이가 오른쪽 차트의 높이 기준이 됨(5.5).

**왕중왕 정의**
- 왕중왕은 **Best Fit(최대 30개) 중 가장 먼저 검토할 매체·상품**을 뜻하는 기획 용어임. 화면에는 "왕중왕"이라는 말을 쓰지 않고 카드명(Best Match 등)만 표기함.
- 구성은 **정답 1개 + 다를 때만 대안**임. Good Fit은 왕중왕 대상이 아님.

| 구분 | 카드 | 관점 | 표시 조건 |
|---|---|---|---|
| 정답 | Best Match | 종합 적합도 | 항상 1개 |
| 대안 | Industry Favorite | 같은 업종 집행 | 이 관점의 1등이 Best Match와 **다른 상품**일 때만 |
| 대안 | Top Performer | 평가 KPI 효율 | 이 관점의 1등이 Best Match와 **다른 상품**일 때만 |

- 표시되는 카드는 **항상 2~3개**(Best Match 1개 + 대안 1~2개)임. 카드가 1개가 되는 경우(Best Match가 두 관점 모두에서 1등, 관점 데이터 산출 불가 등)는 산정 단계에서 발생하지 않도록 함(데이터사이언티스트 확정).
- 카드 순서는 Best Match → Industry Favorite → Top Performer.
- **기획 의도**: 정답이 여러 개이면 정답이 흐려지고, 같은 상품이 카드 여러 장에 반복됨. 그래서 정답은 하나로 두고, "다른 우선순위를 더 중시한다면 이쪽"이라는 대안은 **실제로 다른 선택지가 있을 때만** 보여줌.

### 4.2 카드 정의 (정책서 4.3 변경)

| 카드 | 영문 카드명 | 한글 부제 | 선정 기준 |
|---|---|---|---|
| Best Match | `Best Match` | `캠페인에 딱 맞는` | **Best Fit 중** 종합 적합도가 가장 높은 매체·상품(목록 1위와 같음) |
| Industry Favorite | `Industry Favorite` | `같은 업종에서 많이 쓴` | **Best Fit 중** 동일 업종에서 집행된 캠페인 수가 가장 많은 매체·상품 |
| Top Performer | `Top Performer` | `효율이 가장 좋은` | **Best Fit 중** 이번 캠페인의 평가 KPI 기준 과거 집행 효율이 가장 좋은 매체·상품 |

- 두 관점의 1등이 같은 상품이어도 **카드를 병합하지 않고** Industry Favorite 카드와 Top Performer 카드를 각각 표시함(V16). 이때 두 카드에 같은 상품이 보임.
- 상품명은 레디셋 광고상품명 원문이며, 밑줄(`_`) 뒤에서 줄이 바뀔 수 있게 처리함. 2줄을 넘으면 말줄임함.
- {평가 KPI}·효율 지표의 매핑은 정책서 3.4 확정 후 반영(15.1 Q2).

**판정 규칙** (V16)
1. Best Match = Best Fit 중 종합 적합도 1위.
2. 관점별 1등을 Best Fit 안에서 각각 산정함(같은 업종 집행 1등, 평가 KPI 효율 1등).
3. 관점의 1등이 **Best Match와 같은 상품이면** 그 관점의 대안 카드는 만들지 않음.
4. 관점의 1등이 Best Match와 다르면 그 관점의 대안 카드를 만듦. 두 관점의 1등이 서로 같은 상품이어도 카드는 관점마다 따로 만듦.

### 4.3 산정 경계
- 동점이면 **목록 순위(6.2)가 앞선 매체·상품**을 선택함(15.1 Q2 확정 전 임시 기준).
- 관점에 필요한 데이터(업종 내 집행 건수, 효율 지표)를 산출할 수 없으면 **그 관점은 대안 판정에서 제외**함.
- **Best Fit은 0개가 되지 않음.** 조건으로 걸러낸 결과가 0개이면 일부 조건을 제외(완화)해 다시 선별하며, 어떤 조건을 제외할지는 데이터사이언티스트가 정의함(완화 안내는 3.3).

- **막대 차트**(5.3) 아래에 1px 구분선을 두고 SpinX 해석 블록(5.4)을 둠. 차트는 별도 테두리 카드로 감싸지 않음.
- 선별 과정 수치(전체 풀 → 후보 선정 → 적합도 통과 → Best Fit)와 퍼널은 이 영역에 두지 않음.
- **기획 의도**: 이 차트가 답하는 질문은 "내 캠페인에 어떤 매체·상품이 잘 맞을까?"이므로, 시스템이 후보를 어떻게 걸렀는지가 아니라 **왜 이 상품들이 앞서는지**를 보여 줌. 막대는 평가 축 점수를 그대로 합친 높이이고, 그린은 가중치를 반영한 종합 적합도 1위(Best Match)임. 두 기준이 다르면 "점수만 높은 상품과 내 캠페인에 맞는 상품은 다르다"를 차트가 직접 보여 줌(Reach Caster 리치 커브에서 최대 도달이 아니라 최적점을 짚는 것과 같은 방식).

### 5.2 평가 축과 점수
- 평가 축은 **5개 또는 6개**이며, **어떤 축으로 평가할지는 큐레이션 생성 시 입력한 캠페인 설명에 따라 정해짐**(생성 정의서 3.9, 정책서 3.4). 캠페인마다 축 구성이 달라질 수 있으므로 화면 규칙은 특정 축 이름에 의존하지 않음.
- 캠페인 설명은 선택 입력이므로, 설명 없이 만든 큐레이션은 **기본 평가 축**(5개 또는 6개)으로 평가함. 기본 평가 축의 구성은 데이터사이언티스트가 정의함.
- 축별 점수와 **종합 적합도(순위)**는 데이터사이언티스트가 정의해 결과로 제공하며(캠페인별 가중치 포함), 화면은 산출 방식을 정의하지 않음. 한 큐레이션 안의 모든 매체·상품은 같은 축으로 점수를 받음.
- 목록 순위(6.2)·Best Match(4.2)·카드 판정은 모두 **종합 적합도 순위**를 따름.
- **막대 높이 = 축별 점수의 단순 합**(화면 표시 규칙)임. 종합 적합도는 단순 합과 다를 수 있으므로 막대 순서와 목록 순위는 다를 수 있음.
- 점수 원값은 화면에 표시하지 않고 높이·상대 표현(`상위 N%`)으로만 표현함(정책서 8.6 상대 표현).
- 축 이름과 표시 순서는 결과 데이터가 정하며, hover 칸·툴팁·레이더(6.10.1)가 모두 같은 순서를 씀. 차트에는 범례를 두지 않음.
- **기획 의도**: Ad Curator는 캠페인 설명을 읽고 **무엇으로 평가할지부터 캠페인에 맞춰 고름**. 같은 업종·목적이라도 브리프가 다르면 평가 축이 달라지는 것이 이 솔루션의 차별점이므로, 축 구성은 막대 툴팁·상품 팝업 레이더·SpinX 해석에서 드러냄.

### 5.3 차트 표시 규칙

| 항목 | 규칙 |
|---|---|
| 막대 | Best Fit 매체·상품마다 막대 1개(최대 30개). 평상시에는 **단색 막대**(칸 없음) |
| 정렬 | 점수 합 내림차순으로 왼쪽부터 배치. 합이 같으면 목록 순위가 앞선 쪽이 왼쪽(V17) |
| 막대 폭 | 모든 막대가 같은 폭(Best Match 포함). 칸 폭의 58%이며 최대 32px. 막대 수가 적으면 막대도 넓어져 간격만 벌어지지 않음 |
| 높이·기준선 | 점수 합에 비례함. 막대 간 차이가 보이도록 **기준선을 0이 아니라 Best Fit 최솟값보다 아래**(최솟값 − (최댓값 − 최솟값) × 0.35)에 둠. 그래서 Y축에 숫자 눈금을 두지 않음 |
| Y축 | 축 선 없이 방향 라벨만 둠: 위 `높음`, 아래 `낮음`. 차트 맨 위 왼쪽에 Y축 제목 `적합도 점수 합` |
| X축 | 기준선 1개만 둠. 눈금·X축 제목 없음 |
| Best Match | 위치와 관계없이 Best Match 막대만 시그니처 그린. **말풍선·테두리·폭 차이 등 별도 표식은 두지 않음**. 그린의 뜻은 Info 툴팁(5.1)과 왼쪽 Best Match 카드로 전달함 |
| 나머지 막대 | 무채색 단색. 대안 카드 상품의 막대도 표식 없이 무채색(강조는 한 곳) |
| Best Fit / Good Fit 구분 | Good Fit이 있으면 마지막 Best Fit 막대와 첫 꼬리 막대 사이(보통 막대 간격의 가운데)에 점선 구분선을 두고, 위쪽에 `Best Fit {N}`(굵게)과 `Good Fit {M}`(muted)을 양쪽에 표시함. Good Fit이 0개이면 구분선·꼬리 없이 오른쪽 끝에 `Best Fit {N}`만 표시함 |
| Good Fit 꼬리 | 구분선 오른쪽에 Good Fit 점수 합 상위 최대 **6개**를 옅어지는 짧은 막대로 두고 끝에 `···`를 붙임. 꼬리 막대 높이는 마지막 Best Fit 막대보다 낮게 줄어드는 장식이며 **hover·클릭 동작이 없음** |
| hover / 포커스 | 막대에 올리면 그 막대만 **평가 축 칸**으로 나뉨(축 점수 비율대로, 아래가 첫 축, 명도 단계로 구분. Best Match는 그린 명도 단계). 다른 막대는 흐려짐 |
| 툴팁 | 매체명, 상품명, 축별 `상위 {N}%`를 칸 색 견본과 함께 쌓인 순서대로(맨 위 칸이 맨 위) 표시함. 순위·`Best Match` 표기는 두지 않음 |
| 클릭 | 막대에는 클릭 동작이 없음 |
| 진입 모션 | 진입 시 막대가 바닥에서 왼쪽부터 순서대로 올라오고, 이어서 Good Fit 꼬리와 `···`가 나타남(1회). 시스템 "동작 줄이기" 설정이면 모션 없이 최종 상태를 바로 표시함. 검색·필터·담기로는 다시 재생하지 않음 |

- `상위 {N}%` 임시 기준: 해당 축의 점수를 Best Fit 안에서 내림차순으로 순위(동점은 같은 순위) r, 전체 n개일 때 상위 `ceil(r / n × 100)`%(1~100 정수). 산출 방식은 15.1 Q6.
- 기준선을 0으로 둘지(막대 차이를 과장하지 않음) 지금처럼 최솟값 아래로 둘지(차이가 잘 보임)는 15.1 Q12.
- **기획 의도**: 평상시에는 단색 막대로 "높이 = 점수 합"만 읽히게 하고, 축별 구성은 궁금한 막대에 올렸을 때만 보여 소음을 줄임. 강조는 그린 색 하나로만 하고(강조 한 곳 원칙) 폭을 다르게 하지 않음. 막대 차트에서 폭 차이는 값 차이로 오해될 수 있기 때문임.

### 5.4 SpinX 차트 해석 (정책서 8.4 변경)

> **범위 한정**: 화면에서의 노출·인터랙션만 정의함. 프롬프팅·응답 생성 로직은 별도 SpinX 문서 관할.

| 항목 | 규칙 |
|---|---|
| 위치·구성 | 차트 하단, 1px 구분선 아래. 헤더에 SpinX 심볼 + 워드마크 `SpinX for Ad Curator`(BudgetOpt 2.0 해석 블록과 같은 컴포넌트). 로딩 중 타이핑 효과(심볼 회전 + `analyzing…`) |
| 본문 | Best Match가 어떤 평가 축에서 강했는지, 다음 순위와 어느 축이 차이를 만들었는지, 대안 카드가 있으면 어떤 우선순위에서 다른지를 설명. 점수 값을 반복하지 않고 상대 표현으로 서술. 평가 축이 캠페인 설명의 어떤 내용을 반영했는지 한 문장 포함. Best Match가 점수 합 1위가 아니면, 이번 캠페인에서 중요한 축 덕분에 1위가 되었다는 점을 설명함. 완화된 조건이 있으면 그 사실을 한 문장 포함. 문장은 합니다체 |
| 이어서 질문하기 | 타이핑이 끝난 뒤 텍스트 링크 `이어서 질문하기 →`를 표시. 클릭하면 SpinX 패널을 열고 입력창에 `#Campaign Fit 차트 `를 프리필함(플랫폼 멘션 트리거는 `#`). **자동 전송하지 않음**(BudgetOpt 2.0 결과 7.2와 동일) |
| 생성 실패 | 본문 `이 차트에 대한 SpinX 분석을 생성하지 못했습니다.` / 보조 `새로고침하거나 결과에 다시 들어오면 분석을 다시 시도합니다.` (BudgetOpt 2.0 결과 7.1.1과 동일 문구). muted 톤, 타이핑 효과·`이어서 질문하기` 미노출 |
| 사용량 | 결과 진입 시 자동 생성되는 해석은 사용자 대화 사용량에 포함하지 않음(정책서 8.6) |

- **기획 의도(자동 전송하지 않는 이유)**: 의도치 않은 클릭이 SpinX 사용량을 소모하지 않도록 함(ActionDock 제안 질문도 같은 이유로 자동 전송하지 않음).

### 5.5 좌우 정렬 (상단 2분할)
- **윗선**: 차트 맨 윗줄(Y축 제목 `적합도 점수 합`과 `Best Fit`/`Good Fit` 라벨)이 왼쪽 첫 카드의 윗선과 맞음.
- **아랫선**: SpinX 해석 **본문 텍스트의 끝**이 왼쪽 마지막 카드의 아랫선과 맞음. `이어서 질문하기 →`는 이 선 아래로 넘쳐도 됨.
- 해석이 타이핑되는 동안에도 차트 높이가 바뀌지 않도록 해석 전문 높이를 미리 확보함. 창 크기가 바뀌어도 위 두 선이 유지됨.
- 왼쪽 카드 묶음이 낮아 차트가 너무 작아지는 경우에도 차트 최소 높이는 보장함.
- **기획 의도**: 결론(카드)과 근거(차트+해석)가 같은 높이의 한 덩어리로 읽히게 하고, 타이핑·리사이즈로 화면이 흔들리지 않게 함.

## 6. 매체·상품 목록

### 6.1 구역 구성
- 목록은 **두 구역**으로 나뉨: ① `Best Fit List`(항상 펼침) ② `Good Fit List`(접이식). 탭으로 동등하게 나누지 않음.
- 두 구역의 헤더는 **같은 위계**임: 1줄 제목(섹션 제목급) + 제목 옆 회색 개수 + 2줄 설명 한 줄(작은 muted 텍스트).

| 구역 | 1줄 (제목 + 개수) | 2줄 | 그 밖 |
|---|---|---|---|
| Best Fit | `Best Fit List` + `{N}` | 왼쪽 `이번 캠페인에 가장 잘 맞아 먼저 검토할 매체·상품이에요`, 오른쪽 `생성 시점 기준 · yyyy-mm-dd` + Info(6.4) | 제목 줄 오른쪽에 검색·필터(6.6·6.7) |
| Good Fit | `Good Fit List` + `{N}` | `Best Fit보다 적합도는 낮지만 보조로 검토해 볼 만한 매체·상품이에요` + `펼치기 ↓`(펼친 상태 `접기 ↑`) | 헤더 전체가 토글 버튼 |

- **개수 {N}**: 검색·필터가 없으면 그룹 전체 개수, 검색·필터가 적용 중이면 **일치하는 개수**로 바뀜. 걸러진 개수를 보여 주는 별도 줄은 두지 않음.
- **열 헤더**: 두 구역 모두 행 목록 위에 열 헤더 한 줄을 둠(Good Fit은 펼쳤을 때). 구성: `순위` | `매체·상품` | `선별 이유` + SpinX 심볼 + `SpinX가 선별 이유를 작성했어요` | `전체 담기`/`전체 빼기`(7.3). 배경·글자는 Reach Caster 결과 테이블 헤더와 같음(muted 옅은 배경, 작은 semibold muted).
- **`Good Fit List` 구역**: Best Fit 목록(더 보기 포함) 아래에 여백과 1px 구분선을 두고 놓음.
  - **기본은 접힘**이며 헤더 전체를 눌러 펼침·접힘을 토글함. 펼치면 Good Fit 행을 10개씩 보여주고 `더 보기`로 10개씩 추가함. 접으면 표시 수가 처음 10개로 돌아가고, 새로고침·재진입하면 접힌 상태로 돌아감.
  - Good Fit이 0개이면 이 구역을 표시하지 않음.
  - 검색·필터는 이 구역에도 같이 적용됨. 접혀 있어도 개수에 반영되고, 펼치면 일치하는 행만 보임.
- **Low Fit 구역은 두지 않음**(정책서 3.5: 결과 화면 미제공).
- **그룹당 최대 30개**를 전제로 설계함(정책서에 명시 없음, 15.1 Q1).
- **기획 의도**: 화면에 이미 쓰는 등급 용어(Best Fit / Good Fit)를 제목에 그대로 써서 차트 라벨·카드 기준과 같은 말로 읽히게 하고, 설명 한 줄로 "먼저 볼 것 / 보조로 볼 것"이라는 역할을 알려 줌. Good Fit을 탭으로 나란히 두면 두 그룹이 같은 무게로 읽히므로 아래에 접어 두되, 한 번의 클릭으로 열 수 있어 선택지를 넓히고 싶은 사용자의 길을 막지 않음.

### 6.2 순위
- 각 그룹 안에서 **종합 적합도 내림차순**으로 고정 정렬함. 정렬 변경 기능은 두지 않음.
- 행 왼쪽 순위 번호(01, 02…)는 **그룹 내 순위**이며, 검색·필터를 적용해도 번호가 바뀌지 않음. 모든 행의 순위 번호는 muted이며 색 강조가 없음.
- 적합도 점수 값은 화면에 표시하지 않음(15.1 Q2).
- **기획 의도**: 순위 자체가 곧 적합도 순서이므로 정렬 선택지를 주면 오히려 "무엇이 더 맞는가"가 흐려짐.

### 6.3 행 구성
행은 `순위` / `매체·상품` / `선별 이유` / `담기` 네 열로 나뉘며 선별 이유 열이 가장 넓음. 행 사이는 1px 구분선이고 행 내용은 세로 가운데 정렬함. **행에서 굵은 글씨는 상품명 하나**임.

**Best Fit 행**

| # | 항목 | 화면 표시 | 형식 · 규칙 |
|---|---|---|---|
| 1 | 순위 | 행 맨 앞 번호(muted) | 2자리(01~). 검색·필터를 적용해도 번호 유지 |
| 2 | 매체명 | 상품명 위 작은 글씨(muted) | 원문 그대로(예: `kakao 모먼트`, `NAVER 성과형 DA`, `Google Ads`, `Meta`) |
| 3 | 상품명 | 굵은 글씨. 누르면 상품 팝업 | **레디셋 광고상품명 원문 그대로**(예: `카카오톡비즈보드_전환_카카오톡채널_CPA`). 밑줄(`_`) 뒤에서 줄바꿈될 수 있음. hover 시 밑줄 |
| 4 | 상품 설명 | 상품명 아래 한 줄(muted) | 30자 이내(공백 포함) 명사구, 마침표 없음. **노출 지면을 포함**. 같은 라벨이면 같은 문장(정책서 8.3) |
| 5 | 프로모션 | 상품 설명 뒤 `· 매체 프로모션` 텍스트 버튼 | 6.5 표시 조건(V12)을 만족할 때만. 누르면 상품 팝업이 프로모션 영역 위치로 열림 |
| 6 | 선별 이유 | 선별 이유 열, 보통 굵기 본문 색(옅게) 한 덩어리 | **100~150자**(공백 포함), 1~3문장, **첫 문장이 결론**, **캠페인 입력값(업종·목적·기간 등) 연결 하나 이상 필수**, 해요체(V21) |
| 7 | 담기 | 행 맨 오른쪽 텍스트 버튼 | 7장 |

**예시 (Best Fit 행)**

> 매체명·상품명은 레디셋 카탈로그의 실제 표기이고, 설명·문구는 설명을 위한 예시임(실제 데이터 아님). 캠페인은 `업종 화장품 / 목적 전환 / 기간 12월`로 가정함.

| 순위 | 매체명 | 상품명 | 상품 설명 | 선별 이유 |
|---|---|---|---|---|
| 01 | kakao 모먼트 | 카카오톡비즈보드_전환_카카오톡채널_CPA | 카카오톡 채팅 목록 최상단 배너 | 전환 효율도 상위권이라 믿고 먼저 담기 좋아요. 카카오톡을 여는 순간 채팅 목록 맨 위에 보이는 자리라 12월 신제품 런칭처럼 짧은 기간에 빠르게 알릴 때 잘 맞아요. 카카오톡 채널로 바로 이어져 관심 고객을 모으기도 쉬워요. |
| 02 | NAVER 성과형 DA | 웹사이트 전환_네이버 메인_CPC | 네이버 메인 노출 성과형 디스플레이 | 화장품 업종에서도 많이 쓰여 운영이 안정적이에요. 네이버 메인을 여는 사람에게 넓게 노출되고, 성과형이라 클릭한 만큼만 비용을 내요. 전환 목적 캠페인에서 예산을 나눠 쓰며 비용을 관리하기 좋아요. |

- 별도 결론 구절(굵은 요약 한 줄)은 두지 않음(v1.2에서 제거). 결론은 선별 이유의 첫 문장이 맡음.
- **프로모션을 별도 열로 두지 않는 이유**: 프로모션 "미포함"으로 만든 큐레이션에서는 프로모션 요소가 전혀 없어야 하므로, 열을 만들면 미포함일 때 빈 열이 남음. 상품 설명 뒤 인라인으로 두면 미포함일 때 그 텍스트만 사라지고 **행 레이아웃은 포함·미포함이 완전히 같음**.
- 매체·상품 이름·상품 설명·선별 이유는 모두 생성 시점 값이며 다시 계산하지 않음.
- 행에 hover하면 배경이 은은하게 바뀌고 `담기` 버튼이 진해짐. 상품명·`· 매체 프로모션`·`담기`를 제외한 행 영역에는 클릭 동작이 없음.
- **Good Fit 행**은 같은 구성이되 상품명 굵기와 선별 이유 대비를 한 단계 낮춰 보조용임을 드러냄(색 강조 없음). 선별 이유에는 **상대적으로 낮게 평가된 축을 반드시 포함**함. 길이 규칙은 Best Fit과 같음(V21).
- **기획 의도**: 행을 `무엇(상품) | 왜(선별 이유) | 담기`로 나누면 상품을 확인하고 이유를 읽고 바로 담는 흐름이 한 줄에서 끝남. 행마다 굵은 줄이 둘이면 목록 전체의 피로도가 높아지므로 강조는 상품명 하나로 두고, 선별 이유는 첫 문장만 읽어도 판단할 수 있게 씀. 입력값 연결을 필수로 두는 이유는 같은 상품이 어느 캠페인에서나 똑같이 설명되는 것을 막고 "내 캠페인을 위한 결과"임을 느끼게 하기 위함.

### 6.4 안내 줄 (Best Fit 설명 줄)
`Best Fit List` 제목 바로 아래 한 줄. 목록의 성격을 한 번만 알려 주고 행마다 반복하지 않게 함.

| 위치 | 내용 |
|---|---|
| 좌측 | `이번 캠페인에 가장 잘 맞아 먼저 검토할 매체·상품이에요` |
| 우측 | `생성 시점 기준 · yyyy-mm-dd` + Info 아이콘. hover 시 툴팁 |

- 두 텍스트는 같은 크기·같은 muted 톤(같은 위계)임. 개수는 제목 옆(6.1)에 있음.
- 우측 툴팁 문구(프로모션 포함): `결과는 생성 시점의 데이터·프로모션 기준입니다. 다시 계산하지 않으며, 최신 프로모션은 원문 링크에서 확인할 수 있습니다.`
- 우측 툴팁 문구(프로모션 미포함): `결과는 생성 시점의 데이터 기준입니다. 다시 계산하지 않으며, 최신 기준이 필요하면 복제 후 다시 생성해 주세요.`
- SpinX가 문구를 작성했다는 안내는 열 헤더의 `선별 이유` 옆에 둠(6.1).
- **기획 의도**: 정책서 4.2의 "결과 기준 데이터" 정책을 사용자가 오해하지 않게 함. 프로모션 정보가 시간이 지나 달라졌을 때 결과가 틀린 것으로 오해하지 않도록, 생성 시점 기준임을 목록 곁에 항상 둠.

### 6.5 프로모션 (정책서 5장)

| 구분 | 규칙 |
|---|---|
| 표시 조건 | 큐레이션이 프로모션 **포함**으로 생성되었고, 해당 매체·상품에 **캠페인 기간과 하루 이상 겹치는 프로모션**이 있을 때만 상품 설명 뒤에 `· 매체 프로모션` 표시(V12) |
| 미포함 | 목록·필터·안내 툴팁 어디에도 프로모션 요소를 표시하지 않음(V13) |
| 열기 | `· 매체 프로모션`을 누르면 상품 팝업(6.10)이 열리고 프로모션 영역이 보이는 위치로 스크롤됨. 행 안에서 펼치지 않음 |
| 1개만 표시 | 한 매체·상품에 캠페인 기간과 겹치는 프로모션이 둘 이상이면 **캠페인 기간과 겹치는 날이 가장 많은 프로모션 1개만** 표시함. 겹치는 날 수가 같으면 프로모션 시작일이 빠른 것을 표시함 |

- 프로모션 영역의 구성은 6.10.3.

### 6.6 검색
- 버튼 `검색`을 누르면 입력창으로 확장되고 자동 포커스됨(큐레이션 목록 검색과 동일 방식).

| 항목 | 규칙 |
|---|---|
| 검색 대상 | 매체명 + 상품명 + 상품 설명을 동시에(선별 이유는 대상이 아님) |
| 매칭 방식 | 부분 일치(substring), **대소문자 무시** |
| 공백 처리 | 입력값 앞뒤 공백을 트리밍한 뒤 비교. 공백만 입력하면 검색 미적용 |
| 타이밍 | onChange 실시간(디바운스 없음) |
| 범위 | `Best Fit List`와 `Good Fit List` 두 구역에 함께 적용 |
| 결과 표시 | 두 구역의 개수 줄이 일치 개수로 바뀜(6.1). 0건이면 빈 상태(6.9) |
| placeholder | `매체·상품 검색` |
| 닫힘 | 입력값이 빈 상태에서 blur하면 버튼으로 축소. X 버튼은 검색어 초기화 + 축소 |

### 6.7 필터
- **프로모션 포함으로 만든 큐레이션에서만 `필터` 버튼을 표시함.** 미포함 큐레이션은 고를 항목이 없으므로 버튼 자체가 없음.
- 드롭다운 구성은 레디셋 메인(워크스페이스 목록) 필터와 같음: 그룹 제목 + 체크박스 목록, 맨 아래 폭 전체 `필터 초기화` 버튼. 결과 개수·구분선은 드롭다운에 두지 않음.

| 그룹 | 항목 | 규칙 |
|---|---|---|
| 매체 프로모션 | `포함` / `미포함` 체크박스 | 다중 선택(OR). `포함` = 6.5 표시 조건을 만족하는 행, `미포함` = 그렇지 않은 행. 둘 다 고르거나 아무것도 고르지 않으면 전체 |

- 버튼 배지 숫자 = 선택한 옵션 수(0이면 배지 없음). 선택이 있으면 버튼 배경이 연하게 바뀜.
- `필터 초기화`: 필터 선택만 해제함(검색어는 유지).
- 바깥 클릭·Esc로 드롭다운이 닫힘.
- 매체별 필터는 두지 않음(v1.1에서 제거). 매체로 좁히려면 검색을 씀.
- **기획 의도**: 목록에 보이는 정보 중 검색으로 좁힐 수 없는 것은 프로모션 여부뿐이므로 그것만 필터로 둠. 필터 UI를 메인과 같게 맞춰 새로 배울 것이 없게 함.

### 6.8 더 보기
- 처음에는 **10개**를 표시하고, 남은 항목이 있으면 목록 하단 **가운데**에 `{M}개 더 보기 · {표시 수} / {전체}` 텍스트 버튼을 표시함. M = min(10, 남은 개수). 누를 때마다 10개씩 추가됨.
- 검색·필터 변경 시 두 구역 모두 처음 10개로 초기화함. `Good Fit List`는 더 보기를 따로 가지며 접으면 처음 10개로 돌아감.
- 모두 표시되면 버튼이 사라짐.
- 버튼을 가운데에 두는 이유: 특정 열이 아니라 목록 전체를 이어 주는 동작이기 때문임. 목록 가운데는 우하단 ActionDock보다 충분히 왼쪽이라 겹치지 않음.
- **기획 의도**: 페이지네이션 컨트롤은 목록을 "표"처럼 보이게 해 피로도를 높이므로, 읽는 흐름을 끊지 않는 더 보기를 씀.

### 6.9 빈 상태
| 상황 | 표시 |
|---|---|
| Best Fit 검색·필터 결과 0건 | 열 헤더 아래에 `조건에 맞는 매체·상품이 없습니다.`만 표시(초기화 링크 없음). 제목 옆 개수는 `0`, 열 헤더의 `전체 담기`는 숨김 |
| Good Fit 검색·필터 결과 0건 | 구역을 펼치면 `조건에 맞는 매체·상품이 없습니다.`. 제목 옆 개수는 `0` |
| Good Fit이 0개 | `Good Fit List` 구역을 표시하지 않음. Best Fit은 0개가 되지 않음(4.3) |

- 검색은 입력창 X로, 필터는 드롭다운의 `필터 초기화`로 해제함.

### 6.10 상품 팝업
- **열기**: 행의 상품명을 누르거나 `· 매체 프로모션`을 누르면 열림(후자는 프로모션 영역이 보이는 위치로 스크롤). Best Fit·Good Fit 행 모두 같음. 팝업 위에 다른 팝업을 열지 않음.
- **크기**(ui-dialog-policy): Best Fit 상품은 `lg`(왼쪽 레이더 + 오른쪽 매체·상품 상세 2열), Good Fit 상품은 `md`(레이더 없음, 1열). 헤더·푸터는 고정하고 본문만 스크롤함.
- **닫기**: `확인` 버튼(primary, 푸터의 유일한 버튼. 레디셋 공통 읽기 전용 다이얼로그와 같음), 오버레이 클릭, Esc. 다시 열면 스크롤은 맨 위에서 시작함. 팝업에는 담기 버튼이 없음.
- 팝업의 모든 값은 생성 시점 값이며 다시 계산하지 않음. **캠페인 조건과 비교하지 않는 상품 고유 정보**만 보여 줌(프로모션의 적용 일수 제외, 6.10.3).

| 영역 | 내용 | 표시 조건 |
|---|---|---|
| 헤더 | 매체명(muted, 작게) / 상품명(굵게, 원문) / **상품 상세 설명** 한 문장 | 항상 |
| 레이더 차트(왼쪽) | 6.10.1 | **Best Fit 상품만** |
| 매체·상품 상세(오른쪽) | 6.10.2 | 값이 있는 항목이 하나 이상일 때 |
| 프로모션(하단) | 6.10.3 | 6.5 표시 조건을 만족할 때만 |
| 푸터 | `확인` | 항상 |

- **상품 상세 설명**: 목록의 30자 설명과 별도인 40~55자(공백 포함) 한 문장, 합니다체. 아래 본문과 구분되도록 설명 아래에 여백을 둠. 매체(서비스)와 노출 지면을 포함하고 상품이 무엇을 하는지 설명함(예: `카카오톡 채팅 목록 최상단에 노출되어 카카오톡 채널 추가 등 전환을 이끄는 배너 광고입니다.`).

**6.10.1 레이더 차트 (Best Fit 상품)**
- 축은 이 큐레이션의 평가 축 전체(5개 또는 6개, 5.2)이며 순서는 Curation Fit 축 순서와 같음.
- 두 도형: **이 상품**(그린 면) + **Best Fit 평균**(muted 점선). 평균은 Best Fit 전체(이 상품 포함)의 축별 점수 평균임. 이 상품 면은 **모든 Best Fit 상품에서 그린**임(그린 한 곳 원칙의 예외, 14장).
- 차트 위 가운데에 범례 `이 상품` / `Best Fit 평균`을 둠. 영역 제목은 두지 않음.
- 점수 숫자·점(dot)·해석 문구·툴팁은 두지 않음. 축 이름만 라벨로 표시함.
- **기획 의도**: 막대 차트가 "합"을 보여 준다면 레이더는 "이번 캠페인의 평가 축 중 어디에서 강하고 어디가 약한가"를 보여 줌. 평균을 기준으로 삼아 점수 원값 없이도 상대 위치를 읽게 함. Good Fit은 평균에 못 미치는 것이 당연하므로 차트를 두지 않고 근거 문장에서 설명함.

**6.10.2 매체·상품 상세**

제목 `매체·상품 상세` 아래 옅은 회색(muted) 상자 안에 `항목명 | 값` 읽기 전용 행으로 표시함. 노출 지면은 헤더 설명에 포함되므로 다시 쓰지 않음.

| 순서 | 항목명 | 표시 값 |
|---|---|---|
| 1 | 구매 방식 | `{구매 방식} · {과금 방식}` (예: `성과형 · CPC`) |
| 2 | 소재 형식 | 지원하는 소재 형식을 가운뎃점으로 나열(예: `동영상 · 이미지`). 동영상 상품은 영상 형식 병기(예: `동영상 (스킵 불가 · 15초)`) |
| 3 | 타게팅 지원 | 지원 옵션을 구체 항목으로 나열(예: `연령 · 성별 · 지역 · 관심사`) |
| 4 | 디바이스 | `모바일 · PC` 등 지원 기기 |
| 5 | 보장 형태 | 보장형일 때만 표시(예: `노출 보장`) |
| 6 | 최소 집행 금액 | `{금액}만 원`(천 단위 콤마) |
| 7 | 추천 타겟 | 이 상품이 잘 닿는 대상(예: `20~30대 여성 · 뷰티 관심`). **있을 때만, 항상 맨 마지막** |

- **값이 없는 항목은 행 자체를 숨김**(빈 칸·`-` 표기 없음). 모든 항목이 비면 영역을 숨김.
- 입력한 조건과의 일치 표시(✓)와 `조건 완화` 표시는 두지 않음(v1.1에서 제거). 캠페인 조건과의 관계는 목록의 선별 이유와 속성 조건 모달(3.3)에서 확인함.
- **기획 의도**: 광고주·집행자가 담기 전에 확인할 것은 비용 구조(구매·과금), 만들어야 할 소재, 도달 대상(타게팅·디바이스), 약속 조건(보장), 진입 장벽(최소 금액)임. 추천 타겟은 참고 정보라 맨 끝에 둠.

**6.10.3 프로모션 영역 (정책서 5.3)**

| 요소 | 내용 |
|---|---|
| 제목 | `프로모션` |
| 1줄 | 프로모션명(굵게) + 오른쪽 텍스트 링크 `원문 보기`(외부 링크 아이콘, 새 탭) |
| 2줄 | `{시작일} → {종료일} · 캠페인 기간 중 {N}일 적용`. N = 프로모션 기간과 캠페인 기간이 겹치는 일수(양 끝 포함) |
| 행 | `혜택`(값 굵게) / `조건` / `이점`을 매체·상품 상세와 같은 `항목명 | 값` 행으로 표시 |
| 안내 | `생성 시점(yyyy-mm-dd) 기준입니다. 최신 내용은 MTS 2.0 원문에서 확인해 주세요.` |

- 혜택·조건·이점은 원문 기준이며 **원문에 없는 성과 보장이나 금액 환산은 쓰지 않음**.
- 프로모션 영역 위아래에 충분한 여백을 둬 상세 영역과 구분함.

## 7. 담기

### 7.1 정의
- `담기`는 결과를 검토하면서 BudgetOpt 2.0으로 가져갈 매체·상품 후보를 표시하는 동작임. **이 화면 안에서만 유지되는 임시 선택**이며 서버에 저장하지 않음.
- 정책서 6장의 컬렉션(저장·공유되는 묶음, 패널, `담은 것만` 필터)은 **이번 범위에서 제외**함(15.2).
- 담은 상태는 새로고침·재진입·다른 화면 이동 시 사라짐. 이탈 확인은 표시하지 않음.
- **담기 상한은 50개**임. BudgetOpt 2.0 시나리오는 최대 30개 상품이지만, 연계할 때 미지원 매체·학습 결과 없음으로 빠지는 몫이 있으므로 담기는 넉넉히 허용하고, **전달 30개 초과는 간편 생성 다이얼로그에서 빼게 함**(8.3, V29).
- **기획 의도**: 저장·공유까지 만들기 전에, 결과를 읽는 흐름에서 "이건 가져가자"를 가볍게 표시하고 그 개수가 다음 단계(BudgetOpt 2.0) 버튼에 쌓이게 해 세션이 이어지는 느낌을 줌.

### 7.2 담기 버튼 (행)

| 항목 | 규칙 |
|---|---|
| 위치 | 목록 행 맨 오른쪽(Best Fit·Good Fit 행 모두). 상품 팝업에는 없음 |
| 형태 | 테두리 없는 텍스트 버튼 |
| 담기 전 | muted `+ 담기`. 행에 hover하면 진해짐 |
| 담은 뒤 | 진한 굵은 글씨 `✓ 담음`으로 고정 |
| 토글 | `+ 담기`를 누르면 담기고, `✓ 담음`을 누르면 즉시 빠짐. 확인 다이얼로그 없음(V4) |
| 순서 | 담은 순서대로 기억함 |
| 한도 | 50개가 되면 담지 않은 행의 `+ 담기`는 흐리게 비활성되고 hover 시 `더 담을 수 없어요`를 표시함. 이미 담은 행은 50개에서도 뺄 수 있고, 하나를 빼면 다시 담을 수 있음(V3) |
| 검색·필터 | 담은 상태는 검색·필터와 무관하게 유지됨. 걸러져 안 보이는 행도 담긴 상태로 남음 |

- **기획 의도**: 행마다 박스 버튼이 반복되면 버튼이 세로로 늘어서 소음이 되므로, 평소엔 옅은 글씨로 두고 hover·담은 상태에서만 진하게 해 담은 것만 눈에 띄게 함.

### 7.3 전체 담기 · 전체 빼기 (열 헤더)

| 항목 | 규칙 |
|---|---|
| 위치 | 두 구역 열 헤더의 담기 열(맨 오른쪽). Good Fit은 펼쳤을 때만 보임 |
| 대상 | 그 구역에서 **검색·필터에 걸러진 전체**(더 보기로 펼치지 않은 행 포함) |
| 라벨 | 대상 중 하나라도 안 담겼으면 `전체 담기`, 모두 담겼으면 `전체 빼기` |
| 전체 담기 | 안 담긴 행을 순위 순서대로 담음. 상한(50개)에 닿으면 남은 자리만큼만 담고 토스트 `최대 50개까지 담을 수 있습니다. {N}개만 담았습니다.` 이미 50개이면 버튼이 흐리게 비활성되고 hover 시 `더 담을 수 없어요` |
| 전체 빼기 | 대상 전체를 담기에서 뺌 |
| 대상 0건 | 버튼을 표시하지 않음 |

- **기획 의도**: Best Fit은 이번 캠페인을 위해 고른 목록이라 "일단 다 가져가서 BudgetOpt 2.0에서 거르는" 흐름이 흔함. 행마다 누르게 하지 않고 한 번에 담게 하되, 검색·필터와 연동해 "카카오만 전부"처럼 좁혀 담을 수도 있게 함.

### 7.4 담은 개수 표시
- 담은 개수는 **하단 CTA 버튼**(8.2)과 **ActionDock `예산 최적화 하기` 액션**(9.2)에 숫자 배지로 표시됨. 두 곳은 같은 숫자임.
- 0개이면 두 곳 모두 배지를 표시하지 않음(V5).
- 담은 항목 목록은 간편 생성 다이얼로그의 전달 내역에서 확인함(8.3).

### 8.3 간편 생성 다이얼로그 (`md` 크기)

BudgetOpt 2.0 결과의 "최적화 예산으로 도달 예측하기" 다이얼로그와 같은 구성·여백(제목·설명 아래 본문을 한 단계 안쪽에 둠)임. 입력 필드는 BudgetOpt 2.0 시나리오 생성(Step 1·Step 2)과 같은 컴포넌트·제한·문구를 씀. 헤더·버튼은 고정하고 본문만 스크롤함.

| 영역 | 내용 |
|---|---|
| 제목 | `담은 매체·상품으로 예산 최적화하기` |

| 시나리오명 * | 입력창. 프리필 `(AC-{큐레이션 ID}) {큐레이션명}`(50자를 넘으면 50자까지). 최대 50자, 초과 입력 차단, 카운터 `{n}/50`, placeholder `시나리오명을 입력하세요.` |

| 항목 | 규칙 |
|---|---|
| 개수 줄 | `전달 {N} / 30개` + 있을 때만 ` · 미지원 매체 {n}개`, ` · 학습 결과 없음 {n}개`. 30개를 넘으면 `전달 {N} / 30개`가 destructive 색 |

| 빼기(×) | 모든 행 오른쪽 끝. 누르면 확인 없이 담기에서 빠지고, 목록 담기 표시·CTA·ActionDock 배지도 함께 줄어듦 |

| 0개 | 표 대신 점선 상자 `담은 매체·상품이 없습니다.` |
| 재검증 | **KPI를 바꿀 때마다** 각 행의 제외 여부·순서·개수 줄·하단 설명·개수 유효성·생성 버튼을 즉시 다시 판별함. 행을 빼도 즉시 다시 판별함 |

| 전달 개수 부족 | 전달 < 2, 학습 결과 없음이 없을 때 | `최소 2개 이상의 매체·상품을 담아 주세요.` |
| 전달 개수 부족 | 전달 < 2, 학습 결과 없음이 있을 때 | `최소 2개 이상의 매체·상품이 전달되어야 합니다. 다른 KPI를 선택하거나 더 담아 주세요.` |
| 전달 개수 초과 | 전달 > 30 | `최대 30개까지 전달할 수 있습니다. {초과 수}개를 빼 주세요.` |

- 개수 유효성은 아이콘·배경 없이 12px destructive 텍스트로 표 아래에 둠. 다른 필드 에러는 BudgetOpt 2.0 생성 화면과 같은 크기(현재 11px, 15.1 Q15).
- `BudgetOpt 2.0 생성` 활성 조건: 시나리오명 있음 AND 기간 모두 선택 AND 총 예산 > 0 AND KPI 선택 AND 2 ≤ 전달 ≤ 30.
- **기획 의도**: 큐레이션에서 이미 정한 맥락(업종·기간·매체·상품)은 그대로 가져가고, BudgetOpt 2.0에만 필요한 값(예산·KPI)만 더 묻게 해 세션이 끊기지 않게 함. 넘어간 뒤에 걸러지면 사용자가 이유를 모르므로, 빠지는 상품과 그 이유를 넘기기 전에 보여 주고 KPI를 바꿔 볼 수 있게 함.

### 8.4 확정 시 동작
- `BudgetOpt 2.0 생성`을 누르면 BudgetOpt 2.0 시나리오 생성 화면(`/budgetopt/scenario/new`)으로 이동하며 시나리오명·업종·캠페인 기간·총 예산·KPI·**전달 매체·상품**(제외 행 제외)을 함께 넘김. 브랜드는 넘기지 않음.
- **현재 BudgetOpt 2.0 생성 화면은 넘긴 값을 아직 읽지 않음**(빈 화면으로 열림, 15.1 Q10).
- 이동 전 확인 다이얼로그는 없음. 이동하면 담은 상태는 사라짐.

## 9. SpinX

> **범위 한정**: 이 섹션은 결과 화면에서의 SpinX 노출·인터랙션만 정의함. 프롬프팅·응답 생성·모델 연동은 별도 SpinX 문서 관할.

### 9.1 SpinX가 맡는 영역(정책서 8.1)

| 영역 | 화면 위치 | 비고 |
|---|---|---|
| 매체·상품 설명 | 목록 행의 상품 설명, 상품 팝업의 상세 설명 | 결과 생성 시점에 확정된 문장 |
| 선별 이유 | 목록 행(6.3). 열 헤더에 `SpinX가 선별 이유를 작성했어요` | 결과 생성 시점에 확정된 문장 |
| 차트 해석 | 차트 하단(5.4) | 진입 시 자동 생성 |
| 결과 상담 | ActionDock 입력 바 + SpinX 패널(9.2~9.4) | 사용자가 질문할 때만 |

### 9.2 ActionDock
- 우하단 고정 공통 컴포넌트. 입력 바(메인) + ＋ 런처(보조).
- **입력 바**: placeholder `SpinX에게 물어보세요…`에 제안 질문이 롤링 힌트로 순환함. 입력창에 포커스하면 제안 질문이 바 위로 펼쳐짐. 제안 질문을 누르면 **입력창에 채워지고 자동 전송되지 않음**. Enter 또는 전송 버튼으로 SpinX 패널이 열리며 질문이 전송됨.
- **제안 질문**: 모두 결과 상담 범위(9.4) 안의 질문이어야 함(V15).
  1. `매체·상품이 많이 걸러진 이유가 뭔가요?`
  2. `Best Fit 1위와 2위를 비교해 주세요`
  3. `Best Match는 왜 이 상품인가요?`
- **＋ 런처 액션**: `예산 최적화 하기`(`PieChart` 아이콘) 1개. 담은 개수 배지를 라벨 옆에 표시함(7.4). 누르면 간편 생성 다이얼로그(8.3)를 엶. 큐레이션 복제는 런처에 두지 않고 헤더 더보기 메뉴(3.4.3)에서만 함.
- SpinX 패널이 열려 있는 동안 ActionDock은 숨김.

### 9.3 SpinX 패널
- 우측에서 열리며 본문이 패널 폭만큼 밀림(BudgetOpt 2.0 결과 화면과 동일). 패널의 솔루션 표기는 `Ad Curator`.
- 질문 전송 시 사용자 메시지가 쌓이고 SpinX 답변이 이어짐.
- **멘션**: 입력창에서 `#`을 입력하면 해석 대상 목록(`Campaign Fit 차트`) 자동완성이 뜸. 선택하면 `#{이름} `이 삽입됨(BudgetOpt 2.0 결과 7.3과 동일 방식).

### 9.4 결과 상담 범위(정책서 8.5)

| 구분 | 답변 범위 |
|---|---|
| 큐레이션 결과 이해 | 적용된 조건, 후보 선정 과정, 선별 과정 단계별 기준 |
| 매체·상품 설명 | 개별 매체·상품의 특성과 선정 근거, 해당 Fit에 포함된 이유 |
| 매체·상품 비교 | 후보 간 특성·조건 충족 여부·적합도 평가 근거의 차이 |
| 기본 광고 지식 | 광고 용어·지표 등 일반 개념 |

**수행하지 않는 요청**(안내 문장은 SpinX 문서 관할, 아래는 방향만 정의): 조건 변경에 따른 결과 수정·재산출·추정 → 복제 후 조건을 수정해 재생성하도록 안내 / 매체·상품별 예산 배분 → BudgetOpt 2.0 이용 안내 / 예상 도달 산출 → Reach Caster 이용 안내 / 결과 밖 매체·상품 추천 → 확인할 수 없는 범위 안내 / 최종 조합의 정답 판정 → 검토 근거 설명으로 대체.

- **기획 의도**: 제안 질문이 수행하지 않는 요청을 부추기면 사용자가 거절 답변을 먼저 경험하므로, 제안 질문은 항상 수행 범위 안에서 만듦(V15).

### 9.5 공통 원칙(정책서 8.6)
- **근거 준수**: 확인 가능한 사실만 설명하고 데이터가 부족하면 한계를 안내함.
- **상대 표현**: 비교 대상을 명시하고 "높은 편"·"낮은 편"으로 설명하며, 과거 실적을 미래 성과로 보장하지 않음.
- **사용 기준**: 기존 SpinX 이용 권한·사용량·제한 정책을 따름. 자동 생성되는 결과 설명은 사용자 대화 사용량에서 제외함.

### 10.2 규칙별 상세

**V1 진입 상태**
- 조건: 목록·SNB에서 Pending·Processing·Error 큐레이션 클릭(AdCurator_CurationList_Spec.md 6.2).
- 기대 결과: 이동하지 않음. URL을 직접 입력해 들어온 경우의 처리는 15.1 Q3.

**V2 더보기 메뉴 권한**
- 조건: Agency/Client로 진입(샘플: `?role=agency`).
- 기대 결과: 헤더의 More(⋮) 아이콘이 **화면에 없음**(비활성 아님). 공유·정보 툴팁·SpinX 입력 바는 보임.
- 경계: 담기·CTA·간편 생성의 외부 사용자 노출은 15.1 Q9(현재 구현은 노출).

**V3 최대 개수**
- 조건: 담은 개수 = 50인 상태에서 담지 않은 행(경계: 49 → 담기 가능 / 50 → 차단 / 50에서 1개 빼면 다시 가능).
- 기대 결과: 담지 않은 행의 `+ 담기`가 흐리게 비활성되고 눌러도 담기지 않음. hover 시 `더 담을 수 없어요`. 이미 담은 행은 뺄 수 있음.

**V4 토글**
- 조건: `+ 담기` 클릭 → `✓ 담음` 클릭.
- 기대 결과: 첫 클릭에 즉시 담기고, 두 번째 클릭에 즉시 빠짐. 같은 매체·상품이 두 번 담기지 않음. 확인 다이얼로그 없음.

**V5 개수 표시**
- 조건: 담기·빼기(행, 전체 담기·빼기, 다이얼로그 ×).
- 기대 결과: 하단 CTA 버튼과 ActionDock `예산 최적화 하기`에 같은 숫자 배지가 즉시 갱신됨. 0개 → 배지 없음.

**V6 유지 범위**
- 조건: 담은 뒤 새로고침, 다른 화면으로 이동 후 재진입, BudgetOpt로 이동.
- 기대 결과: 담은 상태가 모두 사라지고 0개로 시작함. 이탈 확인 다이얼로그는 표시되지 않음.

**V7 전체 담기·빼기**
- 조건: 열 헤더의 `전체 담기` / `전체 빼기` 클릭.
- 기대 결과: 그 구역에서 검색·필터에 걸러진 전체(펼치지 않은 행 포함)가 담기거나 빠짐. 모두 담기면 라벨이 `전체 빼기`로 바뀜.
- 경계: 남은 자리 < 담을 수 → 남은 자리만큼만 담고 토스트 `최대 50개까지 담을 수 있습니다. {N}개만 담았습니다.` / 이미 50개 → 버튼 비활성, hover `더 담을 수 없어요` / 대상 0건 → 버튼 없음 / 검색 `kakao` 중 Best Fit 전체 담기 → kakao 행만 담김.

**V8 검색**: 6.6의 규칙(매체명·상품명·상품 설명 부분 일치, 대소문자 무시, 트리밍, 실시간, 두 구역 범위)이 기대 결과임. 선별 이유 문장으로는 찾아지지 않음. 검색 중 두 구역 제목 옆 개수가 일치 개수로 바뀜.

**V9 필터**
- 조건: 프로모션 포함 큐레이션에서 `포함`만 / `미포함`만 / 둘 다 / 없음 선택.
- 기대 결과: `포함`만 → `· 매체 프로모션`이 있는 행만 / `미포함`만 → 없는 행만 / 둘 다·없음 → 전체. 배지 = 선택 수. 검색과 함께 쓰면 AND.
- 경계: 프로모션 미포함 큐레이션 → `필터` 버튼 없음 / `필터 초기화` → 필터만 해제, 검색어 유지.

**V10 더 보기**: 두 구역이 각각 독립적으로, 표시 수 10 → 클릭 시 20 → … 남은 개수가 10 미만이면 `{남은 개수}개 더 보기`. 모두 표시되면 버튼 없음. 버튼은 목록 하단 가운데.

**V11 결과 없음**: 문구 `조건에 맞는 매체·상품이 없습니다.`(초기화 링크 없음). 제목 옆 개수 `0`, 그 구역의 `전체 담기` 없음.

**V12 프로모션 표시 조건**
- 조건: 프로모션 포함 AND 캠페인 기간과 하루 이상 겹치는 프로모션 존재(경계: 겹침 0일 → 미표시 / 하루 → 표시).
- 기대 결과: 상품 설명 뒤 `· 매체 프로모션`, 클릭 시 상품 팝업의 프로모션 영역. 팝업 2줄에 `캠페인 기간 중 {N}일 적용`.

**V13 미포함 비노출**: 프로모션 미포함으로 생성 → `· 매체 프로모션`, 팝업의 프로모션 영역, `필터` 버튼, 안내 툴팁의 프로모션 문장이 없음. 행 레이아웃은 포함일 때와 같음.

**V14 해석 생성 실패**: 5.4의 실패 문구 2개를 원문대로 표시, `이어서 질문하기`·타이핑 효과 미노출. 차트는 정상 표시.

**V15 제안 질문 범위**: ActionDock 제안 질문에 9.4의 "수행하지 않는 요청"에 해당하는 질문이 없음.

**V16 대안 카드 표시**
- 조건: 같은 업종 집행 1등과 평가 KPI 효율 1등을 **Best Fit 안에서** 각각 구함.
- 기대 결과: 1등이 Best Match와 **다른 상품**이면 해당 대안 카드를 표시, **같은 상품**이면 카드를 만들지 않음. 두 관점의 1등이 서로 같은 상품(≠ Best Match)이면 `Industry Favorite` 카드와 `Top Performer` 카드가 **각각** 같은 상품으로 표시됨(병합 없음, 카드 총 3장).
- 경계: 데이터 산출 불가 관점은 제외 / 동점은 목록 순위가 앞선 상품 / 카드는 항상 2~3개.

**V17 막대 높이·정렬·그린**
- 기대 결과: 막대 높이가 점수 합에 비례하고 합 내림차순으로 왼쪽부터 정렬됨. 그린은 종합 적합도 1위(목록 1위) 막대 하나이며 말풍선·테두리 등 별도 표식이 없음. 모든 막대의 폭이 같음(칸의 58%, 최대 32px). 막대 hover 시 그 막대만 축 칸으로 나뉘고 툴팁에 매체명·상품명·축별 `상위 {N}%`(순위·Best Match 표기 없음).
- 경계: Best Match가 점수 합 1위가 아니면 그린이 맨 왼쪽이 아닌 자리에 있음(정상) / 합이 같으면 목록 순위가 앞선 쪽이 왼쪽 / 막대 18개처럼 적으면 막대가 넓어짐(최대 32px).

**V18 Best Fit / Good Fit 구분**
- 기대 결과: Good Fit ≥ 1 → 마지막 Best Fit 막대와 첫 꼬리 막대 사이(보통 간격 가운데)에 점선 + `Best Fit {N}` / `Good Fit {M}` + 꼬리 min(M, 6)개 + `···`. Good Fit 0 → `Best Fit {N}`만. 꼬리 hover 시 반응 없음.

**V19 좌우 정렬**
- 기대 결과: 차트 맨 윗줄(Y축 제목·Best Fit/Good Fit 라벨) = 왼쪽 첫 카드 윗선, 해석 본문 끝 = 왼쪽 마지막 카드 아랫선. 타이핑·리사이즈 중 흔들림 없음. `이어서 질문하기 →`는 아랫선 밖 허용.
- 경계: 카드 2장(9·10번)처럼 왼쪽이 낮으면 차트 최소 높이 때문에 아랫선이 어긋날 수 있음(5.5 예외).

**V20 Good Fit 구역**
- 기대 결과: Good Fit ≥ 1 → 접힌 상태로 `Good Fit List {N}` / `Best Fit보다 적합도는 낮지만 보조로 검토해 볼 만한 매체·상품이에요` + `펼치기 ↓`. 누르면 펼쳐지고(`접기 ↑`, 열 헤더 + 행 10개) 다시 누르면 접힘. 새로고침하면 접힌 상태. Good Fit 0 → 구역 없음.

**V21 행 문구 길이·형식**
- 기대 결과: 상품 설명 30자 이내 명사구·마침표 없음(경계: 30 허용 / 31 위반). 선별 이유 100~150자(경계: 99·151 위반, 100·150 허용), 첫 문장이 결론, 캠페인 입력값 하나 이상과 연결, 해요체. Good Fit 선별 이유에는 낮게 평가된 축이 들어감. 별도 결론 구절은 없음.
- 경계: 위반 문구의 처리는 15.1 Q8.

**V22 상세 표시**: 상품 팝업 `매체·상품 상세`가 구매 방식 → 소재 형식 → 타게팅 지원 → 디바이스 → 보장 형태 → 최소 집행 금액 → 추천 타겟 순서로 값 있는 항목만 표시. 값 없는 항목은 행 없음. ✓·`조건 완화` 없음.

**V23 레이더 표시**: Best Fit은 `lg`, 평가 축 5~6개 레이더(그린 면 + muted 점선 평균) + 가운데 범례, 점수·점·툴팁·해석 없음. Good Fit은 `md`, 레이더 없음. 푸터는 `확인` 1개.

**V24 시나리오명**
- 조건: 다이얼로그 열기 / 입력.
- 기대 결과: `(AC-{큐레이션 ID}) {큐레이션명}`으로 프리필(예: `(AC-1) 11월 신제품 런칭 매체 큐레이션`, `25/50`). 최대 50자(51자째 입력 차단). 공백만 남으면 `시나리오명을 입력해 주세요.` + 생성 비활성.

**V25 캠페인 기간**
- 조건: 큐레이션 캠페인 기간 일수(시작·종료 포함).
- 기대 결과: ≤ 90일 → 그대로 프리필 / > 90일 → 비우고 안내 끝에 `큐레이션 기간이 90일을 넘어 다시 선택해야 합니다.`. 시작·종료 중 하나라도 없으면(첫 입력 이후) `캠페인 시작일과 종료일을 모두 선택해 주세요.`
- 경계: 90일 → 프리필 / 91일 → 비움. 다이얼로그에서 직접 90일을 넘겨 고르는 것은 BudgetOpt 2.0 생성 화면과 같이 막지 않음(15.1 Q14).

**V26 총 예산**: 숫자만 입력(비숫자 무시), 콤마 자동, 최대 11자리(12자리째 차단), 한글 금액 병기. 미입력/0 → `총 예산을 입력해 주세요.`

**V27 KPI**: 노출/클릭/조회/도달 중 1개. 미선택(첫 입력 이후) → 4개 버튼 테두리 destructive + `KPI를 선택해 주세요.`

**V28 전달 판별·재검증**
- 조건: 담은 매체·상품, 선택한 KPI.
- 기대 결과: 미지원 매체 → KPI와 무관하게 `⚠ 미지원 매체` + 취소선, 전달 제외. 학습 결과 없음 → KPI를 고른 뒤에만 `학습 결과 없음` + 취소선, 전달 제외. KPI를 바꾸거나 행을 빼면 판별·순서·개수 줄·하단 설명·생성 버튼이 즉시 다시 계산됨.
- 경계(샘플): 어느 큐레이션이든 Best Fit 상위 3개를 담으면 → KPI 전 `전달 2 / 30개 · 미지원 매체 1개` / `노출` → `전달 1 / 30개 · 미지원 매체 1개 · 학습 결과 없음 1개` / `클릭`으로 변경 → `전달 2 / 30개 · 미지원 매체 1개`.

**V29 전달 개수**
- 기대 결과: 전달 < 2 → `최소 2개 이상의 매체·상품을 담아 주세요.`(학습 결과 없음이 있으면 `최소 2개 이상의 매체·상품이 전달되어야 합니다. 다른 KPI를 선택하거나 더 담아 주세요.`) / 전달 > 30 → `전달 {N} / 30개` 빨간색 + `최대 30개까지 전달할 수 있습니다. {N−30}개를 빼 주세요.` 두 경우 모두 생성 비활성.
- 경계: 1 → 에러 / 2 → 통과 / 30 → 통과 / 31 → 에러. 예: 34개를 담고 KPI `클릭` → `전달 31 / 30개 · 미지원 매체 2개 · 학습 결과 없음 1개` → × 3번 → `전달 28 / 30개`, 생성 활성, CTA 배지 31.

**V30 확정 이동**: 모든 입력이 유효할 때 `BudgetOpt 2.0 생성` → `/budgetopt/scenario/new`로 이동하며 시나리오명·업종·기간·총 예산·KPI·전달 매체·상품을 넘김(브랜드·제외 행은 넘기지 않음). 현재 생성 화면은 값을 읽지 않음(Q10).

## 11. 인터랙션 플로우

### 11.1 정상 플로우
1. 큐레이션 목록(또는 SNB·슬롯 홈)에서 완료된 큐레이션 클릭 → 결과 화면. 막대가 올라오는 모션 뒤에 SpinX 해석이 타이핑됨.
2. 좌측 카드로 결론(Best Match 등)을 확인하고, 차트에서 그린 막대의 위치와 hover 칸으로 근거를 확인함. 그린의 뜻은 Info 툴팁에서 확인함.
3. 목록에서 선별 이유를 읽고, 상품명을 눌러 상세(레이더·매체·상품 상세·프로모션)를 확인함. 필요하면 검색·필터로 좁힘.
4. 마음에 드는 매체·상품의 `+ 담기`를 누르거나, 열 헤더 `전체 담기`로 한 번에 담음. 담은 개수가 하단 CTA와 ActionDock 액션에 배지로 쌓임.
5. 필요하면 `Good Fit List`를 펼쳐 더 검토하고 담음.
6. 하단 `BudgetOpt 2.0으로 예산 최적화하기`(또는 ActionDock `예산 최적화 하기`) → 간편 생성 다이얼로그.
7. 시나리오명·업종·기간을 확인하고 총 예산·KPI를 입력. 전달 내역에서 제외 행을 확인하고, 필요하면 KPI를 바꾸거나 ×로 뺌 → `BudgetOpt 2.0 생성` → BudgetOpt 2.0 시나리오 생성 화면.

### 11.2 에러·경계 플로우
1. 50개를 담은 상태에서 담지 않은 행의 `+ 담기` → 비활성, hover `더 담을 수 없어요`. `전체 담기`로 상한을 넘기면 남은 자리만 담고 토스트.
2. 검색·필터 결과 0건 → `조건에 맞는 매체·상품이 없습니다.` 검색 X·`필터 초기화`로 복원.
3. SpinX 해석 생성 실패 → 차트 아래에 실패 문구(차트·수치는 정상). 새로고침하면 다시 시도.
4. 담은 뒤 새로고침 → 담은 상태가 사라짐(정상 동작).
5. 다이얼로그에서 전달 1개(예: 3개 담고 1개 미지원, 1개 학습 결과 없음) → 개수 부족 에러, KPI를 바꾸면 전달이 늘어 해소될 수 있음.
6. 다이얼로그에서 전달 31개 이상 → 초과 에러, ×로 빼면 해소.

### 11.3 프로모션 미포함 큐레이션
1. 목록 행에 `· 매체 프로모션`이 없고 `필터` 버튼이 없으며 팝업에 프로모션 영역이 없음. 나머지 화면은 포함 큐레이션과 동일.

### 11.4 외부 사용자(Agency/Client)
1. Shared Slot 진입 → 결과 조회·검색·필터·공유(Copy Link, Export to Excel)·SpinX 질문 가능.
2. 헤더 더보기 메뉴는 없음. 담기·CTA·간편 생성 노출은 15.1 Q9.

## 12. 검증 포인트 (TC 도출)

**진입·권한**
- Completed 큐레이션 클릭 시 결과 화면(/adcurator/curation/{id}/result)으로 이동하는가. Pending/Processing/Error는 이동하지 않는가(목록·SNB 모두).
- Admin/Marketer로 진입 시 헤더 더보기 메뉴가 보이는가. Agency/Client로 진입 시 더보기 아이콘이 **화면에 없는가**. 공유 메뉴·정보 툴팁·SpinX 입력 바는 보이는가.

**헤더**
- 헤더가 한 줄(큐레이션명 / 메타 요약 / 세로 구분선 / 공유·정보·더보기)이고 솔루션 뱃지가 없는가. 큐레이션명이 길면 말줄임되고 hover 시 전체 이름이 보이는가.
- 메타 요약이 `•`로 연결되고 업종 → 기간 → 목적 → 속성 조건 → 특성 조건 순서인가. 프로모션 항목이 없는가.
- 브랜드를 선택한 큐레이션은 `브랜드/업종 {브랜드} / {업종}`, 업종을 직접 선택한 큐레이션은 `업종 {업종}`인가. 기간이 `기간 yyyy-mm-dd → yyyy-mm-dd`인가.
- 목적이 줄임 없이 모두 고정 순서·` / ` 구분으로 표시되는가(예: [트래픽, 인지, 조회] → `인지 / 조회 / 트래픽`). 목적 툴팁이 없는가.
- 속성 조건이 1개 이상일 때만 `속성 조건 {N}개` + 돋보기가 있고, 돋보기를 누르면 속성 조건 모달이 열리는가. 특성 조건이 1개 이상일 때만 `특성 조건 {N}개`(동작 없음)가 있고, 0개면 항목 자체가 없는가.
- 완화가 있을 때만 헤더 아래에 `모든 조건을 충족하는 매체·상품이 없어 조건 {N}개를 제외하고 선별했습니다.` + `제외한 조건 보기`가 있고, 링크가 속성 조건 모달을 여는가.
- 속성 조건 모달: 제목 `속성 조건`, 설명 문구, `기준명 | 항목` 표에 속성 기준만 있는가. 완화가 있으면 표 위 알림 `모든 조건을 충족하는 매체·상품이 없어, 결과에 영향이 가장 적은 조건을 제외하고 선별했습니다.`가 있고 해당 행이 흐리게 `미반영`인가. 버튼이 `확인` 1개인가. 오버레이·Esc로 닫히는가.
- Share 클릭 시 `Copy Link`, `Export to Excel` 2개만 표시되는가. Copy Link 시 `링크가 복사되었습니다.`가 표시되는가.
- Info hover 시 Curation ID(#{id})·생성일시(생성자·마스킹 이메일)·완료일시만 표시되고 설명 항목이 없는가.
- 복제 시 `(복제) {원본명}`, 캠페인 기간이 빈 생성 Step 1로 이동하는가. 삭제 확정 시 성공 토스트 후 약 1.5초 뒤 목록으로 이동하는가.

**Curation Highlights**
- 제목 `Curation Highlights` 아래에 캡션이 없는가.
- 카드가 세로로 쌓인 가로형 카드이고, 왼쪽에 영문 카드명 + 한글 부제, 오른쪽에 매체명 + 상품명(최대 2줄)이 있는가. 아이콘·한 줄 설명·개수 타일이 없는가.
- Best Match 카드가 항상 1개이고 목록 Best Fit 1위와 같은 상품인가. 부제가 `캠페인에 딱 맞는`인가. Best Match 카드만 muted 배경인가. 카드 어디에도 그린이 없는가.
- 카드에 마우스를 올려도 변화가 없고, 클릭해도 아무 동작이 없는가. 카드 hover가 차트 막대를 강조하지 않는가.
- 대안 카드 표시가 V16과 같은가(관점 1등이 Best Match와 같으면 카드 없음). 두 관점 1등이 같은 상품이면 병합 없이 카드 2장에 같은 상품이 보이는가(3번 큐레이션). 카드 수가 2~3개인가.

**Curation Fit**
- 헤더가 `Curation Fit` + Info 아이콘이고 한글 질문 제목·부제가 없는가. Info hover 시 5.1의 안내 문구와 그린 견본 + `그린 막대가 Best Match입니다.`가 원문대로 표시되는가.
- 막대 수가 Best Fit 수와 같고, 평상시 단색이며, 점수 합 내림차순인가. 그린 막대가 목록 1위 상품 하나뿐이고 말풍선·테두리·폭 차이가 없는가. 모든 막대 폭이 같은가.
- 막대가 적은 큐레이션(예: 2번, 18개)에서 막대가 넓어지는가(최대 32px).
- Y축 선이 없고 위 `높음` / 아래 `낮음`, 맨 위 왼쪽 `적합도 점수 합`이 있는가. 숫자 눈금·X축 눈금·X축 제목이 없는가.
- Good Fit이 있으면 마지막 Best Fit 막대와 첫 꼬리 막대 사이가 보통 막대 간격과 같고 그 가운데에 점선 구분선이 있는가. `Best Fit {N}` / `Good Fit {M}`, 꼬리 막대(최대 6개) + `···`가 있는가. 꼬리에 hover해도 반응이 없는가. Good Fit이 0이면 `Best Fit {N}`만 있는가.
- 막대 hover 시 그 막대만 축 칸으로 나뉘고 다른 막대가 흐려지는가. 툴팁에 매체명·상품명·축별 `상위 {N}%`(맨 위 칸이 맨 위)가 있고 순위·`Best Match` 표기가 없는가.
- 막대 클릭 시 아무 동작이 없는가. 진입 시 모션이 1회 재생되고, "동작 줄이기" 설정에서는 바로 최종 상태인가.
- 차트 맨 윗줄이 첫 카드 윗선과, 해석 본문 끝이 마지막 카드 아랫선과 맞는가. 해석 타이핑 중·창 크기 변경 중에 차트가 흔들리지 않는가(V19).
- SpinX 해석이 `SpinX for Ad Curator`로 타이핑되고, 끝난 뒤 `이어서 질문하기 →`가 나타나는가. 클릭 시 SpinX 패널이 열리고 입력창에 `#Campaign Fit 차트 `가 채워지며 **전송되지 않는가**.
- 해석 생성 실패 시 실패 문구 2개가 원문대로 표시되고 `이어서 질문하기`가 없는가.

**목록**
- Best Fit 구역이 `Best Fit List {N}`(개수 회색)이고, 아래 줄 왼쪽 `이번 캠페인에 가장 잘 맞아 먼저 검토할 매체·상품이에요` / 오른쪽 `생성 시점 기준 · yyyy-mm-dd` + Info가 같은 위계로 있는가. Info hover 시 포함·미포함에 맞는 툴팁 문구가 나오는가.
- 열 헤더가 `순위 | 매체·상품 | 선별 이유 (SpinX 심볼 + SpinX가 선별 이유를 작성했어요) | 전체 담기`이고, 배경·글자가 Reach Caster 결과 테이블 헤더와 같은가. Good Fit 구역을 펼쳤을 때도 같은 열 헤더가 있는가.
- 처음 10개가 표시되고 가운데 정렬된 `{M}개 더 보기 · {표시} / {전체}`로 10개씩 추가되는가. 모두 표시되면 버튼이 사라지는가.
- 순위 번호가 그룹 내 순위이고 모두 muted이며 검색·필터 후에도 유지되는가.
- 행이 순위 / 매체명 / 상품명(굵게) / 상품 설명(· 매체 프로모션) / 선별 이유(보통 굵기) / 담기로 구성되고 세로 가운데 정렬인가. 행에 굵은 글씨가 상품명 하나뿐인가(결론 구절 없음).
- 상품명 클릭 시 상품 팝업이 열리는가. 상품명·`· 매체 프로모션`·담기 이외의 행 영역 클릭 시 동작이 없는가.
- 선별 이유가 100~150자이고 첫 문장이 결론이며 캠페인 입력값 연결이 있는가. Good Fit 선별 이유에 낮게 평가된 축이 있고 대비가 한 단계 낮은가(V21).
- Good Fit이 1개 이상이면 `Good Fit List {N}` / 설명 한 줄 + `펼치기 ↓`가 접힌 상태로 있고, 누르면 펼쳐지고(`접기 ↑`) 다시 누르면 접히는가. Good Fit 0개면 구역이 없는가(V20).
- 검색: 매체명·상품명·상품 설명 일부(대소문자 무시, 앞뒤 공백 무시)로 두 구역에서 함께 찾아지는가. 선별 이유로는 찾아지지 않는가. 두 구역 제목 옆 개수가 일치 개수로 바뀌는가.
- 필터: 프로모션 포함 큐레이션에만 `필터` 버튼이 있는가. 드롭다운이 `매체 프로모션` / `포함` / `미포함` / `필터 초기화`(폭 전체)이고 결과 개수 표시가 없는가. 선택 결과와 배지 숫자가 V9와 같은가. `필터 초기화`가 검색어를 지우지 않는가.
- 검색·필터 결과 0건에서 `조건에 맞는 매체·상품이 없습니다.`만 표시되고 초기화 링크·`전체 담기`가 없는가.
- 프로모션 표시 조건(V12)과 미포함 비노출(V13)이 지켜지는가. 겹침 0일 → 미표시, 하루 → 표시.

**담기**
- 행의 `+ 담기`가 테두리 없는 muted 텍스트이고, 행 hover 시 진해지며, 누르면 굵은 `✓ 담음`으로 바뀌는가. 다시 누르면 빠지는가.
- 담은 개수가 하단 CTA 버튼과 ActionDock `예산 최적화 하기`에 같은 숫자로 표시되고, 0개면 두 곳 모두 배지가 없는가(V5).
- 50개를 담으면 담지 않은 행의 `+ 담기`가 비활성이고 hover 시 `더 담을 수 없어요`가 보이며 눌러도 담기지 않는가. 50개에서 1개를 빼면 다시 담을 수 있는가.
- Best Fit `전체 담기` → 걸러진 Best Fit 전체(펼치지 않은 행 포함)가 담기고 라벨이 `전체 빼기`로 바뀌는가. `전체 빼기` → 모두 빠지는가. Good Fit은 펼쳤을 때만 버튼이 보이는가(V7).
- 검색 중 `전체 담기`가 검색 결과만 담는가. 상한을 넘기면 남은 자리만 담고 `최대 50개까지 담을 수 있습니다. {N}개만 담았습니다.` 토스트가 뜨는가.
- 검색·필터로 행이 숨어도 담은 상태와 개수가 유지되는가.
- 새로고침·재진입 시 담은 상태가 사라지고 이탈 확인이 뜨지 않는가(V6).

**상품 팝업**

- 레이더에 이 상품(그린 면)과 Best Fit 평균(점선)이 있고, 범례가 가운데에 있으며, 점수·점·툴팁·해석 문구·영역 제목이 없는가. 모든 Best Fit 상품에서 면이 그린인가.
- `매체·상품 상세`가 회색 상자 안 `항목명 | 값` 행이고, 구매 방식 → 소재 형식 → 타게팅 지원 → 디바이스 → 보장 형태 → 최소 집행 금액 → 추천 타겟 순서로 값 있는 항목만 표시되는가. 추천 타겟이 있으면 항상 맨 마지막인가. ✓·`조건 완화`가 없는가(V22).
- 프로모션 영역에 `프로모션` 제목, 프로모션명 + `원문 보기`(새 탭), `{시작일} → {종료일} · 캠페인 기간 중 {N}일 적용`, 혜택(굵게)·조건·이점 행, 생성 시점 안내가 있는가. 겹치는 프로모션이 둘 이상이면 가장 많이 겹치는 1개인가.
- `· 매체 프로모션` 클릭 시 같은 팝업이 프로모션 영역 위치로 열리는가. `확인`·오버레이·Esc로 닫히고 다시 열면 맨 위부터인가.

## 13. 데이터 개념 및 용어 매핑

> 상세 타입은 구현 코드가 단일 진실 공급원임(`src/components/adcurator/resultTypes.ts`). 여기서는 규칙·플로우 이해에 필요한 개념과 용어 매핑만 정리함.

### 13.1 구조적 특징
- 결과는 **생성 시점 스냅샷**임(큐레이션 속성 + 반영된 조건 + 평가 축 목록 + 매체·상품별 축 점수·순위·그룹·문구·속성·프로모션 + 왕중왕 카드 산정 결과 + SpinX 해석 + 생성일). 이후 다시 계산하지 않음.
- 적합도 그룹은 Best Fit·Good Fit만 화면에 노출함. Low Fit은 목록에 포함되지 않음.
- 담은 상태는 결과와 별도인 **화면 상태**이며 저장하지 않음(담은 순서대로 매체·상품 id 목록).
- 검색·필터 상태도 화면 상태이며 두 구역에 함께 적용됨.

| 생성 시점 기준 | 결과 생성일 | 안내 줄·프로모션 안내 |
| 평가 KPI / 효율 지표 | Top Performer 산정 기준 | 정책서 3.4 확정 후 매핑 |

## 14. 스타일·구현 지침

- 화면 고유 스타일은 **Tailwind 유틸리티 클래스**로 작성함. 인라인은 동적 값(막대 진입 모션 지연, 차트 좌표)에만 씀(handoff-implementation-guide).
- 차트는 **Recharts**로 구현함(codebase-patterns 4장): `BarChart` + `Bar`(커스텀 shape로 단색·hover 칸·꼬리), `YAxis`(방향 라벨), `ReferenceLine`(기준선), `Tooltip`(커스텀 content). Y축 제목·구분선·라벨·`···`는 `usePlotArea`로 플롯 영역 기준 좌표에 그림. 상품 팝업 레이더도 Recharts.
- `btn`, `input`, `dropdown`, `dialog-*`, `checkbox-custom`, `custom-scrollbar` 등 공통 클래스는 그대로 사용함.
- 색상은 디자인 토큰(`hsl(var(--...))`)만 사용함. 시그니처 그린은 `--bo-accent` 토큰이며 **차트의 Best Match 막대(hover 칸 포함)** 한 곳과 그 뜻을 알려 주는 Info 툴팁 견본에 씀. 예외는 상품 팝업 레이더의 이 상품 면(모든 Best Fit 상품). 카드·순위·목록에는 그린을 쓰지 않음.
- Primary 버튼은 프로덕트 표준 스펙(BOScenarioList의 New Scenario와 동일 pill)을 따름.
- 다이얼로그는 레디셋 공통 다이얼로그(`dialog-overlay`·`dialog-content`·`dialog-header`·`dialog-footer`)를 그대로 쓰고 하단 영역을 따로 꾸미지 않음. 읽기 전용 다이얼로그 버튼은 primary `확인`. 크기는 ui-dialog-policy: 속성 조건 `md`, 상품 팝업 `lg`(Best Fit) / `md`(Good Fit), 간편 생성 `md`, 삭제·이동 `confirm`(기존 재사용).
- 같은 구조의 선례를 우선 재사용함: 헤더 형식(BudgetOpt 2.0 결과), 헤더 액션(Reach Caster 결과), SpinX 해석 블록(BudgetOpt 2.0 결과 `BOSpinXInsight`, 라벨만 `SpinX for Ad Curator`), 다음 단계 CTA(BudgetOpt 2.0 결과의 Reach Caster CTA), 간편 생성 다이얼로그(BudgetOpt 2.0 결과 `BOReachCasterEasyCreateModal` 구성 + BudgetOpt 2.0 생성 Step 1·2 입력·`CustomDateRangePicker`), 열 헤더(Reach Caster 결과 테이블 헤더), 필터 드롭다운(레디셋 메인 필터), ActionDock(common, 액션 배지 옵션 추가).
- 이벤트 핸들러는 `handle` 접두사를 씀(codebase-patterns 11-3).
- 상품명은 밑줄(`_`) 뒤에 줄바꿈 기회를 넣는 공통 컴포넌트(`ACProductName`)로 표시함.
- 신규 컴포넌트는 `src/components/adcurator/`에 두고 접두사 `AC`를 씀.

### 15.2 구현 완료 후 문서 정합
화면정의서와 구현이 끝난 뒤 한 번에 처리함.
- 정책서 4.3: 왕중왕 카드 정의를 본 문서 4장(정답 1개 + 다를 때만 대안, 항상 2~3개, 후보 풀 Best Fit, 병합 없음)으로 갱신.
- 정책서 4.4·8.4: 시각화와 SpinX 차트 해석 대상을 퍼널에서 평가 축 점수 막대 차트(본 문서 5장)로 갱신. 선별 과정 수치는 화면에 노출하지 않음을 반영.
- 정책서 6장: 컬렉션(저장·공유·패널)은 이번 범위에서 제외하고, 화면 안에서만 유지되는 담기로 대체했음을 반영.
- 정책서 7.2: BudgetOpt 2.0 연계를 간편 생성 다이얼로그(8.3)로 갱신. 시나리오명 접두 `(AC-{ID})`, 미지원 매체·학습 결과 없음 제외, 전달 2~30개.
- 생성 화면정의서(AdCurator_CurationCreate_Spec.md): Step 1 캠페인 설명 입력창 높이 규칙, Step 2 기준 설명 문구·SpinX 안내 상자 삭제·분석 로딩 문구, 속성 기준 추가 다이얼로그 제목·설명, Configuration Summary(특성 기준 개수만, 0개는 `—`) 반영.

### 15.3 문구 톤 (문구 일관성 원칙)
- **목록 설명 줄, 선별 이유, 카드 부제, 다음 단계 CTA 카피, 담기 관련 안내(`더 담을 수 없어요`), 열 헤더 안내**: 해요체 — BudgetOpt 2.0 결과 CTA 선례.
