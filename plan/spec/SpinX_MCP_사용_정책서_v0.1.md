# 1. 목적 및 적용 범위

## 1.1 목적
SpinX App이 MCP 서버의 함수(tool)를 LLM 호출에 사용할 때, **보안 위험을 사전에 걸러내기 위한 심사·승인 원칙과 처리 프로세스**를 정의한다.

## 1.2 적용 범위
- SpinX에 MCP 서버를 등록·사용하려는 모든 SpinX App
- 전역(global) 및 특정 App 소속 서버 전체
- 등록 → 심사 → 승인 → 노출 → 변경 대응에 이르는 전 과정

## 1.3 인터페이스 범위
- 본 정책의 기능은 현재 **백엔드 API 기준**으로 제공되며, 일반 사용자용 운영 UI는 확인되지 않았다. (현재 화면은 개발자용 API 테스트 도구)
- 운영 UI가 구축될 경우 화면 정의는 **별도 화면 정의서**에서 다룬다. `[확인필요:Q10]`

# 2. 용어 정의

> 본 정책서 및 이후 화면 정의서·Docs·TC의 공통 기준 용어. 모든 문서는 이 정의를 따른다.

## 2.1 핵심 개념

| 용어 | 정의 |
|---|---|
| SpinX | 사내 LLM API 게이트웨이. SpinX App이 LLM을 호출할 때 거치는 관문 |
| SpinX App | SpinX를 사용하기 위해 **App 키를 발급받은 사용 단위**. MCP 서버 등록·소속의 기준이 됨 |
| MCP | Model Context Protocol. LLM이 외부 함수(tool)를 호출해 쓰게 하는 규격 |
| MCP 서버 | 함수(tool) 묶음을 제공하는 원격 서버. 등록·심사·승인의 단위 |
| 함수 (tool / 도구) | MCP 서버가 제공하는 개별 기능. LLM이 실제 호출하는 대상 |
| 함수 활성화 | 승인된 함수를 LLM이 실제로 사용할 수 있도록 켜는 것 |

## 2.2 역할

| 용어 | 정의 |
|---|---|
| App 관리자 (사용자) | SpinX App 키를 발급받아 SpinX를 쓰는 사용자. MCP 서버 사용을 **요청**하는 주체 |
| SpinX 관리자 | SpinX 운영 담당(기획·AX팀). 요청 건을 **승인/거부**하는 주체 |

## 2.3 심사 단위

| 용어 | 정의 |
|---|---|
| 서버 | MCP 서버 1개 단위. 소속 App과 상태를 가짐 |
| 함수 | 서버에 속한 개별 기능. 서버에 종속되며 개별 심사 대상 |
| 소속 | 서버를 소유한 SpinX App. 전역(모든 App 공용) 또는 특정 App 소속으로 구분 |

## 2.4 접근 모드 (노출 범위 결정 방식)

| 모드 | 정의 | 노출 범위 |
|---|---|---|
| 전체 (all) | 전체 함수 노출 | 서버의 모든 함수 |
| 화이트리스트 (allow) | 지정한 함수만 노출 | 선택 함수만 |
| 블랙리스트 (deny) | 지정 함수 제외 전체 노출 | 제외 외 전부 |

## 2.5 상태

**서버 상태**

| 상태 | 의미 |
|---|---|
| 등록 대기 (pending) | 등록 직후, 또는 변경 감지로 회귀된 상태. 함수 선택 가능 |
| 승인 요청 (requested) | App 관리자가 승인을 요청한 상태 |
| AI 심사 완료 (ai_reviewed) | AI 1차 심사가 끝나 SpinX 관리자 승인 대기 중 |
| 승인 (approved) | SpinX 관리자 승인 완료. 함수가 활성화되어 사용 가능 |
| 거부 (rejected) | 거부됨. 재요청 가능(사유 유지) |
| 정지 (suspended) | 승인 상태였으나 연결 실패로 일시 정지 |

**함수 상태**: 심사 전(pending) / 승인(approved) / 거부(rejected)

# 3. 역할과 권한

| 역할 | 권한 |
|---|---|
| App 관리자 | 서버 사용 요청, 함수 노출 범위(접근 모드) 설정, 재요청, 상태 알림 수신 |
| SpinX 관리자 | 승인 대기 건 요약 조회, 서버 승인/거부, 변경 감지 건 재검토 |

- App 관리자(요청)와 SpinX 관리자(승인)는 **분리**한다. 자가 승인을 방지하기 위함. `[확인필요:Q8]`
- SpinX 관리자의 승인 작업은 MCP 기반으로 제공될 예정이다. (관리자가 MCP 클라이언트에서 승인 대기 건 요약을 조회·승인) `[확인필요:Q8]`

# 4. 처리 프로세스

전체 흐름은 아래 순서를 따른다. 각 단계의 주체와 결과 상태를 함께 정의한다.

```
[App 관리자] 사전 확인 → 등록 → 노출 범위 설정 → 승인 요청
                                        ↓
[시스템] AI 1차 심사 (데이터 유출 등 위험 판정)
                                        ↓
[SpinX 관리자] 최종 승인 / 거부
                                        ↓
[시스템] 승인 시 함수 활성화 · App 관리자에게 상태 알림
                                        ↓
[시스템] 승인 후 변경 감지 시 → 등록 대기로 회귀 → 재심사
```

## 4.1 사전 확인 (App 관리자)
- 등록 전, 서버가 연결되는지와 함수 목록을 미리 확인한다. (저장하지 않음)
- 이 결과를 보고 어떤 **접근 모드**(전체/화이트리스트/블랙리스트)로 노출할지 판단한다.

## 4.2 등록 (App 관리자)
- 서버명·URL·연결정보와 **상태 알림 수신용 이메일**을 입력해 등록한다.
- 연결 테스트를 통과하면 **등록 대기(pending)** 상태로 저장된다.

## 4.3 노출 범위 설정 (App 관리자)
- 접근 모드를 정해 실제로 노출할 함수를 확정한다.
- 최소 권한 원칙에 따라 **화이트리스트(allow)를 기본 권장**한다.

## 4.4 승인 요청 (App 관리자)
- 노출 함수 확정 후 승인을 요청한다. 상태가 **승인 요청(requested)** 으로 전환된다.

## 4.5 AI 1차 심사 (시스템)
- 함수별로 위험 여부를 자동 판정한다. 현재 심사는 **데이터 유출 가능성 판단에 집중**한다. (판정 기준은 5장)
- 완료 시 상태가 **AI 심사 완료(ai_reviewed)** 로 전환된다.

## 4.6 최종 승인 / 거부 (SpinX 관리자)
- SpinX 관리자가 AI 심사 결과 요약을 확인하고 최종 승인 또는 거부한다.
- 거부 시 **사유를 입력**하며, 사유는 재요청 참고용으로 유지된다.

## 4.7 함수 활성화 및 알림 (시스템)
- 승인되면 함수가 활성화되어 LLM이 사용할 수 있다.
- 각 상태 전환 시 App 관리자에게 **이메일로 상태를 통지**한다.

## 4.8 변경 대응 (시스템)
- 승인된 서버의 함수가 변경되면, 모니터링이 이를 감지해 상태를 **등록 대기(pending)로 되돌린다.**
- 이후 App 관리자에게 알림이 가고, 4.4~4.6의 심사·승인 절차를 다시 거친다.

# 5. 정책 규칙

정의된 프로세스 위에서 적용되는 판단 원칙이다.

## 5.1 노출 범위
- 기본 권장 모드는 **화이트리스트(allow)** — 필요한 함수만 노출하는 최소 권한 원칙.
- 블랙리스트(deny) 서버에 함수가 신규 추가되면, 심사 없이 자동 노출하지 않고 **변경 대응(4.8) 절차를 적용**한다. `[확인필요:Q2]`

## 5.2 거부 · 재요청
- 거부 시 SpinX 관리자는 **사유를 필수 입력**한다.
- 거부 사유는 재요청 참고를 위해 App 관리자에게 **공개**한다. `[확인필요:Q3]`
- 재요청 횟수는 필요 시 제한을 둔다. (제안: 연속 3회) `[확인필요:Q3]`

## 5.3 승인 후 변경
- 승인된 서버의 함수 변경은 **재승인 대상**이다. (등록 대기로 회귀)
- 재승인 완료 전까지 변경분의 노출 처리(중단 여부)는 `[확인필요:Q1]`

## 5.4 상태 알림
- App 관리자는 요청 시 등록한 이메일로 상태 전환(심사 완료·승인·거부·변경 회귀·정지)을 통지받는다.
- SpinX 관리자의 승인 대기 확인은 이메일이 아닌 MCP 요약 조회로 처리한다.
- 통지 이벤트 범위는 `[확인필요:Q5]`

## 5.5 처리 기준 시간 (SLA)
- SpinX 관리자의 최종 승인/거부는 요청 후 **영업일 기준 2일 이내** 처리를 권장한다. (제안값)

# 6. 보안 심사 기준

AI 1차 심사 및 SpinX 관리자 판정 시 아래 위험 유형을 기준으로 한다.
현재 AI 심사는 **데이터 유출 가능성 판단에 집중**되어 있다. 아래 표는 기획(SpinX 관리자)이 검토·확장해 심사 기준에 반영한다. `[확인필요:Q9]`

| 위험 유형 | 판정 기준 | 기본 처리 |
|---|---|---|
| 사내정보 외부 전송 | 데이터를 외부로 보낼 수 있음 | 거부 |
| 파괴적 동작 | 삭제·수정 등 되돌릴 수 없는 동작 | 거부(조건부 검토) |
| 시스템 설정·권한 변경 | 설정·권한·접근제어 변경 | 거부 |
| 임의 코드 실행 | 코드·명령 실행 가능 | 거부 |
| 인증정보·개인정보 노출 | 토큰·PII 반환 | 거부 |
| 설명 모호성 | 함수 목적·동작이 불명확 | 보류(재확인) |
