## 1. 화면 개요

### 1.1 기능 정의
특정 Slot에 속한 **큐레이션 목록**을 조회·관리하는 화면임. 큐레이션을 검색·필터·정렬해 찾고, 생성이 완료된 큐레이션은 결과 화면으로 진입하며, 복제·이동·삭제 같은 관리 작업을 수행함. 큐레이션 생성 요청이 접수되면 이 화면에 즉시 추가되고, 처리 상태가 새로고침 없이 갱신됨.

**기획 의도**
- 한 Slot에서 만든 여러 큐레이션을 업종·캠페인 기간·캠페인 목적 단위로 한눈에 구분하고, 완료된 것만 골라 결과로 진입하게 함.
- 큐레이션은 생성 후 수정할 수 없으므로(정책서 2.1.1), 조건을 바꾸려는 사용자의 경로는 "복제 → 조건 수정 → 재생성"임. 목록은 이 경로의 출발점이므로 복제를 가장 쉬운 관리 작업으로 제공함.
- 생성은 비동기로 처리되므로(정책서 2.1.4), 사용자가 이 화면을 떠나지 않고도 진행 상황과 실패 시점(오류 발생 일시)을 확인할 수 있어야 함.

### 1.2 문서 활용처
- **개발 참고**: 프론트엔드 구현 시 화면 동작·규칙·표기 기준 문서로 활용됨.
- **제품 Docs**: 본 정의서의 기능 설명·의도가 사용자 대상 기능 문서의 기반이 됨.
- **AI 기반 TC 생성**: 상태·검색·필터·정렬·관리 작업 규칙(Section 2~9)이 테스트 케이스의 원천 데이터가 됨. 각 규칙은 조건 → 기대 결과로 검증 가능하게 작성함.

### 1.3 진입 경로
- SNB(사이드바) Ad Curator 클릭, SlotHome 솔루션 카드, SlotBoard 등에서 진입함.
- URL: /adcurator
- Breadcrumb: SlotBoard / {Slot명} / Ad Curator
- 신규 생성 요청 직후 생성 화면에서 이 화면으로 복귀하며, 방금 생성한 큐레이션이 Pending 상태로 최상단에 보임(기본 정렬이 생성일시 내림차순이므로).

### 1.4 화면 구조 (세로 흐름)
Slot 헤더(SlotHeader, Reach Caster 공용)
→ 타이틀("Ad Curator") + New Curation 버튼
→ 액션바(좌: 검색·필터 적용 후 총 개수 / 우: 선택 시 일괄작업(N개 선택됨 · 이동 · 삭제) · 검색 · 필터)
→ 큐레이션 테이블
→ 페이지네이션

- 공통 레이아웃(SlotHeader, workspace-content, 토스트 등)과 권한 매트릭스는 공통 정의서를 따름. 이 문서는 Ad Curator 목록 고유 규칙만 다룸.
  - 레이아웃: plan/spec/Common_Layout_Spec.md
  - 권한: 예측분석_고도화_프로젝트_정책서 1.3.2 (Agency/Client는 조회만 가능하며 생성·선택·메뉴가 노출되지 않음)
- 타이틀 라인 좌측에 "Ad Curator" 제목과 신규 생성 버튼을 둠. 버튼은 BudgetOpt 2.0 목록의 New Scenario 버튼과 동일한 컴포넌트·스펙을 쓰고 라벨만 "New Curation"으로 함. 클릭 시 큐레이션 생성 화면 Step 1로 이동함(/adcurator/curation/new).

### 1.5 역할별 노출

공통 권한 매트릭스(예측분석_고도화_프로젝트_정책서 1.3.2, 시나리오 관리 기준)를 큐레이션에 동일 적용함. 큐레이션도 시나리오와 같은 위치의 관리 단위이기 때문임.

| 요소 | Admin / Marketer | Agency / Client |
|---|---|---|
| 목록 조회 · 검색 · 필터 · 정렬 | 가능 | 가능 |
| Completed 행 클릭(결과 진입) | 가능 | 가능 |
| New Curation 버튼 | 노출 | 미노출 |
| 행 체크박스 · 헤더 체크박스 | 노출 | 미노출 |
| 일괄 작업(N개 선택됨 · 이동 · 삭제) | 노출 | 미노출 |
| 행 컨텍스트 메뉴(⋮: 복제 · 이동 · 삭제) | 노출 | 미노출 |

- Agency/Client는 Shared로 공유된 Slot에서만 이 화면에 접근함(공통 정책 2.3.1).
- **기획 의도**: 외부 사용자는 결과 열람만 하게 하고, 데이터를 바꾸는 모든 진입점을 감춰 오조작과 권한 에러를 원천 차단함. 비활성(disabled)이 아니라 **미노출**로 처리해 "왜 못 누르지?"라는 혼란을 없앰.
- **구현 메모**: 현재 `ACCurationList`의 `canManage` prop으로 분기하도록 구현되어 있으나, 역할 체계 연동 전이라 페이지가 prop을 넘기지 않아 모든 역할에 노출됨. 역할 연동 시 연결 필요.

## 2. 액션바

좌측에 현재 검색·필터가 적용된 큐레이션 개수("N Curations")를 표시하고, 우측에 액션(선택 시 일괄작업 → 검색 → 필터)을 배치함.

| 요소 | 노출 조건 | 동작 |
|---|---|---|
| N Curations | 항상 | 검색·필터 적용 후 결과 개수 |
| N개 선택됨 | 1개 이상 선택 + Admin/Marketer | 현재 선택된 큐레이션 수 |
| 이동 버튼 | 1개 이상 선택 + Admin/Marketer | 이동 다이얼로그 열기(Section 8.2) |
| 삭제 버튼 | 1개 이상 선택 + Admin/Marketer | 선택 항목을 삭제 대상으로 삭제 다이얼로그 열기(Section 8.3) |
| 검색 | 항상 | 클릭 시 검색 입력창 확장(Section 3) |
| 필터 | 항상 | 클릭 시 필터 드롭다운 열기, 적용 개수 배지 표시(Section 4) |

- 일괄 작업에 복제는 없음. 복제는 신규 생성 화면으로 이동하는 동작이라 한 번에 하나만 가능하기 때문임(Section 8.1).
- 선택은 **검색·필터·정렬·페이지 변경 시 해제**됨. 화면에 보이지 않는 항목이 일괄 삭제·이동에 포함되는 사고를 막기 위함.

## 3. 검색

| 항목 | 규칙 |
|---|---|
| 트리거 | 검색 버튼 클릭 시 입력창으로 확장, autoFocus |
| 검색 대상 | 큐레이션명 + 생성자 이름 동시 |
| 매칭 방식 | 부분 일치(substring), **대소문자 무시** |
| 공백 처리 | 입력값 앞뒤 공백을 트리밍(trim) 후 비교. 공백만 입력한 경우 검색 미적용(전체 표시) |
| 타이밍 | onChange 실시간 필터(디바운스 없음) |
| placeholder | "큐레이션명, 생성자 검색" |
| 결과 없을 때 | 별도 "검색 결과 없음" 문구 없이 테이블 빈 상태(Section 6.4)로 빠짐 |
| 닫힘 | 입력값이 빈 상태에서 blur 시 버튼으로 축소. X 버튼 클릭 시 검색어 초기화 + 축소 |

- 생성자 이메일은 마스킹되어 표시되므로 검색 대상에서 제외함(마스킹된 값으로 원본이 추정되는 것을 막기 위함).
- **기획 의도**: 큐레이션명뿐 아니라 생성자로도 찾게 해, 협업 환경에서 "누가 만든 큐레이션"을 빠르게 탐색하게 함.

## 4. 필터

필터 버튼 클릭 시 드롭다운을 열며, 적용된 항목 수를 버튼에 배지로 표시함. 3개 그룹(상태 / 캠페인 목적 / 업종) 모두 다중 선택 체크박스임. UI 톤앤매너는 BudgetOpt 2.0 목록 필터와 동일함.

| 그룹 | 항목 | 매칭 |
|---|---|---|
| 상태 | Completed / Processing / Pending / Error | 선택한 상태만 노출(OR) |
| 캠페인 목적 | 인지 / 조회 / 트래픽 / 전환 | 선택한 목적을 **하나라도 포함**한 큐레이션 노출(OR) |
| 업종 | 목록 데이터에서 수집한 고유 업종 목록 | 선택한 업종만 노출(OR). 목록이 길면 영역 내 스크롤 |

- **다중 그룹 조합**: 서로 다른 그룹 간에는 AND로 적용됨(예: 상태=Completed AND 캠페인 목적=전환).
- **캠페인 목적 매칭 예**: 큐레이션이 [인지, 전환]이고 필터가 "전환"이면 노출됨. 필터가 "조회"이면 미노출됨. 필터가 "인지, 조회"이면 노출됨(하나라도 포함).
- **적용 개수 배지**: 상태+캠페인 목적+업종 선택 수의 합.
- **필터 초기화**: 드롭다운 하단 버튼으로 세 그룹 모두 해제함(항상 노출).

## 5. 정렬

정렬 가능한 컬럼 헤더 클릭으로 정렬함. 같은 컬럼을 다시 클릭하면 방향이 토글됨(오름/내림). 다른 컬럼 클릭 시 해당 컬럼 기준 **내림차순**으로 시작함. 체크박스·컨텍스트 메뉴·목적을 제외한 **모든 데이터 컬럼이 정렬 대상**임.

| 컬럼 | 정렬 기준 | 정렬 방식 |
|---|---|---|
| ID | 큐레이션 ID | 숫자 비교 |
| 큐레이션 | 큐레이션명 | 문자열 비교 |
| 업종 | 업종명 | 문자열 비교 |
| 기간 | 시작일 | 일시 비교 |
| 상태 | 상태명 | 문자열 비교 |
| 생성자 | 생성자 이름 | 문자열 비교 |
| 생성일시 | 생성일시 | 일시 비교(초기 정렬 기준) |

- **초기 상태**: 생성일시 **내림차순** — 최신 생성 큐레이션이 위로 옴.
- **방향 표시**: 활성 정렬 컬럼 헤더에만 화살표 아이콘 표시(오름=위, 내림=아래).
- **정렬 적용 시점**: 검색·필터가 적용된 결과에 정렬을 적용하고, 그 뒤 페이지네이션으로 분할함.
- **목적 컬럼은 정렬 대상이 아님**. 헤더에 정렬 화살표를 두지 않고, 헤더 클릭에도 반응하지 않음(커서 기본). 다중 선택 값이라 "어느 쪽이 위인지" 사용자가 예측할 수 있는 정렬 기준이 없고, 목적별로 좁히는 용도는 필터(Section 4)가 이미 제공하기 때문임.

## 6. 테이블

### 6.1 컬럼

| 컬럼 | 내용 | 비고 |
|---|---|---|
| 체크박스 | 행 선택 | Admin/Marketer만 노출. 헤더 체크박스는 현재 페이지 전체 선택/해제 |
| ID | {id} | muted 표기. "#" 접두 없이 숫자만 표시 |
| 큐레이션 | 큐레이션명 | Completed만 강조(진입 가능), 그 외는 흐리게 |
| 업종 | 업종명 | muted |
| 목적 | 선택한 목적 | 요약 표기(아래 "캠페인 목적 표기 규칙" 참조). 정렬 비대상 |
| 기간 | 시작일 → 종료일 | 각 yyyy-mm-dd, 2줄 표기 |
| 상태 | 상태 뱃지(위) + 보조 정보(아래) | 보조 정보: Completed는 완료일시, Error는 오류 발생 일시(Section 6.2) |
| 생성자 | 이름 + 이메일 | 이름 위, 마스킹된 이메일 아래(maskEmail) |
| 생성일시 | 생성 요청 일시 | **yyyy-mm-dd hh:mm:ss** |
| (컨텍스트 메뉴) | ⋮ | Admin/Marketer만 노출. 행별 복제/이동/삭제(Section 6.3) |

- 설명(description) 속성은 목록에 노출하지 않음(생성 정보 확인용이며 목록 판단 기준이 아님).
- **캠페인 목적 표기 규칙**: 선택 개수와 무관하게 컬럼 폭이 일정하도록 요약 표기를 씀.

| 선택 개수 | 셀 표시 | hover/포커스 시 툴팁 |
|---|---|---|
| 1개 | 목적명(예: "전환") | 없음 |
| 2개 이상 | "{대표 목적} 외 {N-1}"(예: 3개 선택 시 "인지 외 2") | 선택한 목적 전체를 가운뎃점으로 구분해 표시(예: "인지 · 조회 · 트래픽") |

  - **대표 목적**은 사용자가 선택한 순서와 무관하게 "인지 → 조회 → 트래픽 → 전환" 고정 순서에서 가장 앞선 목적임. 같은 큐레이션은 항상 같은 표기가 되도록 하기 위함.
  - 툴팁 안의 목적 나열도 동일한 고정 순서를 따름.
  - 툴팁은 셀 **위쪽**에 표시함. 아래쪽은 마우스 커서에 가려지고, 테이블 하단 행에서는 테이블 영역 밖으로 잘릴 수 있기 때문임.
  - **기획 의도**: 목적은 최대 4개라 전부 나열하면 컬럼이 과도하게 길어지고, 개수만 보이면 어떤 목적인지 알 수 없음. 대표 목적 하나로 성격을 짐작하게 하고, 나머지는 필요할 때 펼쳐 보게 함.

### 6.2 상태별 표시 · 동작

상태 셀 표시와 행 클릭 동작을 상태 기준으로 한 표에서 정의함.

| 상태 | 상태 셀 표시 | 행 클릭 |
|---|---|---|
| Pending | "Pending" 뱃지 | 진입 불가 |
| Processing | "Processing" 뱃지 | 진입 불가 |
| Completed | "Completed" 뱃지 + 아래에 완료일시 | 결과 화면으로 이동(/adcurator/curation/{id}/result). 큐레이션명 정상 강조, 커서 pointer |
| Error | "Error" 뱃지 + 아래에 오류 발생 일시 | 진입 불가 |

- 상태 셀은 위 줄에 상태 뱃지, 아래 줄에 상태별 보조 정보(완료일시 / 오류 발생 일시)를 표시함. Pending과 Processing은 보조 정보가 없어 뱃지만 표시함.
- Processing은 진행 단계를 표시하지 않음. 작업 서버에서 단계 값을 받지 않음(단계별 진행 정보가 사용자에게 의미가 없다고 판단해 제외).
- 완료일시·오류 발생 일시는 **yyyy-mm-dd hh:mm:ss**로 표시함. 완료일시는 별도 컬럼 없이 Completed 뱃지 아래에서만 확인함.
- 완료가 아닌 큐레이션은 이름을 흐리게(opacity) 처리해 진입 불가를 시각적으로 알림.
- 체크박스·컨텍스트 메뉴 영역 클릭은 행 클릭(결과 진입)으로 전파되지 않음.
- 상태 뱃지 스타일은 BudgetOpt 2.0 목록의 상태 뱃지 스타일(STATUS_STYLES)과 동일하게 재사용함.
- Ad Curator는 재시도 기능이 없으므로(정책서 상태 정의에 재시도 없음) Error 행의 복구 경로는 복제 후 재생성임(Section 8.1).


### 6.3 행 컨텍스트 메뉴 (⋮)

| 항목 | 동작 |
|---|---|
| 복제 | 해당 큐레이션 설정을 프리필한 큐레이션 생성 화면으로 이동(Section 8.1) |
| 이동 | 해당 큐레이션을 선택 상태로 두고 이동 다이얼로그 열기 |
| 삭제 | 해당 큐레이션을 삭제 대상으로 두고 삭제 다이얼로그 열기 |

- 메뉴 외부 클릭 시 닫힘.
- 복제·이동·삭제는 큐레이션 상태와 무관하게 모든 행에서 가능함.

### 6.4 빈 상태
- 조건: 현재 페이지에 표시할 큐레이션이 없음.
- 문구: "생성된 큐레이션이 없습니다."
- 검색·필터로 결과가 0건이 된 경우에도 동일한 빈 상태 문구가 노출됨(전용 문구 없음).

## 7. 실시간 상태 갱신

정책서 2.1.3: "화면 새로고침 없이 상태 변경 사항을 동일 화면에 즉시 반영한다."

| 규칙 | 내용 |
|---|---|
| 갱신 대상 | 처리 상태, 완료일시, Error 오류 발생 일시 |
| 갱신 범위 | 변경된 **행만** 갱신. 목록 전체를 다시 그리지 않음 |
| 유지되는 UI 상태 | 검색어, 필터, 정렬, 현재 페이지, 행 선택, 열린 컨텍스트 메뉴·툴팁 |
| 신규 큐레이션 | 다른 곳(생성 화면)에서 요청된 큐레이션은 이 화면 진입 시 Pending으로 목록에 포함됨 |
| 필터와의 관계 | 갱신된 값으로 필터를 다시 평가함. 예: 상태 필터=Processing일 때 해당 행이 Completed가 되면 목록에서 사라지고 "N Curations"가 줄어듦 |
| 정렬과의 관계 | 갱신된 값으로 정렬을 다시 평가함(상태 정렬 중이면 행 위치가 바뀔 수 있음) |
| 선택과의 관계 | 갱신으로 목록에서 사라진 행은 선택에서도 제거됨 |
| 완료 시 | Completed로 전환되면 완료일시가 표시되고 행이 진입 가능한 스타일로 바뀜 |

- **기획 의도**: 비동기 생성은 수 분이 걸릴 수 있으므로, 사용자가 다른 작업을 하다 돌아와도 목록이 최신 상태이고, 보던 맥락(필터·정렬)이 흐트러지지 않아야 함.

## 8. 관리 작업 (복제 / 이동 / 삭제)

### 8.1 복제
- 컨텍스트 메뉴 "복제" 클릭 시 해당 큐레이션의 입력값(큐레이션명, 설명, 업종 결정 방식과 값, 프로모션 포함 여부, 캠페인 목적)을 프리필한 **큐레이션 생성 화면 Step 1**로 이동함.
- 이 시점에는 큐레이션이 생성되지 않음. 생성 화면에서 값을 수정하고 생성 요청을 해야 새 큐레이션이 만들어짐.
- 복제 대상은 한 번에 1개임(일괄 복제 없음).
- **큐레이션명**은 원본 이름 앞에 "(복제)"와 공백 한 칸을 붙여 프리필함(예: 원본 "11월 프로모션" → "(복제) 11월 프로모션"). 복제본을 다시 복제하면 접두가 중첩됨(예: "(복제) (복제) 11월 프로모션"). 접두 추가로 큐레이션명 최대 길이를 넘는 경우의 처리는 생성 화면 정의서를 따름.
- **캠페인 기간은 프리필하지 않고** 시작일·종료일이 모두 빈 상태로 시작함. 프리필 값은 나머지 항목 모두 수정 가능함.
- 캠페인 기간을 비우는 이유: 복제본은 새 캠페인 일정으로 만드는 경우가 대부분이고, 시작일은 오늘부터만 선택할 수 있어(정책서 3.2) 원본의 지난 기간이 남으면 입력 규칙과 충돌하기 때문임.
- **기획 의도**: 생성된 큐레이션은 수정할 수 없고(정책서 2.1.1), 결과도 생성 시점 기준으로 고정됨(정책서 4.2). 최신 데이터나 다른 조건으로 다시 보려면 복제 후 재생성이 유일한 경로이므로, 입력 부담 없이 같은 조건에서 출발하게 함. Error 상태 큐레이션의 복구 경로이기도 함.

### 8.2 이동 다이얼로그
- 제목: "큐레이션 이동", 설명: "선택한 N개 큐레이션을 다른 Slot으로 이동합니다."
- 이동 대상 Slot을 select로 선택함. 목록에는 **현재 Slot과 같은 광고주의 다른 Slot**만 표시함(공통 정책 4.5.2 동일 광고주 제약). **미선택 시 이동 버튼 비활성**.
- 이동된 큐레이션은 대상 Slot의 가시성 설정을 자동으로 상속함(공통 정책 4.5.2).
- **프로모션 포함 큐레이션은 Shared Slot으로 이동할 수 없음**. Shared Slot도 대상 목록에서 선택은 가능하며, 선택 항목에 프로모션 포함 큐레이션이 있는 상태에서 [이동]을 누르면 이동하지 않고 "이동 불가 안내" 다이얼로그를 띄움(Section 8.2.1).
- 확정 시: 처리 후 성공 토스트 "N개 큐레이션이 성공적으로 이동되었습니다.", 선택 해제, 이동된 항목은 이 목록에서 제거됨.
- 실패 시: 오류 토스트 "큐레이션 이동에 실패했습니다. 다시 시도해주세요."를 표시함. 목록에는 변화가 없고(이동 미반영) 선택 상태는 유지됨.
- 취소/닫기 시: 선택한 대상 Slot 값 초기화. 다이얼로그를 다시 열면 미선택 상태로 시작함.

#### 8.2.1 이동 불가 안내 다이얼로그 (Shared Slot × 프로모션 포함)

DataShot 목록의 이동 불가 안내 다이얼로그(DataShot_DatasetList_Spec.md 7.2)와 동일한 패턴·컴포넌트를 사용함.

**의도**: 여러 건을 일괄 이동할 때 대상이 Shared Slot이고 선택 항목에 프로모션 포함 큐레이션이 섞여 있으면, 이동 전에 막고 어떤 건이 문제인지 명확히 보여줌. 프로모션 정보는 내부 운영 정보이므로 외부(Agency/Client)에 공유되는 Shared Slot으로 넘어가면 안 되기 때문임.

| 항목 | 스펙 |
|---|---|
| 트리거 시점 | 이동 다이얼로그에서 [이동] 버튼 클릭 시점 |
| 차단 조건 | 선택 항목 중 1건이라도 프로모션 포함이고, 선택한 대상 Slot이 Shared인 경우 |
| 타이틀 | "이동 불가 안내" |
| 설명 | "아래 {N}건의 프로모션 포함 큐레이션은 Shared Slot으로 이동할 수 없습니다. 해당 큐레이션을 제외한 후 다시 시도해 주세요." |
| 차단 목록 | ID · 큐레이션명 2열 테이블. **이동할 수 없는 큐레이션만** 나열(선택 항목 전체가 아님). {N}은 이 목록의 건수 |
| 버튼 | [확인] 1개 |
| 확인 클릭 | 안내 다이얼로그만 닫음. **이동은 실행되지 않음.** 이동 다이얼로그와 선택 상태, 선택한 대상 Slot은 그대로 유지됨 |

- **전체 차단**: 일부만 프로모션 포함이어도 이동은 한 건도 실행되지 않음(일부만 이동되어 사용자가 결과를 따로 확인해야 하는 상황을 막기 위함).
- 행 컨텍스트 메뉴에서 단건으로 이동하는 경우에도 동일하게 동작함(목록 1건).
- 대상 Slot이 Shared가 아니면(Private/Internal) 프로모션 포함 여부와 무관하게 정상 이동함.

### 8.3 삭제 다이얼로그
- 제목: "큐레이션을 삭제하시겠습니까?", 설명: "선택한 N개 큐레이션을 삭제하면 복원할 수 없습니다. 정말로 삭제하시겠습니까?"
- 확정(삭제, destructive) 시: 목록에서 해당 큐레이션 제거 + 성공 토스트 "N개 큐레이션이 성공적으로 삭제되었습니다.", 선택 해제.
- 실패 시: 오류 토스트 "큐레이션 삭제에 실패했습니다. 다시 시도해주세요."를 표시함. 목록에는 변화가 없고(삭제 미반영) 선택 상태는 유지됨.
- 취소 시: 삭제 대상 초기화, 목록 변화 없음.
- 큐레이션을 삭제하면 해당 큐레이션의 결과와 컬렉션도 함께 삭제됨.
- **기획 의도**: 삭제는 복구할 수 없으므로(정책서 2.1.1) 확정 전 반드시 복구 불가를 고지함.

### 8.4 토스트
- 성공/오류 2종. 우상단 노출, 3초 후 자동 닫힘. 닫기 버튼 제공.
- 오류 문구 — 이동: "큐레이션 이동에 실패했습니다. 다시 시도해주세요.", 삭제: "큐레이션 삭제에 실패했습니다. 다시 시도해주세요."

## 9. 페이지네이션
- **페이지당 표시 개수 선택**: 10 / 20 / 50 중 선택(기본 10). 변경 시 첫 페이지로 이동함.
- 정렬·필터 적용 후 결과 기준으로 페이지 분할함.
- 처음/이전/페이지 번호/다음/마지막 이동을 제공함. 첫 페이지·마지막 페이지에서는 해당 방향 버튼이 비활성됨.
- 페이지 정보 표기: "{시작}-{끝} / {전체}개"(결과 0건이면 0으로 표기).
- 전체 선택 체크박스는 **현재 페이지** 항목 기준으로 동작함.

## 10. 인터랙션 플로우

### 10.1 정상 플로우
1. Marketer가 New Curation 클릭 → 생성 화면에서 요청 → 목록 복귀, 새 행이 Pending으로 최상단에 보임.
2. 별도 조작 없이 상태가 Processing으로 바뀜.
3. Completed가 되면 완료일시가 채워지고 행이 진입 가능한 스타일로 바뀜.
4. 행 클릭 → 결과 화면 진입.

### 10.2 에러 플로우
1. 생성 중 오류로 행이 Error로 바뀌고, 상태 뱃지 아래에 오류 발생 일시가 표시됨. 행을 클릭해도 이동하지 않음.
2. 컨텍스트 메뉴 "복제" → 프리필된 생성 화면에서 조건을 확인·수정하고 캠페인 기간을 다시 입력해 재요청함.
3. 필요하면 실패한 큐레이션을 삭제함.

### 10.3 외부 사용자 플로우
1. Client가 Shared Slot 진입 → 목록 조회·검색·필터·정렬만 가능. 생성·선택·메뉴 미노출.
2. Completed 행 클릭 → 결과 열람.

## 11. 검증 포인트 (TC 도출)

**권한**
- Admin/Marketer로 진입 시 New Curation 버튼, 헤더·행 체크박스, 행 ⋮ 메뉴가 노출되는가. 1개 이상 선택하면 일괄 작업(N개 선택됨·이동·삭제)이 노출되는가.
- Agency/Client로 진입 시 New Curation 버튼, 헤더·행 체크박스, 일괄 작업, 행 ⋮ 메뉴가 모두 미노출인가(비활성이 아니라 화면에 없음).
- Agency/Client도 목록 조회·검색·필터·정렬이 가능하고, Completed 행 클릭 시 결과 화면으로 이동하는가.

**검색**
- 큐레이션명 일부/생성자 이름 일부 입력 → 해당 항목만 노출되는가(대소문자 무시).
- 검색어 앞뒤에 공백을 넣어도 트리밍되어 공백 없는 검색과 동일한 결과가 나오는가. 공백만 입력 시 전체가 표시되는가.
- 생성자 이메일 일부를 입력하면 결과가 나오지 않는가(이메일은 검색 대상 아님).

**필터**
- 상태=Completed AND 캠페인 목적=전환 → 두 조건을 모두 만족하는 큐레이션만 노출되는가.
- 캠페인 목적 [인지, 전환] 큐레이션이 필터 "전환"에서 노출되고, 필터 "조회"에서 미노출되며, 필터 "인지, 조회"에서 노출되는가.
- 필터 배지 숫자 = 선택한 상태+캠페인 목적+업종 항목 수와 일치하는가.
- 필터 초기화 클릭 시 세 그룹이 모두 해제되고 배지가 사라지는가.

**정렬**
- 초기 진입 시 생성일시 내림차순인가. 생성일시 헤더 재클릭 시 오름/내림이 토글되는가.
- 각 데이터 컬럼 헤더 클릭 시 해당 기준으로 정렬되는가(다른 컬럼 클릭 시 내림차순으로 시작).
- ID는 숫자, 기간은 시작일, 생성일시는 일시 기준으로 정렬되는가.
- 목적 헤더에 정렬 화살표가 없고, 클릭해도 정렬이 바뀌지 않는가.
- 캠페인 목적 1개 선택 시 목적명만, 2개 이상 선택 시 "{대표 목적} 외 {N-1}"로 표시되는가(예: [전환]→"전환", [전환, 인지]→"인지 외 1", [트래픽, 조회, 인지]→"인지 외 2", 4개 전부→"인지 외 3").
- 대표 목적이 선택 순서와 무관하게 "인지 → 조회 → 트래픽 → 전환" 고정 순서의 첫 번째인가.
- 2개 이상 선택된 셀에 hover/포커스하면 전체 목적이 고정 순서로 셀 위쪽 툴팁에 표시되고, 1개 선택 셀에는 툴팁이 없는가.

**테이블 · 상태**
- Completed 행 클릭 → 결과 화면으로 이동하는가. Pending/Processing/Error 행 클릭 → 이동하지 않는가.
- 체크박스·⋮ 메뉴 클릭 시 행 클릭(결과 진입)이 발생하지 않는가.
- Completed 행은 뱃지 아래에 완료일시가 표시되고, Pending/Processing/Error 행에는 완료일시가 표시되지 않는가.
- Processing 행에 "Processing" 뱃지만 표시되고 진행 단계 문구가 없는가.
- Processing에서 Completed로 전환되면 뱃지가 바뀌고 아래에 완료일시가 표시되는가.
- 생성일시·완료일시·오류 발생 일시가 yyyy-mm-dd hh:mm:ss(초 단위까지), 기간이 yyyy-mm-dd로 표시되는가.
- 생성자 이메일이 마스킹되어 표시되는가.
- 빈 목록에서 안내 문구가 노출되는가. 검색·필터로 0건이 된 경우에도 동일 문구가 노출되는가.

**실시간 갱신**
- 화면을 새로고침하지 않아도 Pending → Processing → Completed로 행이 갱신되는가.
- 갱신 중 검색어·필터·정렬·페이지·선택이 유지되는가.
- Error로 바뀌면 오류 발생 일시가 표시되는가.

**관리 작업**
- 큐레이션 1개 이상 선택 → 이동/삭제 버튼이 노출되는가. 0개면 숨는가.
- 검색·필터·정렬·페이지를 바꾸면 선택이 해제되는가.
- 복제 클릭 → 입력값이 프리필된 생성 화면 Step 1로 이동하고, 이 시점에 목록에 새 행이 생기지 않는가.
- 복제 시 큐레이션명이 "(복제) {원본 큐레이션명}"으로 프리필되고, 이미 "(복제)"로 시작하는 큐레이션을 복제하면 접두가 한 번 더 붙는가.
- 복제 시 캠페인 기간(시작일·종료일)이 비어 있고, 업종·프로모션 포함 여부·캠페인 목적·설명은 원본 값으로 프리필되는가.
- 이동 다이얼로그에서 대상 Slot 미선택 시 이동 버튼이 비활성인가. 목록에 같은 광고주의 다른 Slot만 나오는가.
- 프로모션 포함 큐레이션 포함 + 대상 Slot이 Shared → [이동] 클릭 시 "이동 불가 안내" 다이얼로그가 뜨고 이동이 실행되지 않는가(목록 변화 없음, 성공 토스트 없음).
- 안내 다이얼로그의 설명 문구가 "아래 {N}건의 프로모션 포함 큐레이션은 Shared Slot으로 이동할 수 없습니다. 해당 큐레이션을 제외한 후 다시 시도해 주세요."이고, {N}이 차단 목록 건수와 일치하는가.
- 일부만 프로모션 포함일 때 차단 목록에 프로모션 포함 큐레이션만 ID·큐레이션명으로 나열되고, 나머지 선택 항목은 이동되지 않는가.
- 안내 다이얼로그 [확인] 클릭 시 안내만 닫히고, 이동 다이얼로그·선택 상태·대상 Slot이 유지되는가.
- 프로모션 포함 큐레이션이라도 대상 Slot이 Private/Internal이면 정상 이동되는가. 프로모션 미포함 큐레이션은 Shared Slot으로 정상 이동되는가.
- 이동 다이얼로그를 취소/닫기 후 다시 열면 대상 Slot이 미선택인가.
- 삭제 확정 시 해당 큐레이션이 목록에서 제거되고 성공 토스트가 뜨는가. 취소 시 목록이 그대로인가.
- 삭제된 큐레이션의 결과와 컬렉션이 더 이상 조회되지 않는가.
- 이동/삭제 처리 실패 시 오류 토스트가 뜨고, 목록과 선택 상태가 그대로인가 — 이동: "큐레이션 이동에 실패했습니다. 다시 시도해주세요.", 삭제: "큐레이션 삭제에 실패했습니다. 다시 시도해주세요."

**페이지네이션**
- 페이지당 10개 초과 시 페이지네이션이 동작하고, 전체 선택이 현재 페이지 기준인가.
- 페이지당 개수를 10→20→50으로 바꾸면 분할이 반영되고 첫 페이지로 이동하는가.
- 첫/마지막 페이지에서 해당 방향 버튼이 비활성인가. 결과 0건이면 "0-0 / 0개"로 표기되는가.

## 13. 스타일·구현 지침

- 화면 고유 스타일은 **Tailwind 유틸리티 클래스**로 작성함. 애니메이션·차트 등 Tailwind로 복잡한 경우에만 CSS Module을 쓰고, 인라인은 동적 값에만 씀(handoff-implementation-guide).
- `btn`, `input`, `card`, `dropdown`, `workspace-content`, `custom-scrollbar` 등 공통 클래스는 그대로 사용함. Tailwind로 복제하지 않음.
- 색상은 디자인 토큰(`hsl(var(--...))`)만 사용함. HEX 하드코딩 금지.
- 구조·톤앤매너는 BudgetOpt 2.0 시나리오 목록(BOScenarioList)과 동일함. 신규 컴포넌트는 `src/components/adcurator/`에 두고 파일 접두사는 `AC`를 씀.
- 상태 뱃지, 토스트, 이동/삭제 다이얼로그, 필터 드롭다운, 페이지네이션은 BO 목록 구현을 우선 재사용 가능한지 확인한 뒤 신규 작성함.
