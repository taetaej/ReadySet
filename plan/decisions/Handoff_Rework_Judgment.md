# 판단 문서 — 핸드오프 산출물의 프로덕트화 범위

> 결정 로그(Decision / Judgment Record). 사실과 코드 근거 기반.
> 작성일: 2026-09-14
> 관련 문서: `plan/methodology/Zero_Rework_Handoff_Project.md`

---

## 배경

이 산출물(기획 화면 코드)은 처음에는 **실제 코드로 쓸 목적이 아닌 단순 프로토타입**으로 시작했다.
그런데 프로토타입이 실제 프로덕트에 그대로 쓰이게 되면서, 위상이 바뀌었다.

- 프로토타입일 때: 빠르게 화면을 찍어 보여주는 게 목적. 인라인 스타일도 문제가 아니었다.
- 실제로 쓰이는 지금: 프론트에서 이어받아 작업하므로, **핸드오프 시 리워크를 없애고 프로덕트 수준으로 격상**할 필요가 생겼다.

이 판단 문서는 그 격상을 위해 **무엇을, 어디까지 손대야 하는지**를 코드와 개발자 답변으로 확인한 결과를 남긴다.

---

## 확인 방법

1. 실제 코드베이스(ReadySet) 직접 확인 — 인라인 스타일 분포, 스타일 시스템 구조.
2. 프론트 개발자에게 7개 항목 직접 확인 — 프로덕트의 스타일 관리 방식, 실제 리워크 지점.

---

## 확인된 사실

### 1. 산출물은 "전부 인라인"이 아니라 하이브리드다
- 디자인 토큰(`--primary` 등)과 공통 클래스(`btn`/`input`/`card`/`dropdown`)는 **이미 프로덕트와 동일하게** 쓰고 있다.
- 인라인은 주로 **화면 고유 레이아웃/간격/타이포**에 한정돼 있다. 프로토타입 시절의 흔적이 이 영역에 남아 있는 셈이다.

### 2. 시스템 불일치는 없다 (번역 비용 = 0)
- 프로덕트도 순수 CSS + 인라인 + CSS Module + Tailwind **혼합**이며, 토큰·공통 클래스가 산출물과 **동일**하다.
- 즉 격상 작업은 "다른 시스템으로 번역"이 아니라 단순 "인라인 걷어내기"다. 근본적 구조 충돌은 없다.

### 3. 격상 대상은 전체가 아니라 일부 모듈뿐이다
- **slot / reachcaster / datashot**: 프로덕트도 인라인을 **그대로 유지**한다 → 손댈 필요 없음.
- **Budget Optimizer**: `*.module.css` + Tailwind로 옮긴다 → 격상 작업은 **이 영역에 국한**된다.

### 4. 작업의 종류는 단일하고 단순하다
- 개발자가 꼽은 리워크는 **"인라인 걷어내기" 하나**뿐이었다.
- 데이터 바인딩 구조, 컴포넌트 분리, 네이밍 충돌 등 **구조적/설계적 작업은 필요하지 않았다.**

---

## 판단

> **프로토타입에서 프로덕트로의 격상은 필요하나, 그 범위는 좁고 성격은 단순하다.**

- 전면 재작업이 필요한 구조적 과제가 아니다. **Budget Optimizer 한 영역의 스타일 전달 형식을 프로덕트에 맞추면** 프로덕트 수준에 도달한다.
- 시스템 불일치·번역 비용·설계 리워크는 없다. 토큰과 공통 클래스는 이미 프로덕트와 정렬돼 있다.
- 따라서 이 격상은 대규모 프로젝트가 아니라, **한 모듈의 스타일 전달 형식을 프로덕트에 맞추는 국소적 개선**으로 다룬다.

> **[방향 재조정 2026-09-14]** 파일럿(CSS Module 전면 분리) 검증 결과, 개발자가 실제로 원하는 형식은 **Tailwind 우선**(복잡한 스타일만 CSS Module)임이 확인되었다. 전면 CSS Module 분리는 프론트의 컴포넌트 분리 작업을 오히려 증가시켰다. 이에 최종 방향을 **Tailwind 우선**으로 확정하고, 프로덕트 버전에 맞춰 Tailwind v4를 도입하였다. 상세는 `Zero_Rework_Handoff_Project.md` Ⅱ·Ⅲ 참조.

---

## 결정

1. Budget Optimizer 코드베이스 기획서는 앞으로 **Tailwind 유틸리티 우선**으로 작성한다. 복잡한 스타일(애니메이션·차트 등)에 한해 CSS Module로 분리한다. (`Zero_Rework_Handoff_Project.md` Ⅱ. 방향 참조)
2. slot / reachcaster / datashot은 **기존 인라인 방식 유지**한다. 불필요하게 손대지 않는다.
3. 이 격상의 목표는 리워크 제거 + 코드베이스 기획서의 프로덕트 수준화이며, 범위는 위 1·2로 한정한다.
