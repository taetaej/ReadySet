## BO-001. 잠금 반영 최적화안 vs 순수 최적화안 KPI 역전 현상

- 관련 기능: Budget Optimizer — 시나리오 생성(예산 잠금) / 결과 화면(잠금 vs 순수 최적화 비교)
- 우선순위: P1
- 상태: 논의 중
- 등록일: 2026-09-01 / 최종 수정: 2026-09-01

### 이슈 개요
Budget Optimizer는 사용자가 예산을 잠금(Lock)한 상태로 최적화를 실행할 수 있고,
결과 화면에서 "잠금 반영 최적화안"과 "순수 최적화안(예산 잠금 없음)"을 비교해서 볼 수 있다.
이때 **사용자가 설정한 잠금 반영 최적화안의 보장 KPI가, 솔루션이 제공하는 순수 최적화안보다 더 높게 나올 가능성**이 있다.
이는 사용자에게 "내가 직접 설정한 게 솔루션 최적화보다 낫다"는 인상을 줘, 솔루션의 최적화 신뢰도에 대한 오해로 이어질 수 있다.

### 발생 조건
- 사용자가 **CPM이 낮은(단가가 저렴한) 상품에 예산을 과도하게 몰아서 잠금**하는 경우
- 단순 노출량(보장 KPI) 극대화 관점에서만 보면 저단가 상품 집중이 단기적으로 더 큰 보장 KPI 수치를 만들 수 있다.

### 원인 분석
1. **효율 포화(Saturation) 지점 미고려** — 순수 최적화안은 각 매체/상품의 효율 포화 지점을 고려해 포화 구간을 넘는 비효율 투입을 피한다. 반면 사용자가 저단가 상품에 예산을 몰면 포화 여부와 무관하게 단순 노출량이 커져 보장 KPI 수치만 높게 보인다. (실질 효율·성과 품질과는 별개)
2. **매체 우선 배분 구조 (Meridian 모델)** — 최적화 모델은 매체 단위 배분을 먼저 하고 상품 단위로 배분한다. Meridian 모델이 매체 단위 배분을 권장하는 방향과 일치한다. 상품 단위에서 임의로 저단가 상품에 몰아넣는 방식은 모델 권장 구조와 어긋나 수치상 역전이 발생할 수 있다. (구조적 암점이나, 모델 권장 방향 자체는 매체 우선 배분이 맞다.)

### 해결 방안 옵션
| 옵션 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 상품 단위 잠금 제한 | 상품 레벨 잠금을 막고 매체 레벨 잠금만 허용 | 근본 원인 차단, 모델 권장 방향과 일치 | 자유도 저하, 정책/구현 재작업 필요 |
| B. 최적화안 설명 강화 | 순수 최적화안의 배분 근거(효율 포화·매체 우선 배분)를 툴팁/인사이트로 안내 | 자유도 유지, 구현 부담 낮음 | 설명 미열람 시 여전히 오해 가능 |
| C. SpinX 활용 설명 | 차이 발생 시 SpinX가 시나리오 맞춤으로 원인 설명 | 맥락 기반 친절 설명, 솔루션 가치 강조 | 설명 로직/문안 정교화 필요 |
