# BudgetOpt 2.0 — 예산 잠금 상태 판정 로직 (설계 정의)

> 상태: **구현 완료 (프론트 전달용)**. `BOStep2.tsx`에 `computeAllocation`으로 구현·테스트 완료. 추후 `BudgetOptimizer_Scenario_Creation_Spec.md`에 정식 반영 예정.
> 대상 화면: 시나리오 생성 Step 2 (예산 잠금 설정) — `src/components/budgetoptimizer/BOStep2.tsx`
> 목적: 각 항목(매체·상품)의 상태를 **케이스 나열이 아니라 레이어별 우선순위 규칙으로** 판정한다.

---

## 0. 설계 원칙 — 케이스가 아니라 규칙으로

이 로직은 조합이 많아 케이스를 하나씩 정의하면 끝이 없다. 그래서 **단 하나의 질문**을 레이어로 반복해 판정한다:

> **"이 항목이 받을 금액이 자유도 0인가? (= 다른 입력에 의해 하나로 정해지는가?)"**

- 자유도 0 + 내가 잠금 → **잠금**
- 자유도 0 + 다른 잠금 영향 → **자동 배정**
- 자유도 ≥ 1 (모델이 나눔) → **최적화 대상**

판정은 **2개 레이어(매체 → 상품)**로 내려가며, 각 레이어는 **우선순위 순서**로 평가한다(위에서 걸리면 멈춤).

---

## 1. 세 가지 상태

| 상태 (내부값) | 정의 | UI 표시 |
|---|---|---|
| **잠금** (`fixed`) | 사용자가 **직접** 잠금 설정 | 금액 입력칸 |
| **자동 배정** (`auto-confirmed`) | 안 잠갔지만 **다른 잠금 영향으로 금액이 하나로 정해짐** | "자동 배정 N원" |
| **최적화 대상** (`optimize`) | 금액이 하나로 안 정해지고 **모델이 배분** | "최적화 대상" |

---

## 2. 핵심 개념 — "실질 자유 매체"

레이어 판정의 뼈대가 되는 정의. **한 번만 정의하고 전부 여기서 파생된다.**

- **실질 자유 매체** = 매체 토글이 **안 잠겼고(미잠금) AND 하위에 미잠금 상품이 1개 이상** 있는 매체.
  - 즉 "모델이 실제로 배분을 결정할 여지가 있는 매체".
  - 매체 토글은 미잠금이지만 **하위가 전부 잠긴** 매체는 실질 자유 매체가 **아니다** (매체 몫이 하위 잠금 합으로 이미 정해지므로).
- **전역 잔여** = 총예산 − (모든 매체 잠금액 + 미잠금 매체의 하위 상품 잠금액). 실질 자유 매체들이 나눠 가질 돈.

---

## 3. 레이어 1 — 매체 몫 판정 (우선순위 순서)

각 매체에 대해 위에서부터 평가, 처음 걸리는 규칙으로 확정한다.

| 순위 | 조건 | 결과 | 매체 몫 |
|---|---|---|---|
| **M1** | 매체를 직접 잠갔다 | **잠금** | = 매체 잠금액 |
| **M2** | 하위 상품이 **전부 잠김** | **자동 배정** | = 하위 잠금액 합 |
| **M3** | **실질 자유 매체가 나 혼자뿐**(= 1개) | **자동 배정** | = 전역 잔여 + 내 하위 잠금액 합 |
| **M4** | 그 외 (실질 자유 매체 2개 이상) | **최적화 대상** | 미정 (모델이 매체 간 배분) |

> **M3 보충**: "실질 자유 매체가 1개"라는 건, 다른 미잠금 매체가 있어도 그들이 전부 하위 전부 잠금(M2로 이미 확정)이라 **배분을 다툴 매체가 나밖에 없다**는 뜻. 그래서 남은 돈 전부가 내게 온다.
> M2·M3가 동시 성립할 수 있으나(하위 전부 잠금 + 유일 미잠금 매체) 순서상 M2가 먼저 걸린다. 두 경우 몫 계산 결과가 동일하거나(하위합=전역잔여일 때) M2가 더 보수적이므로 안전하다.

---

## 4. 레이어 2 — 상품 몫 판정 (우선순위 순서)

각 미잠금 상품에 대해 위에서부터 평가. (잠근 상품은 레이어 평가 전 **잠금** 확정)

| 순위 | 조건 | 결과 | 상품 몫 |
|---|---|---|---|
| **P1** | 상품을 직접 잠갔다 | **잠금** | = 상품 잠금액 |
| **P2** | 속한 매체 몫이 **미정**(M4) | **최적화 대상** | 미정 |
| **P3** | 매체 몫 확정 + 그 매체에서 **내가 유일한 미잠금 상품**(1개) | **자동 배정** | = 매체 몫 − 형제 잠금액 합 |
| **P4** | 매체 몫 확정 + 미잠금 상품 **2개 이상** | **최적화 대상** | 미정 (모델이 매체 몫 안에서 나눔) |

> **매체는 자동 배정인데 상품은 최적화**가 가능하다. 매체 총 몫은 M3로 정해졌지만(예 500만), 그 안의 상품 배분은 미잠금 상품이 여럿이면 모델이 나눈다(P4). 매체 행 라벨과 상품 행 라벨은 **다른 레이어**로 판정되므로 서로 다를 수 있다.

---

## 5. 레이어 3 — 에러 판정 (레이어 1·2 결과로부터)

진행 차단(“다음” 버튼 비활성). 순서대로 평가.

| 규칙 | 조건 | 메시지 |
|---|---|---|
| **R-초과** | 전체 잠금액 합 > 총예산 (전역 잔여 < 0) | "잠금 예산 합계가 총 예산을 초과합니다." |
| **R-배분0 (매체 내부)** | 매체 몫이 확정된 매체 안에, 미잠금 상품이 있는데 그 상품들이 받을 돈(매체 몫 − 형제 잠금) ≤ 0 | "최적화 대상 상품의 배분 가능 예산이 0원입니다. 총 예산을 늘리거나 일부 잠금을 해제해 주세요." |
| **R-배분0 (매체 간)** | **실질 자유 매체가 1개 이상 있는데(= 최적화 매체 존재), 그들이 나눠 가질 전역 잔여 ≤ 0** | 동일 메시지 (배분 가능 예산 0원) |
| **R-공중** | 전역 잔여 > 0 인데 그 잔여를 받을 **실질 자유 매체가 0개** | "남은 예산(N원)을 배분할 대상이 없습니다. 잠금 금액을 늘리거나 일부 잠금을 해제해 주세요." |

> **R-배분0의 두 레벨 구분 (중요)**: 최적화 대상이 배분받을 돈이 0인 상황은 두 군데서 생긴다.
> ① **매체 내부**: 매체 몫은 정해졌는데 그 안 상품들에게 남는 돈이 0 (매체 잠금을 하위가 다 먹음).
> ② **매체 간**: 매체 몫이 아직 안 정해진 '최적화 매체'들이 있는데, 매체 잠금만으로 총예산을 다 소진해 그들이 나눠 가질 전역 잔여가 0.
> ②는 "실질 자유 매체는 존재하지만 줄 돈이 없다"는 R-공중과 R-배분0(①) 사이의 사각지대였다. (속성 테스트로 발견.)

> 하단 요약 "최적화 대상 N개 상품"의 N = **최적화 대상 상태 상품만** 센다 (잠금·자동 배정 제외).

## 6. 판정 순서 요약 (레이어링 한눈에)

```
입력: 총예산, 매체 잠금, 상품 잠금
  │
  ├─ [레이어 1] 각 매체: M1 잠금 → M2 하위전부잠금 → M3 유일 실질자유 → M4 최적화
  │        (매체 몫 + 매체 행 라벨 확정)
  │
  ├─ [레이어 2] 각 미잠금 상품: P1 잠금 → P2 매체미정 → P3 유일미잠금 → P4 최적화
  │        (상품 몫 + 상품 행 라벨 확정)
  │
  └─ [레이어 3] 에러: R-초과 → R-배분0 → R-공중
           (하나라도 걸리면 "다음" 비활성)
```

## 7. 케이스 표 (규칙 검증용 — 테스트 원천)

아래 표는 **규칙을 새로 만드는 게 아니라, 위 레이어 규칙이 올바른지 확인하는 예시**다. 새 케이스를 발견하면 먼저 "위 규칙으로 어떻게 판정되나"를 보고, 규칙이 설명 못 하면 그때 규칙을 고친다. 금액 단위: 만원.

| # | 입력 요약 | 적용 규칙 | 매체 결과 | 상품 결과 | 에러 |
|---|---|---|---|---|---|
| 1 | 총1000. NAVER잠금100. Meta미잠금+하위2잠금(300+500) | Meta=M3(유일실질자유? Meta 하위 전부잠금→M2), NAVER=M1 | Meta=자동배정900 | NAVER하위=P3 확정100 | R-공중(900중 800배분, 100뜸) |
| 2 | 총1000. M1잠금300,M2잠금200. M3미잠금+하위3비잠금 | M3=M3 | M3=자동배정500 | M3하위3=P4 최적화 | 없음 |
| 3 | 총100. A·B·C잠금(10+10+50). D미잠금+하위1비잠금 | D=M3 | D=자동배정30 | D하위=P3 확정30 | 없음 |
| 4 | 총1000. TP미잠금 하위전부잠금(100+100), TT미잠금 하위(잠금100+비잠금1) | TP=M2, TT=M3(실질자유 1개) | TP=자동배정200, TT=자동배정700 | TT비잠금=P3 확정700 | 없음 |
| 5 | 총1000. TP·TT미잠금, 각 하위1상품 잠금(100,100) | TP·TT=M2, 실질자유 0개 | 둘다 자동배정100 | — | R-공중(잔여800) |
| 6 | 총1000. A잠금400,B잠금500, 하위 비잠금 | A·B=M1 | A·B=잠금 | 하위=P3 확정(매체몫) | R-공중(잔여100 받을 실질자유매체 없음) |
| 7 | 총1000. A·B 각 하위 비잠금 | A·B=M4 | A·B=최적화 | 전부 P2 최적화 | 없음 |
| 8 | 총100. A잠금100(=총). B미잠금 상품 | B=M3(몫 0) | B=자동배정0 | B상품=P3 배분0 | R-배분0 |
| 9 | 총200. A잠금100+하위잠금100+비잠금1. B잠금100 | A=M1 | A=잠금 | A비잠금=P3 배분0 | R-배분0 |
| 10 | 총500. A잠금500, 하위2 비잠금 | A=M1 | A=잠금 | A하위2=P4 최적화 | 없음 |
| 11 | 총1000. M1잠금300,M2잠금200. M3미잠금 하위3비잠금 | M3=M3 | M3=자동배정500 | M1·M2·M3 하위 전부 P4 최적화(9개) | 없음 |
| 12 | 총100. M0잠금59,M3잠금41(합=총예산). M1·M2 미잠금(하위비잠금) | M1·M2=M4(최적화), 전역잔여 0 | M1·M2=최적화 | — | **R-배분0(매체 간)** |

> 표의 "적용 규칙" 열이 핵심 — 각 결과가 **어떤 레이어 규칙으로 나오는지**를 보여, 규칙만으로 판정 가능함을 증명한다.
> ⚠️ 케이스 12는 **속성 테스트(랜덤 5만 건)로 발견한 사각지대**다. 매체 잠금만으로 총예산을 다 써버리면, 비잠금 매체(최적화 대상)들이 받을 돈이 0인데 과거엔 어떤 에러도 안 떴다. R-배분0(매체 간) 규칙으로 차단한다.

## 8. 결정 사항 / 미해결

**결정됨:**
- **모델 입력 처리**: "자동 배정" 금액은 **편의를 위해 UI에만 표시**하고 모델에 넘기지 않는다. 넘기지 않아도 모델이 동일하게 수리적으로 알아낼 수 있다. (화면 표시 전용 값)
- **UI 라벨**: "자동 배정"으로 표시한다. (내부 상태값은 `auto-confirmed`)
- **판정은 케이스 나열이 아니라 레이어 규칙으로** 한다. 케이스 표(7절)는 규칙 검증·테스트 원천 용도.

**미해결 / 더 볼 것:**
- [ ] 추가로 발견되는 케이스는 7절 표에 추가하고, 위 레이어 규칙으로 설명되는지 확인 (안 되면 규칙 보강).

## 10. 구현 참조 (프론트 전달용)

이 로직은 `BOStep2.tsx`에 **순수 함수 `computeAllocation`**으로 구현돼 있다. UI와 분리돼 있어 그대로 이식하거나 테스트할 수 있다.

### 10.1 함수 시그니처 / 입출력 타입

```ts
function computeAllocation(
  totalBudget: number,
  mediaFixed: MediaFixedInput[],   // 매체별 토글 잠금 상태 + 매체 잠금액
  products: ProductInput[]         // 상품별 토글 잠금 상태 + 상품 잠금액
): AllocationResult

type MediaFixedInput  = { mediaId: string; isFixed: boolean; fixedAmount: number }
type ProductInput     = { mediaId: string; productName: string; isFixed: boolean; fixedAmount: number }
type AllocStatus      = 'fixed' | 'auto-confirmed' | 'optimize'

interface MediaAllocation {
  mediaId: string
  status: AllocStatus          // 매체 행 라벨 상태 (레이어 1 결과)
  amount: number | null        // 자동 배정/잠금 매체의 몫, 최적화면 null
  shareConfirmed: boolean      // 매체 몫이 확정됐는가
  share: number | null         // 매체 몫 (내부 계산값)
}
interface ProductAllocation {
  mediaId: string
  productName: string
  status: AllocStatus          // 상품 행 라벨 상태 (레이어 2 결과)
  amount: number | null        // 자동 배정 상품의 몫, 최적화/미정이면 null
}
interface AllocationError { rule: 'R4' | 'R5' | 'R6'; message: string }

interface AllocationResult {
  media: MediaAllocation[]
  products: ProductAllocation[]
  remainingBudget: number       // 전역 잔여 = 총예산 − 모든 잠금액
  fixedTotal: number            // 모든 잠금액 합 (중복 차감 방지 적용)
  optimizeProductCount: number  // 최적화 대상 '상품' 수 (하단 요약 "N개 상품"에 사용)
  errors: AllocationError[]     // 비어 있으면 "다음" 활성, 하나라도 있으면 비활성
}
```

### 10.2 금액 계산식 (자동 배정)

- **매체 몫**:
  - M1 매체 잠금 → `매체 잠금액`
  - M2 하위 전부 잠금 → `하위 상품 잠금액 합`
  - M3 유일 실질 자유 매체 → `전역 잔여 + 그 매체 하위 잠금액 합`
- **자동 배정 상품 몫 (P3)**: `max(0, 매체 몫 − 그 매체 하위 잠금액 합)`
- **전역 잔여(remainingBudget)**: `총예산 − (모든 매체 잠금액 + 미잠금 매체의 하위 상품 잠금액)`
  - ⚠️ 매체 잠금 매체의 하위 상품 잠금액은 **중복 차감하지 않는다** (매체 잠금액에 이미 포함).

### 10.3 UI 바인딩 (상태 → 화면)

각 행은 `status`에 따라 렌더한다. 금액 표기는 천단위 콤마.

| status | 매체 행 | 상품 행 |
|---|---|---|
| `fixed` | 금액 입력칸 (사용자 입력) | 금액 입력칸 |
| `auto-confirmed` | "자동 배정 {amount}원" (금액 강조) | "자동 배정 {amount}원" |
| `optimize` | "최적화 대상" (금액 미표시) | "최적화 대상" |

- 상단 안내문에 "다른 잠금으로 배분 금액이 하나로 정해지는 항목은 '자동 배정'으로 표시됩니다." 한 줄.
- 하단 요약: 총예산 / 잠금 합계(`fixedTotal`) / 잔여 예산(`remainingBudget`, "최적화 대상 `optimizeProductCount`개 상품").
- `errors`가 비어 있지 않으면 하단에 첫 에러 `message`를 destructive 스타일로 표시하고 "다음" 버튼 비활성.
- 색은 토큰(`hsl(var(--...))`)만 사용, HEX 금지 (BudgetOptimizer 모듈 Tailwind-first).

### 10.4 기존 유효성 규칙과의 관계 (R1/R3는 별도)

`computeAllocation`은 **R4·R5·R6(예산 배분 전역)**만 담당한다. 아래는 `BOStep2`의 별도 로직이며 이 함수 밖이다.
- **R1 (매체-상품 계층)**: 하위 상품 잠금액 합 > 매체 잠금액, 하위 전부 잠금 시 합 ≠ 매체액 등.
- **R3 (잠금 시 금액 필수)**: 잠금 토글 ON인데 금액 0/미입력.
- 종합 유효성("다음" 활성)은 R1·R3·R4·R5·R6를 **모두** 통과해야 한다.
