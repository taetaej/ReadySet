# 1. Budget Optimizer 정의

## 1.1 솔루션 개요

Budget Optimizer는 사용자가 설정한 KPI 목표에 따라 선택된 매체/광고상품 간 **최적 예산 배분안**을 도출하는 솔루션이다.

- 22개 업종별 Meridian(Media Mix Model) 기반 예측 모델 보유
- 외생변수(Meridian 기본 기능) 적용으로 시장 환경 반영
- KPI 최적화 목적함수에 따라 배분 결과 산출

## 1.2 AS-IS → TO-BE

| 구분 | AS-IS (MTS) | TO-BE (ReadySet) |
|---|---|---|
| 플랫폼 | 사내 기간계(MTS) | ReadySet 예측/분석 플랫폼 |
| 모델 | Meridian (외생변수 미적용) | Meridian + 외생변수 적용 (고도화) |
| KPI | 노출, 클릭, 조회, 도달 | 동일 (확장 가능) |
| 매체 | Google Ads, Meta, Naver GFA, Kakao (4개 매체) | Google Ads, Meta, NAVER 보장형 DA(NOSP), NAVER 성과형 DA(GFA), kakao 모먼트, TikTok, SMR, Targetpick (8개 매체) |
| 예산 고정 | 미제공 | 특정 매체/상품 예산 고정 후 잔여 최적화 |
| 시각화 | 2종 | 보강 예정 (상세 기획 시 확정) |
| AI 인사이트 | 미제공 | SpinX 기반 결과 해석 텍스트 생성 |
| Reach Caster 연계 | 미제공 | 결과 → Reach Predictor 자동 매핑 |
| 외부 사용자 접근 | 불가 | 광고주/에이전시 직접 결과 조회 가능 |

# 2. 모델 정책

## 2.1 모델 구조

| 항목 | 정의 |
|---|---|
| 모델 기반 | Google Meridian (Bayesian MMM) |
| 업종 수 | 22개 업종별 개별 모델 |
| 외생변수 | Meridian 기본 기능 활용 (시장 환경, 계절성 등) |
| 최적화 목적함수 | 사용자 선택 KPI에 따라 결정 |
| 학습 데이터 | BRIDGE 원천 데이터 기반 |

## 2.2 업종 매핑

- 시나리오 생성 시 아래 2가지 방식 중 택 1로 업종을 결정
  - ① 브랜드 선택 → 브랜드로부터 업종 자동 식별
  - ② 업종 직접 선택 → 22개 업종 목록에서 사용자가 직접 지정
- 식별/선택된 업종에 해당하는 Meridian 모델이 분석에 사용됨
- 업종 목록: 🚩 DS팀 확정 후 업데이트 (기존 22개 업종 기준 유지)

## 2.3 모델 업데이트 주기

| 항목 | 정책 |
|---|---|
| 정기 업데이트 | 월 1회 (BRIDGE 원천 데이터 갱신 시) |
| 모델 버전 관리 | 업데이트 시 이전 버전 보관, 기존 시나리오 결과는 생성 시점 모델 버전 기준 유지 |
| 외생변수 갱신 | 모델 업데이트와 동기화 |

## 2.4 KPI별 최적화 정의

| KPI | 최적화 목적 | 설명 |
|---|---|---|
| 노출 (Impression) | 노출 수 최대화 | 총 예산 내 노출 극대화 배분 |
| 클릭 (Click) | 클릭 수 최대화 | 총 예산 내 클릭 극대화 배분 |
| 조회 (View) | 조회 수 최대화 | 총 예산 내 영상 조회 극대화 배분 |
| 도달 (Reach) | 도달률 최대화 | 총 예산 내 도달 극대화 배분 |

- KPI는 시나리오당 **1개만** 선택 가능
- 선택된 KPI에 따라 모델의 목적함수가 결정됨

## 3.3 예산 잠금(Lock) 정책

### 3.3.1 정의

사용자가 특정 매체/광고상품에 예산을 **잠금 지정**하면, 해당 금액은 최적화 대상에서 제외되고 나머지 잔여 예산만 최적화 대상으로 배분된다.

### 3.3.2 2depth 계층 구조

잠금은 매체(Parent) 레벨과 상품(Child) 레벨에서 독립적으로 설정 가능하다.

| 잠금 레벨 | 의미 | 동작 |
|---|---|---|
| 매체 잠금 | 해당 매체 전체에 고정 금액 배정 | 하위 상품은 매체 잠금 금액 안에서 최적화 |
| 상품 잠금 | 해당 상품에만 고정 금액 배정 | 상품 금액은 매체 잠금 금액(또는 전체 예산)에서 차감 |

**예시**: 총 예산 10억, 매체A 잠금 1억, 하위 상품 5개 중 2개 잠금(각 2천만)  
→ 매체A 내 비잠금 3개 상품에 1억 - 4천만 = 6천만 배분 최적화  
→ 나머지 9억은 다른 비잠금 매체에 배분 최적화

### 3.3.3 잔여 예산 계산

```
배분 가능 예산 = 총 예산
  - Σ(잠금된 매체의 잠금 금액)
  - Σ(상위 매체가 잠금되지 않은 상품의 잠금 금액)
```

**중복 차감 방지**: 매체가 잠금된 경우, 하위 상품의 잠금 금액은 매체 잠금 금액에 포함된 것으로 간주하여 별도 차감하지 않음.

### 3.3.4 유효성 검증

상세 유효성 검증 규칙(조건, 에러 메시지, 표시 위치, 타이밍)은 `BudgetOptimizer_Scenario_Creation_Spec.md` Section 5에 명시한다.

### 3.3.5 UI 동작

1. 매체/광고상품 선택 후, 각 행에 "잠금" 토글(🔒/🔓) 제공
2. 잠금 설정 시 잠금 금액 입력 필드 활성화, 비잠금 행은 "최적화 대상" 표시
3. 잔여 예산 실시간 계산 표시
4. 유효성 위반 시 해당 행 인라인 에러 + 다음 버튼 disabled

## 3.5 믹스안 비교 (P1: MVP 캐파 가용 시 포함)

### 3.5.1 정의

하나의 시나리오 생성 시 모델이 산출하는 복수의 배분안을 스코어카드 + 차트로 비교하여, 최적화 효과를 정량적으로 검증시키는 기능이다.

### 3.5.2 비교 대상

| 믹스안 | 조건 | 표시 |
|---|---|---|
| A: 최적화 결과 | 사용자 설정 기반 모델 최적 배분 | "추천" 뱃지 |
| B: 균등 배분 (1/N) | 선택된 매체/상품에 예산 균등 분배 | 항상 표시 |
| C: 고정 미적용 최적화 | 고정 설정 없이 전체 최적화 | 고정 설정이 있는 경우에만 표시 |

- 3안 모두 백엔드에서 모델을 통해 결과를 산출하여 보유
- 고정 설정이 없는 경우 A와 C가 동일하므로 2안(A/B)만 비교

### 3.5.3 표시 구성

| 구성 요소 | 유형 | 설명 |
|---|---|---|
| 스코어카드 | 3안 나란히 배치 | 핵심 KPI 값, 효율 지표(CPM/CPC/CPV), 최적화 안 대비 개선율(%) |
| 매체별 예산 배분 비교 | Grouped Bar | 매체별 3안의 배분 예산 금액을 나란히 비교 |
| 다차원 KPI 비교 | Radar | 3안의 노출/클릭/조회/도달/효율을 오버레이 비교 |

### 3.5.4 배치 위치

- 결과 페이지 **최상단** (결과 헤더 직후, 결과 테이블 이전)
- "최적화가 왜 좋은지" 먼저 납득 → 이후 상세 배분 데이터 확인 흐름

## 3.6 결과 시각화

### 3.6.1 차트 구성

결과 화면은 **2×2 그리드** 레이아웃으로 4종 차트를 동시 제공한다.

| 위치 | 차트명 | 유형 | 설명 |
|---|---|---|---|
| 좌상 | 예산 비중 파이차트 | Pie / Donut | 매체별 예산 배분율(%) 및 배분 금액 표시 |
| 우상 | 반응곡선 (Response Curve) | Line | 매체별 예산 투입 대비 KPI 반응 곡선, 포화 구간 및 한계 효율 시각화 |
| 좌하 | 일자별 기여도 차트 | Stacked Area | 캠페인 기간 내 매체별 KPI 기여를 누적 표시 (baseline + 채널별 contribution 시계열) |
| 우하 | KPI 창출 차트 | Vertical Bar (양/음) | 최적화 전후 매체별 예산 변동분 표시, 증가(+)/감소(-) 매체를 색상으로 구분 |

### 3.6.2 배치 논리

- **상단 행**: 입력(예산) 관점 — 얼마를 어디에 넣었고, 효율 여유가 있는지
- **하단 행**: 출력(성과) 관점 — 언제·얼마나 성과가 발생했는지

### 3.6.3 드릴다운

- 각 차트는 클릭/탭을 통해 세부 데이터로 드릴다운 가능
- 🚩 드릴다운 상세 동작 및 진입 UI는 상세 기획 시 확정

# 4. Reach Caster 간편 생성 (Easy Create) 정책

## 4.1 기능 정의

Budget Optimizer 결과를 기반으로 Reach Caster 시나리오를 **간편 생성**하는 기능이다.

- 두 시나리오 간 **연결(Link) 관계를 표시하지 않음** — 의존성을 최소화하기 위함
- 생성 완료 후 Reach Caster 시나리오는 완전히 독립적으로 존재
- Budget Optimizer 결과 화면의 CTA를 통해 Reach Caster 시나리오 생성 프로세스를 빠르게 진입하는 **편의 기능** 수준으로 정의

## 4.2 진입 및 플로우

```
Budget Optimizer 시나리오 결과 화면 (완료 상태)
    ↓ "Reach Caster로 분석하기" CTA
중간 설정 레이어 (모달/바텀시트)
    → 타겟 GRP 선택
    → 매핑 불일치 항목 안내 확인
    ↓ "생성" 버튼
Reach Caster > Reach Predictor Step 2 화면 진입
    → 매체별 배분 예산 자동 프리필 (매핑 가능 항목만)
```

## 4.3 중간 설정 레이어

Budget Optimizer 결과에서 Reach Caster 생성으로 넘어가기 전, 중간 레이어를 통해 추가 설정을 수행한다.

### 4.3.1 설정 항목

| 항목 | 필수 | 설명 |
|---|---|---|
| 타겟 GRP | 필수 | Reach Caster에서 요구하는 타겟 GRP 선택 |
| 매핑 불일치 안내 | 정보 표시 | Budget Optimizer 결과 매체/상품 중 Reach Caster 해당 업종에서 지원하지 않는 항목 표시 |

### 4.3.2 매핑 불일치 처리

| 규칙 | 설명 |
|---|---|
| 불일치 발생 조건 | Budget Optimizer 결과에 포함된 매체/광고상품이 Reach Caster 해당 업종에서 선택 불가한 경우 |
| 안내 방식 | 중간 레이어에서 불일치 항목을 명시적으로 리스트 표시 (예: "⚠️ 다음 항목은 Reach Caster에서 지원하지 않아 제외됩니다: Kakao > OO상품") |
| 처리 방식 | 불일치 항목은 Reach Caster 생성 시 자동 제외, 매핑 가능한 항목만 프리필 |
| 전체 불일치 | 매핑 가능한 항목이 0개인 경우 생성 불가 안내 및 CTA 비활성화 |

## 4.4 데이터 매핑 규칙

| 규칙 | 설명 |
|---|---|
| 진입 조건 | Budget Optimizer 시나리오 상태가 `완료(Completed)`인 경우에만 CTA 활성화 |
| 동일 Slot 원칙 | 생성되는 Reach Caster 시나리오는 동일 Slot 내에 위치 |
| 업종 | Budget Optimizer와 동일 업종 자동 적용 |
| 매체별 예산 | Budget Optimizer 결과의 매체별 배분 예산 → Reach Predictor Step 2 매체별 예산 입력에 프리필 |
| 수정 가능 | 프리필된 값은 사용자가 자유롭게 수정 가능 |
| 진입 위치 | Reach Caster 시나리오 생성의 **Step 2**로 바로 진입 (Step 1 스킵) |

## 4.5 시나리오명 규칙

| 규칙 | 설명 |
|---|---|
| 자동 네이밍 | `(BO-{시나리오ID}) {원본 시나리오명}` 형식으로 시나리오명 자동 생성 |
| 예시 | Budget Optimizer 시나리오명이 "25년 3분기 최적화"인 경우 → `(BO-1234) 25년 3분기 최적화` |
| 수정 가능 | 사용자가 생성 후 시나리오명 자유롭게 수정 가능 |

## 4.6 독립성 원칙

- 생성된 Reach Caster 시나리오는 Budget Optimizer 시나리오와 **어떠한 연결 관계도 갖지 않음**
- Budget Optimizer 시나리오가 삭제되어도 생성된 Reach Caster 시나리오에 영향 없음
- 연결 이력, 참조 메타데이터 등을 기록하지 않음
- Reach Caster 시나리오에서 원본 Budget Optimizer로의 역추적 기능 미제공

# 5. SpinX for Budget Optimizer

## 5.1 서비스 레벨

| 서비스 레벨 | 설명 |
|---|---|
| 시나리오 상세 결과 뷰 | 단일 시나리오 결과에 대한 질의응답 |
| 차트별 해석 메시지 | 4종 차트 각각에 대한 SpinX 기반 자동 해석 텍스트 제공 |

## 5.2 인터페이스 및 사용 방식

- **플로팅 인터페이스**: 상세 결과 화면 우측 하단의 플로팅 액션 버튼을 통해 채팅 서비스를 호출함
- **채팅 기반 UI**: 버튼 클릭 시 전용 채팅 UI가 확장되며, 사용자는 자연어 기반의 질의응답을 통해 인사이트를 획득함
- **차트 해석 메시지**: 각 차트 하단에 SpinX가 생성한 1~2줄 해석 텍스트를 인라인 제공 (별도 호출 없이 결과 로드 시 자동 표시)

## 5.3 차트별 해석 메시지 정책

| 차트 | 해석 방향 | 예시 |
|---|---|---|
| 예산 비중 파이차트 | 배분 구조 요약 + 최대/최소 비중 매체 하이라이트 | "Meta에 42%가 배분되어 가장 높은 비중을 차지하며, Naver GFA는 18%로 최저입니다." |
| 반응곡선 | 포화 여부 판단 + 추가 투입 효율 코멘트 | "Google은 포화 구간에 근접하며, Meta는 추가 투입 시 KPI 상승 여력이 있습니다." |
| 일자별 기여도 | 기여 집중 구간 식별 + 시계열 패턴 요약 | "캠페인 2주차에 전체 KPI의 35%가 집중되었습니다." |
| KPI 창출 | 최대 기여 매체 식별 + 전체 대비 비중 | "최적화 결과 Channel5에 +13M 증액, Channel4에서 -22M 감액이 배분되었습니다." |

### 생성 규칙

- 결과 데이터 기반 SpinX 자동 생성
- 비교·판단 문장 위주 (단순 수치 나열 지양)
- 차트당 최대 2문장
- 결과 로드 완료 시 차트와 동시 표시 (별도 사용자 액션 불필요)

## 5.4 채팅 질의응답 원칙

### 데이터 근거 답변

| 참조 범위 | 설명 |
|---|---|
| 해당 시나리오 결과 데이터 | 배분 결과, KPI 예측값, 반응곡선 데이터, 일자별 기여도 데이터 |

- **근거 자료 제시**: 답변 도출에 활용된 관련 수치 및 계산 근거를 함께 제시하여 정보의 신뢰성을 확보함. Web Search 결과, RAG Search 결과는 출처 표시 UI 제공
- **자연어 확장**: 사용자는 자연어 질문을 던져 심층적인 분석을 이어갈 수 있음

## 5.5 인사이트 내용 방향

- 최적 배분 결과 요약
- KPI 관점에서 가장 효율적인 매체/상품 하이라이트
- 예산 고정이 적용된 경우, 고정 vs 최적화 결과 비교 코멘트
- 차트 간 크로스 인사이트 (예: 반응곡선 포화도 + 실제 기여도 비교)
- 🚩 상세 프롬프트 및 출력 형식은 상세 기획 시 DS/SpinX팀 협의

## 5.6 사용량 정책

- 사용량은 플랫폼 단위로 관리됨 (Budget Optimizer 단독 정책 아님)
- 사용자당 월 100건 대화 전송 제한
- 상세 정책은 플랫폼 공통 정책 참조
