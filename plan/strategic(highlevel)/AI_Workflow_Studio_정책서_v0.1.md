# 1. AI Workflow Studio

## 1.1 정의

AI Workflow Studio는 사용자가 **노드(Node)를 캔버스 위에 배치하고 연결하여, 광고 데이터 수집·가공·분석·리포팅을 자동화하는 워크플로우를 시각적으로 설계하고 실행**하는 솔루션임.

기존 솔루션(Reach Caster, Budget Optimizer 등)이 정해진 분석 로직을 실행하는 것과 달리, AI Workflow Studio는 **사용자가 분석/자동화 흐름 자체를 조립**한다는 점에서 구분됨.

외부 서비스는 **MCP(Model Context Protocol)** 규격을 통해 노드 형태로 연결되며, 광고 매체·분석·리포팅 도구를 코드 수정 없이 확장할 수 있음.

---

## 1.2 구조

### 1.2.1 진입 플로우

- 워크스페이스 진입: 예측/분석 플랫폼 워크스페이스 진입 (공통 정책 준수)
- 폴더 선택: 작업할 폴더(광고주) 선택
- 솔루션 선택: 폴더 내 솔루션 메뉴에서 AI Workflow Studio 선택
- 워크플로우 진입: 신규 워크플로우 생성 또는 기존 워크플로우 조회

### 1.2.2 계층 구조

```
워크스페이스
└── 폴더 (광고주)
    └── 솔루션 (AI Workflow Studio)
        └── 워크플로우 (최소 실행 단위)
            └── 노드 (Node) × N + 연결(Edge) × N
                └── MCP 커넥션 (외부 서비스 연결)
```

### 1.2.3 구성 요소 정의

| 구성 요소 | 정의 |
|---|---|
| 워크플로우(Workflow) | 노드와 연결로 구성된 하나의 자동화 흐름. 실행/저장/관리의 기본 단위 |
| 노드(Node) | 워크플로우를 구성하는 최소 작업 단위 (데이터 수집, 변환, 분석, 출력 등) |
| 연결(Edge) | 노드 간 데이터 흐름을 정의하는 선. 앞 노드의 출력이 뒤 노드의 입력으로 전달됨 |
| 캔버스(Canvas) | 노드를 배치하고 연결하는 시각적 편집 영역 |
| MCP 커넥션 | 외부 서비스를 노드로 연결하기 위한 프로토콜 규격 연결 정보 |

## 1.3 노드(Node) 정책

### 1.3.1 노드 카테고리

| 카테고리 | 정의 | 예시 |
|---|---|---|
| 트리거(Trigger) | 워크플로우 실행 시작점 | 수동 실행, 스케줄(정기 실행) |
| 데이터 소스(Source) | 외부/내부에서 데이터 수급 | 매체 MCP(Google/Meta/TikTok), 분석 MCP(GA4) |
| 변환(Transform) | 데이터 가공·정규화 | Normalizer(매핑 JSON 기반 용어 통일), 필터, 집계 |
| AI(LLM) | 자연어 처리·요약·해석 | 요약, 인사이트 생성, 질의응답 |
| 로직(Logic) | 흐름 제어 | 조건 분기, 반복, 병합 |
| 출력(Output) | 결과 전달 | 리포트 생성, Export(CSV), 외부 공유(Sheets/Slack) |

🚩 노드 카테고리 및 세부 노드 목록은 상세 기획 시 확정

### 1.3.2 노드 공통 속성

| 구분 | 속성명 | 필수 여부 | 설명 |
|---|---|---|---|
| 식별자 | 노드 ID | 필수 | 워크플로우 내 고유 식별자 |
| 기본 정보 | 노드 타입 | 필수 | 노드 카테고리 및 세부 종류 |
|  | 노드명 | 선택 | 사용자 지정 라벨 |
| 입출력 | 입력 스키마 | 필수 | 노드가 받는 데이터 구조 |
|  | 출력 스키마 | 필수 | 노드가 내보내는 데이터 구조 |
| 설정 | 파라미터 | 조건부 필수 | 노드별 개별 설정값 (예: 조회 기간, 매체 계정) |
| 상태 | 실행 상태 | 필수 | 대기중 / 처리중 / 완료 / 오류 / 건너뜀 |

### 1.3.3 노드 연결 규칙

- 데이터 흐름: 앞 노드의 출력이 뒤 노드의 입력으로 전달됨 (공통 정책 4.1.2 "상속성" 개념 적용)
- 스키마 정합성: 연결 시 앞 노드 출력 스키마와 뒤 노드 입력 스키마 호환 여부 검증
- 순환 금지: 워크플로우는 순환(Cycle) 없는 방향 그래프(DAG)로 제한
- 트리거 유일성: 하나의 워크플로우는 최소 1개의 트리거 노드로 시작 🚩상세 때 확정

## 2. 워크플로우

## 2.1 정의

워크플로우는 AI Workflow Studio 내에서 자동화 흐름이 설계·실행되는 최소 실행 단위임.

## 2.1.1 워크플로우 관리 기능

| 기능 | 정의 |
|---|---|
| Create (C) | 폴더 내에서 신규 워크플로우 생성 (빈 캔버스 또는 템플릿 기반) |
| Read (R) | 워크플로우 구성 및 실행 결과 조회 |
| Update (U) | 노드/연결/설정 편집 (※ 실행 완료 이력은 불변) |
| Delete (D) | 워크플로우 삭제, 삭제 시 복구 불가 |
| Copy | 기존 워크플로우 구성 복제 |
| Move | 동일 광고주 내 다른 폴더로 이동 |
| Export | 워크플로우 구성(JSON) 및 실행 결과 내보내기 |

> **주의:** 공통 정책서(4.1.1)에서 시나리오는 Update 미제공이나, 워크플로우는 "설계 산출물" 성격이므로 **구성 편집(Update)을 허용**함. 단, 개별 실행 이력(Run)은 불변으로 관리. 🚩공통 정책과의 정합성 상세 때 확정

## 2.2 워크플로우 속성 정의

| 구분 | 속성명 | 필수 여부 | 설명 |
|---|---|---|---|
| 식별자 | 워크플로우 ID | 필수 | PK, 자동 증분 |
| 기본 정보 | 워크플로우명 | 필수 | 사용자 지정 식별 명칭 |
|  | 설명 | 선택 | 부연 설명 |
| 구성 | 노드/연결 그래프 | 필수 | 노드·연결 정의 (JSON) |
| 실행 설정 | 트리거 방식 | 필수 | 수동 / 스케줄 |
|  | 스케줄 | 조건부 필수 | 스케줄 트리거 시 실행 주기 |
| 상태 | 처리 상태 | 필수 | 대기중 / 처리중 / 완료 / 오류 / 취소 |
|  | 진행률 | 필수 | 실행 진행 % (완료 노드 수 기준) |
| 메타데이터 | 생성자 | 필수 | 🚩adly 계정 정책 확인 필요 |
|  | 생성일시 | 필수 | yyyy-mm-dd hh:mm:ss |
|  | 최종 수정자 | 필수 | 🚩adly 계정 정책 확인 필요 |
|  | 수정일시 | 필수 | yyyy-mm-dd hh:mm:ss |

## 2.3 워크플로우 실행(Run) 정책

### 2.3.1 실행 상태

공통 정책서(4.3.1) 상태 체계를 준용함.

| 상태 | 설명 | 요청 가능 작업 |
|---|---|---|
| 대기중 (Pending) | 실행 요청 후 대기 | 취소 |
| 처리중 (Processing) | 노드 순차/병렬 실행 중 | 취소 |
| 완료 (Completed) | 전체 노드 실행 완료 | - |
| 오류 (Error) | 특정 노드 실행 실패 | 재시도 |
| 취소 (Cancelled) | 사용자 취소 | - |

### 2.3.2 실행 프로세스

- 실행 요청: 사용자가 실행 시, 워크플로우 그래프를 위상 정렬하여 노드 실행 순서 결정
- 노드 실행: 앞 노드 완료 후 출력을 뒤 노드 입력으로 전달하며 순차/병렬 실행
- 상태 추적: 노드 단위 실행 상태를 실시간 표시 (완료 노드 기준 진행률 산출)
- 오류 처리: 특정 노드 실패 시 해당 노드에서 중단, 오류 상태 및 실패 노드/사유 표시
- 실행 이력(Run): 각 실행은 고유 Run ID로 기록되며 입력·출력·상태를 불변 보관 🚩보관 범위 상세 때 확정

### 2.3.3 실행 이력 관리

- 각 워크플로우는 복수의 실행 이력(Run)을 가질 수 있음
- 실행 이력은 실행 시점의 구성·입력·결과 스냅샷을 보관
- 보관 기간 및 용량 정책 🚩상세 때 확정

# 3. MCP 연동

## 3.1 정의

MCP(Model Context Protocol)는 외부 서비스를 워크플로우 노드로 연결하기 위한 표준 규격임. AI Workflow Studio는 MCP 클라이언트로서 외부 MCP 서버에 연결하여 해당 서비스의 기능을 노드로 제공함.

## 3.2 MCP 커넥션 유형

| 유형 | 정의 | 예시 |
|---|---|---|
| 공식 MCP | 외부 서비스가 공식 제공하는 MCP 서버 연결 | Google Ads, Meta Ads, TikTok Ads, GA4 |
| 자체 MCP | ReadySet이 자체 구축·운영하는 MCP 서버 | Normalizer(매핑 JSON), Kakao/Naver 래퍼 |

## 3.3 연동 대상 후보 (구상)

| 분류 | 대상 | 커넥션 유형 | 비고 |
|---|---|---|---|
| 매체 | Google Ads | 공식 | 성과·비용·캠페인 |
|  | Meta(FB/IG) Ads | 공식 | 광고세트·인사이트 |
|  | TikTok Ads | 공식 | |
|  | Kakao Moment | 자체 | 공식 MCP 부재, 래퍼 구축 |
|  | Naver GFA | 자체 | 공식 MCP 부재, 래퍼 구축 |
| 분석 | GA4 | 공식 | 트래픽·전환 |
| 변환 | ReadySet Normalizer | 자체 | 매핑 JSON 기반 용어 정규화 |
| 리서치 | 웹 검색 | 공식 | 경쟁사·트렌드 |
| 출력 | Google Sheets, Slack | 공식 | 리포트 자동화 |

> **차별점:** Kakao/Naver 등 국내 매체는 공식 MCP가 부재하므로, 기 보유 매핑 자산(`google/kakao/naver_gfa/facebook_api_mapping.json`)을 기반으로 자체 MCP를 구축하여 연결. ReadySet만의 국내 매체 통합 강점.

## 3.4 Normalizer(정규화) 정책

- 목적: 매체별로 상이한 코드값(캠페인 유형·입찰 전략·광고 포맷 등)을 ReadySet 공통 용어로 통일
- 근거 데이터: 매체별 API 매핑 JSON 자산 활용
- 위치: 데이터 소스 노드 직후, 분석/AI 노드 이전 단계에 배치 권장

## 3.5 인증 및 보안 정책

- 토큰 격리: 매체별 인증 토큰(OAuth 등)은 **폴더(광고주) 단위**로 분리 보관 (공통 정책 2.4 데이터 격리 준수)
- 권한 상속: 워크플로우 실행 시 해당 폴더의 가시성·접근 권한을 상속하여 데이터 접근 통제
- 외부 사용자 제한: 외부 사용자(대행사/광고주)의 MCP 커넥션 생성·토큰 관리 권한 🚩상세 때 확정
- 레이트리밋: 매체 API 호출량 및 LLM 토큰 사용량 관리 정책 🚩상세 때 확정

| 2 | 백엔드/실행 엔진 신규 구축 범위 | 현 ReadySet은 프론트 중심 구성 |
| 3 | 신규 독립 솔루션 vs 기존 솔루션 부가 기능 | 포지셔닝 확정 필요 |
| 4 | 외부 사용자(대행사/광고주) 실행·커넥션 권한 범위 | 데이터 격리 정책과 연계 |
| 5 | 1순위 연동 매체 및 노드 우선순위 | MVP 범위 산정 |
| 6 | 공통 정책서 시나리오(Update 미제공)와의 정합성 | 워크플로우 Update 허용 여부 |

# 핵심 용어 정의

| 용어 | 정의 |
|---|---|
| 워크플로우(Workflow) | 노드와 연결로 구성된 자동화 흐름, 실행/관리의 기본 단위 |
| 노드(Node) | 워크플로우의 최소 작업 단위 |
| 연결(Edge) | 노드 간 데이터 흐름을 정의하는 선 |
| MCP | 외부 서비스를 노드로 연결하는 표준 프로토콜 |
| Normalizer | 매체별 코드값을 ReadySet 공통 용어로 통일하는 변환 노드 |
| Run | 워크플로우 1회 실행 및 그 이력 |
| DAG | 순환 없는 방향 그래프 (워크플로우 구조 제약) |
