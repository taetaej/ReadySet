# ReadySet Crew 구상 (가칭)

> 상태: **구상 중 (ideas)**. 확정 스펙 아님. 네이밍(Crew)도 잠정.
> 한 줄: 지휘관(사용자) 곁에서 일하는 **전략 크루가 사는 독립 공간**. AI 에이전트와 사람 전문가(데싸)를 영입·편성해 부리고, 그들이 만든 지식을 콘텐츠로 발행한다.

---

## 0. 이 문서의 위치

흩어져 있던 세 갈래 구상을 **하나의 상위 IA**로 묶는다.

- `Insight_Archive_구상.md` — 분석 연구소(가설·외생변수 검증 아카이브) + 브리핑 데스크(매체 공지 큐레이션)
- `AI_Workflow_Studio_정책서_v0.1.md` — 노드·MCP 기반 워크플로우 조립
- (신규) 에이전트 채용/보유 + 에이전트 마켓 + 콘텐츠 발행

세 갈래는 따로 노는 기능이 아니라, **"크루"라는 한 단위의 진화 단계**다.

---

## 1. 정체 (What)

- 기존 솔루션(Reach Caster / DataShot / Budget Optimizer)이 **특정 Slot(광고주·캠페인)에 종속된 작업 공간**이라면,
  Crew는 **Slot에 종속되지 않는 크로스 공간**이다. 여기 사는 크루는 여러 캠페인을 넘나들며 일한다.
- 핵심 단위 = **크루(Crew member)**. AI 에이전트일 수도, 사람 전문가(데싸)일 수도 있다.
  - 그래서 이름을 "Agent ~"로 못박지 않는다. **"에이전트 전용"이라 하면 사람(데싸)이 튕겨나간다.**
  - "Crew"는 공간(Office)이 아니라 **구성원**을 가리켜서, AI든 사람이든 다 품는다.

### 왜 War Room DNA와 맞나
- War Room에서 지휘관이 참모진을 부리듯, 사용자는 크루를 영입·편성해 부린다.
- SpinX = 이 크루의 리더 격. "내 캠페인을 나보다 잘 아는 전략 파트너"가 크루의 일원이 된다.

---

## 2. 진화 단계 (Roadmap)

### 1단계 — 크루 채용/보유 (Hire)
- AI 에이전트 + 사람 전문가를 **영입(Hire)**해 내 팀에 앉힌다.
- 인터랙션 은유 = **채용/인력시장.** 카탈로그를 "채용 보드"처럼, 에이전트 카드를 **프로필/이력서**(특기·이력·평판)처럼, 추가 버튼을 **"영입하기 / Hire"**로.
- 여기 사는 초기 크루 예:
  - **브리핑 크루** — 매체(구글·메타·네이버·카카오 등) 공지사항을 모아 정리 (수동적 큐레이션)
  - **리서치 크루(분석 연구소)** — 가설·외생변수 상관관계를 데이터로 검증해 아카이브 (사람 데싸가 주체)
- ⚠️ 1단계가 킬러여야 한다. 각 크루가 **혼자서도 쓸 가치**가 있어야 2단계까지 사람이 남는다.

### 2단계 — 크루 편성 (워크플로우)
- 영입한 크루를 노드로 엮어 미션(워크플로우)을 수행 → `AI_Workflow_Studio_정책서` 흡수.
- 은유: 특공대 편성. "크루를 뽑아 → 스쿼드를 짜고 → 미션을 돌린다"가 한 이름 아래 흐른다.
- ⚠️ 무거운 단계. (실행 엔진 신규 구축, 프론트 중심 아키텍처 등 — `AI_Workflow_Studio` 8장 미결 참조.) 1단계 검증 후 얹는다.

### 3단계 — 크루 마켓 (공유/거래)
- **사용자가 만든 에이전트를 남이 쓰게** 한다. 공유 → (나중엔) 거래/평판.
- 은유 확장: 채용 보드가 **오픈 마켓**으로 진화. "내가 키운 크루를 다른 지휘관에게 파견/공유."
- 오픈 퀘스천 많음(아래 6장).

### 가로지르는 축 — 콘텐츠 발행 (Publishing)
- **어려운 주제를 재밌게 푸는 발행물.** 예: *POV: "제 리스폰스커브는 왜 직각이죠…?"* 같은 훅으로 반응곡선 포화를 설명.
- 소스 = 분석 연구소(검증된 인사이트) + 브리핑 Desk(매체 소식). 크루가 일한 결과가 콘텐츠로 발행된다.
- 성격: 마케팅/브랜딩 + 지식 베이스 + SpinX RAG 소스. "있어 보임 = 근거 + 크래프트맨십"의 콘텐츠 버전.
- 톤: 어려운 용어를 **쉬운 말로 바꾸지 않고**, 어려운 그대로 + 재밌는 훅/짧은 각주로 푼다. (초등학생 말로 바꾸면 "있어 보임"이 죽는다.)

## 3. IA 스케치 (잠정)

```
GNB
├── 솔루션 (드롭다운)                 ← Slot 종속 작업 공간
│   └── Reach Caster / DataShot / Budget Optimizer / Ad Curator
└── ReadySet Crew (독립 메뉴)         ← Slot 비종속. 나의 전략 크루 ★신규
    ├── 채용 보드 (Hire)              ← 에이전트·전문가 영입 [1단계]
    │   └── 크루 프로필 카드 (특기·이력·평판)
    ├── 브리핑 Desk                   ← 매체 공지 큐레이션 창구
    ├── 분석 연구소 (Lab)              ← 데싸(사람) 크루의 검증 아카이브
    ├── 크루 편성 (Squad/워크플로우)    ← 크루를 엮어 미션 수행 [2단계]
    ├── 크루 마켓                      ← 내 에이전트를 남이 쓰게 [3단계]
    └── 발행 (Publishing)             ← 어려운 주제를 재밌게 (콘텐츠 채널)
        └── 최신 발행물은 메인(SlotBoard) 상단 티커/카드로도 노출
```

> "Desk"는 상위가 아니라 **하위 창구** 이름으로 쓴다(브리핑 Desk). 상위는 여럿을 품는 그릇이어야 해서 Crew.

## 4. 네이밍 검토 기록 (왜 Crew로 기울었나)

| 후보 | 가리키는 것 | 사람(데싸) 품나 | 채용 은유 | 메모 |
|---|---|---|---|---|
| Agent Office | 공간 + 주체(에이전트) | ✗ 못 품음 | 약함 | "Agent" 박으면 연구소(데싸)가 튕겨나감 |
| ReadySet Office | 공간 | 품음 | 약함 | 무난하나 밋밋, MS Office 연상 |
| **ReadySet Crew** | **구성원(팀)** | **품음** | **자연스러움("크루 모집")** | **1·2·3단계 다 흐름. War Room DNA 일치** |
| Roster | 선수 명단 | 품음 | 제일 정확 | 채용 은유 문자 그대로. 한국어 대중성 약함 |
| Guild | 전문가 조합 | 품음 | 강함 | 게임 파티 은유. 젊고 강하나 도메인 톤과 거리 |
| Desk | 창구 하나 | - | - | 단일 창구라 상위 그릇으론 좁음 → 하위(브리핑)로 |

- 결론: **상위 그릇 = Crew(구성원을 담아 AI·사람 다 품음), 채용 느낌 = "영입/Hire" 인터랙션으로 화면에서 살린다.** 이름을 동사(Recruit)에 걸면 1단계만 가리켜 2·3단계로 못 뻗으므로, 결과물(팀)에 건다.

---

## 5. 제품 태도와의 연결 (Why 강한가)

- **에이전트를 개체로 존중** (프로필·이력·특기) = "있어 보임 = 크래프트맨십".
- **AI + 사람 전문가 혼성 크루** = War Room 참모진. 자동화만이 아니라 사람 데싸의 판단도 제품 안에 산다.
- **콘텐츠 발행** = 수치 너머의 큐레이션 / 발견의 희열. 크루가 일한 결과에 서사를 붙인다.

## 6. 오픈 퀘스천

- [ ] 상위 네이밍 확정 (Crew / Office / Roster / 그 외)
- [ ] "Crew member"의 데이터 모델 — AI 에이전트와 사람 전문가를 한 스키마로 볼지, 구분할지
- [ ] 채용(Hire) 인터랙션의 실제 의미 — 활성화 토글인가, 구독인가, 권한 부여인가
- [ ] 1단계 MVP 범위 — 어떤 크루부터 (브리핑? 리서치?)
- [ ] 2단계(워크플로우)와의 접합 — `AI_Workflow_Studio_정책서`를 Crew 하위로 흡수할지, 별도 유지할지
- [ ] 3단계 크루 마켓 — 공유 범위(사내/오픈), 거래·정산·평판, 저작권·책임 소재
- [ ] 콘텐츠 발행 — 생산 주체(내부 큐레이션/자동생성/혼합), 발행 채널, 톤 가이드
- [ ] Slot 비종속 크로스 공간의 데이터 격리·권한 (기존 폴더 단위 격리 정책과의 정합성)
