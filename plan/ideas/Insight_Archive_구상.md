# 인사이트 아카이브 구상 (가칭)

> 상태: **구상 중 (ideas)**. 확정 스펙 아님.
> 한 줄: 마케터가 감으로 결정하던 것(가설)을 실제 데이터로 검증하고, 그 검증 결과를 쌓아 발송·아카이브하는 콘텐츠 허브.

---

## 1. 정체 (What)

- "뉴스레터"는 **발송 방식**을 가리키는 말이라, 메뉴명으로는 부적합하다. 이건 뉴스레터가 아니라 **검증된 인사이트의 아카이브**다.
- 핵심 콘텐츠 단위 = **하나의 가설 → 데이터 검증 → 결론**.
  - 예: "이 업종은 프리퀀시 3 이상에서 효율이 꺾인다" 같은 마케터의 통념(감)을 실제 데이터로 검증하고, 근거와 함께 결론을 올린다.
- 성격: 콘텐츠이자 지식 베이스. 특정 솔루션에 종속되지 않는 **크로스 인사이트**다.

## 2. 프로덕트 내 위치 (Where)

- **독립 IA 진입점**이 적합하다. 솔루션(DataShot / Budget Optimizer / Reach Caster)과 나란히 서는 콘텐츠 허브.
- 메뉴명 후보: "인사이트", "리서치랩" 등. ("뉴스레터"는 발송 채널명이라 제외.)
- 부적합 후보와 이유:
  - Docs 하위 → Docs는 "사용법", 이건 "발견/주장"이라 성격이 다름.
  - 각 솔루션 내부 탭 → 특정 솔루션에 종속되지 않는 크로스 인사이트라 부적합.

독립 진입점 하나로 두면 세 목표가 한 자리에서 풀린다:
- **아카이브** = 진입점의 리스트/상세
- **SpinX RAG 참조** = 지식 소스의 단일 출처(single source)라 인덱싱 대상이 명확
- **메인의 살아있는 느낌** = 최신 검증 결과를 메인에 카드/티커로 노출

## 3. 확장 방향 (Later)

- **SpinX RAG 참조**: 쌓인 인사이트를 SpinX가 RAG로 참조. "내 캠페인을 나보다 잘 아는 전략 파트너"의 근거 소스가 된다.
- **플랫폼 메인 노출**: 최신 검증 결과를 메인에 얹어 "지금도 새 인사이트가 쌓이고 있다"는 살아움직이는 감각(War Room 상황판)을 준다.
- **발송(뉴스레터)**: 아카이브에 쌓인 인사이트를 주기적으로 발송하는 채널. 아카이브가 원본, 발송은 배포 채널.

## 4. 제품 태도와의 연결 (Why 강한가)

- "감으로 결정하던 걸 데이터로 검증" = 우리 DNA의 **수치 너머의 큐레이션 / 발견의 희열**.
- 검증 결과에 방법론·데이터 근거를 붙이는 것 = **"있어 보임 = 근거 + 크래프트맨십"**의 콘텐츠 버전.

## 5. 검증 대상 가설 예시 (데이터사이언티스트 제공)

아카이브에 담길 인사이트 1건이 어떤 모습인지 감을 잡기 위한 초기 예시. 콘텐츠 제목(마케터 언어) + 가설 원문(검증 언어)의 짝으로 구성된다.

### 예시 1 — "체류시간이 길다고 다 좋은 게 아니다" : 롱세션 vs 숏세션 맞춤 포맷
- **가설 원문**: 긴 세션이 소수 발생하는 앱과 짧은 세션이 다수 발생하는 앱을 비교할 때, 전자에서 영상 완주율이 높고 후자에서 짧은 소재의 클릭률이 높은 교차 패턴을 보일 것이다. 이를 통해 렙사는 총체류시간이 아닌 세션 구조에 맞춰 광고 포맷을 제안할 수 있다.

### 예시 2 — "피크 치고 나서 후회하지 마라" : 수요 급증 시그널 선제 포착법
- **가설 원문**: 광고주 자체 앱의 이용자 증가 가속도가 카테고리 평균을 연속 상회할 때, 피크가 꺾이기 전에 예산을 증액하고 피크 이후에는 선제적으로 감액할 수 있다.

### 예시 3 — "돈을 더 썼는데 왜 순도달은 그대로지?" : 동종 매체 잠식의 비밀
- **가설 원문**: 타겟과 시간대가 겹치는(패턴이 비슷한) 두 매체는 합산 노출만 늘고 순도달은 안 늘어나는 '대체 관계'이다. 렙사는 두 매체를 추가 조합이 아니라 비용 효율에 따른 대체 관계로 제안할 수 있다.

> 공통 패턴: **마케터의 통념/감(제목) → 데이터로 검증 가능한 명제(가설 원문) → 렙사의 실행 제안**. 인사이트 1건의 데이터 모델(4.오픈퀘스천)을 설계할 때 이 3층 구조를 기준으로 삼는다.

## 6. 오픈 퀘스천

- [ ] 인사이트 1건의 데이터 모델 (가설 / 검증 방법 / 데이터 출처 / 결론 / 신뢰도)
- [ ] 검증 데이터의 출처 — 플랫폼 내부 데이터인가, 외부 벤치마크인가, 둘 다인가
- [ ] 콘텐츠 생산 주체 — 내부 큐레이션인가, 자동 생성인가, 혼합인가
- [ ] RAG 인덱싱 시점 — 발행과 동시인가, 별도 큐인가
- [ ] 메인 노출 형태 — 카드 / 티커 / 피드
