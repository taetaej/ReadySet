# 기획자 온보딩 가이드 (ReadySet)

> 새로 합류한 기획자가 **가장 먼저 읽는 문서**입니다.
> "무엇을 어디서 보고, 어떻게 일하는가"를 한 곳에 모았습니다. 세부 규칙은 각 원본 문서로 연결합니다.
> 이 문서는 안내판입니다. 실제 규칙의 원천은 항상 `.kiro/steering/` 과 `plan/spec/` 입니다.

---

## 1. ReadySet은 어떤 제품인가

광고 캠페인의 **예측·분석·최적화**를 다루는 통합 플랫폼입니다.
단순 계산기가 아니라 **미디어 전략을 다루는 상황실(War Room)** 을 지향합니다. 제품 철학은 아래에서 확인하세요.

- 제품 철학: `plan/ReadySet_Philosophy_The_Media_War_Room.md`
- 한 장 요약: `plan/ReadySet_Philosophy_OnePager.html`
- 전체 시스템 IA: `plan/strategic(highlevel)/예측분석_플랫폼_IA_v1.0.md`

### 솔루션 구성

하나의 **Slot**(광고주별 워크스페이스) 안에서 여러 솔루션이 맥락을 이어받으며 흐릅니다.

| 솔루션 | 하는 일 | 상태 |
|---|---|---|
| **Reach Caster** | 도달·프리퀀시·리치커브 예측 (Ratio Finder / Reach Predictor) | 구현됨 |
| **DataShot** | 데이터셋 생성·상세·목록 | 구현됨 |
| **Budget Optimizer** | 예산 배분·KPI 최적화 (Meridian 기반) | 구현됨 |
| **SpinX** | 결과를 해석해주는 AI 전략 파트너 (우하단 상주) | 구현됨 |

> 핵심 경험: 사용자는 도구를 갈아타는 게 아니라 **하나의 캠페인 판단 세션**을 이어간다.
> 예) Budget Optimizer 결과 → "이 예산안이면 몇 명에게 닿을까?" → Reach Caster로 맥락을 그대로 넘김.

## 2. 기술 스택 (기획자가 알아둘 만큼만)

- **React 18 + TypeScript + Vite**
- 라우팅: React Router DOM 7
- 차트: ECharts, Recharts
- 아이콘: Lucide React
- 스타일: **인라인 스타일 + 일부 전역 CSS 클래스** (Tailwind/CSS Modules 미사용)
- 색상: 항상 `hsl(var(--토큰))` 사용 → 다크모드 자동 지원

개발 서버 실행:

```bash
npm install   # 최초 1회
npm run dev   # http://localhost:5173
```

## 3. 코드/화면은 어디에 있나 (모듈 지도)

작업 대상을 찾을 때 이 표에서 모듈을 먼저 찾습니다. 대부분 **파일명 == 컴포넌트명** 규칙을 따릅니다.

| 모듈 | 경로 | 내용 |
|---|---|---|
| ReachCaster | `src/components/reachcaster/` | 슬롯 홈, 시나리오, 결과 화면 |
| DataShot | `src/components/datashot/` | 데이터셋 생성·상세·목록 |
| Scenario | `src/components/scenario/` | 시나리오 스텝(RatioFinder / ReachPredictor) |
| Budget Optimizer | `src/components/budgetoptimizer/` | `BO*` 프리픽스 컴포넌트 |
| SpinX | `src/components/spinx/` | SpinX 챗/심볼/패널 |
| Layout | `src/components/layout/` | GNB, Sidebar, Breadcrumb, Footer 등 공통 |
| Docs | `src/components/docs/` | 제품 문서 페이지 |
| Common | `src/components/common/` | Avatar, Calendar 등 공용 UI |

라우팅 전체는 `src/App.tsx` 에서 한눈에 볼 수 있습니다. 화면을 찾을 땐 URL → App.tsx → 컴포넌트 순으로 따라가세요.

주요 경로:

```
/slotboard                              SlotBoard (워크스페이스)
/slot/:slotId                           Slot 홈
/reachcaster/scenario/new               시나리오 생성
/reachcaster/scenario/ratio-finder/result
/reachcaster/scenario/reach-predictor/result
/datashot, /datashot/new, /datashot/:id DataShot
/budgetoptimizer, .../scenario/new, .../scenario/:id/result
/docs/:slug                             제품 문서
/component                              컴포넌트 라이브러리(참고용)
```

## 4. 기획자의 핵심 산출물: 화면 정의서(Spec)

기획자가 만드는 가장 중요한 문서는 **화면 상세 명세서**입니다. `plan/spec/` 에 모여 있습니다.

### 반드시 먼저 읽을 것

1. **작성 가이드** → `.kiro/steering/screen-specification-guide.md`
   - 정의서는 두 곳의 원천 데이터가 됩니다: (1) 제품 Docs, (2) AI 기반 테스트케이스(TC)
   - 그래서 "왜 이렇게 정했는가(의도)" + "검증 가능한 규칙(조건→기대결과)"을 **둘 다** 담아야 합니다
2. **퀄리티 기준(합격선)** → `.kiro/steering/spec-quality-bar.md`
   - 5개 항목 × 20점, **85점 합격**. 스펙을 넘기기 전 자가 채점하세요

### 기존 스펙을 참고하세요 (`plan/spec/`)

새 스펙은 백지에서 쓰지 말고 유사 화면의 기존 스펙을 본떠 작성합니다. 예:

- `BudgetOptimizer_Result_Spec.md`, `BudgetOptimizer_Scenario_Creation_Spec.md`
- `DataShot_CreateDataset_Spec.md`, `DataShot_DatasetDetail_Spec.md`
- `Reach_Caster_Result_Screens_Spec.md`, `Scenario_Creation_Spec.md`
- `Common_Layout_Spec.md`, `Breadcrumb_Navigation_Policy.md`

### 스펙 작성 시 지켜야 할 정책들 (`.kiro/steering/`)

| 상황 | 참조 문서 |
|---|---|
| 다이얼로그(모달) 설계 | `ui-dialog-policy.md` |
| 유효성 검증 메시지 문구 | `ui-validation-message-policy.md` |
| 아이콘 선택 | `lucide-icon-reference.md` |
| 릴리즈 노트 작성 | `release-notes-guide.md` |

## 5. 디자인 판단 기준 (UI를 그릴 때)

ReadySet은 **Linear / Vercel / Spotify** 류의 고밀도·저소음·고마감 인터페이스를 지향합니다.

- **판단 원칙(어떻게 배치·판단하는가)** → `.kiro/steering/ui-design-principles.md`
  - 강조는 한 곳만, 군더더기 제거, 근거를 붙인 숫자, 시그니처 그린은 "정답"에만
- **토큰·사이즈(무엇을 쓰는가)** → `.kiro/steering/design-system-guide.md`
  - 컬러 토큰, 타이포, 간격, 그림자 등 구체 값
- **코드 패턴/컨벤션** → `.kiro/steering/codebase-patterns-steering.md`
  - 인라인 스타일 규칙, import 경로, 라이브러리 사용 방식

한 줄 원칙: **어려운 걸 쉽게 보여주되, 그 쉬움이 "단순해서"가 아니라 "똑똑하게 정리해서"라는 게 느껴지게 한다.**

## 6. 협업 도구: Kiro (AI 에이전트)

이 프로젝트는 Kiro 에이전트와 함께 개발합니다. 기획자도 Kiro로 스펙 초안·리서치·문서 정리를 진행할 수 있습니다.

- 기획 방법론 정리: `plan/methodology/Kiro_기획방법론_정리.md`
- 핸드오프(개발 이관) 가이드: `.kiro/steering/handoff-implementation-guide.md`

Kiro가 항상 참조하는 규칙은 `.kiro/steering/` 에 있습니다. 새 규칙을 팀 표준으로 만들고 싶으면 이 폴더에 문서를 추가/수정하면 됩니다.

## 7. 첫 주 추천 순서

1. **제품 이해** — 철학 문서 + IA 읽기 (섹션 1)
2. **화면 둘러보기** — `npm run dev` 실행 후 각 솔루션 클릭해보기 (섹션 2·3)
3. **기존 스펙 3개 정독** — Budget Optimizer / DataShot / Reach Caster 각 1개씩 (섹션 4)
4. **작성 규칙 습득** — screen-specification-guide + spec-quality-bar (섹션 4)
5. **디자인 감각 맞추기** — ui-design-principles 읽기 (섹션 5)
6. **작은 스펙 하나 시도** — 유사 스펙을 본떠 초안 작성 → 85점 기준 자가 채점
