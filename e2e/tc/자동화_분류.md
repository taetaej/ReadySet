## 3. 보류 — 바인딩 생기면 자동 가능 (바인딩 종류별)

프로토타입이 아닌 실제 환경(fixture·계정·DATA_CONTRACT)에서 자동화 가능. 많은 TC가 한 ID 안에
"표시(AUTO) + 수치/전송(보류)"를 함께 가지며, 표시부는 §2에서 AUTO로 커버하고 수치·전송부만 여기 보류로 남긴다.

| TC ID 범위 | 내용 | 필요한 바인딩 |
|---|---|---|
| BO-RESULT-002~006 | 상태별 진입(Processing/Pending/Error), 삭제·권한 접근 | FIXTURE(상태별 시나리오), AUTH(권한 계정) |
| BO-RESULT-011~013 | Copy Link/Excel/PDF 수행 "성공"(메뉴 항목 존재는 010 AUTO) | DOWNLOAD_CONTRACT |
| BO-RESULT-016~018 | 복제/이동/삭제 실제 수행·토스트(항목 존재는 015 AUTO) | 승인 QA 계정·폐기 가능 데이터 |

## 4. 수동 유지 (MANUAL_REVIEW)

자동 채점이 **원리적으로 부적합**한 항목. 사람이 봐야 한다. (차트 제목·설명·토글·툴팁 열림 등
"텍스트/상태" 부분은 §2에서 AUTO로 커버하고, 아래의 "시각·주관·체감" 부분만 수동으로 남긴다.)

| 유형 | 대표 TC | 왜 수동인가 |
|---|---|---|
| 차트 시각 | BO-RESULT-059~064·066~078·082~096 (Budget Share 바 폭·색 / Response Curve 곡선 path·마커 Y / Weekly 음영 밴드 / Incremental 워터폴 막대·Y축 절단) | SVG/Canvas 픽셀·곡선 모양은 문서로 단정 불가, 허용오차 기준 없음 (원본 §1.4) |
| 문구 품질 | BO-RESULT-047·098·099 (스코어카드·SpinX 해석 약 300자·정성 표현) | "자연스러운가"는 주관. 고정 임계값 아님 |

## 5. ROI 요약 (현 시점) — 원본 200건 기준

- **자동(AUTO) 45건**: 핵심 렌더·헤더/메타·모드 전환·스코어카드 라벨·차트 제목/툴팁·SpinX 패널 열림·테이블 헤더/토글·0원 배분·Easy Create 모달 → **매 실행 약 35초 자동 채점(45 passed)**.
- **보류(바인딩 생기면 자동) 약 95건**: 상태별 진입·KPI별 수치·스코어카드/테이블 수치 정합·Easy Create 전송 payload·Export 다운로드 등 (FIXTURE·AUTH·DATA_CONTRACT·TRANSFER_CONTRACT·DOWNLOAD_CONTRACT 확보가 전제).
- **수동(MANUAL) 약 60건**: 차트 시각(픽셀·곡선·path)·문구 품질(약 300자 정성)·다크모드·반응형·서버 권한·접근성 체감.

> 집계: **자동 45 / 보류 ~95 / 수동 ~60** (원본 200건 + 직접 연관 부록 10건 기준, 한 ID가 표시=AUTO·수치=보류로 중복 성격을 가지는 경우 대표 분류로 집계).
> 결론: 바인딩(fixture·testid·계정·DATA_CONTRACT)에 투자하면 보류 ~95건을 추가로 자동 채점 전환 가능.
> 특히 프론트에 **`data-testid` 부여**를 요청하면 셀렉터가 안정화돼 자동화 적중률이 크게 오른다.
